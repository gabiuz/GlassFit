> **Identifier note:** `IMP-MS39` (documented in `docs/implementation/ms39.md`) succeeds `IMP-MS38` in the sequential implementation specification series in `docs/implementation/`. This specification resolves precision limitations in the visualization placement controls where adjusting 3D model orientation via continuous range sliders makes landing on precise integer degrees (such as 0 deg, 1 deg, -5 deg, or 15 deg) difficult and error-prone on both desktop mice and compact touchscreens. `IMP-MS39` introduces accessible, bounded `+` and `-` stepper buttons that increment and decrement yaw and pitch by exactly 1 degree while preserving slider synchronization, numerical clamping, touch target ergonomics, keyboard accessibility, and downstream Three.js render pipeline integrity.

## 1. Authorized Requirement

In the GlassFit photo-based visualization workspace (`/visualize/[productId]/workspace`), users orient 3D fenestration models against uploaded room backgrounds using the "Placement" accordion inside `src/features/visualization/components/ProductModelWorkspace.tsx`.

Currently, yaw ("Turn Left / Right") and pitch ("Tilt Up / Down") adjustments are driven exclusively by continuous HTML range sliders (`<input type="range" />`). While range sliders excel at coarse rotational sweeps, they exhibit notable usability deficiencies during fine-tuning:

1. Dragging a range slider with a mouse or trackpad frequently skips 2 to 5 degrees per micro-movement, making exact alignment with architectural mullions, jambs, or walls tedious.
2. On compact touch screens, finger width obscures the slider thumb and degree label, preventing precise single-degree adjustments.
3. Returning to neutral orientation (0 deg) or stepping incrementally by 1 deg requires repeated sliding attempts rather than direct, deterministic clicks.

IMP-MS39 must deliver these outcomes:

1. Dedicated decrement (`-`) and increment (`+`) stepper buttons for yaw that change the orientation angle by exactly -1 deg and +1 deg per interaction.
2. Dedicated decrement (`-`) and increment (`+`) stepper buttons for pitch that change the tilt angle by exactly -1 deg and +1 deg per interaction.
3. Strict clamping within authorized angle domains: yaw within [-180, 180] degrees, and pitch within [-90, 90] degrees.
4. Automatic disablement of stepper buttons when boundary limits are reached (`-` disabled at minimum limit; `+` disabled at maximum limit).
5. Bi-directional synchronization between the stepper buttons, range slider thumb, and degree numerical readout.
6. Zero degradation or desynchronization in downstream consumers, including the Three.js offscreen renderer, scene cache fingerprints, snapshot persistence, and quotation payloads.
7. Mobile and touch compliance with the 44px by 44px minimum interactive target in DSD-UI15 and IMP-MS37, without introducing horizontal clipping at 320px viewport widths.

No database migration, backend CV microservice change, pricing engine modification, or new external dependency is authorized. This document is an implementation specification; no application code is to be executed or committed during planning.

## 4. Functional, UI/UX, and Interaction Contracts

### 4.1 Numerical Stepping & Clamping Contract

The stepper logic must be deterministic and pure. It must snap existing values to integers before applying the step delta to ensure non-integer values (from automatic angle estimation) do not produce fragmented decimal angles.

| Function | Signature | Bound Minimum | Bound Maximum | Step Delta |
|---|---|---|---|---|
| `stepYaw` | `(current: number, delta: 1 \| -1) => number` | -180 | 180 | +1 or -1 |
| `stepPitch` | `(current: number, delta: 1 \| -1) => number` | -90 | 90 | +1 or -1 |

Behavior Specifications:
1. `stepYaw(0, 1)` returns `1`.
2. `stepYaw(0, -1)` returns `-1`.
3. `stepYaw(180, 1)` returns `180` (clamped at upper boundary).
4. `stepYaw(-180, -1)` returns `-180` (clamped at lower boundary).
5. `stepYaw(14.7, 1)` returns `16` (snaps 14.7 to 15, then increments to 16).
6. `stepYaw(14.7, -1)` returns `14` (snaps 14.7 to 15, then decrements to 14).
7. `stepPitch(0, 1)` returns `1`.
8. `stepPitch(0, -1)` returns `-1`.
9. `stepPitch(90, 1)` returns `90` (clamped at upper boundary).
10. `stepPitch(-90, -1)` returns `-90` (clamped at lower boundary).

### 4.2 UI Layout and Component Structure

Use a responsive layout for the Placement accordion controls. Keep the slider and stepper on one row when the available control width can preserve the minimum slider track and full-size touch targets. Stack the slider and stepper when it cannot.

#### Standard Layout: Slider and Stepper on One Row

At widths with at least 320px of available control-row width, the range slider and stepper pill may sit side-by-side beneath the label, provided the slider retains at least 120px of usable track width.

Row Structure:
- Label row: Section title (e.g. `Turn Left / Right`)
- Control row:
  - Range slider: `flex-1 min-w-0 accent-[#07b6d3] h-2 bg-[#c3c3c3] rounded-lg cursor-pointer`
  - Stepper pill: white surface, `border border-[#c3c3c3] rounded-[10px]`, horizontal padding, flex layout, and no shrink.
    - Decrement and increment buttons each have `min-h-11 min-w-11 shrink-0` (44px by 44px minimum), centered 16px to 20px icon, visible focus ring, and disabled styling.
    - Numerical readout: `text-[#0f1422] text-xs font-normal tabular-nums whitespace-nowrap min-w-12 text-center`.

The stepper pill must reserve at least 164px: two 44px buttons, a 48px readout, inter-item gaps, padding, and borders. The slider must retain at least 120px when displayed beside it. These are minimum content widths; available width must be measured inside the actual Placement accordion, after its padding.

#### Narrow Layout: Stacked Slider and Stepper

- When the available control-row width is less than 320px, put the full-width range slider on its own row and put the stepper pill on a second row, aligned to the end.
- Preserve the pill's 164px minimum width and both buttons' 44px by 44px minimum footprints. Do not compress, overlap, or clip the controls to keep them on one row.
- At 320px viewport width, verify the stacked layout inside the actual mobile configuration drawer and its padded accordion content. The slider remains full-width within the content column, the pill fits without horizontal scrolling, and all controls remain visible.

The responsive switch is based on measured available control-row width, not only the device viewport width. This accommodates desktop sidebars and mobile drawers with different internal padding.

### 4.3 Icon Assets and Design Token Consistency (BAN-UI-09)

In compliance with BAN-UI-09:
1. Stepper icons must reuse existing project assets:
   - Option 1 (Preferred for consistency with Quantity control): `Image` components referencing `/visualization/minus-solid-full 1.svg` and `/visualization/plus-solid-full 1.svg`.
   - Option 2 (Preferred for clean inline SVG scaling): `Minus` and `Plus` from `lucide-react` (already present in `package.json`).
2. Disabled State Tokens:
   - When disabled, buttons apply `opacity-30 cursor-not-allowed` and HTML `disabled={isAtLimit}`.
   - Hover effects are suppressed when disabled.
3. Active State Tokens:
   - Interactive buttons provide `hover:opacity-75 active:scale-95 transition-all cursor-pointer`.
   - Focus outline matches the system accent `#07b6d3` via `focus-visible:ring-2 focus-visible:ring-[#07b6d3] outline-none` and remains visible around the full hit target.

### 4.4 Accessibility Contract

1. Attribute Specifications:
   - Yaw Decrement: `aria-label="Decrease yaw by 1 degree"`, `type="button"`, `disabled={yaw <= -180}`
   - Yaw Increment: `aria-label="Increase yaw by 1 degree"`, `type="button"`, `disabled={yaw >= 180}`
   - Pitch Decrement: `aria-label="Decrease pitch by 1 degree"`, `type="button"`, `disabled={pitch <= -90}`
   - Pitch Increment: `aria-label="Increase pitch by 1 degree"`, `type="button"`, `disabled={pitch >= 90}`
2. Slider Semantic Parity:
   - Slider elements retain `aria-label="Turn Left / Right"` and `aria-label="Tilt Up / Down"` respectively.
   - Native arrow key manipulation on focused sliders remains fully operational.
3. Touch Target Dimensions:
   - Every stepper button has a minimum 44px by 44px interactive footprint in all viewport modes, including disabled states.
   - The required target size applies to the button hit area, not just the icon or visible glyph.
   - The mobile stacked layout may increase the control group's height; it must not reduce button hit areas or cause horizontal overflow at 320px.
4. Typography:
   - `tabular-nums` class applied to the numerical degree text ensures uniform digit widths so the stepper container does not flutter in width as values switch between 1, 2, and 3 digits.

## 8. Definition of Done

IMP-MS39 is considered complete only when all of the following criteria are satisfied:

1. Both yaw and pitch controls feature dedicated `-` and `+` stepper buttons.
2. Clicking a stepper button increases or decreases the respective angle by exactly 1 degree.
3. Angles are strictly clamped within [-180, 180] for yaw and [-90, 90] for pitch.
4. Stepper buttons automatically disable when their respective boundaries are reached.
5. The range slider thumb, degree text, and Three.js canvas update in complete synchronization.
6. Controls are fully responsive and do not clip or overflow on viewports down to 320px width.
7. Accessibility standards are satisfied (`aria-label`, `type="button"`, visible focus ring, keyboard activation, and 44px by 44px minimum stepper button targets).
8. Automated tests in `tests/unit/rotationStepper.test.ts` pass cleanly.
9. Full repository verification commands (`npm run test`, `npm run lint`, `npx tsc --noEmit`, `npm run build`) execute with zero errors.
10. No application code has been implemented prior to plan approval.
