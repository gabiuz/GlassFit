## 1. Outcome and Problem Context

In Philippine residential and commercial fenestration, security grilles are installed across windows and architectural openings to deter unauthorized ingress and provide barrier safety. However, windows installed behind security grilles (such as jalousie windows with mechanical rotary operators, awning windows with cam latches, casement windows with espagnolette or push handles, and sliding windows with recessed flush pulls) require physical access so occupants can open, close, and lock the sashes from inside or outside the building.

In `IMP-MS80`, GlassFit introduced operator-targeted alignment for insect screens. When an insect screen is placed over operating mechanisms, it generates hinged or sliding wicket access hatches (doors). Because insect mesh must maintain an unbroken barrier against mosquitoes and pests, an operable door with latches is required.

Security grilles serve a different functional and physical purpose:
1. **Protection Without Operable Doors:** A security grille does not need a hinged door hatch. Hinged wicket doors on security grilles require heavy padlocks or security mortise locks, which increase fabrication costs, invite lock jamming, and complicate emergency egress.
2. **Framed Rectangular Clearance Openings:** Instead of a moving hatch, fabricators weld or fasten a compact rectangular sub-frame (clearance collar) into the grille pattern directly aligned with the window handle or operator. The area inside this rectangular collar is completely empty, allowing an occupant's hand and wrist to reach through the grille to operate the handle, while the surrounding rigid aluminum bars prevent full-body entry or physical breach.
3. **Picket Interruption and Cutout Framing:** When an opening is formed in a grille, the continuous vertical pickets or horizontal bars that would otherwise cross the handle space must be clipped and capped. A four-piece rectangular frame (two horizontal border rails and two vertical border stiles) surrounds the opening to structurally anchor the cut bar ends, eliminate sharp raw extrusion edges, and maintain structural rigidity.

```
Physical Comparison: Screen Hatch vs Grille Opening
-----------------------------------------------------------------------------
Feature               Insect Screen Add-on          Security Grille Add-on
-----------------------------------------------------------------------------
Alignment Source      Host operator/handle target   Same host target components
Physical Form         Hinged wicket door hatch      Framed rectangular opening
Interior Space        Covered by operable mesh      Completely empty inside
Hardware Required     Hinges, wicket latch, clips   4-sided frame collar, cleats
Protection Focus      Pest barrier (sealed)         Physical intruder deterrence
-----------------------------------------------------------------------------
```

This milestone document establishes the end-to-end engineering specification to extend operator alignment targets to security grilles, generate parametric rectangular handle openings with empty interiors in Three.js, accurately clip crossing pickets, calculate linear framing extrusion cut lists in the BOM engine, and disclose handle openings across customer quotation summaries and fabricator consultation PDFs.

## 3. Technical Contract and Architectural Design

### 3.1 Unified Alignment Target Binding Contract

To maximize code reuse and eliminate duplicate configuration effort for administrators, security grilles can share the exact same operator and handle alignment targets already defined for insect screens, or bind to specific handle components on the host product.

```typescript
export interface GrilleOpeningConfig {
  enabled: boolean;
  targetComponentKeys: string[];
  cutoutWidthMm: number;    // Default: 150mm (range: 100mm to 250mm)
  cutoutHeightMm: number;   // Default: 180mm (range: 120mm to 300mm)
  collarExtrusionCode?: string; // Optional raw material code for border collar
  cornerCleatCountPerOpening: number; // Default: 4 pieces
}

export interface GrilleOpeningInstance {
  index: number;
  targetKey: string;
  centerCoordinates: { x: number; y: number; z: number };
  boundingBox: {
    minX: number;
    maxX: number;
    minY: number;
    maxY: number;
  };
  dimensionsMm: { width: number; height: number };
}
```

1. **Target Component Inheritance:** When an administrator configures a host window that already has operator targets assigned (e.g. `operator_lower`, `operator_upper` on a jalousie window, or `cam_handle` on an awning window), the Security Grille setup interface exposes an option:
   `[x] Inherit Host Operator Targets (2 targets detected)`.
2. **Independent Selection Mode:** If unchecked, administrators can independently select specific hardware components from the host product's constituent parts list in Step 4.
3. **Opening Dimension Defaults:** Standard Philippine fenestration requires a minimum hand clearance of 120mm width and 150mm height for operating jalousie cranks or casement handles. The default cutout dimension is set to $150\text{mm} \times 180\text{mm}$ ($0.15\text{m} \times 0.18\text{m}$), fully adjustable by the administrator within safe structural bounds ($100\text{mm} \le W \le 250\text{mm}$, $120\text{mm} \le H \le 300\text{mm}$).

### 3.2 3D Parametric Rectangular Cutout Generation and Bar Clipping Contract

In `src/lib/visualization/parametricProductBuilder.ts`, the procedural grille assembly engine must construct rectangular openings centered on target centroids and clip crossing pickets.

#### 3.2.1 Target Centroid and Clearance Bounding Box Resolution
For each assigned target component key $T_i \in \{T_1, \dots, T_N\}$:
1. Locate the corresponding 3D mesh object $M(T_i)$ within the host product group.
2. Calculate its world or group-local bounding box centroid:
   $$\vec{C}_i = \text{centroid}(M(T_i)) = (X_i, Y_i, Z_i)$$
3. Define the 2D clearance bounding box in the grille's local coordinate plane:
   $$X_{\min, i} = X_i - \frac{W_{\text{cutout}}}{2}, \quad X_{\max, i} = X_i + \frac{W_{\text{cutout}}}{2}$$
   $$Y_{\min, i} = Y_i - \frac{H_{\text{cutout}}}{2}, \quad Y_{\max, i} = Y_i + \frac{H_{\text{cutout}}}{2}$$
4. Boundary Clamping Guardrail: Clamp $[X_{\min, i}, X_{\max, i}]$ and $[Y_{\min, i}, Y_{\max, i}]$ to ensure a minimum structural perimeter margin of 35mm from the grille outer perimeter frame.

#### 3.2.2 Picket Bar Clipping Algorithm
When generating vertical pickets at lateral positions $X_p$:
1. Check if the picket's X position falls within any opening's lateral span:
   $$X_p \in [X_{\min, i}, X_{\max, i}]$$
2. If $X_p$ does NOT intersect any opening:
   - Generate a single continuous vertical bar spanning from bottom frame rail to top frame rail.
3. If $X_p$ DOES intersect opening $i$:
   - Do NOT generate a bar passing through $[Y_{\min, i}, Y_{\max, i}]$.
   - Generate two discrete bar segments:
     - **Lower Segment:** Extends from the bottom frame rail ($Y_{\text{sill}}$) to the bottom collar rail ($Y_{\min, i}$).
     - **Upper Segment:** Extends from the top collar rail ($Y_{\max, i}$) to the top frame rail ($Y_{\text{head}}$).
   - This physically eliminates bars from the interior volume of the opening, leaving it completely empty for hand insertion.

#### 3.2.3 Four-Piece Rectangular Collar Sub-Frame Assembly
To structurally frame the cutout and cap the cut picket ends, construct a dedicated `THREE.Group` named `Grille_Opening_Collar_${i}` containing four linear extrusion members:
1. **Bottom Border Rail:** Horizontal bar of length $W_{\text{cutout}}$, positioned at $(X_i, Y_{\min, i}, Z_{\text{grill}})$.
2. **Top Border Rail:** Horizontal bar of length $W_{\text{cutout}}$, positioned at $(X_i, Y_{\max, i}, Z_{\text{grill}})$.
3. **Left Border Stile:** Vertical bar of length $H_{\text{cutout}}$, positioned at $(X_{\min, i}, Y_i, Z_{\text{grill}})$.
4. **Right Border Stile:** Vertical bar of length $H_{\text{cutout}}$, positioned at $(X_{\max, i}, Y_i, Z_{\text{grill}})$.
5. Material and Finish: Assigned the active grille aluminum finish material (`addonAluminumFinish`), matching the outer grille frame and pickets.
6. Empty Interior Invariant: No mesh, plane, glass, or wire infill is added inside the opening group. `userData.isOpenClearance = true` is stamped on the collar container.

### 3.3 Parametric BOM and Linear Cut List Accounting Contract

In `calculateGrilleLinearBOM()` and `addonPricingEngine.ts`, handle access openings directly impact material quantities and cutting lists:

```typescript
export interface GrilleOpeningBOMImpact {
  openingCount: number;
  collarLinearMeters: number;     // 2 * (W + H) * N
  collarPieceCount: number;       // 4 * N pieces
  interruptedPicketCount: number; // Number of pickets split by cutouts
  netPicketLengthDeduction: number; // Total length of omitted bar sections
  cornerCleatQuantity: number;    // 4 * N corner connecting brackets
}
```

1. **Linear Extrusion Quantity Formulation:**
   For an aperture of width $W$, height $H$, with $N$ handle openings of size $w \times h$:
   - **Outer Perimeter Frame:** $L_{\text{perimeter}} = 2W + 2H$
   - **Uninterrupted Pickets:** For $P_{\text{full}}$ pickets not crossing cutouts:
     $$L_{\text{pickets\_full}} = P_{\text{full}} \times H_{\text{infill}}$$
   - **Interrupted Pickets:** For $P_{\text{split}}$ pickets crossing cutouts:
     $$L_{\text{pickets\_split}} = P_{\text{split}} \times (H_{\text{infill}} - h)$$
   - **Opening Collar Frames:** For $N$ rectangular collars:
     $$L_{\text{collars}} = N \times (2w + 2h)$$
   - **Total Extrusion Linear Meters:**
     $$L_{\text{total}} = L_{\text{perimeter}} + L_{\text{pickets\_full}} + L_{\text{pickets\_split}} + L_{\text{collars}}$$
2. **Hardware Accounting:**
   - Security grilles with handle openings DO NOT bill for screen wicket hinges or screen latches.
   - Each rectangular collar utilizes 4 internal corner cleats or L-brackets to join the four border profiles:
     $$\text{Corner Cleats} = 4 \times N \text{ pieces}$$
3. **BOM Consolidation Alignment (MS85 Parity):**
   - The linear meters from outer frame, pickets, and collar border bars consolidate into the single `Security Grille Aluminum Framing` line item per `IMP-MS85`.
   - The contributing component trace records:
     `Collar Border Rails: 2x 150mm, Collar Border Stiles: 2x 180mm (per opening)`.

## 8. Scope Boundary

1. **In Scope:**
   - Schema support for `grille_opening_target_component_keys` and `grille_opening_config` in `product_compatible_addons`.
   - Admin UI controls in `AddonInheritanceSection.tsx` for toggling handle openings, selecting targets, and setting dimensions.
   - 3D Three.js parametric generation of rectangular collar frames with empty interiors and clipped picket segments.
   - Parametric BOM calculations for collar extrusions, split pickets, and corner cleat hardware.
   - Customer workspace feature badges, quotation cut list accordions, and consultation PDF disclosures.
2. **Out of Scope:**
   - Movable hinged wicket doors or padlocks on security grilles (grille openings are permanent framed cutouts, not operable doors).
   - Altering existing insect screen hatch logic or database columns.
   - Modifying OpenCV fiducial paper detection microservices or space photo calibration.
   - Introducing external styling libraries or foreign UI dependencies.
