## 1. Outcome and Scope

`IMP-MS46` implements the server-side computer vision algorithms within `fastapi-service/` to detect standard paper sheets placed on interior walls and calculate a coplanar metric scale factor (centimeters per pixel) along with a 3x3 planar homography transformation matrix.

When a client dispatches an uploaded space photo with `calibration_mode="paper_fiducial"` and an explicit `paper_standard` (Short, A4, or Long, per IMP-MS45), the FastAPI `/analyze-image` pipeline:

1. Ingests the normalized image and targeted paper dimensions.
2. Applies a multi-scale adaptive edge detection and contour approximation pipeline.
3. Filters candidates using geometric constraints (convexity, 4-vertex quadrilateral check, interior angle limits, and aspect ratio matching).
4. Re-orders detected vertices into canonical perspective orientation (top-left, top-right, bottom-right, bottom-left).
5. Computes the planar homography matrix ($H$) mapping pixel coordinates directly to canonical millimeters.
6. Derives the true metric scale factor (`scale_cm_per_px`) for the wall plane.
7. Computes a detection confidence score:
   - Confidence $\ge 0.65$: Returns `status="detected"`, corner coordinates, scale factor, and homography matrix.
   - Confidence $< 0.65$ or no candidate found: Returns `status="manual_pin_required"` with optional best candidate hints, triggering the interactive client-side 4-point pin confirmation (IMP-MS47).
8. When `calibration_mode="standard"`, the module bypasses paper detection completely, guaranteeing zero performance regression for standard uploads.

### 1.1 Non-Negotiable Invariants

1. **Deterministic Geometry over Black-Box Heuristics:** The system uses deterministic OpenCV contour detection and projective planar homography, rather than ungrounded neural hallucinations.
2. **Strict Time Budget:** The fiducial detection pipeline must execute in under 45ms on a 1024x1024 normalized image, staying well within the master 2,500ms response time requirement (`QAD-TC4`).
3. **No External ML Weights:** No additional heavy model weights (such as secondary neural networks) may be introduced into the repository. The algorithm relies solely on OpenCV (`cv2`) and NumPy (`numpy`), both already installed in `fastapi-service/requirements.txt`.
4. **Graceful Fallback:** If edge contrast is insufficient (e.g., white bond paper on an off-white wall), the endpoint must never raise an HTTP 500 error. It must return `status="manual_pin_required"` with `confidence=0.0`.
5. **No Em-Dashes:** In compliance with `BAN-PUNCT-01`, all documentation, docstrings, and code comments must use hyphens, colons, or parentheses.

## 2. Mathematical Formulation & Coordinate Geometry

### 2.1 Canonical Metric Paper Definitions

Let standard paper dimensions in millimeters be defined as $(W_m, H_m)$ oriented upright:

| Paper Standard Identifier | Metric Width ($W_m$) | Metric Height ($H_m$) | Canonical Aspect Ratio ($H_m / W_m$) |
|---|---|---|---|
| `short` (Letter) | 215.9 mm | 279.4 mm | 1.2941 |
| `a4` (ISO 216) | 210.0 mm | 297.0 mm | 1.4143 |
| `long` (Folio) | 215.9 mm | 330.2 mm | 1.5294 |

Let the canonical destination points in metric space (in centimeters, origin at top-left) be:
$$P_0 = (0, 0), \quad P_1 = (W_m / 10, 0), \quad P_2 = (W_m / 10, H_m / 10), \quad P_3 = (0, H_m / 10)$$

### 2.2 Planar Homography Transformation

Given four ordered image pixel coordinates $p_i = (u_i, v_i)$ for $i \in \{0, 1, 2, 3\}$, the projective mapping between pixel coordinates and the metric wall plane is represented by a 3x3 homography matrix $H$:

$$\begin{bmatrix} x_{\text{metric}} \\ y_{\text{metric}} \\ 1 \end{bmatrix} \sim H \begin{bmatrix} u \\ v \\ 1 \end{bmatrix} = \begin{bmatrix} h_{11} & h_{12} & h_{13} \\ h_{21} & h_{22} & h_{23} \\ h_{31} & h_{32} & h_{33} \end{bmatrix} \begin{bmatrix} u \\ v \\ 1 \end{bmatrix}$$

$H$ is calculated using the Direct Linear Transform (DLT) via `cv2.getPerspectiveTransform(src_pts, dst_pts)`.

### 2.3 Coplanar Scale Factor Derivation

While $H$ allows rectifying any arbitrary point on the wall plane, a global scalar scale factor `scale_cm_per_px` provides backward compatibility with downstream consumption in `src/lib/visualization/scaleEstimation.ts`.

The physical scale factor is derived from the geometric mean of top/bottom edge lengths and left/right edge lengths:

$$\text{topWidth}_{\text{px}} = \|p_1 - p_0\|, \quad \text{bottomWidth}_{\text{px}} = \|p_2 - p_3\|$$
$$\text{leftHeight}_{\text{px}} = \|p_3 - p_0\|, \quad \text{rightHeight}_{\text{px}} = \|p_2 - p_1\|$$

$$\text{avgWidth}_{\text{px}} = \sqrt{\text{topWidth}_{\text{px}} \cdot \text{bottomWidth}_{\text{px}}}$$
$$\text{avgHeight}_{\text{px}} = \sqrt{\text{leftHeight}_{\text{px}} \cdot \text{rightHeight}_{\text{px}}}$$

$$\text{scale}_W = \frac{W_m / 10}{\text{avgWidth}_{\text{px}}}, \quad \text{scale}_H = \frac{H_m / 10}{\text{avgHeight}_{\text{px}}}$$

$$\text{scale}_{\text{cm\_per\_px}} = \frac{\text{scale}_W + \text{scale}_H}{2}$$

## 3. Computer Vision Detection Algorithm

The detection pipeline is implemented in a dedicated module `fastapi-service/paper_calibration.py`:

```
Input: Image BGR + paper_standard ('short' | 'a4' | 'long')
   │
   ├── 1. Pre-Processing: Grayscale + Bilateral Filter (noise reduction preserving edges)
   │
   ├── 2. Multi-Thresholding:
   │       ├── Path A: Adaptive Gaussian Thresholding (illumination invariance)
   │       └── Path B: Canny Edge Detection with Otsu upper bound
   │
   ├── 3. Morphological Closing (closing gaps in paper edges)
   │
   ├── 4. Contour Extraction: cv2.findContours (RETR_EXTERNAL, CHAIN_APPROX_SIMPLE)
   │
   ├── 5. Polygon Approximation: cv2.approxPolyDP(cnt, epsilon = 0.02 * perimeter, closed = True)
   │
   ├── 6. Geometric Filter Cascade:
   │       ├── Constraint 1: Exactly 4 vertices
   │       ├── Constraint 2: Strictly convex (cv2.isContourConvex)
   │       ├── Constraint 3: Bounding area between 0.05% and 15% of total image pixels
   │       ├── Constraint 4: Interior corner angles within [60 deg, 120 deg]
   │       └── Constraint 5: Aspect ratio within +/- 15% of target standard (either upright or landscape)
   │
   ├── 7. Corner Ordering: Re-order vertices to [TL, TR, BR, BL]
   │
   ├── 8. Homography & Metric Scale Math: cv2.getPerspectiveTransform + scale derivation
   │
   └── 9. Confidence Scoring & Result Packaging
```

### 3.1 Geometric Constraints and Filtering Logic

```python
def _evaluate_paper_candidate(
    contour: np.ndarray,
    target_aspect: float,
    image_area: int,
) -> tuple[bool, float, list[list[float]]]:
    """
    Evaluates a 4-vertex contour against physical paper criteria.
    Returns (is_valid, confidence, ordered_corners).
    """
    # 1. Vertex count check
    if len(contour) != 4:
        return False, 0.0, []

    # 2. Convexity check
    if not cv2.isContourConvex(contour):
        return False, 0.0, []

    # 3. Area threshold check (0.05% to 15% of photo area)
    area = cv2.contourArea(contour)
    area_ratio = area / max(image_area, 1)
    if not (0.0005 <= area_ratio <= 0.15):
        return False, 0.0, []

    pts = contour.reshape(4, 2).astype(np.float32)
    ordered_pts = _order_corners(pts)

    # 4. Angle validation (ensure corners are near-rectangular: 60 to 120 degrees)
    if not _validate_interior_angles(ordered_pts, min_deg=60.0, max_deg=120.0):
        return False, 0.0, []

    # 5. Aspect ratio check
    w = np.linalg.norm(ordered_pts[1] - ordered_pts[0])
    h = np.linalg.norm(ordered_pts[3] - ordered_pts[0])
    measured_aspect = max(w, h) / max(min(w, h), 1e-5)

    aspect_error = abs(measured_aspect - target_aspect) / target_aspect
    if aspect_error > 0.15:  # Allow up to 15% perspective distortion tolerance
        return False, 0.0, []

    # Score calculation based on aspect match and squareness
    confidence = max(0.1, min(1.0, 1.0 - (aspect_error / 0.15) * 0.5))
    return True, confidence, ordered_pts.tolist()
```

### 3.2 Canonical Corner Ordering

The 4 points are deterministically ordered as `[top_left, top_right, bottom_right, bottom_left]`:

- Sort points based on their sum ($x + y$):
  - Top-left corner has the smallest $x + y$.
  - Bottom-right corner has the largest $x + y$.
- Sort remaining two points based on their difference ($y - x$):
  - Top-right corner has the smallest $y - x$.
  - Bottom-left corner has the largest $y - x$.

   - Implement `detect_paper_fiducial()` using adaptive thresholding and Canny edge detection.
   - Filter contours and score the best candidate by aspect ratio proximity.

4. **Step 4: Homography and Scale Computation**
   - Compute `cv2.getPerspectiveTransform` mapping corners to canonical paper dimensions in cm.

   - Wire `detect_paper_fiducial()` into `fastapi-service/main.py` under the `/analyze-image` route handler.
   - Expose the `paper_calibration` payload in the JSON response.

## 8. Risks and Mitigations

| Risk | Severity | Mitigation |
|---|---|---|
| Glare or low contrast prevents contour closure | Medium | Bilateral filtering and morphological closing reconnect broken edge segments; if still unclosed, graceful fallback to `manual_pin_required` allows customer corner adjustment. |
| User photographs paper in landscape orientation | Low | Aspect ratio matching tests both $H/W$ and $W/H$ configurations, correctly detecting landscape-taped sheets without false rejections. |
| False positive detection on a rectangular picture frame | Medium | Area bounds (0.05% to 15%) and strict aspect ratio matching against the chosen standard (Short, A4, or Long) reject non-paper fixtures. |
