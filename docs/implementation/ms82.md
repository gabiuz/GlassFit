## 1. Executive Summary, Outcome, and Problem Context

In Philippine architectural fenestration, customized aluminum windows and doors rarely scale as monolithic, uniformly stretched blocks. Structural limitations of extruded aluminum profiles, glass dead-load deflection limits (Universal 2.5 rule), and mechanical travel limits of operating hardware require fenestration units to expand in discrete modular bays (also termed panels, lights, or sides).

For example, a standard 2-sided jalousie window manufactured for a 1200mm aperture consists of a left jamb, a right jamb, an intermediate center mullion, top and bottom framing rails, an optional projecting window sill, two discrete vertical arrays of glass louver blades, and two sets of mechanical window operators. When a client or estimator expands the window width from 1200mm to 1800mm, physical fabrication rules dictate that the window cannot simply stretch the existing glass louvers from 560mm to 860mm wide (which would cause excessive wind-load flex and glass blade cracking). Instead, fabricators insert a second center mullion, creating a **3-sided window** with three discrete louver stacks and three sets of operating hardware.

Currently, GlassFit administrators in Step 5 of the Product Setup Wizard (`ParametersAndRulesSection.tsx`) must manually author brittle, combinatorial logic rules:
- `WHEN width >= 1800 THEN frame-center set_quantity = 1, glass-panel set_quantity = 2`
- `WHEN width >= 2600 THEN frame-center set_quantity = 2, glass-panel set_quantity = 3`

This manual rule approach creates four severe engineering bottlenecks:

1. **High Administrative Burden and Brittle Configurations:** Fabricators produce windows across dozens of standard width intervals. Authoring individual WHEN/THEN or Step Loop rules for every component (mullions, glass panels, clips, operators) is tedious, prone to human error, and fails when unexpected aperture sizes are entered in the client visualization workspace.
2. **Spatial Blindness in Scene Graph Assembly:** When a rule increases `frame-center` from 1 to 2, the current 3D builder (`parametricProductBuilder.ts`) does not know how to assemble multi-part bay sub-assemblies. It places generic mullions at equal fractions, but cannot duplicate coupled bay sub-assemblies (such as louver clip banks and operator crank handles) into the newly created aperture bay.
3. **Directional Ignorance During Aperture Resizing:** When modifying dimensions in the 3D viewport or interactive measurement modal, an opening is often expanded toward a specific flank (for example, extending the right edge of a rough opening while keeping the left jamb anchored against an existing masonry column). The system currently lacks directional expansion awareness; it scales symmetrically around the origin ($X=0$), shifting existing panels rather than emerging the newly created bay on the active expansion flank.
4. **Lack of Universal Architecture Across Product Types:** This modular bay replication requirement is not unique to jalousie windows. Multi-panel sliding windows (Series 798 2-panel, 3-panel, 4-panel), multi-sash casement windows, and commercial fixed transom/storefront framing all scale by adding modular bays separated by vertical intermediate mullions. The platform requires a generalized, flag-gated engine capability that can be enabled on any product.

| Challenge Domain | Physical Reality in Workshop | Current System Limitation | Mandated Architectural Solution (IMP-MS82) |
|---|---|---|---|
| 1. Rule Configuration Overhead | Modular bays replicate automatically every nominal bay pitch (e.g., 600mm) | Admin must manually author combinatorial WHEN/THEN rules for each component | Smart Dynamic Parameter Logic calculates nominal bay pitch and automates bay scaling |
| 2. Multi-Part Bay Sub-Assembly | A new bay introduces framing, glass infill, and operator hardware simultaneously | Manual rules mutate isolated quantities without sub-assembly coordination | Cohesive bay replication clones intermediate mullions, infills, and operators as unified bay units |
| 3. Directional Aperture Expansion | Rough openings expand leftward or rightward against architectural anchors | Resizing uniformly scales around origin, displacing existing bays | Directional anchoring places newly emerged bays directly on the active expansion flank |
| 4. System-Wide Reusability | Jalousies, sliding windows, casements, and fixed transoms all use modular bays | Hard-coded heuristics in isolated builders; no universal engine contract | Configurable `dynamic_bay_replication_enabled` toggle and generalized semantic bay roles |
| 5. Parametric Pricing Integrity | Each new bay adds intermediate mullion linear meters and per-piece infill/hardware | Pricing fails to scale unmapped constituent components in dynamic bays | Parametric BOM scales linear framing, discrete louvers, and operators with exact bay itemization |

## 3. Mathematical Modeling and Technical Architecture

### 3.1 Mathematical Formulation of Modular Bay Replication

Let $W_{target}$ be the configured target window aperture width in millimeters.  
Let $W_{default}$ be the default width declared in the product parameter definition (e.g., $W_{default} = 1200\text{mm}$).  
Let $N_{base}$ be the baseline bay count detected from uploaded geometry or specified by the administrator (for the 2-sided jalousie fixture, $N_{base} = 2$).  

#### Nominal Bay Pitch Equation
The nominal bay width pitch $W_{bay\_pitch}$ represents the modular width increment required to trigger an additional bay:
$$W_{bay\_pitch} = \frac{W_{default}}{N_{base}}$$

For the baseline jalousie fixture:
$$W_{bay\_pitch} = \frac{1200\text{mm}}{2} = 600\text{mm}$$

#### Dynamic Bay Count Equation ($N_{bays}$)
The dynamic count of modular bays $N_{bays}(W_{target})$ is evaluated using standard midpoint thresholding with a minimum clamp of 1 bay:
$$N_{bays}(W_{target}) = \max\left(1, \operatorname{round}\left(\frac{W_{target}}{W_{bay\_pitch}}\right)\right) = \max\left(1, \left\lfloor\frac{W_{target} + \frac{W_{bay\_pitch}}{2}}{W_{bay\_pitch}}\right\rfloor\right)$$

| Target Width Range ($W_{target}$) | Dynamic Bay Count ($N_{bays}$) | Window Classification | Intermediate Center Mullions ($N_{mullions}$) | Total Louver Sets | Total Operator Sets (per MS81 bank ratio) |
|---|---|---|---|---|---|
| $W < 900\text{mm}$ (e.g., 600mm) | 1 bay | 1-Sided Window | 0 mullions | 1 louver set | 1 bay $\times$ $N_{ops\_per\_bay}$ |
| $900\text{mm} \le W < 1500\text{mm}$ (e.g., 1200mm Baseline) | 2 bays | 2-Sided Window | 1 mullion (`JW_Frame_Center`) | 2 louver sets | 2 bays $\times$ $N_{ops\_per\_bay}$ |
| $1500\text{mm} \le W < 2100\text{mm}$ (e.g., 1800mm User Target) | 3 bays | 3-Sided Window | 2 mullions (`JW_Frame_Center` $\times$ 2) | 3 louver sets | 3 bays $\times$ $N_{ops\_per\_bay}$ |
| $2100\text{mm} \le W < 2700\text{mm}$ (e.g., 2400mm) | 4 bays | 4-Sided Window | 3 mullions (`JW_Frame_Center` $\times$ 3) | 4 louver sets | 4 bays $\times$ $N_{ops\_per\_bay}$ |
| $2700\text{mm} \le W < 3300\text{mm}$ (e.g., 3000mm) | 5 bays | 5-Sided Window | 4 mullions (`JW_Frame_Center` $\times$ 4) | 5 louver sets | 5 bays $\times$ $N_{ops\_per\_bay}$ |

#### Intermediate Mullion Count Equation
Intermediate divider mullions always equal the number of bays minus one:
$$N_{mullions} = N_{bays} - 1$$

#### Clear Bay Width Equation
Let $W_{left\_jamb}$ and $W_{right\_jamb}$ be the widths of the outer vertical jambs (each 60mm in the Series 798 profile).  
Let $W_{mullion}$ be the width of the intermediate center mullion (80mm).  
The clear aperture width per bay $W_{bay\_clear}$ is distributed equally:
$$W_{bay\_clear} = \frac{W_{target} - (W_{left\_jamb} + W_{right\_jamb}) - (N_{bays} - 1) \cdot W_{mullion}}{N_{bays}}$$

For example, at $W_{target} = 1800\text{mm}$ ($N_{bays} = 3$):
$$W_{bay\_clear} = \frac{1800 - (60 + 60) - (3 - 1) \cdot 80}{3} = \frac{1800 - 120 - 160}{3} = \frac{1520}{3} \approx 506.7\text{mm}$$

### 3.2 Directional Aperture Expansion Coordinate Mathematics

When an aperture width changes, the emergent bay position is governed by the **Expansion Anchor Mode**:
1. **Rightward Expansion (Left-Anchored):** The left jamb remains stationary at world coordinate $X_{left\_fixed}$.
2. **Leftward Expansion (Right-Anchored):** The right jamb remains stationary at world coordinate $X_{right\_fixed}$.
3. **Symmetric Expansion (Center-Anchored):** The fixture center remains stationary at $X = 0$.

#### Case 1: Symmetric Expansion (Center-Anchored, Standard Slider / Default Mode)
In symmetric mode, the overall window bounding box spans $X \in [-W_{target} / 2, +W_{target} / 2]$.

1. **Outer Perimeter Profiles:**
   - Left Jamb (`JW_Frame_Left`): $X_{jamb\_left} = -\frac{W_{target}}{2} + \frac{W_{left\_jamb}}{2}$
   - Right Jamb (`JW_Frame_Right`): $X_{jamb\_right} = +\frac{W_{target}}{2} - \frac{W_{right\_jamb}}{2}$
   - Top Header (`JW_Frame_Top`) & Bottom Sill (`JW_Frame_Bottom`): Centered at $X = 0$, scaled along X by $scaleX = W_{target} / W_{base\_framing}$.
   - Removable Sill (`JW_Window_Sill`): Centered at $X = 0$, scaled along X by $scaleX = W_{target} / W_{base\_sill}$.

2. **Intermediate Mullions ($m = 0, 1, \dots, N_{mullions} - 1$):**
   The center coordinates for each mullion $m$ are placed at bay boundaries:
   $$X_{mullion, m} = -\frac{W_{target}}{2} + W_{left\_jamb} + (m + 1) \cdot W_{bay\_clear} + (m + 0.5) \cdot W_{mullion}$$

3. **Modular Infill and Operator Assemblies ($b = 0, 1, \dots, N_{bays} - 1$):**
   The center coordinate for each bay $b$ is:
   $$X_{bay, b} = -\frac{W_{target}}{2} + W_{left\_jamb} + (b + 0.5) \cdot W_{bay\_clear} + b \cdot W_{mullion}$$

#### Case 2: Rightward Expansion (Left-Anchored, Dragging Right Resize Handle)
When the user drags the right bounding handle from 1200mm to 1800mm, the left jamb position is held fixed at $X_{origin}$.
- Left Jamb remains at $X_{jamb\_left} = X_{origin}$.
- Right Jamb translates rightward to $X_{jamb\_right} = X_{origin} + W_{target} - W_{right\_jamb}$.
- Existing bays on the left retain their relative positions.
- **Emergence on Right Flank:** When $N_{bays}$ increases from 2 to 3, the newly generated 3rd bay, its associated center mullion (Mullion 1), and its operator mechanism emerge exclusively on the right side of the existing assembly.

#### Case 3: Leftward Expansion (Right-Anchored, Dragging Left Resize Handle)
When the user drags the left bounding handle leftward:
- Right Jamb remains fixed at $X_{origin}$.
- Left Jamb translates leftward to $X_{jamb\_left} = X_{origin} - W_{target} + W_{left\_jamb}$.
- **Emergence on Left Flank:** The newly generated bay emerges on the left side, prepending a new bay, mullion, louver set, and operator handle while keeping the right-side assemblies intact.

### 3.3 Three.js Scene Graph Assembly Engine Architecture (`parametricProductBuilder.ts`)

To assemble multi-bay products dynamically without manual WHEN/THEN rules:

1. **Sub-Assembly Prototype Extraction:**
   - On model load, the assembly builder extracts a single canonical **Bay Infill Prototype** (one stack of louvers spanning $W_{bay\_clear}$) and a canonical **Operator Prototype**.
   - If the uploaded asset contains dual bays (as verified in Section 2.3 for `JW_Louver_Clips_And_Glass.glb`), the geometry analyzer isolates a single bay slice ($X \in [-0.84, -0.04]\text{m}$) normalized to local origin $(0, 0, 0)$.
2. **Dynamic Instantiation Loop:**
   - The engine queries $N_{bays}(W_{target})$.
   - It iterates $b$ from 0 to $N_{bays} - 1$:
     - Clones the Bay Infill Prototype (`JW_Louver_Clips_And_Glass`).
     - Scales the prototype along X: $scaleX = W_{bay\_clear} / W_{prototype\_bay\_width}$.
     - Clamps scale along Y and Z strictly to $1.0$ ($scaleY = 1.0, scaleZ = 1.0$) to preserve louver blade thickness and vertical clip geometry.
     - Translates the bay group to $(X_{bay, b}, 0, 0)$.
     - Clones the Operator Prototype (`JW_Operators`).
     - Positions the operator along the bay's driving stile at $(X_{bay, b} \pm (W_{bay\_clear} / 2 - 25\text{mm}), Y_{operator}, Z_{operator})$.
     - Adds custom `userData`: `{ isDynamicBay: true, bayIndex: b, totalBays: N_bays }`.
3. **Mullion Generation Loop:**
   - If $N_{bays} > 1$, the engine iterates $m$ from 0 to $N_{mullions} - 1$:
     - Clones `JW_Frame_Center`.
     - Scales along Y to span the inner aperture height: $scaleY = H_{aperture} / H_{base\_mullion}$.
     - Clamps scale along X and Z to $1.0$.
     - Translates to $(X_{mullion, m}, 0, 0)$.
     - Adds custom `userData`: `{ isDynamicMullion: true, mullionIndex: m }`.
4. **Perimeter Frame Stretching:**
   - `JW_Frame_Top` and `JW_Frame_Bottom` scale continuously along X to span $W_{target}$.
   - Outer vertical jambs (`JW_Frame_Left` and `JW_Frame_Right`) scale along Y to span $H_{target}$ and translate laterally to $\pm (W_{target} / 2 - W_{jamb} / 2)$.

### 3.4 Orthogonal Coupling with MS81 and MS80

The dynamic bay replication architecture of MS82 operates in complete mathematical orthogonality with MS81 (vertical louver scaling) and MS80 (operator-targeted screen access hatches):

1. **Orthogonal Dimensional Driving:**
   - **Width ($W$):** Governs horizontal bay replication ($N_{bays} = \operatorname{round}(W / W_{bay\_pitch})$) and intermediate mullions ($N_{mullions} = N_{bays} - 1$).
   - **Height ($H$):** Governs vertical louver blade addition/deletion ($N_{louvers} = \operatorname{round}((H - 50) / 175)$) and operator banks ($N_{ops\_per\_bay} = \lceil N_{louvers} / 4 \rceil$) within every bay, per MS81.
2. **Coupled Multi-Bay Louver and Operator Counts:**
   $$\text{Total Louver Blades} = N_{bays} \times N_{louvers}(H)$$
   $$\text{Total Window Operators} = N_{bays} \times N_{ops\_per\_bay}(H)$$
   For a 3-sided window ($W = 1800\text{mm}$) at height $H = 2100\text{mm}$ (12 louvers, 3 operators per bay):
   $$\text{Total Blades} = 3 \times 12 = 36\text{ glass blades}$$
   $$\text{Total Operators} = 3 \times 3 = 9\text{ window operators}$$
3. **Coupling with MS80 Screen Access Hatches:**
   - MS80 dynamically binds insect screen access hatches to host product operating mechanisms.
   - Because MS82 instantiates $N_{total\_ops} = N_{bays} \times N_{ops\_per\_bay}$ operators across the multiple bays, the MS80 multi-hatch alignment engine detects all $N_{total\_ops}$ operator centroids and automatically generates $N_{total\_ops}$ screen access hatches in 1:1 spatial alignment across all bays.

### 3.5 Generalization to Arbitrary Architectural Fixtures

While exemplified using the 8 jalousie constituent models, the dynamic bay replication system is architecturally decoupled and applies across all fenestration product categories when the feature flag is enabled:

1. **Sliding Windows and Doors (Series 798 / Series 900):**
   - At $W = 1200\text{mm}$: 2-Panel sliding window ($N_{bays} = 2$, 2 sashes, 1 interlocker).
   - At $W = 2400\text{mm}$: Automatically replicates into a 3-Panel or 4-Panel sliding unit with additional intermediate interlockers, meeting structural wind-load deflection limits without manual rules.
2. **Multi-Sash Casement & Awning Windows:**
   - At $W = 600\text{mm}$: 1-Sash casement ($N_{bays} = 1$).
   - At $W = 1200\text{mm}$: 2-Sash French casement ($N_{bays} = 2$, 1 center mullion, 2 friction hinges, 2 cam handles).
   - At $W = 1800\text{mm}$: 3-Sash casement ($N_{bays} = 3$, 2 center mullions, 3 handles).
3. **Commercial Storefronts and Fixed Picture Window Grids:**
   - Distributes vertical division bars and glazed vision panels every 1000mm nominal bay pitch.
4. **Feature Disabled Invariant:**
   - If `dynamic_bay_replication_enabled` is set to `false`, the product behaves statically: components do not replicate into modular bays, and width adjustment continuously stretches existing framing and infills.

### 3.6 Parametric Bill-of-Materials (BOM) Pricing Engine Architecture

`IMP-MS82` updates `src/lib/pricing/pricingEngine.ts` to compute costs based on dynamic bay replication:

```
Framing_Linear_Meters = Top_Rail(W) + Bottom_Rail(W) + Sill(W) + 2 * Jamb(H) + N_mullions * Mullion(H)
Cost_Framing = Framing_Linear_Meters * Rate_Aluminum_per_meter * (1 + Scrap_Framing_0.12)

Cost_Louvers = (N_bays * N_louvers) * Unit_Price_blade * Finish_Multiplier_glass
Cost_Operators = (N_bays * N_ops_per_bay) * Unit_Price_operator
```

Where:
- `N_mullions = N_bays - 1`
- `Unit_Price_blade`: Direct per-piece price from linked raw material (`pc` billing unit).
- `Unit_Price_operator`: Direct per-piece price from linked hardware raw material (`pc` billing unit).
- Scrap factor for aluminum framing is strictly 12% (0.12).
- Zero-markup raw quotation invariant preserved (labor floor and contractor gross margin remain 0.00 during customer quotation phase).

## 4. Database Schema Extensions and Migration Specification

To persist dynamic bay replication settings, nominal bay pitches, and semantic bay component roles without hard-coding, migration `029_dynamic_modular_bay_replication.sql` extends `public.product_templates`, `public.products`, and `public.product_components`.

### Forward DDL Migration (`supabase/migrations/029_dynamic_modular_bay_replication.sql`)

```sql
-- Migration: Add dynamic modular bay replication configuration and component bay roles
-- Supports automated multi-bay window generation, directional expansion, and dynamic BOM (IMP-MS82)

-- 1. Add dynamic_bay_config JSONB column to product_templates and products
ALTER TABLE public.product_templates
  ADD COLUMN IF NOT EXISTS dynamic_bay_config JSONB DEFAULT NULL;

ALTER TABLE public.products
  ADD COLUMN IF NOT EXISTS dynamic_bay_config JSONB DEFAULT NULL;

COMMENT ON COLUMN public.product_templates.dynamic_bay_config IS
'Structured configuration for dynamic modular bay replication: enabled (bool), primary_dimension (text), default_bay_count (int), nominal_bay_pitch_mm (numeric), min_bay_width_mm (numeric), max_bay_width_mm (numeric), expansion_anchor_mode (text), divider_component_key (text), bay_infill_component_keys (text[]), bay_hardware_component_keys (text[])';

-- 2. Add bay_role column to product_components
ALTER TABLE public.product_components
  ADD COLUMN IF NOT EXISTS bay_role VARCHAR(35) DEFAULT NULL;

ALTER TABLE public.product_components
  DROP CONSTRAINT IF EXISTS product_components_bay_role_check;

ALTER TABLE public.product_components
  ADD CONSTRAINT product_components_bay_role_check
  CHECK (bay_role IS NULL OR bay_role IN (
    'OUTER_JAMB_LEFT',
    'OUTER_JAMB_RIGHT',
    'OUTER_HEAD',
    'OUTER_SILL',
    'REMOVABLE_SILL',
    'BAY_DIVIDER',
    'BAY_INFILL',
    'BAY_HARDWARE',
    'GLOBAL_ACCESSORY'
  ));

COMMENT ON COLUMN public.product_components.bay_role IS
'Semantic role in modular bay assembly: OUTER_JAMB_LEFT, OUTER_JAMB_RIGHT, OUTER_HEAD, OUTER_SILL, REMOVABLE_SILL, BAY_DIVIDER, BAY_INFILL, BAY_HARDWARE, GLOBAL_ACCESSORY';
```

### Reversible Rollback Script (Down Migration)

```sql
-- Down Migration for 029_dynamic_modular_bay_replication.sql
ALTER TABLE public.product_components DROP CONSTRAINT IF EXISTS product_components_bay_role_check;
ALTER TABLE public.product_components DROP COLUMN IF EXISTS bay_role;

ALTER TABLE public.products DROP COLUMN IF EXISTS dynamic_bay_config;
ALTER TABLE public.product_templates DROP COLUMN IF EXISTS dynamic_bay_config;
```

## 5. Experience Contract and User Interface Interactions

### 5.1 Admin Product Setup Wizard (Step 4 Part Inspector & Step 5 Parameters & Rules)

#### 1. Step 4 Part Inspector: Semantic Bay Role Assignment
In `/admin/products/[productId]/setup` Step 4, when viewing constituent uploaded models:
- The Part Inspector Drawer renders a **Modular Bay Role** dropdown under the Physical Properties section.
- Automatic Role Tagging: When uploading constituent models, the system scans filenames:
  - `*center*` or `*mullion*` $\implies$ sets `bay_role = 'BAY_DIVIDER'`
  - `*left*` or `*jamb_left*` $\implies$ sets `bay_role = 'OUTER_JAMB_LEFT'`
  - `*right*` or `*jamb_right*` $\implies$ sets `bay_role = 'OUTER_JAMB_RIGHT'`
  - `*top*` or `*header*` $\implies$ sets `bay_role = 'OUTER_HEAD'`
  - `*bottom*` or `*sill_rail*` $\implies$ sets `bay_role = 'OUTER_SILL'`
  - `*window_sill*` $\implies$ sets `bay_role = 'REMOVABLE_SILL'`
  - `*louver*` or `*glass*` $\implies$ sets `bay_role = 'BAY_INFILL'`
  - `*operator*` or `*crank*` $\implies$ sets `bay_role = 'BAY_HARDWARE'`
- The administrator can review and change any semantic role cleanly.

#### 2. Step 5 Parameters and Rules: Smart Dynamic Logic Toggle
In `ParametersAndRulesSection.tsx`, a prominent new card appears at the top of the Rules tab:
- **Feature Toggle:** `[x] Enable Smart Dynamic Bay Replication`
  - Subtitle: *Automatically generates intermediate mullions, infills, and operating hardware as aperture dimensions scale, eliminating manual WHEN/THEN rules.*
- When enabled, the UI reveals the automated configuration panel:
  - **Baseline Bay Count:** `2 bays` (auto-detected from 1 divider mullion).
  - **Nominal Bay Pitch:** `600 mm` (calculated from default width 1200mm / 2 bays). Editable if the fabricator desires a different threshold (e.g., 650mm).
  - **Min / Max Bay Width Limits:** `400 mm` minimum, `1000 mm` maximum.
  - **Default Expansion Anchor:** Segmented control `[ Symmetric (Center) | Expand Rightward | Expand Leftward ]`.
- When this feature is active, manual rule authoring is disabled with an informative banner:
  *Smart Bay Replication is active. Component quantities for mullions, louvers, and operators are computed dynamically.*

### 5.2 Customer Visualization Workspace & Validation Workspace

1. **Interactive Width Resizing:**
   - In `ProductModelWorkspace.tsx` and `ValidationWorkspaceSection.tsx`, dragging the Width slider from 1200mm to 1800mm triggers real-time (< 16ms) 3D scene graph updates.
   - At $W = 1200\text{mm}$: viewport displays a 2-sided window (1 center mullion, 2 louver stacks, 2 operators).
   - At $W = 1800\text{mm}$: viewport smoothly instantiates the 3rd bay (2 center mullions, 3 louver stacks, 3 operators).
2. **Directional Drag Handle Feedback:**
   - Dragging the right bounding box handle anchors the left jamb in place; the new 3rd bay emerges on the right flank.
   - Dragging the left bounding box handle anchors the right jamb; the new 3rd bay emerges on the left flank.
3. **Real-Time Pricing Dock:**
   - The pricing breakdown dynamically itemizes:
     - `Top/Bottom Framing: 3.60 m @ ₱320.00/m`
     - `Intermediate Center Mullions (2x): 2.40 m @ ₱380.00/m`
     - `Glass Louver Blades: 21 pcs (3 bays x 7 blades) @ ₱45.00/pc`
     - `Window Operators: 6 pcs (3 bays x 2 ops) @ ₱450.00/pc`
4. **Consultation PDF Specification Handoff:**
   - Downloadable consultation PDF export lists:
     `Configuration: 3-Sided / 3-Bay Jalousie Window (2x Center Mullions, 21x Glass Blades, 6x Operators)`.
