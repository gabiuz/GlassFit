## 1. Outcome and Scope

In the standard product setup wizard, an administrator selects an uploaded or decomposed part, such as a door knob, and marks it as replaceable. The administrator then chooses one or more replacement options from products already registered and published under the Accessories role. The original part remains the default. For example, a door knob slot can offer a previously registered lever handle of the compatible category. The administrator cannot create or upload an accessory from this picker.

This milestone completes the existing MS75 slot configuration by making `allowed_accessory_ids` an explicit, reviewed list of actual catalog product IDs. It also ensures the MS76 preview and customer workflow respect that list. Product pricing, geometry placement, and the Accessory authoring workflow retain their existing contracts except where needed to enforce the approved choices.

**Definition of available:** An option must be an existing `products` row with `is_accessory = true`, `status = 'Active'`, the slot's `accessory_category`, and a usable model asset for the swap preview. Draft, inactive, deleted, incompatible, or model-less products are unavailable for new bindings. The default uploaded part is always available without an Accessories record.

## 3. Required Behavior and Invariants

1. **Existing records only:** The picker reads Accessories products already saved in the catalog. It has no inline create, upload, or free-text ID entry.
2. **Explicit approval:** Every replacement choice is an administrator-selected product ID. The category alone never grants access to all category members.
3. **Compatibility:** A selected product must match the part's accessory category. Changing the category clears incompatible selections and explains the change before save.
4. **Published availability:** New selections require an active, published Accessories product with a renderable asset. Save and publish checks repeat this validation on the server to handle stale browser data or forged requests.
5. **Default continuity:** With no customer choice, the original uploaded part remains visible and the accessory price delta remains zero.
6. **Draft workflow:** Auto-detection may suggest that a part is replaceable. A product draft may retain this pending configuration, but publication must identify every replaceable slot without an approved option and block publication until resolved or the replaceable toggle is turned off.
7. **Revocation:** An accessory later made inactive, deleted, or moved to another category is removed from selectable customer options. Admin edit and validation views show the stale binding and require repair before republishing. Existing quotation snapshots remain historical records.
8. **Security and consistency:** Use authenticated Supabase access and existing `manage_products` authorization for admin actions. Keep category and ID validation in a shared server-side contract; do not rely on UI filtering alone.
9. **UI consistency:** Reuse the current Part Inspector controls, spacing, colors, typography, and accessibility patterns. Do not add a new UI library or unrelated styling.

## 4. Planned Design

### 4.1 Admin authoring flow

1. The admin uploads or selects a standard product part in the Components step and opens its Part Inspector.
2. The admin enables **Swappable with Accessories** and confirms the accessory category.
3. The inspector loads eligible Accessories records for that category. Each choice shows its name, category, preview, and price where those values are available. Search narrows the loaded choices without creating records.
4. The admin selects one or more existing options. A selected list shows exactly what will be offered to customers and allows removal.
5. If there are no eligible records, the inspector explains that an accessory must first be registered and published in the Accessories section. The admin can continue editing the draft, but cannot publish a replaceable slot with no option.
6. Save and reload preserve the explicit selected IDs. The Validation step previews only the approved records and the original default part.

### 4.2 Data contract and lifecycle

Retain `product_components.is_accessory_slot`, `accessory_category`, and `allowed_accessory_ids` from MS75. Define `allowed_accessory_ids` as a deduplicated UUID list with no implicit category-wide meaning. The default part is represented separately, not as a product ID. Use the existing `products` accessory classification as the source of truth.

Before implementation, audit existing rows where `is_accessory_slot = true` and `allowed_accessory_ids IS NULL`. Include a reversible migration only if a data transition is needed. Normalize legacy open-category bindings to an explicit empty list and mark them for admin review rather than silently approving every active accessory. Document the migration and rollback in BUILD. Database constraints may enforce field shape, while server validation must verify each referenced product's current role, status, category, and asset readiness.

### 4.3 Enforcement boundaries

- **Admin save and publish:** Reject duplicate, nonexistent, inactive, non-accessory, category-mismatched, or asset-less IDs. Surface errors beside the affected part. Recheck all slots when publishing because a previously selected accessory may have changed.
- **Admin validation sandbox:** Resolve only IDs in the saved allowlist. Remove canonical procedural examples from the available replacement choices for this workflow. A missing or revoked accessory shows a repair message rather than silently falling back to another item.
- **Customer workspace:** Intersect the slot's approved IDs with active eligible Accessories records. An empty or missing allowlist shows the original part only. Preserve the exact selected `slotComponentId` and accessory ID for pricing and quotation.
- **Quotation boundary:** Revalidate each non-default selected accessory against the host product's slot and current approved catalog record before accepting a new quotation. Resolve name and price from trusted catalog data. Keep already saved quotation documents unchanged.
