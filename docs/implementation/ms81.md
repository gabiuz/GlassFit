## 1. Executive Summary, Outcome, and Problem Context

In Philippine architectural fenestration, aluminum jalousie windows (louver windows) are one of the most widely fabricated fixtures for residential and commercial natural ventilation. Unlike fixed picture windows or sliding sashes where glass infill expands continuously across an aperture area ($W \times H$), a jalousie window is composed of a discrete vertical array of standardized, pre-cut glass louver blades clamped into metal pivot clips and actuated by mechanical operator handles (rotopers/cranks).

When administrators upload 3D models for jalousies (`JW_Louver_Clips_And_Glass.glb` and `JW_Operators.glb`) and customize them in the administrative setup wizard (`/admin/products/[productId]/setup`) or client visualization workspace (`ProductModelWorkspace.tsx`), four critical architectural challenges emerge:

1. **Automated Baseline Part Counting:** Uploaded constituent meshes contain multiple discrete glass blades and clips. The system must automatically analyze the mesh geometry to detect the exact number of louver blades and operators rather than defaulting to a generic `baseQuantity = 1` or forcing manual manual counting.
2. **Parametric Height Scaling without Mesh Distortion:** In standard Three.js scaling (`group.scale.set(scaleX, scaleY, scaleZ)`), adjusting window height stretches the glass blades and metal clips vertically. Louver blades in reality have a fixed height (e.g., 4-inch or 6-inch pre-cut slats) and a fixed vertical pitch/gap. Modifying window height must dynamically add or delete discrete louver blade instances based on the modeled gap distance.
3. **Louver-Proportional Operator Scaling:** Window operators (crank handles and linkage bars) have mechanical load limits and typically operate a bank of 3 to 4 louvers. In the baseline 7-louver fixture, 2 operators are installed. As aperture height expands and louver count increases, the system must automatically scale operator count proportionally (adding one operator for every additional bank of louvers) and position them evenly along the window jamb.
4. **Per-Piece Parametric BOM Costing:** Both jalousie glass blades and mechanical operators are procured, stocked, and priced per piece (`pc` billing unit). The parametric pricing engine must evaluate total costs based on dynamic piece counts, feeding directly into quotation snapshots and fabricator consultation PDFs.

| Challenge Domain | Physical Reality in Workshop | Current System Limitation | Mandated Architectural Solution (IMP-MS81) |
|---|---|---|---|
| 1. Louver Mesh Ingestion | Uploaded GLB contains 7 discrete glass slats and clips | Treated as a single static mesh with `baseQuantity = 1` | Automated 3D geometry analyzer detects distinct louver levels and counts 7 pieces |
| 2. Aperture Height Scaling | Increasing window height requires adding more glass slats | Scaling Y stretches the glass mesh, distorting clips and thickness | Dynamic instantiation adds or deletes discrete louver instances spaced by 175mm pitch |
| 3. Operator Hardware Load | 7 louvers require 2 operators (~4 louvers per operator bank) | Operators are static; tall windows retain only 2 handles | Automatically computes `ceil(louvers / 4)` operators, positioning each at bank center |
| 4. Per-Piece Pricing | Glass slats and operator handles are billed strictly per piece (`pc`) | Fixed base quantity fails to scale when window dimensions change | Parametric BOM scales blade and operator line item quantities and itemizes in quotation PDF |

## 3. Mathematical Modeling and Technical Architecture

### 3.1 Mathematical Formulation for Dynamic Louver Blade Sizing

Let $H_{target}$ be the target window aperture height (in millimeters) and $W_{target}$ be the target aperture width (in millimeters).  
Let $\Delta Y_{pitch} = 175.0\text{mm}$ (0.175m) be the modeled vertical pitch derived from the baseline GLB geometry.  
Let $H_{blade} = 105.3\text{mm}$ be the single blade height.  
Let $H_{clearance} = 50.0\text{mm}$ be the combined top head and bottom sill profile margin.

#### Louver Count Equation
The dynamic count of louver blades $N_{louvers}$ is evaluated as:
$$N_{louvers}(H_{target}) = \max\left(1, \operatorname{round}\left(\frac{H_{target} - H_{clearance}}{\Delta Y_{pitch}}\right)\right)$$

For standard heights:
- $H = 600\text{mm} \implies N = \operatorname{round}((600 - 50) / 175) = 3\text{ louvers}$
- $H = 900\text{mm} \implies N = \operatorname{round}((900 - 50) / 175) = 5\text{ louvers}$
- $H = 1200\text{mm} \implies N = \operatorname{round}((1200 - 50) / 175) = 7\text{ louvers}$ (Baseline)
- $H = 1500\text{mm} \implies N = \operatorname{round}((1500 - 50) / 175) = 8\text{ louvers}$
- $H = 1800\text{mm} \implies N = \operatorname{round}((1800 - 50) / 175) = 10\text{ louvers}$
- $H = 2100\text{mm} \implies N = \operatorname{round}((2100 - 50) / 175) = 12\text{ louvers}$

#### Louver Blade Vertical Elevation Matrix
For a stack of $N_{louvers}$ blades centered within an aperture of height $H_{target}$, the local Y position of blade $i$ (where $i = 0, 1, \dots, N_{louvers} - 1$) is:
$$Y_{blade, i} = -\frac{(N_{louvers} - 1) \cdot \Delta Y_{pitch}}{2} + (i \cdot \Delta Y_{pitch})$$

This formulation guarantees that the louver array remains centered within the perimeter framing head and sill.

### 3.2 Mathematical Formulation for Operator Count and Spatial Distribution

In commercial and residential fenestration practice, a manual jalousie operator linkage bar cannot exceed approximately 4 to 5 louver clips without excessive operating torque and mechanical binding.

#### Operator Bank Ratio
From the baseline model:
$$\text{blades\_per\_operator} = \operatorname{round}\left(\frac{N_{base\_louvers}}{N_{base\_operators}}\right) = \operatorname{round}\left(\frac{7}{2}\right) = 4\text{ blades}$$

#### Operator Count Equation
The required number of operating mechanisms $N_{operators}$ is:
$$N_{operators}(N_{louvers}) = \max\left(1, \left\lceil\frac{N_{louvers}}{\text{blades\_per\_operator}}\right\rceil\right) = \max\left(1, \left\lceil\frac{N_{louvers}}{4}\right\rceil\right)$$

| Louver Count ($N_{louvers}$) | Operator Count ($N_{operators}$) | Louvers Assigned Per Bank |
|---|---|---|
| 1 to 4 louvers | 1 operator | 1 bank of 1 to 4 louvers |
| 5 to 8 louvers | 2 operators | 2 banks (e.g., 3 + 4 louvers, matching 7-blade baseline) |
| 9 to 12 louvers | 3 operators | 3 banks (e.g., 4 + 4 + 4 louvers) |
| 13 to 16 louvers | 4 operators | 4 banks (e.g., 4 + 4 + 4 + 4 louvers) |

#### Operator Vertical Placement Coordinates
Each operator $k$ (for $k = 0, 1, \dots, N_{operators} - 1$) controls a vertical bank of louvers. The target vertical position $Y_{operator, k}$ aligns with the centroid of bank $k$:
$$Y_{operator, k} = -\frac{(N_{louvers} - 1) \cdot \Delta Y_{pitch}}{2} + \left(\frac{(k + 0.5) \cdot N_{louvers}}{N_{operators}} - 0.5\right) \cdot \Delta Y_{pitch}$$

Each operator handle is positioned along the window jamb at its modeled lateral offset ($X_{operator} \approx \pm (W_{target} / 2 - 25\text{mm})$), maintaining 1:1 metric scale along all axes ($scale = 1.0$).

### 3.3 Three.js Scene Graph Assembly Engine (`parametricProductBuilder.ts`)

To prevent mesh stretching along the Y axis:
1. **Louver Blade Generation:**
   - The assembly builder slices or references a single prototype louver blade mesh (or clones from the loaded template).
   - The blade is scaled along X by $scaleX = W_{target} / W_{base}$ so the glass slat spans the aperture width.
   - The blade scale along Y and Z is clamped strictly to $1.0$ ($scaleY = 1.0$, $scaleZ = 1.0$).
   - The engine iterates $i$ from $0$ to $N_{louvers} - 1$, generating $N_{louvers}$ blade instances placed at coordinates $(0, Y_{blade, i}, 0)$.
2. **Operator Instantiation:**
   - The assembly builder references a single operator handle mesh.
   - Clones are generated for $k = 0$ to $N_{operators} - 1$.
   - Scale is clamped to $1.0$ across all axes ($scaleX = 1.0, scaleY = 1.0, scaleZ = 1.0$).
   - Clones are positioned at $(X_{operator}, Y_{operator, k}, Z_{operator})$.
3. **Synergy with MS80 (Screen Access Hatches):**
   - In MS80, screen access hatches automatically align to host operator centroids.
   - Because MS81 dynamically scales operator count from 2 to $N_{operators}$, the MS80 multi-hatch alignment engine detects all $N_{operators}$ target keys and automatically generates $N_{operators}$ screen access hatches in 1:1 alignment.

### 3.4 Parametric Pricing Engine Architecture (`pricingEngine.ts`)

Under `IMP-MS24`, glass materials support a per-piece (`pc`) billing unit. `IMP-MS81` extends the pricing engine to evaluate jalousie blades and operators dynamically:

```
Cost_Jalousie_Glass = N_louvers * Unit_Price_blade * Finish_Multiplier_glass
Cost_Operators = N_operators * Unit_Price_operator
```

Where:
- `Unit_Price_blade`: Direct per-piece price from linked raw material (`pc` billing unit) or fixed component price.
- `Finish_Multiplier_glass`: 1.0 for Clear/Bronze, 2.0 for Frosted/Tinted Blue/Silver Reflective.
- `Unit_Price_operator`: Direct per-piece price from linked hardware raw material or fixed component price.
- Direct labor floor and contractor gross margin remain 0.00 during quotation phase (per `IMP-MS24` zero-markup raw quotation invariant).

## 4. Database Schema Extensions and Migration Specification

To persist the dimensional bindings, pitch, and bank rules without ad-hoc calculations, migration `027_jalousie_louver_dimension_bindings.sql` updates `product_components`.

### Forward DDL Migration (`supabase/migrations/027_jalousie_louver_dimension_bindings.sql`)

```sql
-- Migration: Add LOUVER_BLADE and LOUVER_OPERATOR to product_components dimension_binding check constraint
-- Supports parametric jalousie blade addition/deletion and proportional operator scaling (IMP-MS81)

-- 1. Update dimension_binding check constraint
ALTER TABLE public.product_components
  DROP CONSTRAINT IF EXISTS product_components_dimension_binding_check;

ALTER TABLE public.product_components
  ADD CONSTRAINT product_components_dimension_binding_check
  CHECK (dimension_binding IN ('WIDTH', 'HEIGHT', 'AREA', 'FIXED', 'GRILLE_LINEAR', 'PERIMETER', 'LOUVER_BLADE', 'LOUVER_OPERATOR'));

-- 2. Add jalousie_config column for pitch and bank configuration
ALTER TABLE public.product_components
  ADD COLUMN IF NOT EXISTS jalousie_config JSONB DEFAULT NULL;

COMMENT ON COLUMN public.product_components.jalousie_config IS
'Structured configuration for parametric jalousies: pitch_mm, blade_height_mm, blades_per_operator, base_blade_count, base_operator_count';
```
