## 1. Problem Context & Motivation

In the current GlassFit administrative setup (`/admin/products/[id]/setup` -> Step 4: Structural Components), administrators configure parametric products by manually uploading individual 3D structural component files one by one (such as `series798_double_sill.glb`, `series798_jamb_left.glb`, `series798_sash_top_rail.glb`, and `window_glass_pane_6mm.glb`).

While this part-by-part upload guarantees granular control over individual 3D assets, it introduces severe workflow bottlenecks for 3D modelers and administrators:
1. **Manual Export Overhead:** A 3D CAD designer or Blender artist must manually isolate, set origins for, and export 8 to 15 individual `.glb` files for every window, door, or partition profile assembly.
2. **Repetitive File Handling:** The administrator must drag and drop a large collection of disjointed files, increasing the risk of missing critical structural components (such as an interlocker or sill).
3. **Loss of Relative Spatial Context:** When parts are exported individually without spatial references, verifying how parts fit together into a unified parametric assembly requires mental reconstruction.

### The Dual-Mode Solution: Preserving Part-by-Part Upload While Adding Whole-Model Decomposition

To streamline administrative product onboarding without compromising system flexibility, MS-06 introduces an **Assembled Whole-Model Decomposition** ingestion option:
- **Zero Regression on Existing Workflow:** The existing part-by-part file upload remains completely intact as a standard ingestion mode.
- **New Ingestion Option:** Administrators can toggle an alternate mode: "Upload Assembled Model". In this mode, the admin uploads a single, complete `.glb` file representing the finished product assembly.
- **Client-Side Scene Graph Extraction:** The system inspects the internal node and mesh hierarchy of the uploaded GLB, extracts each distinct named mesh, centers each part geometry, generates individual standalone `.glb` binary blobs in memory, and passes them through the existing `autoDetectComponentSettings` engine.
- **Admin Verification & Mapping:** The extracted parts are populated directly into the established `StructuralComponentsSection` state, where the administrator reviews detected bindings, assigns raw materials, and commits the product structure.

### 3.2 Out of Scope

| Component / Layer | Rationale |
|---|---|
| Monolithic Mesh Geometric Slicing | Slicing arbitrary continuous solid meshes (where all geometry was joined into one mesh without named parts) using plane cutting is brittle, produces open non-manifold edges, and breaks extruded profiles. |
| AI / CV Mesh Segmentation | Computer vision segmentation models (e.g., SAM-3D) are experimental, resource-intensive, and non-deterministic for millimetric architectural glass/aluminum tolerances. |
| Supabase Database Schema Migrations | The existing `product_components` and `product_assets` tables already store component keys, names, types, dimensions, and `glb_file_url`. No database schema change is needed. |
| FastAPI Microservice Changes | Model decomposition is a client-side geometry and file-format operation executed natively via WebGL/Three.js; backend CV service is untouched. |

## 4. Technical Feasibility & Prerequisites

### 4.1 Prerequisites for 3D Modeling (Blender / CAD Export Guidelines)

To enable automatic decomposition, 3D artists follow standard industry modeling conventions:
1. **Preserve Object Hierarchy:** Rather than joining all pieces into a single mesh (`Ctrl + J` in Blender), each structural element remains a distinct object under the scene collection.
2. **Meaningful Object Naming:** Objects are given standard descriptive names (e.g., `series798_sill`, `jamb_left`, `jamb_right`, `top_rail`, `bottom_rail`, `glass_pane_left`, `pom_roller_left`).
3. **Export Settings in Blender:** When exporting to `.gltf` / `.glb`:
   - Include: `Selected Objects` or active collection.
   - Transform: `+Y Up`.
   - Geometry: Apply modifiers if needed; do **NOT** merge meshes or flatten hierarchy.

### 4.2 Handling Monolithic Single-Mesh Models (Graceful Degradation)

If an administrator uploads a model that contains only one monolithic mesh:
- The system detects `meshCount === 1`.
- The system presents an informative alert modal explaining that the file contains no distinct sub-components.
- The administrator is prompted to either:
  1. Switch to "Individual Parts" upload mode to drop separate GLB files.
  2. Use the model as a Fixed Whole Model in Step 1 (for non-parametric display).
  3. Re-export the 3D file from their CAD software with separated objects.

## 5. System Design & Architectural Workflow

### 5.1 End-to-End Workflow Steps

1. **Mode Selection:** In Step 4 of the Product Setup Wizard, the admin sees an ingestion mode selector:
   - Tab 1: **Upload Individual Parts** (existing drag-and-drop zone).
   - Tab 2: **Decompose Whole Model** (new whole-model ingestion zone).
2. **Whole Model Ingestion:** The admin drags `series798_assembled_window.glb` into the decomposition dropzone.
3. **Local In-Memory Parsing:**
   - Three.js `GLTFLoader` parses the file in browser memory without sending large files over the network prematurely.
   - The scene graph is traversed to identify all leaf `THREE.Mesh` instances and grouped sub-assemblies.
4. **Sub-Mesh Isolation & Extraction:**
   - For each detected mesh, the engine clones its geometry and materials.
   - The geometry is recentered to local origin `(0,0,0)`, and its natural bounding box size $(X, Y, Z)$ is recorded.
   - Three.js `GLTFExporter` serializes the isolated mesh into a standalone `.glb` binary `ArrayBuffer` / `File`.
5. **Auto-Detection Analysis:**
   - The node name is passed to `autoDetectComponentSettings(child.name)`.
   - Structural attributes are populated: component key, presentation category, dimension binding (`WIDTH`, `HEIGHT`, `AREA`, `FIXED`), span ratio, and removable toggle.
6. **Admin Review Drawer:**
   - A drawer appears showing the extracted parts table and a 3D preview with sub-mesh isolation.
   - The admin can uncheck decorative or helper meshes (e.g., handles or camera empties) that should not be structural components.
   - The admin clicks **"Apply Extracted Parts"**.
7. **Pipeline Transition & Persistence:**
   - The extracted parts are injected into the wizard's `mappedFiles` state.
   - The wizard proceeds using the established asset upload and database synchronization routines.

### 6.1 Data Structures (`src/lib/admin/products/modelDecomposer.ts`)

import * as THREE from 'three';
import type { DimensionBinding, PresentationCategory } from '@/lib/pricing/types';
import type { ComponentType } from './componentMutations';

export interface ExtractedComponentPart {
  id: string;
  sourceNodeName: string;
  componentKey: string;
  componentName: string;
  componentType: ComponentType;
  presentationCategory: PresentationCategory;
  dimensionBinding: DimensionBinding;
  spanRatio: number;
  isRemovable: boolean;
  togglePropertyKey: string | null;
  baseQuantity: number;
  dimensionsMm: {
    width: number;
    height: number;
    depth: number;
  };
  file: File;
  previewMesh: THREE.Group;
  isSelected: boolean;
}

export interface ModelDecompositionResult {
  success: boolean;
  sourceFileName: string;
  totalNodesDetected: number;
  extractedParts: ExtractedComponentPart[];
  warnings: string[];
  error?: string;
}

export interface ModelDecomposerOptions {
  sanitizeKeys?: boolean;
  filterEmptyNodes?: boolean;
  minBoundingDimensionMeters?: number; // Ignores micro-geometry below 1mm
}

### 6.2 Decomposition Engine Logic (`modelDecomposer.ts`)

```typescript
import * as THREE from 'three';
import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js';
import { GLTFExporter } from 'three/addons/exporters/GLTFExporter.js';
import { autoDetectComponentSettings } from './autoDetection';

export async function decomposeWholeModel(
  file: File,
  options: ModelDecomposerOptions = {}
): Promise<ModelDecompositionResult> {
  const url = URL.createObjectURL(file);
  const loader = new GLTFLoader();
  const exporter = new GLTFExporter();

  try {
    const gltf = await loader.loadAsync(url);
    const root = gltf.scene;

    const meshNodes: THREE.Mesh[] = [];
    root.traverse((node) => {
      if (node instanceof THREE.Mesh && node.geometry) {
        meshNodes.push(node);
      }
    });

    if (meshNodes.length <= 1) {
      return {
        success: false,
        sourceFileName: file.name,
        totalNodesDetected: meshNodes.length,
        extractedParts: [],
        warnings: [],
        error: 'The uploaded GLB contains only a single merged mesh. To use decomposition, export with separate named objects from your 3D modeling tool.',
      };
    }

    const extractedParts: ExtractedComponentPart[] = [];
    const minDim = options.minBoundingDimensionMeters ?? 0.001;

    for (const mesh of meshNodes) {
      const box = new THREE.Box3().setFromObject(mesh);
      const size = new THREE.Vector3();
      box.getSize(size);

      // Skip negligible helper geometries
      if (size.x < minDim && size.y < minDim && size.z < minDim) {
        continue;
      }

      // Create isolated scene for standalone export
      const isolatedGroup = new THREE.Group();
      const clonedMesh = mesh.clone(true);

      // Center geometry around origin
      clonedMesh.position.set(0, 0, 0);
      clonedMesh.rotation.set(0, 0, 0);
      clonedMesh.scale.set(1, 1, 1);
      clonedMesh.updateMatrixWorld(true);

      const center = new THREE.Vector3();
      box.getCenter(center);
      clonedMesh.position.sub(center);

      isolatedGroup.add(clonedMesh);

      // Export isolated mesh as standalone binary GLB
      const glbBuffer = await new Promise<ArrayBuffer>((resolve, reject) => {
        exporter.parse(
          isolatedGroup,
          (result) => {
            if (result instanceof ArrayBuffer) {
              resolve(result);
            } else {
              reject(new Error('GLTFExporter did not return an ArrayBuffer'));
            }
          },
          (error) => reject(error),
          { binary: true }
        );
      });

      const sanitizedKey = mesh.name
        .replace(/[^a-zA-Z0-9_-]/g, '_')
        .toLowerCase();
      const partFileName = `${sanitizedKey || 'component'}.glb`;
      const partFile = new File([glbBuffer], partFileName, {
        type: 'model/gltf-binary',
      });

      const detected = autoDetectComponentSettings(partFileName);

      extractedParts.push({
        id: crypto.randomUUID(),
        sourceNodeName: mesh.name,
        componentKey: sanitizedKey,
        componentName: formatLabel(mesh.name),
        componentType: detected.componentType,
        presentationCategory: detected.presentationCategory,
        dimensionBinding: detected.dimensionBinding,
        spanRatio: detected.spanRatio,
        isRemovable: detected.isRemovable,
        togglePropertyKey: detected.togglePropertyKey,
        baseQuantity: 1,
        dimensionsMm: {
          width: Math.round(size.x * 1000),
          height: Math.round(size.y * 1000),
          depth: Math.round(size.z * 1000),
        },
        file: partFile,
        previewMesh: isolatedGroup,
        isSelected: true,
      });
    }

    return {
      success: true,
      sourceFileName: file.name,
      totalNodesDetected: meshNodes.length,
      extractedParts,
      warnings: [],
    };
  } finally {
    URL.revokeObjectURL(url);
  }
}

function formatLabel(name: string): string {
  return name
    .replace(/[-_]/g, ' ')
    .replace(/\b\w/g, (char) => char.toUpperCase());
}
```
