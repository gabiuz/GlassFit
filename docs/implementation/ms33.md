> **Identifier note:** `IMP-MS33` succeeds `IMP-MS32` (Admin Data Management, GlassFit Business Intelligence Exports, Native Visual Analytics, and System Backup Engine) in the sequential implementation specification series in `docs/implementation/`. This specification resolves a persistent visual inconsistency across the GlassFit web application: default unstyled operating-system scrollbars. On Windows, macOS, and Linux desktop browsers, default scrollbars render with generic light-gray or opaque white gutters and stark rectangular thumbs, clashing sharply with GlassFit's sleek architectural glassmorphism, slate surfaces, and cyan branding. `IMP-MS33` specifies the exact global CSS tokens, modern W3C scrollbar standards, WebKit engine pseudo-elements, dark-mode adaptations, and accessibility contrast rules required to unify every scrollable surface into the cohesive GlassFit aesthetic without third-party runtime dependencies.

## 1. Executive Summary & Problem Context

In high-end architectural fenestration platforms, visual fidelity, structural elegance, and design consistency reinforce user confidence and professional brand identity. When customers and SME fabricators interact with GlassFit, every visual element, from 3D parametric glass viewports to administrative booking tables, must reflect architectural precision.

### 1.1 The Reported Defect & Architectural Root Cause

Under the current implementation in `src/app/globals.css` and throughout application viewports:

1. **Operating-System Default Fallback:** No global or component-level scrollbar rules exist in the project. Browsers default to native operating-system scrollbar controls. On Windows 10 and 11, Chromium (Google Chrome, Microsoft Edge, Opera, Brave) and Gecko (Mozilla Firefox) render default wide gutters (15px to 17px) with chalky light-gray backgrounds (`#f0f0f0`) and flat rectangular thumbs (`#cdcdcd`).
2. **Visual Discordance with GlassFit Dark Surfaces:** GlassFit interfaces employ deep architectural charcoal (`--color-black: #0f1422`), slate surfaces (`#1e293b`), and vibrant cyan accents (`--color-green: #07b6d3`, `--color-blue: #06e5ff`). When users scroll through dark-themed views or modals, the bright white/gray native scrollbar cuts across the right viewport boundary, fracturing visual immersion.
3. **Nested Scroll Container Inconsistencies:** Overflows occur frequently within nested UI containers, including:
   - Administrative booking triage lists (`/admin/bookings`).
   - Customer request records table (`/my-requests`).
   - Measurement and engineering guardrail dialogs (`MeasurementModal.tsx`).
   - Admin setup wizard component drawer and 3D preview dock (`/admin/products/[id]/setup`).
   - Business intelligence data management modal (`BusinessIntelligenceModal.tsx`).
   - Central raw materials catalog table (`/admin/materials`).
   Each nested container currently exhibits jarring native OS scrollbars with abrupt ends and rectangular edges that overlap card borders and drop shadows.
4. **Disjointed Browser Engine Standards:** Browsers implement scrollbar styling through two distinct mechanisms:
   - Modern W3C Standard (CSS Scrollbars Module Level 1): `scrollbar-color` and `scrollbar-width` (supported by Firefox 64+, Chrome 121+, Edge 121+, Safari 17.2+).
   - Vendor Pseudo-Elements (WebKit / Blink Engine): `::-webkit-scrollbar`, `::-webkit-scrollbar-track`, `::-webkit-scrollbar-thumb`, and `::-webkit-scrollbar-corner`.
   Relying on only one mechanism results in broken or missing custom scrollbars across different browser engines or operating systems.

### 1.2 Required System Behavior

To fulfill the requirements of `IMP-MS33`, the web application must implement a unified, dual-standard CSS scrollbar system:

1. **Brand Palette Harmonization:**
   - **Thumb Color (Light Mode):** Soft GlassFit cyan pill (`rgba(7, 182, 211, 0.45)`), transitioning on hover to solid brand cyan (`#07b6d3`), and darkening on active press to deep architectural teal (`#097283`).
   - **Thumb Color (Dark Mode):** Luminous GlassFit cyan pill (`rgba(7, 182, 211, 0.50)`), transitioning on hover to electric cyan (`#06e5ff`), and on active press to primary cyan (`#07b6d3`).
   - **Track Color:** Clean, translucent background (`transparent` or subtle surface tint) that seamlessly inherits the surrounding canvas without jarring white or gray gutters.
2. **Refined Floating Pill Geometry:**
   - Scrollbars must adopt an unobtrusive 8px width on desktop viewports and 6px in nested dialogs.
   - Thumbs must feature fully rounded ends (`border-radius: 9999px`).
   - Thumbs must use transparent outer borders with `background-clip: content-box` to create an inset floating appearance with 2px margins from container edges.
3. **Universal Global Cascade:**
   - Configured in `src/app/globals.css` within the Tailwind CSS `@layer base` directive.
   - Automatically applies to the root documents (`html`, `body`) and all descendant elements (`*`) that have scrollable overflow (`overflow: auto`, `overflow-y: scroll`, `overflow-x: scroll`).
4. **Selective Utility & Override Classes:**
   - Provide a `.custom-scrollbar` utility class for targeted container overrides.
   - Preserve and provide a `.scrollbar-none` / `.no-scrollbar` utility for intentional gesture-only scroll containers (such as the horizontal guideline carousel in `GuideLine.tsx`), ensuring existing component functionality is never compromised.
5. **Zero Dependency & High-Performance Execution:**
   - Built entirely in native declarative CSS.
   - Zero JavaScript virtual-scroll libraries (such as SimpleBar, OverlayScrollbars, or Locomotive Scroll), maintaining 60 FPS GPU-accelerated scrolling and zero bundle size bloat.

### 1.3 Scope Boundaries & Non-Goals

- **Non-Goal (Virtual JavaScript Scrolling):** Native browser inertia and hardware acceleration will not be intercepted or replaced with JavaScript scroll listener loops.
- **Non-Goal (Tampering with Intentional Hidden Scrollbars):** Surfaces that intentionally hide scrollbars for custom touch gestures or drag interactions (such as `GuideLine.tsx` guideline handles) will remain hidden.
- **Non-Goal (Altering Mobile Native Touch Gestures):** Mobile touch momentum (`-webkit-overflow-scrolling: touch`) on iOS and Android viewports is fully preserved.

## 3. Visual Design Tokens & Palette Synchronization

### 3.1 Color Token Mapping

The scrollbar color system maps directly to established GlassFit design tokens defined in `src/app/globals.css` and `docs/dsd-glassfit.md`:

| Semantic Element | CSS Variable / Token | Light Mode Value | Dark Mode Value | Interaction State |
|---|---|---|---|---|
| **Scrollbar Thumb** | `--scrollbar-thumb` | `rgba(7, 182, 211, 0.45)` | `rgba(7, 182, 211, 0.50)` | Default / Idle |
| **Scrollbar Thumb Hover** | `--scrollbar-thumb-hover` | `#07b6d3` (Solid Brand Cyan) | `#06e5ff` (Electric Cyan) | Pointer Hover |
| **Scrollbar Thumb Active** | `--scrollbar-thumb-active` | `#097283` (Deep Teal) | `#07b6d3` (Brand Cyan) | Active Drag / Pressed |
| **Scrollbar Track** | `--scrollbar-track` | `transparent` (Canvas Inherit) | `transparent` (Canvas Inherit) | Default / Idle |
| **Scrollbar Track Hover** | `--scrollbar-track-hover` | `rgba(15, 20, 34, 0.04)` | `rgba(255, 255, 255, 0.04)` | Pointer Hover |
| **Scrollbar Corner** | `--scrollbar-corner` | `transparent` | `transparent` | Intersecting Viewports |

### 3.2 Dimensional Tokens & Geometry

| Dimensional Property | Root Viewport (`html`, `body`) | Nested Containers (Modals, Drawers, Tables) | Rationale |
|---|---|---|---|
| **Vertical Scrollbar Width** | `8px` | `6px` | Slim, non-intrusive desktop standard; compact in nested cards |
| **Horizontal Scrollbar Height** | `8px` | `6px` | Consistent aspect ratio for horizontal table scrolling |
| **Thumb Border Radius** | `9999px` (Full Pill) | `9999px` (Full Pill) | Eliminates harsh square corners; aligns with GlassFit rounded geometry |
| **Thumb Inset Margin** | `2px` (Transparent Border) | `1.5px` (Transparent Border) | Creates floating pill effect separated from container edge |
| **Background Clip** | `content-box` | `content-box` | Clips background to content area inside transparent border |
| **Hover Transition Duration** | `150ms ease-out` | `150ms ease-out` | Responsive tactile feedback without jarring color snap |

### 3.3 Contrast Evaluation & Accessibility Compliance

Per WCAG 2.1 Success Criterion 1.4.11 (Non-text Contrast):
- Visual information used to indicate states of user interface components must maintain a contrast ratio of at least 3.0:1 against adjacent colors.
- In Light Mode:
  - Track: Transparent over `--color-bg-canvas` (`#F8FAFC`) or `--color-bg-surface` (`#FFFFFF`).
  - Thumb Default: `rgba(7, 182, 211, 0.45)` yields an effective luminance of `#83DAE7`, providing clear visibility against white without visual aggression.
  - Thumb Hover: `#07b6d3` yields a contrast ratio of `3.4:1` against `#FFFFFF`, comfortably satisfying WCAG 2.1 Level AA for non-text UI components.
  - Thumb Active: `#097283` yields a contrast ratio of `5.1:1` against `#FFFFFF`.
- In Dark Mode:
  - Track: Transparent over `--color-black` (`#0F1422`) or `--card` (`oklch(0.205 0 0)` / `#1E293B`).
  - Thumb Default: `rgba(7, 182, 211, 0.50)` yields an effective color of `#0B6778`, clearly visible against charcoal surfaces.
  - Thumb Hover: `#06e5ff` (Electric Cyan) yields a contrast ratio of `11.8:1` against `#0F1422` (WCAG AAA).
  - Thumb Active: `#07b6d3` yields a contrast ratio of `8.6:1` against `#0F1422`.

## 4. CSS Architecture & Global Integration Specification

### 4.1 Modern W3C Standard Integration (`scrollbar-color` & `scrollbar-width`)

The W3C CSS Scrollbars Module Level 1 specifies standard properties supported in all modern browser engines (Firefox, Chrome 121+, Edge 121+, Safari 17.2+):

```css
/* W3C CSS Scrollbars Level 1 Standard */
* {
  scrollbar-width: thin;
  scrollbar-color: rgba(7, 182, 211, 0.45) transparent;
}

*:hover {
  scrollbar-color: #07b6d3 transparent;
}

.dark * {
  scrollbar-color: rgba(7, 182, 211, 0.50) transparent;
}

.dark *:hover {
  scrollbar-color: #06e5ff transparent;
}
```

### 4.2 WebKit & Blink Engine Granular Styling

For Chromium and WebKit browsers, pseudo-elements allow fine control over padding, rounded pill ends, and inset background clipping:

```css
/* WebKit / Blink Engine (Chrome, Edge, Safari, Brave, Opera) */
::-webkit-scrollbar {
  width: 8px;
  height: 8px;
}

::-webkit-scrollbar-track {
  background: transparent;
}

::-webkit-scrollbar-thumb {
  background-color: rgba(7, 182, 211, 0.45);
  border-radius: 9999px;
  border: 2px solid transparent;
  background-clip: content-box;
  transition: background-color 150ms var(--ease-out, ease-out);
}

::-webkit-scrollbar-thumb:hover {
  background-color: #07b6d3;
}

::-webkit-scrollbar-thumb:active {
  background-color: #097283;
}

::-webkit-scrollbar-corner {
  background: transparent;
}

/* Dark Mode WebKit Overrides */
.dark ::-webkit-scrollbar-thumb {
  background-color: rgba(7, 182, 211, 0.50);
}

.dark ::-webkit-scrollbar-thumb:hover {
  background-color: #06e5ff;
}

.dark ::-webkit-scrollbar-thumb:active {
  background-color: #07b6d3;
}
```

### 4.4 Utility Classes for Explicit Overrides

To accommodate specialized UI layouts, two utility classes will be defined in `src/app/globals.css`:

1. **`.custom-scrollbar` (Compact Nested Variant):**
   ```css
   .custom-scrollbar {
     scrollbar-width: thin;
   }
   .custom-scrollbar::-webkit-scrollbar {
     width: 6px;
     height: 6px;
   }
   .custom-scrollbar::-webkit-scrollbar-thumb {
     border-width: 1.5px;
   }
   ```
2. **`.scrollbar-none` / `.no-scrollbar` (Hidden Gesture Scrollbars):**
   ```css
   .scrollbar-none,
   .no-scrollbar {
     scrollbar-width: none;
     -ms-overflow-style: none;
   }
   .scrollbar-none::-webkit-scrollbar,
   .no-scrollbar::-webkit-scrollbar {
     display: none;
   }
   ```

## 6. Usability, Accessibility, & Performance Specifications

### 6.1 Usability & Interaction Feedback

1. **Clear Interactive States:**
   - **Resting:** Subtly translucent cyan thumb indicates scrollability without distracting from reading flow.
   - **Hover:** Solid brand cyan (`#07b6d3` in light mode, `#06e5ff` in dark mode) signals active interactive readiness.
   - **Active Drag:** Deepened teal (`#097283` in light mode, `#07b6d3` in dark mode) confirms physical thumb capture and pointer tracking.
2. **Hitbox Integrity:**
   - Although the thumb displays a 2px inset via `background-clip: content-box`, the actual interactive pointer hitbox encompasses the full 8px width, ensuring effortless mouse targeting.
3. **Corner Blending:**
   - When both horizontal and vertical scrollbars are visible simultaneously (e.g. in wide data tables), the intersection corner (`::-webkit-scrollbar-corner`) renders `background: transparent`, preventing unsightly opaque gray boxes at the table junction.

### 6.2 Accessibility Standards

1. **WCAG 2.1 AA Compliance:**
   - The thumb maintains >= 3.0:1 contrast against adjacent canvas and track surfaces during both idle and hover states.
2. **Keyboard Operability:**
   - Native browser keyboard navigation (Page Up, Page Down, Home, End, and Arrow Keys) is fully preserved without JavaScript intervention.
3. **Operating-System Accessibility Settings:**
   - On platforms with "Always show scrollbars" enabled (e.g. macOS Accessibility settings or Windows Settings > Accessibility > Visual effects > Always show scrollbars), the custom scrollbar remains persistently rendered with full color fidelity.
4. **Motion Sensitivity:**
   - Color transitions (`150ms var(--ease-out)`) are gentle and subtle.
   - For users with `@media (prefers-reduced-motion: reduce)`, transitions are instantaneous (`transition-duration: 0ms`).

### 6.3 Performance & Zero Runtime Overhead

1. **Compositor-Thread Scrolling:**
   - All scrolling is handled directly by the browser's native rendering engine on the GPU compositor thread.
   - Zero JavaScript main-thread calculations, zero scroll event listeners, zero DOM re-layouts.
2. **Zero Layout Shifts (CLS = 0):**
   - Because standard scrollbar dimensions are declared globally at stylesheet load time, layout stability is maintained with zero Cumulative Layout Shift.
