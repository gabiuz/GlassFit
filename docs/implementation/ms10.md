## 1. Problem Context & Motivation

When a customer places a product in the visualization workspace and confirms the 4-point perspective quad, the system calls `estimateDimensionsFromCorners()` in `src/lib/visualization/perspectiveTransform.ts` to derive real-world dimensions from the quadrilateral's pixel edge lengths. The current implementation:

1. **Averages pixel edge lengths** without correcting for perspective foreshortening caused by oblique camera angles.
2. **Anchors against hardcoded default heights** (120cm for windows, 210cm for doors from template defaults) regardless of the actual spatial context in the uploaded photo.
3. **Ignores available contextual signals** that are already computed during the FastAPI image analysis pipeline: YOLOv8 detected object bounding boxes, Depth Anything V2 relative depth maps, and camera EXIF metadata.

This produces initial dimension estimates with approximately 25-35% error compared to real-world tape measurements, which flows directly into quotation pricing via the parametric BOM engine (PRD-F10). The measurement confirmation modal (IMP-MS08) allows users to override these values manually, but a more accurate starting estimate reduces user friction, increases trust in the system's intelligence, and provides a better default for users who cannot access a measuring tape.

### The IMP-MS10 Solution: Multi-Signal Measurement Estimation Engine

IMP-MS10 introduces four complementary estimation techniques that piggyback on existing infrastructure (YOLOv8, Depth Anything V2, OpenCV, and Pillow) without adding new ML model downloads or increasing mobile client compute:

1. **Cross-Ratio Geometry Correction:** Improves the perspective quad aspect ratio calculation using projective cross-ratio invariants.
2. **Known-Object Scale Anchoring:** Uses YOLOv8-detected objects with known real-world dimensions (person, refrigerator, chair, etc.) as scale references.
3. **Depth-Ratio Cross-Calibration:** Samples the existing DA V2 relative depth map to correct for distance differences between reference objects and the target opening.
4. **EXIF Focal Length Extraction:** Opportunistically extracts camera intrinsics from uploaded JPEG EXIF metadata when available.

## 4. Technique 1: Cross-Ratio Geometry Correction

### 4.1 Current Problem

The current `estimateDimensionsFromCorners()` in `src/lib/visualization/perspectiveTransform.ts` (lines 166 to 183) computes:

```typescript
const avgWidth = (topWidth + bottomWidth) / 2;
const avgHeight = (leftHeight + rightHeight) / 2;
```

This simple averaging ignores perspective foreshortening. When a user photographs a window from an oblique angle, the far edge appears shorter than the near edge. Averaging these produces an incorrect width-to-height ratio.

### 4.2 Solution: Projective Cross-Ratio

For a rectangle viewed in perspective, the cross-ratio of opposite edge products is preserved under projective transformation. Given four corners P0 (top-left), P1 (top-right), P2 (bottom-right), P3 (bottom-left), the corrected aspect ratio is:

```
topWidth    = ||P1 - P0||
bottomWidth = ||P2 - P3||
leftHeight  = ||P3 - P0||
rightHeight = ||P2 - P1||

A = topWidth * bottomWidth         (product of horizontal edge pairs)
B = leftHeight * rightHeight       (product of vertical edge pairs)

correctedAspect = sqrt(A / B)
```

This is valid under the assumption that the opening is rectangular (true for architectural window and door openings).

### 4.3 Implementation

Replace the body of `estimateDimensionsFromCorners()` with:

```typescript
export function estimateDimensionsFromCorners(corners: QuadrilateralCorners): {
  widthRatio: number;
  heightRatio: number;
} {
  const dist = (p1: Point2D, p2: Point2D) => Math.hypot(p2.x - p1.x, p2.y - p1.y);

  const topWidth = dist(corners[0], corners[1]);
  const bottomWidth = dist(corners[3], corners[2]);
  const leftHeight = dist(corners[0], corners[3]);
  const rightHeight = dist(corners[1], corners[2]);

  // Cross-ratio invariant: corrects for perspective foreshortening
  // when the camera is at an oblique angle to the opening.
  const horizontalProduct = topWidth * bottomWidth;
  const verticalProduct = leftHeight * rightHeight;

  const guard = Math.max(verticalProduct, 1e-6);
  const correctedAspect = Math.sqrt(horizontalProduct / guard);

  // Return corrected values using geometric mean for each axis.
  // This preserves the function signature and downstream consumer compatibility.
  const correctedWidth = Math.sqrt(horizontalProduct);
  const correctedHeight = Math.sqrt(verticalProduct);

  return {
    widthRatio: correctedWidth,
    heightRatio: correctedHeight,
  };
}
```

The function signature and return type remain identical. All downstream consumers (`ProductModelWorkspace.tsx` line 3575) are unaffected.

## 5. Technique 2: Known-Object Scale Anchoring (YOLO Reference Objects)

### 5.1 Rationale

YOLOv8 already detects and returns bounding boxes for COCO-class objects in the uploaded photo via `segmentation.py`. Each object's `bbox` (pixel coordinates `[x1, y1, x2, y2]`) is included in the `/analyze` API response. Objects like persons, refrigerators, chairs, and tables have well-documented real-world dimensions.

If a detected object appears at a similar depth plane as the target opening, its known real-world height provides a physical scale anchor:

```
scale_factor = known_real_height_cm / detected_bbox_height_px
opening_height_cm = quad_height_px * scale_factor
```

### 5.2 Reference Object Dimension Table

Philippine anthropometric and National Building Code reference values:

| COCO Label | Mapped Label | Real-World Reference Height (cm) | Confidence Tier | Notes |
|---|---|---|---|---|
| `person` | `person` | 163 | High | Average Filipino adult height (Philippine Statistics Authority) |
| `refrigerator` | `refrigerator` | 165 | Medium | Standard two-door household refrigerator |
| `toilet` | `toilet` | 40 | Medium | Standard bowl rim height |
| `dining table` | `table` | 75 | Medium | Standard dining table height |
| `chair` | `chair` | 90 | Low-Medium | Standard chair back height (variable) |
| `couch` / `sofa` | `sofa` | 85 | Low-Medium | Standard sofa back height (variable) |
| `bed` | `bed` | 55 | Low | Mattress top height (highly variable) |
| `tv` | `television` | 65 | Low | Estimated average screen height (variable) |
| `oven` | `oven` | 85 | Medium | Standard built-in oven height |
| `microwave` | `microwave` | 30 | Medium | Standard countertop microwave height |

Confidence tiers determine the weight assigned during ensemble blending (Section 8).

### 5.3 Implementation: `fastapi-service/scale_estimation.py`

```python
"""
Scale estimation engine for GlassFit measurement improvement.

Uses YOLOv8-detected reference objects and Depth Anything V2 relative depth maps
to compute a physical scale factor (cm per pixel) for the uploaded space photo.

Traces to: PRD-F4, PRD-F10, SDD-C3, BRD-M1, BRD-M5, BRD-M6
"""

from __future__ import annotations

from dataclasses import dataclass
from typing import Any

import numpy as np

# Reference object heights in centimeters.
# Sources: Philippine Statistics Authority (anthropometric), National Building Code
# of the Philippines (architectural fixtures), and manufacturer standards.
REFERENCE_OBJECT_HEIGHTS_CM: dict[str, tuple[float, float]] = {
    # label: (reference_height_cm, confidence_weight)
    "person":       (163.0, 0.90),
    "refrigerator": (165.0, 0.70),
    "toilet":       (40.0,  0.65),
    "table":        (75.0,  0.60),
    "chair":        (90.0,  0.50),
    "sofa":         (85.0,  0.45),
    "bed":          (55.0,  0.30),
    "television":   (65.0,  0.30),
    "oven":         (85.0,  0.60),
    "microwave":    (30.0,  0.55),
}


@dataclass
class ScaleAnchor:
    """A single scale estimate derived from a detected reference object."""
    label: str
    bbox_height_px: float
    reference_height_cm: float
    scale_cm_per_px: float
    confidence: float
    depth_correction: float


@dataclass
class ScaleEstimationResult:
    """Aggregated scale estimation from all available signals."""
    anchors: list[dict[str, Any]]
    best_scale_cm_per_px: float | None
    confidence: float
    method: str
    exif_focal_length_mm: float | None
    exif_focal_length_35mm: float | None
    exif_device_model: str | None


def estimate_scale_from_objects(
    detected_objects: list[dict[str, Any]],
    depth_array_normalized: "np.ndarray | None" = None,
    image_height: int = 1,
    image_width: int = 1,
) -> ScaleEstimationResult:
    """
    Computes a physical scale factor (cm per pixel) from YOLO-detected
    reference objects, optionally corrected by relative depth ratios.

    Args:
        detected_objects:       The ``objects`` list from the YOLO segmentation result.
                                Each entry must have ``label`` (str) and ``bbox`` ([x1, y1, x2, y2]).
        depth_array_normalized: The 0.0-to-1.0 normalized depth map from Depth Anything V2.
                                When provided, enables depth-ratio cross-calibration.
        image_height:           Original image height in pixels.
        image_width:            Original image width in pixels.

    Returns:
        ScaleEstimationResult with computed anchors, best scale, and confidence.
    """
    anchors: list[ScaleAnchor] = []

    for obj in detected_objects:
        label = str(obj.get("label", "")).lower().strip()
        bbox = obj.get("bbox")

        if label not in REFERENCE_OBJECT_HEIGHTS_CM or bbox is None:
            continue

        x1, y1, x2, y2 = bbox
        bbox_height_px = float(y2 - y1)
        if bbox_height_px < 10:
            continue

        ref_height_cm, base_confidence = REFERENCE_OBJECT_HEIGHTS_CM[label]
        scale = ref_height_cm / bbox_height_px

        # Apply depth-ratio correction if depth map is available.
        depth_correction = 1.0
        if depth_array_normalized is not None:
            depth_correction = _compute_depth_correction(
                depth_array_normalized,
                bbox,
                image_height,
                image_width,
            )
            scale *= depth_correction

        # Weight by YOLO detection confidence if available.
        detection_confidence = float(obj.get("confidence", 0.5))
        combined_confidence = base_confidence * detection_confidence

        anchors.append(ScaleAnchor(
            label=label,
            bbox_height_px=bbox_height_px,
            reference_height_cm=ref_height_cm,
            scale_cm_per_px=scale,
            confidence=combined_confidence,
            depth_correction=depth_correction,
        ))

    if not anchors:
        return ScaleEstimationResult(
            anchors=[],
            best_scale_cm_per_px=None,
            confidence=0.0,
            method="none",
            exif_focal_length_mm=None,
            exif_focal_length_35mm=None,
            exif_device_model=None,
        )

    # Confidence-weighted average of all anchor scale estimates.
    total_weight = sum(a.confidence for a in anchors)
    if total_weight < 1e-6:
        best_scale = anchors[0].scale_cm_per_px
        overall_confidence = 0.1
    else:
        best_scale = sum(a.scale_cm_per_px * a.confidence for a in anchors) / total_weight
        overall_confidence = min(1.0, total_weight / len(anchors))

    return ScaleEstimationResult(
        anchors=[
            {
                "label": a.label,
                "bbox_height_px": round(a.bbox_height_px, 1),
                "reference_height_cm": a.reference_height_cm,
                "scale_cm_per_px": round(a.scale_cm_per_px, 6),
                "confidence": round(a.confidence, 3),
                "depth_correction": round(a.depth_correction, 4),
            }
            for a in anchors
        ],
        best_scale_cm_per_px=round(best_scale, 6),
        confidence=round(overall_confidence, 3),
        method="yolo_anchor" + ("_depth_corrected" if depth_array_normalized is not None else ""),
        exif_focal_length_mm=None,
        exif_focal_length_35mm=None,
        exif_device_model=None,
    )


def _compute_depth_correction(
    depth_array_normalized: np.ndarray,
    bbox: list[int],
    image_height: int,
    image_width: int,
) -> float:
    """
    Samples the relative depth at the center of a bounding box using a 5x5 patch average.

    The depth correction factor compensates for distance differences between
    the reference object and the target opening. Since the perspective quad
    is not yet known at this stage, this returns a raw depth sample that
    the client can use for correction when the quad is placed.

    Returns 1.0 if the depth map cannot be sampled.
    """
    try:
        h, w = depth_array_normalized.shape[:2]
        x1, y1, x2, y2 = bbox

        # Map bbox to depth map coordinates (depth map may differ from image size).
        cx = int(((x1 + x2) / 2) * w / max(image_width, 1))
        cy = int(((y1 + y2) / 2) * h / max(image_height, 1))

        # 5x5 patch average for noise reduction.
        patch_half = 2
        y_start = max(0, cy - patch_half)
        y_end = min(h, cy + patch_half + 1)
        x_start = max(0, cx - patch_half)
        x_end = min(w, cx + patch_half + 1)

        patch = depth_array_normalized[y_start:y_end, x_start:x_end]
        if patch.size == 0:
            return 1.0

        depth_value = float(np.mean(patch))
        if depth_value < 0.01:
            return 1.0

        return depth_value
    except Exception:
        return 1.0
```

### 5.4 Depth-Ratio Cross-Calibration Detail

The `_compute_depth_correction()` function returns a depth sample at the reference object's center. The client-side integration (Section 8) also samples the depth at the perspective quad's center. The ratio between these two depth samples corrects the scale factor:

```
corrected_scale = object_scale * (depth_at_object / depth_at_opening)
```

If the reference object is closer to the camera (higher depth value in DA V2's near-is-bright convention), its pixels are "larger" per real-world cm. Dividing by the opening's depth normalizes for this difference.

## 6. Technique 3: EXIF Focal Length Extraction

### 6.1 Rationale

Smartphone JPEG uploads frequently contain EXIF metadata with `FocalLength`, `FocalLengthIn35mmFilm`, and device `Model` tags. When present, these provide the camera's actual horizontal field of view, which is more accurate than the hardcoded 60-degree default.

EXIF metadata is stripped by social media platforms (Facebook Messenger, Viber) and screenshot tools. Therefore, this technique is **strictly optional** and must never gate any feature.

### 6.2 Implementation: `fastapi-service/exif_extraction.py`

```python
"""
Safe EXIF metadata extraction for camera intrinsics.

Extracts focal length and device model from uploaded JPEG EXIF tags
using Pillow (already a project dependency). Returns None for all
fields when EXIF data is absent or unreadable.

Traces to: PRD-F3, SDD-C2
"""

from __future__ import annotations

from dataclasses import dataclass
from pathlib import Path


@dataclass
class ExifCameraInfo:
    """Camera intrinsics extracted from EXIF metadata."""
    focal_length_mm: float | None
    focal_length_35mm_equiv: float | None
    device_model: str | None
    image_width_exif: int | None
    image_height_exif: int | None


def extract_exif_camera_info(image_path: Path | str) -> ExifCameraInfo:
    """
    Extracts camera focal length and device model from JPEG EXIF metadata.

    Returns an ExifCameraInfo with all None fields if EXIF is absent,
    corrupt, or the image format does not support EXIF.

    This function never raises exceptions. All failures return empty results.
    """
    empty = ExifCameraInfo(
        focal_length_mm=None,
        focal_length_35mm_equiv=None,
        device_model=None,
        image_width_exif=None,
        image_height_exif=None,
    )

    try:
        from PIL import Image as PILImage
        from PIL.ExifTags import Base as ExifBase

        img = PILImage.open(str(image_path))
        exif_data = img.getexif()
        if not exif_data:
            return empty

        # Tag 37386: FocalLength (rational number, actual lens focal length in mm)
        focal_raw = exif_data.get(ExifBase.FocalLength)
        focal_length_mm = None
        if focal_raw is not None:
            try:
                focal_length_mm = float(focal_raw)
            except (TypeError, ValueError):
                pass

        # Tag 41989: FocalLengthIn35mmFilm (integer, 35mm equivalent)
        focal_35mm_raw = exif_data.get(ExifBase.FocalLengthIn35mmFilm)
        focal_length_35mm = None
        if focal_35mm_raw is not None:
            try:
                focal_length_35mm = float(focal_35mm_raw)
            except (TypeError, ValueError):
                pass

        # Tag 272: Model (device model string)
        device_model = None
        model_raw = exif_data.get(ExifBase.Model)
        if model_raw is not None:
            device_model = str(model_raw).strip() or None

        # Tag 40962 / 40963: PixelXDimension / PixelYDimension
        exif_width = None
        exif_height = None
        width_raw = exif_data.get(ExifBase.ExifImageWidth)
        height_raw = exif_data.get(ExifBase.ExifImageHeight)
        if width_raw is not None:
            try:
                exif_width = int(width_raw)
            except (TypeError, ValueError):
                pass
        if height_raw is not None:
            try:
                exif_height = int(height_raw)
            except (TypeError, ValueError):
                pass

        return ExifCameraInfo(
            focal_length_mm=focal_length_mm,
            focal_length_35mm_equiv=focal_length_35mm,
            device_model=device_model,
            image_width_exif=exif_width,
            image_height_exif=exif_height,
        )

    except Exception:
        return empty
```

### 6.3 Privacy Safeguard

EXIF data may contain GPS coordinates, timestamps, and device serial numbers. The extraction function reads **only** focal length, device model, and image dimensions. GPS tags (`GPSInfo`, tag 34853) and timestamp tags (`DateTime`, tag 306) are **never** read, logged, stored, or forwarded. The `ExifCameraInfo` dataclass contains no PII fields.

## 8. Client-Side Integration & Ensemble Blending

### 8.1 New Module: `src/lib/visualization/scaleEstimation.ts`

This module receives the `scale_estimation` field from the API response and computes a final dimension estimate when the user confirms the perspective quad.

```typescript
/**
 * Scale estimation integration for improved initial dimension defaults.
 *
 * Receives scale signals from the FastAPI /analyze response and combines
 * them with the cross-ratio-corrected perspective quad measurements to
 * produce confidence-weighted initial widthCm / heightCm values.
 *
 * Traces to: PRD-F10, SDD-C5, BRD-M1
 */

export interface ScaleEstimationSignal {
  anchors: Array<{
    label: string;
    bbox_height_px: number;
    reference_height_cm: number;
    scale_cm_per_px: number;
    confidence: number;
    depth_correction: number;
  }>;
  best_scale_cm_per_px: number | null;
  confidence: number;
  method: string;
  exif_focal_length_mm: number | null;
  exif_focal_length_35mm: number | null;
  exif_device_model: string | null;
}

export interface DimensionEstimate {
  widthCm: number;
  heightCm: number;
  confidence: number;
  method: string;
}

/**
 * Computes improved initial dimensions by blending the scale estimation
 * signal with the perspective quad's cross-ratio-corrected aspect ratio.
 *
 * When a YOLO reference object anchor is available, the quad's pixel
 * dimensions are multiplied by the physical scale factor. When no anchor
 * is available, falls back to the existing default-height heuristic.
 */
export function computeEstimatedDimensions(
  quadWidthPx: number,
  quadHeightPx: number,
  scaleSignal: ScaleEstimationSignal | null,
  isDoor: boolean,
  templateDefaultHeightCm: number | null,
  depthAtQuadCenter: number | null,
): DimensionEstimate {
  const defaultHeight = isDoor
    ? (templateDefaultHeightCm ?? 210)
    : (templateDefaultHeightCm ?? 120);

  // No scale signal available: fall back to existing behavior.
  if (
    !scaleSignal ||
    scaleSignal.best_scale_cm_per_px === null ||
    scaleSignal.confidence < 0.1
  ) {
    const aspect = quadWidthPx / Math.max(quadHeightPx, 1);
    return {
      widthCm: Math.round(defaultHeight * aspect),
      heightCm: defaultHeight,
      confidence: 0,
      method: "default_heuristic",
    };
  }

  let effectiveScale = scaleSignal.best_scale_cm_per_px;

  // Apply depth correction for the quad position if depth data is available.
  // The API returns depth_correction per anchor (depth at the object).
  // We need to adjust for the depth at the quad center.
  if (depthAtQuadCenter !== null && depthAtQuadCenter > 0.01) {
    // Find the average depth_correction across anchors (depth at reference objects).
    const anchorDepths = scaleSignal.anchors
      .map((a) => a.depth_correction)
      .filter((d) => d > 0.01);
    if (anchorDepths.length > 0) {
      const avgAnchorDepth =
        anchorDepths.reduce((sum, d) => sum + d, 0) / anchorDepths.length;
      // Correct scale: if opening is farther (lower depth value),
      // each pixel covers more real-world distance.
      effectiveScale *= avgAnchorDepth / depthAtQuadCenter;
    }
  }

  const estimatedWidth = Math.round(quadWidthPx * effectiveScale);
  const estimatedHeight = Math.round(quadHeightPx * effectiveScale);

  // Blend with default heuristic using confidence weight.
  const w = Math.min(scaleSignal.confidence, 0.85);
  const blendedWidth = Math.round(
    w * estimatedWidth + (1 - w) * defaultHeight * (quadWidthPx / Math.max(quadHeightPx, 1)),
  );
  const blendedHeight = Math.round(
    w * estimatedHeight + (1 - w) * defaultHeight,
  );

  // Clamp to architecturally reasonable ranges.
  const clampedWidth = Math.max(30, Math.min(600, blendedWidth));
  const clampedHeight = Math.max(30, Math.min(400, blendedHeight));

  return {
    widthCm: clampedWidth,
    heightCm: clampedHeight,
    confidence: scaleSignal.confidence,
    method: scaleSignal.method,
  };
}
```

## 9. Fallback & Degradation Strategy

| Scenario | Behavior | User Impact |
|---|---|---|
| No YOLO reference objects detected | Scale estimation returns `confidence: 0`, `method: "none"` | Client falls back to the existing default-height heuristic. No change from current behavior. |
| YOLO detects objects but depth map is unavailable | Scale estimation uses uncorrected object anchoring (no depth ratio) | Slightly less accurate than depth-corrected, but still better than hardcoded defaults. |
| EXIF metadata is stripped (social media upload) | EXIF fields return `null` | Scale estimation proceeds without EXIF. No feature is gated on EXIF availability. |
| FastAPI scale estimation module fails | Main pipeline catches the exception, returns `scale_estimation: null` | Client falls back to existing behavior. No degradation to the core upload flow. |
| Depth map at quad center is near-zero (edge case) | Depth correction is skipped (`depth_correction: 1.0`) | Uses uncorrected scale anchor. |
| All reference objects have low confidence | Ensemble blending weights default-height heuristic more heavily | Produces a conservatively blended estimate closer to the existing defaults. |

## 12. Risks and Mitigations

| Risk | Severity | Mitigation |
|---|---|---|
| Reference object dimensions are averages, not exact | Medium | Use confidence weighting and ensemble blending to reduce the impact of any single inaccurate reference. Label all estimates as "Estimated" in the UI. |
| YOLO may detect a child as "person" (shorter than 163cm) | Low | The confidence-weighted ensemble blends toward defaults when scale signal is uncertain. The measurement modal always allows manual override. |
| Depth map noise at object edges produces incorrect depth samples | Medium | Use 5x5 patch averaging centered on the bounding box midpoint, not edge pixels. |
| Cross-ratio correction assumes rectangular openings | Low | Valid for architectural window and door openings per the Philippine National Building Code. Non-rectangular openings (arches) are outside GlassFit's current product catalog. |
| EXIF focal length reports 35mm-equivalent, not true sensor focal length | Low | EXIF data is informational only in IMP-MS10. It is included in the response for potential future metric depth usage but does not directly affect the scale computation in this milestone. |
| Users over-trust AI estimates and skip tape measurement | Medium | The measurement modal (IMP-MS08) always opens before quotation. Estimates are labeled "Estimated" with a visual distinction from "Manual (Tape Measured)" source. |
