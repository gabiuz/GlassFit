## 1. Problem Context & Motivation

When a customer finishes configuring a product in the visualization workspace and clicks "Continue to Comparison", the current `handleContinueToComparison` function (in `src/features/visualization/components/ProductModelWorkspace.tsx`) immediately captures the workspace snapshot and routes to `/comparison` without any user-facing checkpoint on the dimensional measurements that feed the parametric Bill-of-Materials (BOM) pricing engine.

The width and height stored in `widthCm` / `heightCm` are system-estimated values derived from the perspective plane fitting algorithm (or from default parametric template values). These values are used verbatim to compute the final quotation via `calculateBOMFromStructuralDefinition`. This creates two user experience problems:

1. **Silent Measurement Ambiguity:** The customer proceeds to comparison without ever explicitly seeing or confirming the measurements the system used to price the product. If the system estimated poorly (e.g., a skewed perspective plane produced an unlikely 94-inch width), the final quotation will be wrong.

2. **No Opportunity for Real-World Override:** Customers who have a measuring tape or know their actual opening dimensions have no mechanism in the current flow to assert those real measurements before the quotation is generated and sent to the fabricator.

### The MS-08 Solution: Measurement Confirmation Modal Gate

MS-08 introduces a **Measurement Confirmation Modal** that intercepts the "Continue to Comparison" action and presents each product in a paged modal flow before navigation to `/comparison`. The modal:

- Displays the system-computed outer width and height converted to inches for each product in the session.
- Renders the parametric 3D model preview of each product (matching the product showcase viewer `ProductModel3D`) with the configured variation (aluminum finish) visually applied.
- Shows the computed finish price for the product at the displayed dimensions.
- Allows the user to override the width and height fields; any override triggers live BOM recalculation so that the displayed price updates in real-time.
- When a user overrides any measurement, presents a formal acknowledgement checkbox agreement that the entered measurements are real, accurate, and the user's own responsibility.
- For multi-product sessions (where `placedOverlays.length > 0` and/or `selectedProduct` is active), the modal pages through one product at a time using left/right navigation arrows.
- Confirms (commits) all measurements from all modal pages before allowing navigation to `/comparison`.

## 4. User Flow Specification

### 4.1 Trigger Point

The modal is triggered by the user clicking "Continue to Comparison" in `ProductModelWorkspace.tsx`. The existing `handleContinueToComparison` (starting around line 1585) captures the snapshot, assembles `comparisonOverlays`, and calls `router.push("/comparison")`.

MS-08 inserts a modal interception step before the final `router.push`:

1. Snapshot capture still happens first (to produce the flattened images).
2. Before `router.push`, the modal opens with the assembled product list.
3. The user pages through each product's measurement confirmation page.
4. On the final page, clicking "Confirm All & Continue" commits overrides and routes to `/comparison`.

### 4.2 Modal Product Entry Assembly

When the modal opens, a `MeasurementConfirmationEntry[]` list is built from the current session state:

| Entry Source | Product Name | Dimensions Source | Price Source | 3D Model Source |
|---|---|---|---|---|
| Each item in `placedOverlays` (non-active), in array order | `overlay.productName` | `overlay.configuration.widthCm`, `overlay.configuration.heightCm` | `overlay.totalPrice` (static; override recalculation uses `overlay.bomResult` if available) | Resolved from `catalogProducts` by matching `overlay.productId` to retrieve `preview_glb_url` |
| Active product (`selectedProduct === true`) | `selectedProductName` | `widthCm`, `heightCm` from workspace state | `realtimePricing.totalPrice` | `structuralDefinition.product.preview_glb_url` |

The active product is always presented as the last page.

### 4.3 Per-Page Modal Content

Each page of the modal presents one product and contains the following sections in vertical order:

**1. Product Identity Header**

Product name in the section heading, a variation badge showing the selected aluminum finish (e.g., "White Powder Coat"), and a page counter label ("1 of 3") on the right.

**2. 3D Model Preview Panel**

A square canvas rendering `ProductModel3D` (dynamically imported with `ssr: false`, same pattern as `ProductDetails.tsx`) using the product's `preview_glb_url`. The panel uses `rounded-[20px] overflow-hidden bg-neutral-50 border border-neutral-200/80` with a minimum height of 240px. Auto-rotation and orbit controls are active. When `preview_glb_url` is null, the panel shows the product catalog thumbnail image with the label "3D preview unavailable".

**3. Measurement Verification Section**

Section label: "Confirm Opening Measurements"
Subtext: "These are the outer dimensions (width x height) the system computed for your product. Verify against your actual wall opening."

Two side-by-side measurement fields:
- **Outer Width (in):** System-computed value: `parseFloat((widthCm * 0.393701).toFixed(1))`. Centimeter echo label below: e.g., "120 cm".
- **Outer Height (in):** System-computed value: `parseFloat((heightCm * 0.393701).toFixed(1))`. Centimeter echo label below: e.g., "150 cm".

Both fields are initially non-editable (styled as read-only display). Each has an independent "Edit" text button to unlock it for numeric input. Unlocking one field does not affect the other. When unlocked, the field uses the teal active border (`border-[#07b6d3]`) input style.

**4. Estimated Price Display**

A price card labeled "Estimated Price" showing the formatted total (Php format, integer precision). On modal open, the price reflects the system-computed value. After an override, the price updates after a 200ms debounce to reflect the BOM recalculation at the override dimensions.

**5. Override Acknowledgement Agreement (conditional)**

Appears only when at least one dimension field on the current product page has been modified. Contains:
- An amber-styled bordered card with the text: "By overriding the system-computed measurements, I confirm that the width and height I have entered are real, accurate measurements I have personally taken or verified. I understand that incorrect measurements may result in fabrication errors and that GlassFit and the fabricator are not responsible for discrepancies arising from customer-provided overrides."
- A checkbox: "I confirm the measurements I entered are accurate."
- The "Next" or "Confirm All & Continue" button is disabled until this checkbox is checked when an override is active.

**6. Navigation Controls**

- Left arrow (`ChevronLeft`): disabled on page 1, enabled on subsequent pages.
- Right side: "Next" button (with `ChevronRight`) on all pages except the last. On the last page: primary "Confirm All & Continue" button.
- Bottom: "Cancel" secondary button that dismisses the modal without navigating.

### 4.4 Measurement Override Behavior

When a user modifies a width or height field:

1. The inch input value is converted to cm: `cm = inches / 0.393701`.
2. `MeasurementConfirmationEntry.override.widthIn` or `heightIn` is updated in local state.
3. The corresponding `widthOverridden` or `heightOverridden` flag is set to `true`.
4. `calculateBOMFromStructuralDefinition` is called (debounced 200ms) with `widthMm = Math.round(overrideCmW * 10)` and `heightMm = Math.round(overrideCmH * 10)`.
5. `entry.recalculatedTotalPrice` updates with `finalQuotation * quantity`.
6. The price card displays `recalculatedTotalPrice`.
7. If the override exceeds structural limits (width > 2400mm for a 2-panel product), an inline amber badge appears below the field: "Exceeds recommended structural limit. Consult with the fabricator." The navigation button is not blocked.
8. The acknowledgement section becomes visible.
9. The navigation/confirm button is disabled until `entry.override.acknowledged` is `true`.

### 4.5 Commit and Navigation

When the user clicks "Confirm All & Continue" on the final page:

1. **Active product:** If `widthOverridden`, call `setWidthCm(String(Math.round(override.widthIn / 0.393701)))`. If `heightOverridden`, call `setHeightCm(String(Math.round(override.heightIn / 0.393701)))`.
2. **Non-active placed overlays:** For each overlay with a corresponding `MeasurementConfirmationEntry` where `widthOverridden` or `heightOverridden` is `true`:
   - Patch `overlay.configuration.widthCm` and `heightCm` with `Math.round(override.widthIn / 0.393701)` and `Math.round(override.heightIn / 0.393701)` respectively.
   - Patch `overlay.configuration.visualParameterValues.width` with the override width in mm.
   - Patch `overlay.configuration.visualParameterValues.height` with the override height in mm.
3. Pass patched overlays to `onPlacedOverlaysChange` and `onComparisonOverlaysChange`.
4. Call `router.push("/comparison")`.

```typescript
const handleContinueToComparison = useCallback(async () => {
  setIsCapturingSnapshot(true);

  try {
    await captureCurrentSnapshot();
    setIsSnapshotApplied(true);

    if (!selectedProduct && placedOverlays.length === 0) {
      await generateVariationSnapshots();
    }

    const comparisonOverlays = selectedProduct

  } catch (error) {

      error instanceof Error
        ? error.message
        : "Unable to prepare the visualization comparison.";
    setProductBuildError(message);
  } finally {
    setIsCapturingSnapshot(false);
  }
}, [/* deps */]);
```

#### 5.4.3 New `handleMeasurementConfirmAll` Callback

```typescript
const handleMeasurementConfirmAll = useCallback(
  (confirmedEntries: MeasurementConfirmationEntry[]) => {
    setIsMeasurementModalOpen(false);

    const activeEntry = confirmedEntries.find((e) => e.isActiveProduct);
    if (activeEntry?.override.widthOverridden) {
      setWidthCm(String(convertInToCm(activeEntry.override.widthIn)));
    }
    if (activeEntry?.override.heightOverridden) {
      setHeightCm(String(convertInToCm(activeEntry.override.heightIn)));
    }

    const patchedOverlays = applyMeasurementOverridesToOverlays(
      confirmedEntries.filter((e) => !e.isActiveProduct),
      placedOverlays,
    );

    onPlacedOverlaysChange?.(patchedOverlays);
    onComparisonOverlaysChange?.(patchedOverlays);
    router.push("/comparison");
  },
  [/* deps */],
);
```

```typescript
const handleMeasurementModalCancel = useCallback(() => {

  setIsSnapshotApplied(false);
}, []);
```

## 7. Measurement Conversion Reference

All measurement display in the modal uses inches as the primary unit, with centimeters as a secondary reference.

| Conversion Direction | Formula | Display Precision |
|---|---|---|
| cm to inches (display) | `inches = cm * 0.393701` | 1 decimal place (e.g., 47.2 in) |
| inches to cm (commit) | `cm = Math.round(inches / 0.393701)` | Integer cm (e.g., 120 cm) |
| cm to mm (BOM input) | `mm = Math.round(cm * 10)` | Integer mm |

The outer measurement corresponds directly to `widthCm` and `heightCm` in `ProductConfigurationSnapshot`. These are the full outer frame dimensions of the product (not glass daylight area, not sash leaf width). Both fields are labeled "Outer Width" and "Outer Height" in the modal.

## 8. Multi-Product Pagination Specification

When the entry count is 1 (single-product session), the modal renders with no navigation arrows and a direct "Confirm & Continue" primary button.

When the entry count is 2 or more (multi-product session):

| UI State | Left Arrow | Right Side | Primary Button Visibility |
|---|---|---|---|
| Page 1 of N (N > 1) | Disabled | "Next" with `ChevronRight` icon | Hidden |
| Page M of N (1 < M < N) | Enabled with `ChevronLeft` | "Next" with `ChevronRight` icon | Hidden |
| Last page (M = N) | Enabled with `ChevronLeft` | Hidden | Shown: "Confirm All & Continue" |

Page ordering:
1. Non-active placed overlays in their `placedOverlays` array order (pages 0 through N-2).
2. Active product as the last page (page N-1).

## 9. Definition of Done (Exit Criteria)

The implementation of MS-08 is complete when all of the following verification criteria are satisfied:

1. **Modal Gate Enforcement:** Clicking "Continue to Comparison" opens `MeasurementConfirmationModal` instead of navigating directly to `/comparison`.
2. **System Dimension Display:** Each product page shows system-computed outer width and height in inches, with centimeter echo labels below each field.
3. **3D Model Preview Rendered:** Each product page embeds a functioning `ProductModel3D` viewer using the product's `preview_glb_url`, with auto-rotation and orbit controls enabled.
4. **Price Display Accuracy:** The displayed price matches the BOM calculation for the current system-computed dimensions at modal open.
5. **Edit Toggle Behavior:** Both width and height fields start as non-editable; each has an independent "Edit" toggle. Unlocking one does not unlock the other.
6. **Override Recalculation:** Typing a different inch value into an unlocked field triggers a debounced (200ms) BOM recalculation; the price card updates accordingly.
7. **Acknowledgement Enforcement:** When any measurement is overridden, the "Next" or "Confirm All & Continue" button is disabled until the acknowledgement checkbox is checked for that product page.
8. **Multi-Product Navigation:** Navigation arrows page through each product sequentially; left arrow is disabled on page 1; "Confirm All & Continue" appears only on the last page.
9. **Measurement Commit:** After "Confirm All & Continue", overridden measurements are applied to workspace state and overlay configurations before `router.push("/comparison")`.
10. **Cancel Behavior:** Clicking "Cancel" dismisses the modal without navigating; `isSnapshotApplied` is reset to `false` to restore workspace edit mode.
11. **Zero Regressions:** Perspective plane fitting, structural guardrail modal, and snapshot capture continue to function correctly.
12. **Build & Quality Assurance:**
    - `npm run lint` passes with zero errors.
    - `npx tsc --noEmit` passes with zero type errors.
    - `npm run build` compiles without errors.
    - Zero em-dashes in any code comment or documentation (BAN-PUNCT-01).
    - Zero `any` types in TypeScript (BAN-TYPE-05).

## 10. Risk Assessment & Mitigations

| Identified Risk | Severity | Probability | Mitigation Strategy |
|---|---|---|---|
| Non-active placed overlays lack a live `structuralDefinition` for override BOM recalculation | Medium | High | Use `overlay.bomResult` (stored as `CalculatedBOMResult` in `PlacedOverlay.bomResult`) for recalculation. If `bomResult` is unavailable, display the price as static with a note: "Live price recalculation unavailable for this product. The shown price reflects the originally configured dimensions." Navigation is not blocked. |
| `preview_glb_url` is null for a product | Low | Medium | Replace the 3D viewer panel with the product catalog thumbnail and the label "3D preview unavailable". The measurement confirmation flow proceeds normally. |
| User overrides dimensions beyond structural guardrail thresholds | Medium | Low | Show an inline amber badge below the field: "Exceeds recommended structural limit. Consult with the fabricator." Navigation is not blocked; the guardrail modal belongs to the workspace edit flow and is not re-triggered here. |
| Modal state out of sync if user cancels after modal open | Low | Low | The cancel handler resets `isSnapshotApplied` to `false`, restoring edit mode. Modal state is not persisted to the session store. |
