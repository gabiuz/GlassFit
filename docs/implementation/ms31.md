## 1. Executive Summary & Problem Context

In the GlassFit operational workflow, customer consultation requests originate from parametric 3D space visualizer sessions and quotation compilations. These consultations are persisted as interrelated database entities spanning quotation estimates, line items, signed booking links, and consultation booking requests.

### 1.1 The Reported Defect & Architectural Root Cause

Under the current implementation in `src/features/admin/bookings/BookingsContent.tsx` and `src/features/admin/bookings/bookingState.ts`:

1. **No-Op Discard Action:** In the administrative booking inspector panel, a prominent red button labeled "Discard" (`bg-[#c50000]`) is rendered adjacent to "Save Changes". When clicked, it invokes `handleDiscardChanges()`, which dispatches `{ type: "discard-status" }`.
2. **Local State Only:** The reducer action `discard-status` only resets the local React state variable `currentStatus` back to the booking's currently selected database status (`selected?.status ?? "Pending"`). If the administrator has not changed the status dropdown, clicking "Discard" produces zero visual feedback and zero system effect.
3. **Missing Delete Capability:** Administrators frequently encounter test bookings, invalid inquiries, duplicates, or abandoned consultations that need to be permanently removed from the system. No mechanism exists in the back office to discard or delete these records.
4. **Foreign Key Deletion Blocks:** At the database level, foreign key constraints on `signed_booking_links(link_id)` and `quotation_estimates(quotation_id)` use `ON DELETE RESTRICT`. Directly calling a naive delete on either table fails with a PostgreSQL constraint violation unless deleted in strict topological sequence or handled through a cascading transaction.
5. **Missing Delete RLS Policies:** The table `public.booking_requests` currently lacks an explicit `DELETE` Row-Level Security policy, preventing even authenticated administrators from deleting consultation booking rows via standard PostgREST endpoints.
6. **Ghost Quotations on Customer Surface:** Because records cannot be purged, discarded quotations remain indefinitely visible to the customer on `/my-requests` and remain accessible via public signed links (`/q/[code]`), leading to customer confusion and erroneous consultation expectations.

### 1.2 Required System Behavior

To fulfill the operational requirements, the Discard control must function as a comprehensive hard-delete mechanism:

1. **Destructive Confirmation Guard:** Clicking "Discard" in `/admin/bookings` must not trigger an instant unconfirmed deletion. Instead, it must open a confirmation dialog styled strictly according to GlassFit design tokens (`DSD-UI12`). The dialog must explicitly warn the administrator that the quotation, consultation request, and all associated line items will be permanently erased.
2. **Atomic Hard Deletion in Database:** Upon confirmation, the backend must execute an atomic hard-delete transaction across all associated relational records:
   - `public.booking_requests` (the customer consultation request)
   - `public.signed_booking_links` (the secure signed link)
   - `public.quotation_items` (all itemized product and fixture lines)
   - `public.quotation_estimates` (the primary quotation estimate record)
   - `public.visualization_snapshots` and associated `public.product_configurations` (if the snapshot is exclusive to this quotation)
3. **Cloudflare R2 Storage Cleanup:** If a consultation quotation PDF has been generated and stored (`pdf_r2_object_key`), the backend must clean up the binary asset in Cloudflare R2 to prevent storage leaks.
4. **Bidirectional Purge Reflection:**
   - **Admin Surface:** The deleted booking is removed immediately from `/admin/bookings`, the selection moves to the next available booking (or renders a clean empty state), and the dashboard metrics refresh.
   - **Customer Surface:** The consultation booking immediately disappears from the customer's `/my-requests` portal. Navigating to the public signed link (`/q/[code]`) returns a clean 404 / Not Found screen.
5. **Strict Permission Enforcement:** The hard deletion must require the `manage_bookings` administrative permission, verified both at the Next.js server action layer and inside PostgreSQL via RLS policies or Security Definer functions.

### 1.3 Scope Boundaries & Non-Goals

- **Non-Goal (Soft Deletion):** The requirement specifically mandates a hard delete so the quotation is permanently erased from the database, not flagged with an `is_deleted` column.
- **Non-Goal (Customer Self-Service Deletion):** Customers cannot unilaterally delete admin-triageable booking requests from `/my-requests`; deletion remains an administrative governance capability.
- **Non-Goal (Catalog Asset Purging):** Shared product templates, global materials, and public catalogue entries are never touched when deleting a customer consultation quotation.

## 3. Relational Persistence & Database Migration

### 3.1 Migration File Specification

### 3.2 Constraint Analysis & Foreign Key Topology

The current foreign key topology imposes `ON DELETE RESTRICT` constraints that prevent child and parent records from being deleted independently:

| Dependent Table | Foreign Key Column | Referenced Table | Current Action | Required Update in Migration 013 |
|---|---|---|---|---|
| `booking_requests` | `link_id` | `signed_booking_links` | `ON DELETE RESTRICT` | Update to `ON DELETE CASCADE` |
| `signed_booking_links` | `quotation_id` | `quotation_estimates` | `ON DELETE RESTRICT` | Update to `ON DELETE CASCADE` |
| `signed_booking_links` | `snapshot_id` | `visualization_snapshots` | `ON DELETE RESTRICT` | Maintain or update to `ON DELETE SET NULL` |
| `quotation_items` | `quotation_id` | `quotation_estimates` | `ON DELETE CASCADE` | Retained (already `CASCADE`) |
| `product_configurations` | `snapshot_id` | `visualization_snapshots` | `ON DELETE CASCADE` | Retained (already `CASCADE`) |
| `configuration_variations` | `configuration_id` | `product_configurations` | `ON DELETE CASCADE` | Retained (already `CASCADE`) |

By configuring `booking_requests.link_id` and `signed_booking_links.quotation_id` with `ON DELETE CASCADE`, deleting a quotation estimate automatically and cleanly cascades to its signed booking link and booking request, ensuring zero orphaned records.

### 3.4 Atomic PostgreSQL Stored Function (`public.hard_delete_booking_quotation`)

To guarantee transaction atomicity and collect storage keys for cleanup, migration 013 defines an administrative stored procedure:

```sql
create or replace function public.hard_delete_booking_quotation(
  p_booking_request_id uuid
)
returns jsonb
language plpgsql
security definer
set search_path = public, pg_temp
as $$
declare
  v_admin_id uuid;
  v_link_id uuid;
  v_quotation_id uuid;
  v_snapshot_id uuid;
  v_pdf_r2_key text;
  v_image_r2_key text;
  v_quotation_number text;
  v_other_links_count int;
begin
  -- 1. Authenticate caller and assert admin privileges
  v_admin_id := auth.uid();
  if v_admin_id is null then
    raise exception 'UNAUTHENTICATED: Caller must be authenticated.';
  end if;

  if not (public.has_admin_permission('manage_bookings') or public.is_admin()) then
    raise exception 'UNAUTHORIZED: Insufficient permissions to delete booking consultations.';
  end if;

  -- 2. Locate the booking request and associated keys
  select
    br.link_id,
    sbl.quotation_id,
    qe.snapshot_id,
    qe.pdf_r2_object_key,
    qe.quotation_number
  into
    v_link_id,
    v_quotation_id,
    v_snapshot_id,
    v_pdf_r2_key,
    v_quotation_number
  from public.booking_requests br
  left join public.signed_booking_links sbl on sbl.link_id = br.link_id
  left join public.quotation_estimates qe on qe.quotation_id = sbl.quotation_id
  where br.booking_request_id = p_booking_request_id;

  if not found then
    raise exception 'NOT_FOUND: Booking request % does not exist.', p_booking_request_id;
  end if;

  -- 3. Delete booking request
  delete from public.booking_requests
  where booking_request_id = p_booking_request_id;

  -- 4. Delete signed booking link if present
  if v_link_id is not null then
    delete from public.signed_booking_links
    where link_id = v_link_id;
  end if;

  -- 5. Delete quotation items and quotation estimate if present
  if v_quotation_id is not null then
    delete from public.quotation_items
    where quotation_id = v_quotation_id;

    delete from public.quotation_estimates
    where quotation_id = v_quotation_id;
  end if;

  -- 6. Evaluate snapshot cleanup: check if snapshot is referenced by any other quotation
  if v_snapshot_id is not null then
    select count(*) into v_other_links_count
    from public.quotation_estimates
    where snapshot_id = v_snapshot_id;

    if v_other_links_count = 0 then
      select final_image_r2_key into v_image_r2_key
      from public.visualization_snapshots
      where snapshot_id = v_snapshot_id;

      delete from public.visualization_snapshots
      where snapshot_id = v_snapshot_id;
    end if;
  end if;

  -- 7. Return summary payload containing storage keys for external purge
  return jsonb_build_object(
    'success', true,
    'booking_request_id', p_booking_request_id,
    'quotation_id', v_quotation_id,
    'quotation_number', v_quotation_number,
    'pdf_r2_object_key', v_pdf_r2_key,
    'image_r2_key', v_image_r2_key
  );
end;
$$;

revoke all on function public.hard_delete_booking_quotation(uuid) from public;
grant execute on function public.hard_delete_booking_quotation(uuid) to authenticated;
```

export const DeleteBookingQuotationInputSchema = z.object({
  bookingRequestId: z.string().uuid("Invalid booking request UUID"),
  quotationId: z.string().uuid("Invalid quotation UUID").optional(),

export type DeleteBookingQuotationResult =
  | {
      success: true;
      bookingRequestId: string;
      quotationId: string | null;
      quotationNumber: string;
      pdfR2ObjectKey: string | null;
    }

### 4.2 Server Action Implementation (`src/lib/booking/bookingActions.ts`)

Export a dedicated server action that coordinates permission verification, the atomic database RPC call, and path revalidations:

```typescript
/**
 * Admin action to permanently hard-delete a consultation booking request,
 * its signed booking link, and backing quotation estimate (IMP-MS31).
 *
 * Traceability: PRD-F13, PRD-F14, SDD-C8, SDD-C9, ERD-E13, ERD-E16, QAD-TC46
 */
export async function deleteBookingQuotation(
  input: DeleteBookingQuotationInput
): Promise<DeleteBookingQuotationResult> {
  try {
    // 1. Assert admin permission
    await requirePermission("manage_bookings");
    const validated = DeleteBookingQuotationInputSchema.parse(input);

    const supabase = await createSupabaseServerClient();

    // 2. Execute atomic database deletion function
    const { data, error } = await supabase.rpc("hard_delete_booking_quotation", {
      p_booking_request_id: validated.bookingRequestId,
    });

    if (error) {
      console.error("[deleteBookingQuotation] RPC failed:", error);
      return {
        success: false,
        code: "PERSISTENCE_ERROR",
        error: error.message || "Failed to delete booking quotation.",
      };
    }

    const payload = data as {
      success: boolean;
      booking_request_id: string;
      quotation_id: string | null;
      quotation_number: string;
      pdf_r2_object_key: string | null;
      image_r2_key: string | null;
    };

    // 3. Purge cached next.js routes for both admin and customer surfaces
    revalidateBookingPaths();
    revalidatePath("/admin/bookings");
    revalidatePath("/admin");
    revalidatePath("/my-requests");

    return {
      success: true,
      bookingRequestId: payload.booking_request_id,
      quotationId: payload.quotation_id,
      quotationNumber: payload.quotation_number || "Quotation",
      pdfR2ObjectKey: payload.pdf_r2_object_key,
    };
  } catch (err: unknown) {
    console.error("[deleteBookingQuotation] Unexpected error:", err);
    return {
      success: false,
      code: "PERSISTENCE_ERROR",
      error: err instanceof Error ? err.message : "An unexpected error occurred.",
    };
  }
}
```

case "delete-booking": {
  const remainingBookings = state.bookings.filter(
    (booking) => booking.id !== action.bookingId
  );
  
  // If the deleted booking was selected, choose the next available or first remaining
  let nextSelectedId = "";
  let nextStatus: BookingStatus = "Pending";

  if (remainingBookings.length > 0) {
    const deletedIndex = state.bookings.findIndex((b) => b.id === action.bookingId);
    const candidate = remainingBookings[deletedIndex] || remainingBookings[deletedIndex - 1] || remainingBookings[0];
    nextSelectedId = candidate.id;
    nextStatus = candidate.status;
  }

  return {
    ...state,
    bookings: remainingBookings,
    selectedBookingId: nextSelectedId,
    currentStatus: nextStatus,
  };
}

## 6. Customer Surface & Public Route Behavior

### 6.1 Customer "My Requests" Reflection (`/my-requests`)

1. The customer request query in `src/features/my-requests/clientRequestQueries.ts` queries `public.booking_requests` filtered by `profile_id = auth.uid()`.
2. Because the record is hard-deleted from `public.booking_requests`, subsequent page loads or client-side revalidations omit the deleted request completely.
3. If the customer is actively on `/my-requests` when the administrator deletes the consultation, the server action's call to `revalidatePath("/my-requests")` guarantees that any navigation or refresh presents the updated list without the deleted quotation.

### 6.2 Public Signed Consultation Link Invalidation (`/q/[code]`)

1. Public consultation links resolve through `src/app/q/[code]/page.tsx` and query `public.signed_booking_links`.
2. When the signed booking link is hard-deleted by the cascade or stored procedure, PostgREST returns no matching record.
3. The page handles the missing record gracefully by rendering the existing `QuotationNotFound` or expired link screen, confirming to the customer that the consultation reference is no longer active.
