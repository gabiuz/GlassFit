## 1. Problem Context & Motivation

IMP-MS10 improves measurement accuracy for the **perspective picker flow** (4-point quad confirmation). However, the workspace supports a second configuration path where users skip the perspective picker entirely and configure the overlay manually using sidebar controls (width/height inputs, drag-resize handles, yaw/pitch sliders, zoom). In this flow, `estimateDimensionsFromCorners()` is never called, and IMP-MS10's improvements do not apply.

### The Manual Configuration Path Today

When a user enters the workspace without using the perspective picker:

1. **Initial dimensions** start at hardcoded constants `DEFAULT_PRODUCT_WIDTH_CM = 210` and `DEFAULT_PRODUCT_HEIGHT_CM = 150` (or the structural template default from `getStructuralDefaultMm()` in `ProductModelWorkspace.tsx` lines 861 to 866). These values have no relationship to the actual room in the uploaded photo.

2. **Drag-resize** via `applyOverlaySize()` (lines 1859 to 1877) computes cm using a proportional ratio relative to the starting cm value:

    ```typescript
    const widthRatio = nextWidth / Math.max(session.startWidth, 1);
    setWidthCm(String(Math.max(1, Math.round(session.startWidthCm * widthRatio))));
    ```

    This proportional method preserves the user's resize intent correctly, but the resulting cm values are only as accurate as the starting cm value. If the initial default was 210cm but the real opening is 140cm, every subsequent resize propagates from the wrong baseline.

3. **Sidebar typed values** are direct user input (e.g., the user types "140" for widthCm). These are authoritative and do not need estimation.

### The IMP-MS11 Solution

IMP-MS11 uses the `scale_estimation` signal from IMP-MS10 (already present in the `SpaceImageSession` via the `/analyze` API response) to:

1. Compute **photo-grounded initial defaults** at workspace load time, replacing the hardcoded 210x150cm with estimates derived from the overlay's pixel footprint in the photo's spatial context.
2. Provide **photo-grounded cm tracking during drag-resize**, giving the system a spatial-reality cross-check alongside the existing proportional method.

## 4. Core Concept: Canvas-to-Photo Pixel Mapping

The workspace renders the uploaded room photo scaled to fit the canvas container. The overlay is positioned and sized in **canvas-space pixels** (CSS pixels on screen). To convert between overlay canvas pixels and the photo's original pixel coordinates:

```
canvasToPhotoRatio = photoWidthPx / canvasDisplayWidthPx
```

Where:
- `photoWidthPx` is `spaceImageSession.workspaceImage.width` (the photo's actual pixel width after pre-flight normalization)
- `canvasDisplayWidthPx` is the canvas container's rendered CSS width on screen

When the overlay is `overlayWidthPx` wide in canvas-space, it spans `overlayWidthPx * canvasToPhotoRatio` pixels in photo-space.

Combined with `best_scale_cm_per_px` from IMP-MS10:

```
overlayWidthCm = overlayWidthPx * canvasToPhotoRatio * best_scale_cm_per_px
```

This gives a photo-grounded real-world dimension estimate for the overlay at its current size and position.

### Limitations

- The `best_scale_cm_per_px` is a **single global scale factor** for the entire photo. It does not account for depth variation across the image (objects closer to the camera have a different px-to-cm ratio than objects farther away). IMP-MS10's depth-ratio correction partially addresses this for the perspective picker, but the manual flow overlay can be positioned anywhere.
- The canvas-to-photo ratio assumes the photo fills the canvas width, which is true for the current responsive layout. If the layout changes to letterbox/pillarbox, the ratio calculation must be updated.
- Zoom level affects the overlay's visual size on screen but is handled separately (zoom does not change cm values in the current system).

## 5. Technique 1: Scale-Aware Initial Defaults

### 5.1 Current Behavior

```typescript
// ProductModelWorkspace.tsx lines 214-223
const [widthCm, setWidthCm] = useState(
  initialConfiguration?.widthCm
    ? String(initialConfiguration.widthCm)
    : String(DEFAULT_PRODUCT_WIDTH_CM),   // 210
);
const [heightCm, setHeightCm] = useState(
  initialConfiguration?.heightCm
    ? String(initialConfiguration.heightCm)
    : String(DEFAULT_PRODUCT_HEIGHT_CM),  // 150
);
```

When `initialConfiguration` is not provided (first-time product placement), the user always starts at 210x150cm regardless of the room context.

### 5.2 Proposed Behavior

When `scaleEstimation` is available from the space analysis session and no `initialConfiguration` is provided, compute initial dimensions based on the overlay's default pixel footprint in the photo's spatial context:

```typescript
/**
 * Computes photo-grounded initial dimensions using the scale estimation signal.
 *
 * Uses the overlay's default pixel footprint and the photo's spatial scale
 * factor to estimate what real-world dimensions the overlay "covers" in the
 * uploaded room photo.
 *
 * Falls back to hardcoded defaults when the scale signal is unavailable
 * or has low confidence.
 *
 * Traces to: PRD-F6, PRD-F10, SDD-C5, IMP-MS10
 */
export function getScaleAwareInitialDimensions(
  scaleSignal: ScaleEstimationSignal | null,
  defaultWidthCm: number,
  defaultHeightCm: number,
  overlayWidthPx: number,
  overlayHeightPx: number,
  canvasWidthPx: number,
  canvasHeightPx: number,
  photoWidthPx: number,
  photoHeightPx: number,
): { widthCm: number; heightCm: number; method: string } {
  if (
    !scaleSignal ||
    scaleSignal.best_scale_cm_per_px === null ||
    scaleSignal.confidence < 0.2
  ) {
    return {
      widthCm: defaultWidthCm,
      heightCm: defaultHeightCm,
      method: "default_fallback",
    };
  }

  // Convert overlay screen pixels to photo-space pixels.
  const canvasToPhotoRatioW = photoWidthPx / Math.max(canvasWidthPx, 1);
  const canvasToPhotoRatioH = photoHeightPx / Math.max(canvasHeightPx, 1);
  const overlayWidthInPhotoPx = overlayWidthPx * canvasToPhotoRatioW;
  const overlayHeightInPhotoPx = overlayHeightPx * canvasToPhotoRatioH;

  // Apply the photo-grounded scale factor.
  const estimatedWidth = overlayWidthInPhotoPx * scaleSignal.best_scale_cm_per_px;
  const estimatedHeight = overlayHeightInPhotoPx * scaleSignal.best_scale_cm_per_px;

  // Blend with defaults using confidence weight.
  // Cap confidence contribution at 0.7 to remain conservative.
  const w = Math.min(scaleSignal.confidence, 0.7);
  const blendedWidth = Math.round(w * estimatedWidth + (1 - w) * defaultWidthCm);
  const blendedHeight = Math.round(w * estimatedHeight + (1 - w) * defaultHeightCm);

  return {
    widthCm: Math.max(30, Math.min(600, blendedWidth)),
    heightCm: Math.max(30, Math.min(400, blendedHeight)),
    method: "scale_aware_initial",
  };
}
```

### 5.3 Integration in `ProductModelWorkspace.tsx`

The `useState` initializers for `widthCm` and `heightCm` are modified to call `getScaleAwareInitialDimensions()` when:
- `initialConfiguration` is not provided (first-time placement)
- `spaceImageSession?.scaleEstimation` is available

```typescript
const scaleAwareDefaults = useMemo(() => {
  if (initialConfiguration?.widthCm && initialConfiguration?.heightCm) {
    return null; // Use initialConfiguration as-is
  }
  return getScaleAwareInitialDimensions(
    spaceImageSession?.scaleEstimation ?? null,
    DEFAULT_PRODUCT_WIDTH_CM,
    DEFAULT_PRODUCT_HEIGHT_CM,
    DEFAULT_OVERLAY_WIDTH_PX,
    DEFAULT_OVERLAY_HEIGHT_PX,
    canvasDisplaySize.width,
    canvasDisplaySize.height,
    spaceImageSession?.workspaceImage?.width ?? 0,
    spaceImageSession?.workspaceImage?.height ?? 0,
  );
}, [initialConfiguration, spaceImageSession, canvasDisplaySize]);
```

When the structural template default is applied (lines 861 to 872), it overrides the scale-aware default. The structural template defaults (from `getStructuralDefaultMm()`) represent the product's design-spec dimensions and take priority over photo-estimated dimensions.

## 6. Technique 2: Photo-Grounded Drag-Resize cm Tracking

### 6.1 Current Behavior in `applyOverlaySize()`

```typescript
// Lines 1859-1877: proportional cm from pixel ratio
const applyOverlaySize = useCallback(
  (width: number, height: number, session: ResizeSession) => {
    const nextWidth = clampNumber(width, MIN_OVERLAY_WIDTH, MAX_OVERLAY_WIDTH);
    const nextHeight = clampNumber(height, MIN_OVERLAY_HEIGHT, MAX_OVERLAY_HEIGHT);
    setOverlaySize({ width: nextWidth, height: nextHeight });

    if (session.mode === "scale" || session.mode === "width") {
      const widthRatio = nextWidth / Math.max(session.startWidth, 1);
      setWidthCm(String(Math.max(1, Math.round(session.startWidthCm * widthRatio))));
    }
    if (session.mode === "scale" || session.mode === "height") {
      const heightRatio = nextHeight / Math.max(session.startHeight, 1);
      setHeightCm(String(Math.max(1, Math.round(session.startHeightCm * heightRatio))));
    }
  },
  [],
);
```

The proportional method is correct when `session.startWidthCm` is accurate. Since IMP-MS11 Technique 1 improves the initial cm value, all subsequent proportional resizes automatically inherit the improved starting point.

### 6.2 Proposed Enhancement: Photo-Grounded Cross-Check

When `scaleEstimation` is available, `applyOverlaySize()` additionally computes a photo-grounded cm estimate and blends it with the proportional result:

```typescript
/**
 * Converts overlay pixel dimensions to real-world cm using the photo's
 * spatial scale factor.
 *
 * This provides a "what does this pixel footprint physically represent"
 * cross-check alongside the proportional method that preserves user intent.
 *
 * Traces to: PRD-F6, SDD-C5, IMP-MS10
 */
export function computePhotoGroundedCm(
  overlayWidthPx: number,
  overlayHeightPx: number,
  canvasWidthPx: number,
  canvasHeightPx: number,
  photoWidthPx: number,
  photoHeightPx: number,
  scaleCmPerPx: number,
): { widthCm: number; heightCm: number } {
  const canvasToPhotoRatioW = photoWidthPx / Math.max(canvasWidthPx, 1);
  const canvasToPhotoRatioH = photoHeightPx / Math.max(canvasHeightPx, 1);
  return {
    widthCm: Math.max(1, Math.round(overlayWidthPx * canvasToPhotoRatioW * scaleCmPerPx)),
    heightCm: Math.max(1, Math.round(overlayHeightPx * canvasToPhotoRatioH * scaleCmPerPx)),
  };
}
```

### 6.3 Blending Strategy

Inside `applyOverlaySize()`, when both methods are available:

```typescript
// Proportional method (preserves user intent)
const proportionalWidthCm = Math.round(session.startWidthCm * widthRatio);

// Photo-grounded method (anchors to spatial reality)
const photoGrounded = computePhotoGroundedCm(
  nextWidth, nextHeight,
  canvasWidthPx, canvasHeightPx,
  photoWidthPx, photoHeightPx,
  scaleCmPerPx,
);

// Blend: weight proportional method more heavily (0.6) to preserve user intent,
// but allow photo-grounded method (0.4) to pull toward spatial reality.
const confidence = scaleSignal.confidence;
const photoWeight = Math.min(confidence * 0.4, 0.35);
const blendedWidthCm = Math.round(
  (1 - photoWeight) * proportionalWidthCm + photoWeight * photoGrounded.widthCm,
);
```

The proportional method is weighted more heavily (60%+) because the user is actively dragging and expects the cm to respond proportionally to their pixel movement. The photo-grounded signal acts as a gentle corrective pull toward spatial reality, preventing the cm from drifting too far from what the overlay physically represents on the photo.

When `scaleEstimation` is unavailable or has confidence below 0.2, `applyOverlaySize()` remains unchanged (pure proportional method).

## 7. Edge Cases & Fallback Strategy

| Scenario | Behavior | User Impact |
|---|---|---|
| No `scaleEstimation` in the space session (IMP-MS10 not deployed or no reference objects) | All functions fall back to existing behavior. `getScaleAwareInitialDimensions()` returns hardcoded defaults. `applyOverlaySize()` uses pure proportional method. | Identical to current system. Zero regression. |
| `scaleEstimation.confidence < 0.2` | Treated as unavailable. Falls back to defaults and proportional method. | Avoids applying unreliable scale signals. |
| Canvas size is zero or not yet measured (initial render) | `canvasToPhotoRatio` uses a guard of `Math.max(canvasWidthPx, 1)`. Result may be inaccurate on first frame but corrects on the next render cycle. | Negligible: the user does not interact with resize handles during initial render. |
| User applies structural template defaults after workspace load | Template defaults (from `getStructuralDefaultMm()`) override the scale-aware initial values. | Correct behavior: structural templates represent design-spec dimensions and take priority. |
| User manually types cm in the sidebar after scale-aware initialization | User-typed values are authoritative and replace the estimate. | Correct behavior: manual input always wins. |
| Overlay is positioned in a depth region very different from the reference objects | The global `best_scale_cm_per_px` may be inaccurate for that depth plane. | The blending strategy (60% proportional, 40% photo-grounded) limits the impact. The measurement modal always allows manual override. |

## 10. Risks and Mitigations

| Risk | Severity | Mitigation |
|---|---|---|
| Global scale factor is inaccurate for the overlay's depth region | Medium | Blending strategy weights proportional method at 60%+, limiting photo-grounded influence. Measurement modal always allows manual override. |
| Scale-aware initial defaults surprise users who expect 210x150cm | Low | The values remain architecturally reasonable (clamped 30-600cm width, 30-400cm height) and are always editable in the sidebar and measurement modal. |
| Canvas-to-photo ratio changes during responsive resize | Low | The initial defaults are computed once via `useMemo`. Drag-resize reads canvas size at interaction time. |
| Proportional and photo-grounded methods diverge significantly during extreme resizes | Low | The blending weights favor proportional (user intent) over photo-grounded (spatial reality). The photo-grounded signal is corrective, not authoritative. |
| Structural template defaults are overridden by scale-aware initialization | Medium | Template defaults are applied in a `useEffect` that fires after initial state. The effect takes priority, so template dimensions always win when present. |
