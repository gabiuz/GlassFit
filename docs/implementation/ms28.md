## 1. Executive Summary & Problem Context

In Philippine fenestration and glazing operations, client consultation estimates and ocular site inspection appointments depend directly on the fabricator shop's active business days and operating hours.

### 1.1 The Operational Need & Back-Office Gap

Under the current implementation in `src/features/admin/settings/SettingsContent.tsx` and `src/lib/pricing/quotationPdfGenerator.ts`:

1. **Transient Preferences State:** The `SystemPreferencesCard` component relies entirely on hardcoded local state (`DEFAULT_PREFERENCES`). Edits are lost on browser refresh, and a code comment (`TODO BAN-MIGR-06`) explicitly marks the missing database persistence migration.
2. **Absence of Owner Role Gate:** In `SettingsContent.tsx`, any authenticated administrative user (including `Staff` and `Manager` accounts) can click "Edit" on System Preferences. System-wide business parameters (legal name, contact channels, and operating hours) must be strictly governed by users possessing the `Owner` administrative title.
3. **Rigid Text Input for Operating Hours:** Operating hours are currently entered through an unvalidated single-line text input (`placeholder="e.g. Monday - Friday, 8AM - 5PM"`). This prevents structured validation, fails to enforce valid day and time ranges, and does not allow fabricators to select and add distinct operating day and hour windows (e.g. Weekday core hours vs Saturday half-day schedules).
4. **Missing Quotation PDF Integration:** The consultation quotation PDF engine (`quotationPdfGenerator.ts`) displays static company partner text (`Consultation Partner: R.R.D. Aluminum & Glass Works`) without indicating shop operating days or consultation hours. Customers receiving preliminary quotations have no visibility into when shop estimators are available for follow-up inquiries, ocular site measurements, or physical shop visits.

### 1.2 Core Functional & Architectural Objectives

To resolve these defects, `IMP-MS28` establishes the following system capabilities:

1. **Owner-Only Governance:** Only authenticated administrators whose active profile role is `Owner` are authorized to edit and save system preferences. Non-owner administrators (`Manager`, `Staff`) view system preferences in a clean read-only state with an informative badge. Server actions enforce strict server-side role validation.
2. **Interactive Day Range & Hour Range Builder:** Administrators can select operating days range (start day to end day, e.g. Monday to Saturday) and operating hours range (start time to end time, e.g. 08:00 AM to 05:00 PM). The UI supports adding multiple operating schedule windows (e.g. Primary weekday range plus weekend operating hours) with intuitive dropdown selectors.
3. **Robust Database Persistence:** Migration `011_system_preferences_operating_schedule.sql` introduces `public.system_preferences` with a singleton constraint, audit columns (`updated_by`, `updated_at`), and secure Row-Level Security (RLS) policies permitting read access to active consultations and restricting updates to verified Owners.
4. **Dynamic PDF Quotation Integration:** The quotation document view model (`QuotationDocumentViewModel`) and PDF HTML generator (`quotationPdfGenerator.ts`) dynamically ingest the active operating days and operating hours, rendering them prominently in the quotation header and ocular inspection guidance sections.
5. **Seamless Fallback Guarantee:** If system preferences have not yet been customized, the PDF generator and UI fall back deterministically to canonical enterprise defaults ("Monday - Saturday", "8:00 AM - 5:00 PM") without breaking quotation compilation.

## 3. Architecture & Security Invariants

### 3.1 Owner-Exclusive Authorization Gate

System-level business preferences dictate customer-facing legal representations, official communication channels, and shop operating availability. Consequently, back-office access to these controls must adhere to strict role isolation:

1. **Client-Side Enforcement:**
   - In `SettingsContent.tsx`, the authenticated admin session is retrieved via `useAdminSession()`.
   - The user's role is checked: `const isOwner = role.roleName.toLowerCase() === "owner";`.
   - When `isOwner` is false:
     - The "Edit" button in the card header is replaced by a non-interactive pill badge: "Owner Managed".
     - All form controls, range selectors, and time pickers remain disabled.
     - An informational banner notifies the user: "System preferences can only be modified by the business Owner."
2. **Server-Side Enforcement:**
   - All mutation server actions in `src/features/admin/settings/settingsActions.ts` verify the active session through `createSupabaseServerClient()`.
   - The action queries `public.profiles` joined with `public.admin_roles` for the authenticated `auth.uid()`.
   - If `profiles.account_type !== 'Admin'`, `profiles.status !== 'Active'`, or `admin_roles.role_name !== 'Owner'`, the action terminates immediately and returns `{ ok: false, error: "Unauthorized: Only business Owners can modify system preferences." }`.
   - Under no circumstances is client-side session state trusted for persistence mutations.

### 3.2 Operating Schedule Domain Model (Days Range & Hours Range)

Fabricators require flexibility to express standard operational schedules. GlassFit formalizes the operating schedule as both structured range entities and human-readable composite strings.

#### Canonical Days of Week Enum
```typescript
export const DAYS_OF_WEEK = [
  "Monday",
  "Tuesday",
  "Wednesday",
  "Thursday",
  "Friday",
  "Saturday",
  "Sunday",
] as const;

export type DayOfWeek = (typeof DAYS_OF_WEEK)[number];
```

#### Structured Schedule Range Block
```typescript
export interface OperatingScheduleRange {
  id: string;
  startDay: DayOfWeek;
  endDay: DayOfWeek;
  startTime: string; // "HH:MM" 24h format (e.g. "08:00")
  endTime: string;   // "HH:MM" 24h format (e.g. "17:00")
}
```

#### Formatted Composite Derivation Rules
1. **Day Range String:**
   - If `startDay === endDay`: Formatted as `${startDay}` (e.g. "Saturday").
   - If `startDay !== endDay`: Formatted as `${startDay} - ${endDay}` (e.g. "Monday - Saturday").
2. **Hour Range String:**
   - Converts 24h `HH:MM` into standard 12-hour Philippine standard time with AM/PM markers:
     - "08:00" converts to "8:00 AM"
     - "17:00" converts to "5:00 PM"
     - "12:00" converts to "12:00 PM"
   - Combined hour range: `${format12h(startTime)} - ${format12h(endTime)}` (e.g. "8:00 AM - 5:00 PM").
3. **Composite Schedule String (for PDF and Badges):**
   - Single block: `${dayRange}: ${hourRange}` (e.g. "Monday - Saturday: 8:00 AM - 5:00 PM").
   - Multiple blocks: Joined by ` | ` (e.g. "Monday - Friday: 8:00 AM - 5:00 PM | Saturday: 8:00 AM - 12:00 PM").

### 3.3 Quotation PDF Embedding & Presentation Contract

Consultation quotation PDFs serve as official customer handoff instruments. Operating schedule metadata must be rendered accurately:

1. **Header Partner Block:** In the PDF document header (`.document-header`), underneath the partner shop name (`Consultation Partner: R.R.D. Aluminum & Glass Works`), render a designated schedule indicator:
   ```html
   <div class="partner-schedule">
     <span>Operating Schedule:</span>
     <strong>Monday - Saturday: 8:00 AM - 5:00 PM</strong>
   </div>
   ```
2. **Ocular Inspection & Consultation Card:** In the ocular inspection guidance section (`.ocular-card`), render an operational notice informing customers when estimators are dispatched for site verification:
   ```html
   <div class="ocular-schedule-notice">
     <span>Ocular Inspection Availability:</span>
     <p>Consultations and site measurements are conducted during shop operating days (<strong>Monday - Saturday</strong>) between <strong>8:00 AM - 5:00 PM</strong>.</p>
   </div>
   ```
3. **Print-Friendly Styling:** CSS rules in `@media print` must ensure the schedule blocks maintain strict typography hierarchy, do not break across pages, and adhere to high-contrast monochrome and teal branding.

## 4. Database Persistence & Migration Schema

To persist enterprise preferences, operating schedule blocks, and audit metadata, table `public.system_preferences` is introduced via migration `011_system_preferences_operating_schedule.sql`.

### 4.1 Migration DDL (`supabase/migrations/011_system_preferences_operating_schedule.sql`)

```sql
-- Migration: 011_system_preferences_operating_schedule.sql
-- Description: Establishes system_preferences table with singleton constraint, operating schedule ranges, and Owner-exclusive RLS

-- 1. Create public.system_preferences table
CREATE TABLE IF NOT EXISTS public.system_preferences (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    singleton_key VARCHAR(50) NOT NULL DEFAULT 'GLOBAL_PREFERENCES' UNIQUE,
    business_name VARCHAR(255) NOT NULL DEFAULT 'GlassFit',
    contact_email VARCHAR(255) NOT NULL DEFAULT 'glassfit@gmail.com',
    contact_phone VARCHAR(50) NOT NULL DEFAULT '+63 917 123 4567',
    operating_days_range VARCHAR(100) NOT NULL DEFAULT 'Monday - Saturday',
    operating_hours_range VARCHAR(100) NOT NULL DEFAULT '8:00 AM - 5:00 PM',
    operating_schedules JSONB NOT NULL DEFAULT '[
        {
            "id": "default-schedule-1",
            "start_day": "Monday",
            "end_day": "Saturday",
            "start_time": "08:00",
            "end_time": "17:00"
        }
    ]'::jsonb,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by UUID REFERENCES public.profiles(profile_id) ON DELETE SET NULL,
    CONSTRAINT system_preferences_singleton_check CHECK (singleton_key = 'GLOBAL_PREFERENCES')
);

-- 2. Trigger for updated_at
CREATE OR REPLACE TRIGGER set_system_preferences_updated_at
BEFORE UPDATE ON public.system_preferences
FOR EACH ROW EXECUTE FUNCTION public.set_updated_at();

-- 3. Seed initial default enterprise preferences row
INSERT INTO public.system_preferences (
    singleton_key,
    business_name,
    contact_email,
    contact_phone,
    operating_days_range,
    operating_hours_range,
    operating_schedules
) VALUES (
    'GLOBAL_PREFERENCES',
    'GlassFit',
    'glassfit@gmail.com',
    '+63 917 123 4567',
    'Monday - Saturday',
    '8:00 AM - 5:00 PM',
    '[
        {
            "id": "default-schedule-1",
            "start_day": "Monday",
            "end_day": "Saturday",
            "start_time": "08:00",
            "end_time": "17:00"
        }
    ]'::jsonb
)
ON CONFLICT (singleton_key) DO NOTHING;

-- 4. Enable Row Level Security (RLS)
ALTER TABLE public.system_preferences ENABLE ROW LEVEL SECURITY;

-- 5. RLS Policies
-- Read access: Publicly readable for active quotation generation, customer view, and back-office review
CREATE POLICY "system_preferences_read_policy" ON public.system_preferences
    FOR SELECT TO public
    USING (true);

-- Update access: Strictly restricted to authenticated Admins with Owner role
CREATE POLICY "system_preferences_owner_update_policy" ON public.system_preferences
    FOR UPDATE TO authenticated
    USING (
        EXISTS (
            SELECT 1 FROM public.profiles p
            JOIN public.admin_roles r ON r.role_id = p.admin_role_id
            WHERE p.profile_id = auth.uid()
            AND p.account_type = 'Admin'
            AND p.status = 'Active'
            AND r.role_name = 'Owner'
        )
    )
    WITH CHECK (
        EXISTS (
            SELECT 1 FROM public.profiles p
            JOIN public.admin_roles r ON r.role_id = p.admin_role_id
            WHERE p.profile_id = auth.uid()
            AND p.account_type = 'Admin'
            AND p.status = 'Active'
            AND r.role_name = 'Owner'
        )
    );

-- Mutations via Service Role client (bypasses RLS for trusted server actions)
CREATE POLICY "system_preferences_service_all" ON public.system_preferences
    FOR ALL TO service_role
    USING (true)
    WITH CHECK (true);
```

## 5. Backend Server Actions & Service Layer

### 5.1 Zod Validation Schema (`src/lib/settings/types.ts`)

```typescript
import { z } from "zod";

export const DAYS_OF_WEEK = [
  "Monday",
  "Tuesday",
  "Wednesday",
  "Thursday",
  "Friday",
  "Saturday",
  "Sunday",
] as const;

export const DayOfWeekSchema = z.enum(DAYS_OF_WEEK);

export const OperatingScheduleRangeSchema = z.object({
  id: z.string().min(1),
  startDay: DayOfWeekSchema,
  endDay: DayOfWeekSchema,
  startTime: z.string().regex(/^([01]\d|2[0-3]):[0-5]\d$/, "Start time must be in HH:MM format"),
  endTime: z.string().regex(/^([01]\d|2[0-3]):[0-5]\d$/, "End time must be in HH:MM format"),
}).refine((data) => data.startTime < data.endTime, {
  message: "End time must be after start time",
  path: ["endTime"],
});

export const SystemPreferencesSchema = z.object({
  businessName: z.string().trim().min(2, "Business name must be at least 2 characters").max(100),
  contactEmail: z.string().trim().email("Invalid email address"),
  contactPhone: z.string().trim().min(7, "Contact number is too short").max(30),
  schedules: z.array(OperatingScheduleRangeSchema).min(1, "At least one operating schedule is required"),
});

export type SystemPreferencesInput = z.infer<typeof SystemPreferencesSchema>;
export type OperatingScheduleRange = z.infer<typeof OperatingScheduleRangeSchema>;

export interface SystemPreferencesRecord {
  id: string;
  businessName: string;
  contactEmail: string;
  contactPhone: string;
  operatingDaysRange: string;
  operatingHoursRange: string;
  operatingSchedules: OperatingScheduleRange[];
  updatedAt: string;
  updatedBy: string | null;
}
```

### 5.2 Server Action Contracts (`settingsActions.ts`)

```typescript
"use server";

import { createSupabaseServerClient } from "@/lib/supabase/server";
import { createSupabaseServiceClient } from "@/lib/supabase/service";
import {
  SystemPreferencesSchema,
  SystemPreferencesInput,
  SystemPreferencesRecord,
} from "@/lib/settings/types";
import { formatTime12h, formatScheduleSummary } from "@/lib/settings/formatters";

export type SettingsActionResult<T = void> =
  | { ok: true; message: string; data?: T }
  | { ok: false; error: string };

/**
 * Retrieves the current system preferences.
 * Safe for use by both admin settings and quotation generation.
 */
export async function getSystemPreferences(): Promise<SettingsActionResult<SystemPreferencesRecord>> {
  const supabase = createSupabaseServiceClient();

  const { data, error } = await supabase
    .from("system_preferences")
    .select("*")
    .eq("singleton_key", "GLOBAL_PREFERENCES")
    .maybeSingle();

  if (error || !data) {
    // Return enterprise fallback if table or row not yet initialized
    return {
      ok: true,
      message: "Using default preferences",
      data: {
        id: "default",
        businessName: "GlassFit",
        contactEmail: "glassfit@gmail.com",
        contactPhone: "+63 917 123 4567",
        operatingDaysRange: "Monday - Saturday",
        operatingHoursRange: "8:00 AM - 5:00 PM",
        operatingSchedules: [
          {
            id: "default-1",
            startDay: "Monday",
            endDay: "Saturday",
            startTime: "08:00",
            endTime: "17:00",
          },
        ],
        updatedAt: new Date().toISOString(),
        updatedBy: null,
      },
    };
  }

  return {
    ok: true,
    message: "Preferences loaded",
    data: {
      id: data.id,
      businessName: data.business_name,
      contactEmail: data.contact_email,
      contactPhone: data.contact_phone,
      operatingDaysRange: data.operating_days_range,
      operatingHoursRange: data.operating_hours_range,
      operatingSchedules: (data.operating_schedules as OperatingScheduleRange[]) ?? [],
      updatedAt: data.updated_at,
      updatedBy: data.updated_by,
    },
  };
}

/**
 * Updates system preferences. Strictly restricted to Owner administrators.
 */
export async function updateSystemPreferences(
  input: SystemPreferencesInput
): Promise<SettingsActionResult<SystemPreferencesRecord>> {
  // 1. Validate payload against Zod schema
  const parsed = SystemPreferencesSchema.safeParse(input);
  if (!parsed.success) {
    return { ok: false, error: parsed.error.issues[0]?.message ?? "Invalid preferences payload" };
  }

  // 2. Verify authenticated caller role is Owner
  const serverSupabase = await createSupabaseServerClient();
  const { data: { user } } = await serverSupabase.auth.getUser();

  if (!user) {
    return { ok: false, error: "Authentication required." };
  }

  const serviceClient = createSupabaseServiceClient();
  const { data: profile } = await serviceClient
    .from("profiles")
    .select(`
      profile_id,
      account_type,
      status,
      admin_roles ( role_name )
    `)
    .eq("profile_id", user.id)
    .maybeSingle();

  const roleName = Array.isArray(profile?.admin_roles)
    ? profile?.admin_roles[0]?.role_name
    : (profile?.admin_roles as { role_name?: string } | null)?.role_name;

  if (
    profile?.account_type !== "Admin" ||
    profile?.status !== "Active" ||
    roleName?.toLowerCase() !== "owner"
  ) {
    return {
      ok: false,
      error: "Unauthorized: Only business Owners can modify system preferences and operating schedules.",
    };
  }

  // 3. Derive primary summary strings
  const primarySchedule = parsed.data.schedules[0];
  const derivedDaysRange = primarySchedule.startDay === primarySchedule.endDay
    ? primarySchedule.startDay
    : `${primarySchedule.startDay} - ${primarySchedule.endDay}`;

  const derivedHoursRange = `${formatTime12h(primarySchedule.startTime)} - ${formatTime12h(primarySchedule.endTime)}`;

  // 4. Upsert singleton system preferences
  const { data: updatedRecord, error: updateError } = await serviceClient
    .from("system_preferences")
    .upsert({
      singleton_key: "GLOBAL_PREFERENCES",
      business_name: parsed.data.businessName,
      contact_email: parsed.data.contactEmail,
      contact_phone: parsed.data.contactPhone,
      operating_days_range: derivedDaysRange,
      operating_hours_range: derivedHoursRange,
      operating_schedules: parsed.data.schedules,
      updated_by: user.id,
      updated_at: new Date().toISOString(),
    }, { onConflict: "singleton_key" })
    .select()
    .single();

  if (updateError || !updatedRecord) {
    console.error("[updateSystemPreferences] Error:", updateError?.message);
    return { ok: false, error: "Failed to save system preferences. Please try again." };
  }

  return {
    ok: true,
    message: "System preferences updated successfully.",
    data: {
      id: updatedRecord.id,
      businessName: updatedRecord.business_name,
      contactEmail: updatedRecord.contact_email,
      contactPhone: updatedRecord.contact_phone,
      operatingDaysRange: updatedRecord.operating_days_range,
      operatingHoursRange: updatedRecord.operating_hours_range,
      operatingSchedules: updatedRecord.operating_schedules,
      updatedAt: updatedRecord.updated_at,
      updatedBy: updatedRecord.updated_by,
    },
  };
}
```

### 6.2 Operating Schedule Range Builder UI

The existing single-line text input is replaced with an interactive multi-row schedule builder:

#### 1. Range Row Anatomy
Each schedule block is rendered as a clean card containing:

- **Days Range Selectors:**
  - "From Day" dropdown (`Monday` through `Sunday`).
