## 1. Outcome and Scope

The ultimate purpose of paper fiducial calibration is to ensure that parametric 3D models placed into client room photos represent true real-world dimensions (within 2% to 5% accuracy) rather than rough visual ballpark estimates.

In prior implementations (IMP-MS45 through IMP-MS50), the computer vision microservice autonomously detects standard Philippine paper sheets (Short, A4, Long) and computes planar homography. However, a major architectural usability gap persisted in the upload-to-workspace transition:

1. **Blind Workspace Ingress:** Once image analysis completes, the customer is shown a generic success modal (`ImageSuccessModal`) stating "Image analysis is complete. You may now place your selected product." Clicking "Place Product" immediately navigates to `/visualize/[productId]/workspace`.
2. **Unverified Automatic Scale Commitment:** If the backend computer vision service detects paper corners with confidence >= 0.65, `status` is marked as `"calibrated"`, which completely bypasses user review. If the algorithm slightly misaligned corners due to wall shadows, tape strips, or textured paint, or if it detected a light switch or rectangular wall tile instead of the taped paper, the 3D model loads with distorted physical dimensions.
3. **Frustrating Late-Stage Correction:** The customer only discovers dimensional discrepancies after entering the workspace, requiring them to hunt for manual adjustment controls in the canvas HUD or backtrack through the upload flow.

`IMP-MS51` closes this gap by establishing an explicit, user-friendly **Pre-Workspace Fiducial Paper Detection Confirmation Gateway**:

- **Pre-Workspace Interception:** Intercepts upload completion in `ProductAwareUploadPage.tsx` and `DirectVisualizationPage.tsx`. When paper fiducial calibration mode is active, the generic success dialog is replaced with `PaperDetectionConfirmationModal`.
- **Visual Detection Overlay:** Displays the uploaded room photo with the detected paper quadrilateral highlighted via semi-transparent fill, glowing perimeter lines, and numbered corner markers (1: Top-Left, 2: Top-Right, 3: Bottom-Right, 4: Bottom-Left).
- **One-Click Approval Path:** If the computer vision detection is accurate, the customer clicks a prominent "Looks Right / Confirm & Enter Workspace" button, instantly locking the verified corners and transitioning to the workspace with high-precision scale.
- **Interactive Corner Refinement:** If the detected corners are slightly off (e.g. snapped to a shadow or tape edge), the customer can drag any corner handle directly. A 2.5x circular magnifier loupe (`TouchDragProxy`) provides pixel-level placement precision on both mobile touchscreens and desktop pointers.
- **Paper Standard Correction:** Allows the customer to toggle or verify the paper format (Short Bond, A4, Long Bond) if the algorithm misclassified the standard, dynamically recalculating the scale factor in real time.
- **False-Positive Dismissal:** If the detection selected an unintended wall artifact or the customer changed their mind, clicking "Skip Calibration" smoothly falls back to standard visual heuristic estimation (`status: "heuristic_fallback"`) without blocking workspace entry.
- **Unified Low-Contrast Fallback:** If the backend returns `status: "manual_pin_required"` (confidence < 0.65), the same modal opens in manual placement mode right here in the pre-workspace flow, eliminating fragmented modal logic.

### 1.1 Non-Negotiable Invariants

1. **Customer Verification Authority:** The customer must always be granted visual proof of the detected paper boundary before 3D model dimensions are locked. No automatic detection may bypass this confirmation gate when calibration mode is active.
2. **Non-Blocking Fallback:** Customers must never be trapped in the confirmation modal. If they cannot or do not want to calibrate, a prominent "Skip to Quick Preview" button allows continuing with standard visual heuristics.
3. **Preserve System Styling Standards:** All dialog cards, buttons, badges, and corner handles must strictly adhere to the GlassFit design system tokens in `src/app/globals.css` and established component conventions (`BAN-UI-09`).
4. **No Em-Dashes:** In compliance with `BAN-PUNCT-01`, all documentation, user-facing copy, and code comments must use hyphens, colons, or parentheses.
5. **No Box Diagrams in Code Blocks:** All UI tables, state flow descriptions, and layout structures must use standard Markdown tables and ordered prose (`BAN-DIAG-03`).
6. **Strict Type Safety:** Zero usage of `any` across TypeScript interfaces and component props (`BAN-TYPE-05`).
7. **No Continuous AR Tracking:** All calculations are static, one-shot geometric evaluations on the uploaded room photo (`BAN-AR-08`).

## 3. Pre-Workspace Confirmation Gateway Architecture

### 3.1 Upload Lifecycle and Interception Flow

```
1. Customer Uploads Space Photo with Taped Paper Marker
   |
2. FastAPI Microservice Executes /analyze-image
   - Multi-standard paper detection, homography, and scale estimation
   |
3. Client Receives Session Payload
   |
   +--> If Mode is Standard (Quick Preview):
   |      Show ImageSuccessModal -> Route to Workspace (Heuristic Sizing)
   |
   +--> If Mode is Paper Fiducial (or Paper Detected):
          Show PaperDetectionConfirmationModal (IMP-MS51 Gate)
          |
          +--> Path A: Auto-Detected Success (Confidence >= 0.65)
          |      Preview photo with detected paper quad overlay and pins
          |      - Option A1: Click "Looks Right / Confirm" -> Lock scale -> Enter Workspace
          |      - Option A2: Drag corners to adjust -> Recompute scale -> Enter Workspace
          |      - Option A3: Change paper standard (Short/A4/Long) -> Recompute scale
          |      - Option A4: Click "Skip Calibration" -> Mark heuristic fallback -> Enter Workspace
          |
          +--> Path B: Low Contrast / Undetected (Confidence < 0.65)
                 Open directly in manual pin mode: "Place 4 pins on your taped paper"
                 - Option B1: Pin 4 corners -> Recompute scale -> Enter Workspace
                 - Option B2: Click "Skip Calibration" -> Mark heuristic fallback -> Enter Workspace
```

### 3.2 Extended Type Definitions (`src/lib/visualization/types.ts`)

```typescript
export type PaperCalibrationStatus =
  | "detected"
  | "manual_pin_required"
  | "verified_calibrated"
  | "heuristic_fallback"
  | "not_requested";

export interface CalibrationMeta {
  mode: CalibrationMode;
  paperStandard: FiducialPaperStandard | null;
  status: PaperCalibrationStatus;
  confidence: number;
  user_verified?: boolean;
  verified_corners?: [Point2D, Point2D, Point2D, Point2D] | null;
  verified_scale_cm_per_px?: number | null;
}
```

## 4. UI & Interaction Specification: `PaperDetectionConfirmationModal`

### 4.1 Component Header and Readout HUD

The modal opens full-screen or as a large bounded modal (`max-w-4xl`) with dark backdrop blur (`bg-black/75 backdrop-blur-sm`):

| UI Sub-Component | Placement & Styling | Display Content & Behavior |
|---|---|---|
| **Modal Header** | Top bar with high-contrast text | Title: "Confirm Reference Paper Marker" with subtitle: "Verify the detected paper boundary to ensure millimeter-accurate 3D model sizing." |
| **Detection Badge** | Top right pill (`bg-emerald-50 text-emerald-700 border-emerald-200`) | Displays detection state: "Auto-Detected (95% Match)" or "Manual Adjustment Active" |
| **Paper Standard Selector** | Segmented radio pill in header | Buttons for "Short Bond (8.5x11in)", "A4 (210x297mm)", and "Long Bond (8.5x13in)". Switching standard re-runs `computeScaleFromPaperCorners()` instantly. |
| **Live Metric Scale Readout** | Sub-header monospace chip | Displays computed physical scale: e.g. "Scale: 0.0418 cm/px (1 px = 0.42 mm)" |

### 4.2 Interactive Canvas Viewport

The interactive canvas reuses proven touch and mouse handling from `PerspectivePlanePicker.tsx` and `TouchDragProxy.tsx`:

1. **Background Space Photo:** Rendered maintaining natural aspect ratio within the viewport bounds.
2. **Quadrilateral SVG Polygon:**
   - Semi-transparent fill: `rgba(16, 185, 129, 0.20)` (emerald tint indicating calibration).
   - Perimeter stroke: `stroke="#10b981" strokeWidth="2.5" strokeDasharray="none"`.
3. **Corner Handle Pins (1 through 4):**
   - Labeled vertices: Pin 1 (Top-Left), Pin 2 (Top-Right), Pin 3 (Bottom-Right), Pin 4 (Bottom-Left).
   - Visual handle: Outer white ring (`r=14`), emerald center core (`r=8`), drop shadow.
   - Touch Proxy Magnifier: When a corner is dragged, a 2.5x circular loupe with fine crosshairs appears offset by 60px above the finger, guaranteeing that the user's thumb does not obstruct the paper corner.
4. **Interactive Action Bar (Modal Footer):**
   - **Primary Action ("Looks Right / Confirm & Enter Workspace"):** Prominent button (`bg-green hover:bg-[#06a3bd] text-white px-8 py-3.5 rounded-[25px] font-medium text-base shadow-md`). Locks the verified corners, sets `status: "verified_calibrated"`, updates the session context, and executes workspace routing.
   - **Secondary Action ("Reset Corners"):** Reverts corner handles back to the initial auto-detected positions if the user wants to undo manual edits.
   - **Tertiary Action ("Skip Calibration"):** Text button (`text-neutral-500 hover:text-neutral-800 text-sm font-normal`). Dismisses calibration, sets `status: "heuristic_fallback"`, and proceeds to workspace with standard visual heuristics.

## 5. Mathematical Corner Ordering & Scale Verification

When the customer adjusts corners or switches the paper standard, the client re-evaluates the metric scale factor using `computeScaleFromPaperCorners()` from `src/lib/visualization/scaleEstimation.ts`:

1. **Vertex Normalization:** Raw screen coordinates are denormalized to natural photo pixel space.
2. **Canonical Ordering:** Points are sorted into `[Top-Left, Top-Right, Bottom-Right, Bottom-Left]` using sum and difference heuristics:
   - Top-Left minimizes $x + y$
   - Bottom-Right maximizes $x + y$
   - Top-Right minimizes $y - x$
   - Bottom-Left maximizes $y - x$
3. **Orientation Invariance:**
   - Width span: $W_{\text{px}} = \sqrt{\text{dist}(P_{\text{TL}}, P_{\text{TR}}) \cdot \text{dist}(P_{\text{BL}}, P_{\text{BR}})}$
   - Height span: $H_{\text{px}} = \sqrt{\text{dist}(P_{\text{TL}}, P_{\text{BL}}) \cdot \text{dist}(P_{\text{TR}}, P_{\text{BR}})}$
   - If $W_{\text{px}} > H_{\text{px}}$, orientation is resolved as landscape; otherwise portrait.
4. **Physical Scale Computation:**
   - $S_{\text{cm/px}} = \frac{1}{2} \left( \frac{\text{MetricWidth}_{\text{cm}}}{W_{\text{px}}} + \frac{\text{MetricHeight}_{\text{cm}}}{H_{\text{px}}} \right)$
5. **Convexity & Aspect Guardrail:**
   - The cross product of consecutive edge vectors must retain uniform signs. Self-intersecting "bow-tie" polygons trigger an inline warning badge: *"Please ensure corner pins form a valid 4-sided rectangle."*

   - Add unit tests in `tests/unit/paperConfirmationGateway.test.ts` validating corner ordering, magnifier offset mapping, paper standard switching, and session state persistence.

## 9. Risks and Mitigations

| Risk | Severity | Mitigation |
|---|---|---|
| User accidentally inverts corner pins while dragging on touch screen | Medium | The client executes automatic canonical corner re-ordering (`[TL, TR, BR, BL]`) on every touch release and warns if geometry is non-convex. |
| Customer finds pre-workspace confirmation an unnecessary extra click on high-confidence captures | Low | The modal presents an prominent "Looks Right / Confirm & Enter Workspace" primary button, requiring only a single tap to proceed, while guaranteeing dimensional trust. |
| Magnifier loupe is clipped by screen edges on small mobile viewports | Low | The loupe positioning algorithm clamps coordinates within screen boundaries and flips the vertical offset downward if the dragged pin is in the top 15% of the screen. |
