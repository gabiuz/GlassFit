## 1. Outcome and Scope

For a flat reference sheet and an opening boundary on the same physical plane, transform each opening corner into metric plane coordinates before calculating width and height. This addresses the angled-photo failure reported for sample 1. It does not correct unknown depth displacement between paper and opening; [MS55](ms55.md) handles that eligibility boundary.

This specification supersedes the global scalar formulas in MS46, MS47, MS48, MS50, and MS52 for calibrated measurement. A single centimeters-per-pixel value varies across a perspective image. Geometric means of paper edges do not make it constant across the wall. Showing millimeters does not establish millimeter accuracy.

The mathematical basis is the planar projective transform described in the [OpenCV homography tutorial](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html). The following coordinate contracts and quality limits are GlassFit design requirements, not accuracy guarantees from OpenCV.

## 3. Coordinate and Unit Contract

### 3.1 Canonical Frames

| Frame | Definition | Requirement |
|---|---|---|
| Normalized decoded image | Decoded image after EXIF orientation normalization | Detector records exact width and height and subsequent processing transforms |
| Analysis image | Resized or cropped detector input | Preserve full invertible mapping to canonical workspace pixels |
| Workspace image | Actual oriented room bitmap used for saved placement | Canonical stored paper and opening coordinates, independent of viewport |
| Display surface | Current image content rectangle inside picker or canvas | Remove letterbox offsets, pan and zoom; distinguish CSS pixels from backing-store pixels |
| Metric plane | Physical paper plane, in millimeters | Sole calibrated measurement space |

Store normalized overlay coordinates against the actual workspace image dimensions. Define their pixel conversion consistently, including whether image boundaries are at width/height. Do not mix detector pixels, viewport pixels, device pixels, or original unrotated dimensions.

### 3.2 Transform Composition

Let `A` map normalized decoded-image points into workspace-image pixels. Let `H_decoded_mm` map normalized decoded-image points into metric plane millimeters. Then:

`H_workspace_mm = H_decoded_mm * inverse(A)`

If detection occurs in analysis coordinates, first compose the normalized-image-to-analysis transform into the detector homography. Include resize, crop, translation, and orientation exactly once. Alternatively, recompute the homography from the final workspace corners and declared metric rectangle. Do not average horizontal and vertical resize factors.

Persist the direction `workspace_pixels_to_plane_mm`, coordinate image identity, image dimensions, algorithm version, and paper corner correspondence. Use full practical floating-point precision; normalize matrix scale without rounding coefficients to six decimal places before projection.

## 4. Metric Geometry Contract

1. Require four distinct, finite paper corners in cyclic order and a confirmed physical format. Associate edges with the paper's physical short and long sides explicitly. Automatic image width versus height cannot resolve all projected orientation ambiguities; provide a swap-sides correction and require confirmation when uncertain.
2. Map those corners to a known paper rectangle: `(0,0)`, `(paperWidthMm,0)`, `(paperWidthMm,paperHeightMm)`, `(0,paperHeightMm)`. Manual and automatic corners use the same solver and validation.
3. For each opening corner `p = (x,y,1)`, compute `q = H_workspace_mm * p`, then `P = (q.x/q.z,q.y/q.z)`. Validate the denominator and its sign throughout the opening region. Reject a horizon crossing or numerically unstable projection.
4. For ordered opening points `P0,P1,P2,P3`, compute top `|P1-P0|`, bottom `|P2-P3|`, left `|P3-P0|`, and right `|P2-P1|` in millimeters.
5. Validate rectangular fit in metric space before reducing four spans to product dimensions. For an eligible rectangular opening, width is the mean of top and bottom, and height is the mean of left and right. Preserve all four spans and discrepancies for diagnostics. Do not average materially inconsistent edges into an apparently valid rectangle.
6. Return a typed valid result or explicit rejection reasons. Include unrounded width/height, edge spans, revision, plane ID, and sensitivity summary. Convert millimeters to centimeters only at existing model/pricing adapter boundaries; round at established display or storage boundaries, not intermediate geometry.

The product must be fitted to the intended installation perimeter, rather than an arbitrary preview rectangle or a recessed back wall. Automatic paper detection does not automatically locate the opening. Continue using the existing opening-fit controls; do not label default model dimensions as measured opening dimensions.

### 4.1 Quality Gates

Reject nonfinite, duplicate, collinear, crossed, off-image, or near-zero-area paper input before solving. Check transform rank, denominator stability, and resulting geometry. Avoid using a small reprojection residual at the four fitting points as independent evidence of accuracy: four point pairs can fit a wrong paper boundary exactly.

Perturb paper and opening corners using a documented image-space localization uncertainty derived from MS57 annotations. Propagate through the full opening region, including extrapolation far beyond the paper. Record the resulting width and height sensitivity independently. Reject or request a better capture when either exceeds the validated operating envelope. Treat sensitivity as a quality diagnostic, not a statistically calibrated confidence interval.

Choose and freeze numeric degeneracy, edge-disagreement, and sensitivity thresholds using MS57 development data before holdout evaluation. Until validated, do not emit an accuracy badge. Strong lens distortion, curled paper, extreme foreshortening, and a tiny distant reference require a retake or manual dimensions. Do not invent camera intrinsics from EXIF or apply guessed undistortion.

## 5. Step-by-Step Implementation Plan

1. Add a domain geometry utility under `src/lib/visualization/` with explicit matrix, corner, frame, unit, and valid/invalid result types. Use existing dependencies and no TypeScript `any`.
2. Align FastAPI and client homography direction, millimeter units, corner correspondence, and image transforms. Version the new contract so legacy centimeter matrices cannot be misread as millimeter matrices.
3. Replace calibrated scalar calculations in `scaleEstimation.ts`, picker edge labels, active workspace fitting, and session overlay updates with the shared evaluator.
4. Separate fabrication validation from measurement: an out-of-range dimension is an explicit guardrail result, not a silently clamped physical reading. Follow current product parameters and MS43 rules rather than impose new global limits.
5. Retain legacy scalar fields only for compatibility or clearly approximate preview. They must not establish valid metric status.
6. Register QAD-TC69 and reconcile conflicting upstream calibrated-scale wording during implementation.

## 6. Verification and Acceptance Criteria

| Test ID | Scenario | Expected outcome | Severity |
|---|---|---|---|
| QAD-TC69.1 | Synthetic known plane under perspective | Recover width and height to relative numeric error at most 0.000001 without image localization noise | P0 |
| QAD-TC69.2 | Same opening at different image positions | Same metric result; no global-scale position bias | P0 |
| QAD-TC69.3 | Resize, crop, orientation normalization, letterboxing, zoom, and DPR changes | Same result within numeric tolerance after correct transform composition | P0 |
| QAD-TC69.4 | Landscape or rotated reference | Correct physical edge correspondence, including explicit swap when needed | P0 |
| QAD-TC69.5 | Degenerate paper, horizon crossing, or severe sensitivity | Invalid result with actionable reason, never NaN or plausible clamped dimensions | P0 |
| QAD-TC69.6 | Automatic outline replaced by manual corners | Identical geometry for identical corners and format | P0 |
| QAD-TC69.7 | Real angled sample with later measured ground truth | Pass independent width and height gates in MS57, or abstain | P0 |

Add focused geometry tests and extend existing calibration tests during implementation. MS57 defines real-photo accuracy evaluation separately from exact synthetic math tests.

## 7. Risks and Mitigations

Projective extrapolation from a small sheet can amplify tiny corner errors over a large opening. Transforming corners correctly is necessary but insufficient for trustworthy measurement. Use sensitivity gates and larger, clearer, coplanar reference placement; never promise a fixed error percentage solely because a homography exists.
