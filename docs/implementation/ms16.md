# Implementation Specification: Canonical Quotation and Negotiated Final Price (IMP-MS16)

**Project:** GlassFit  
**Version:** 2.0.0  
**Date:** September 25, 2026  
**Status:** Ready for Implementation  
**Traceability:** PRD-F9, PRD-F10, partial PRD-F11, PRD-F14; SDD-C6, SDD-C7, SDD-C9; ERD-E10, ERD-E13, ERD-E14, ERD-E15, ERD-E16; QAD-TC9, QAD-TC10, QAD-TC11, QAD-TC14, QAD-TC30

IMP-MS16 is a planning contract only. It succeeds IMP-MS15 and does not redefine `docs/milestone.md`.

## 1. Required Outcome and Fixed Decisions

The following operations shall consume one quotation representation and one renderer:

1. Client `/send-booking` Preview quotation.
2. Client Print / Save as PDF.
3. Admin `/admin/bookings` View PDF.
4. Admin Download PDF, which uses the existing browser Print / Save as PDF mechanism.

Architectural decisions:

- `generateQuotationPdfHtml()` remains the only document template and print stylesheet.
- A new versioned `QuotationDocumentSnapshotV1` is the canonical renderer data model.
- New quotations persist that exact model in `quotation_estimates.quotation_document_snapshot`.
- `quotation_items` remains normalized reporting data and the legacy fallback, not the canonical document source for new quotations.
- `total_estimated_amount` remains the immutable calculated total.
- `negotiated_amount` is a separate optional override.
- Admin preview and print regenerate HTML from current persisted state. They never open `pdf_r2_object_key`.
- No PDF-byte generator or R2 PDF upload is added. Full server-side PRD-F11 remains separate work.
- Negotiation controls remain outside generated HTML and never appear in client, preview, print, or saved-PDF output.

### 2.2 Admin

Both PDF buttons are inert and have no handlers. `BookingQuotation.pdfUrl` is never populated. The displayed filename comes from `pdf_r2_object_key`, but no code uploads PDF bytes to that key.

### 2.3 Shared backend

- `quotation_estimates` stores quotation identity and original total.
- `quotation_items` stores grouped rows and `pricing_details` JSONB.
- `visualization_snapshots.final_image_r2_key` stores the final image key.
- `signed_booking_links` joins customer, quotation, and snapshot.
- `booking_requests` stores platform and booking status.
- Booking mutations are Next.js Server Actions in top-level `"use server"` file `bookingActions.ts`; no REST controller exists.
- `requirePermission("manage_bookings")` is the application guard.
- Current quotation RLS still uses broad `is_admin()` for writes and must be replaced for updates.

### 2.4 Exact mismatch cause

The admin has no competing PDF template; it has no working renderer. More importantly, the persisted BOM is not guaranteed to match the client BOM. `BookingFlow` may use a structural-definition or cached overlay BOM, while `generateSignedBookingLink()` discards the submitted `bomResult` and recalculates every submitted item through `calculateStandardSeries798()`. Reconstruction from current rows can therefore show Series 798 data for a different product. The fix must occur at the persistence boundary.

## 3. Canonical Quotation Domain

Create browser-safe `src/lib/pricing/quotationDocument.ts`. It must not import React, Supabase, Next server APIs, `server-only`, `snapshotStorage.ts`, or AWS SDK packages.

It owns:

- `QuotationDocumentSnapshotV1Schema` and types;
- `createQuotationDocumentSnapshotV1()` from actual client calculation results;
- `reconstructLegacyQuotationDocument()` from persisted rows;
- `deriveQuotationPricing()` using integer centavos;
- `createQuotationDocumentViewModel()` with runtime asset URLs.

Required persisted shape:

```typescript
type QuotationDocumentSnapshotV1 = {
  schemaVersion: 1;
  quotationNumber: string;
  referenceCode: string;
  shareablePath: string;
  createdAt: string;
  customer: { name: string; phone: string | null; email: string | null; siteLocation: string | null };
  projectName: string;
  snapshotObjectKey: string | null;
  hasSill: boolean;
  structuralWaiver: boolean;
  items: Array<{
    itemId: string;
    productId: string | null;
    productName: string;
    productType: string;
    variantName: string;
    specificationSummary: string;
    dimensionsFormatted: string;
    widthMm: number;
    heightMm: number;
    panelCount: number;
    hasSill: boolean;
    structuralWaiver: boolean;
    finishLabel: string;
    glassLabel: string;
    quantity: number;
    unitPrice: number;
    calculatedSubtotal: number;
    imageSource: string | null;
    groups: Array<{ groupName: string; description: string; quantity: number; unit: string; unitPrice: number; subtotal: number }>;
  }>;
  pricing: { directMaterialsSubtotal: number; laborSubtotal: number; contractorMargin: number; calculatedFinalPrice: number };
};
```

Groups come from the actual `CalculatedBOMResult` used by the client. The renderer shall consume normalized groups instead of a synthetic reconstructed `CalculatedBOMResult`.

`QuotationDocumentViewModel` extends the snapshot with `brandLogoUrl`, `shareableUrl`, `snapshotImageUrl`, `allowedImageOrigins`, `calculatedFinalPrice`, `negotiatedFinalPrice`, `effectiveFinalPrice`, and `isPriceModified`.

### Legacy records

When `quotation_document_snapshot` is null, reconstruct from ordered persisted rows without calling a pricing calculator. Use `total_estimated_amount` as calculated price and deduplicate products by `item_id`, then `item_index`, then product name. If no usable rows exist, disable preview/print and show Quotation data unavailable. Historical reconstruction is best-effort; exact fidelity is guaranteed only for post-MS16 snapshots.

## 4. Price and Transparency Rules

| Value | Rule |
|---|---|
| `calculatedFinalPrice` | Original `total_estimated_amount`; immutable after creation. |
| `negotiatedFinalPrice` | Nullable `negotiated_amount`. |
| `effectiveFinalPrice` | `negotiatedFinalPrice ?? calculatedFinalPrice`. |
| `isPriceModified` | Negotiated value is non-null and differs from calculated value in integer centavos. |

An entered value equal to the calculated value is canonicalized to reset: clear amount, admin, and timestamp. Reset also sends null.

When modified, the HTML summary and grand total use the effective price, while BOM rates and subtotals stay calculated. Immediately above the effective total show the original calculated price. Immediately below the total table show:

> Final price adjusted by an authorized administrator for negotiation. The original system-calculated estimate is shown for transparency.

This appears in client saved-quotation preview, admin preview, public reference, print, and saved PDF. It disappears after reset.

## 6. Server-Action Contracts

No REST route is added.

### 6.1 Signed-link generation

Extend `GenerateBookingLinkInputSchema` with a validated `quotationDocument` draft lacking server-assigned identity. `generateSignedBookingLink()` shall authenticate, validate, upload the snapshot, assign identifiers, complete V1, set `total_estimated_amount` from V1, derive `quotation_items` from V1 groups, persist V1, and return identifiers. It shall not recalculate submitted items as Series 798.

Reject unsupported versions, blank required strings, nonpositive quantities, money outside `numeric(12,2)`, more than two decimals, item arithmetic mismatch, or project-total mismatch. This milestone preserves the current client-calculated preliminary-pricing trust boundary while validating and freezing exact arithmetic.

### 6.2 Negotiated update

```typescript
type UpdateNegotiatedPriceInput = { quotationId: string; negotiatedAmount: number | null; expectedUpdatedAt: string };
type UpdateNegotiatedPriceResult =
  | { ok: true; quotationId: string; calculatedFinalPrice: number; negotiatedFinalPrice: number | null; effectiveFinalPrice: number; isPriceModified: boolean; negotiatedBy: string | null; negotiatedAt: string | null; updatedAt: string }
  | { ok: false; code: "VALIDATION_ERROR" | "NOT_FOUND" | "CONFLICT" | "PERSISTENCE_ERROR"; message: string };
```

The action calls `requirePermission("manage_bookings")`, validates UUID, ISO timestamp, finite value, range, and two-decimal precision, reads the row, checks `expectedUpdatedAt`, canonicalizes equality to reset, and updates using both quotation ID and prior `updated_at`. Active override sets admin ID and current timestamp; reset clears all three fields. Zero updated rows means conflict. Revalidate booking paths only after success.

### 6.3 Reads

Add `getOwnQuotationDocument(quotationId)` using the authenticated server client, owner filter, and RLS. Never use service role for this read.

Extend `getPublicBookingReference()` and `PublicQuotationSummarySchema` with calculated, negotiated, effective, and modified fields. Keep `totalEstimatedAmount` as a calculated-price compatibility alias. `/q/[code]` must render `effectiveFinalPrice`.

## 7. UI and State Contract

### Client

`BookingFlow` builds one memoized canonical draft used by step summary, preview, print, and signed-link input. After generation it stores quotation ID and completed identity. On window focus or visibility restoration, it calls `getOwnQuotationDocument()` so a still-open saved session can observe negotiation. On refresh failure retain the last good model and show a nonblocking error. A new visit without saved ID is a new draft; `/q/[code]` is the durable saved view.

### Admin

Keep the existing detail panel and enhance its quotation card. Do not add a route, modal, drawer, or iframe. Show calculated price, final price, negotiated badge, Edit Final Price, View PDF, and Download PDF with helper text Opens Print / Save as PDF.

Editing is inline. Input uses decimal mode and step 0.01. Save validates then sends quotation ID, value, and `updatedAt`. During save disable editing, reset, preview, and print and set `aria-busy`. Success applies returned values, closes editor, shows toast, and refreshes. Cancel discards only local input. Reset sends null and is disabled without an override. Zero requires a second explicit confirmation. Conflict keeps the editor open, reports stale state, and refreshes. Errors preserve input.

Both PDF buttons call one `buildSelectedQuotationHtml()` helper and `openQuotationPreview()`; only `autoPrint` differs. Missing data or generation failure shows a card error and never opens a blank window.

### State ownership

Persisted: snapshot, calculated total, negotiation and audit fields, updated timestamp. Derived: all effective pricing, modified flag, URLs, HTML, legacy model. Local: edit mode, input string, zero confirmation, loading, error, toast, selection, and status draft. `deriveQuotationPricing()` is the only price-derivation implementation.

## 8. Validation and Edge Cases

| Case | Behavior |
|---|---|
| Blank/non-numeric/NaN/Infinity/negative | Reject in client and server. Blank is not reset. |
| More than two decimals or above max | Reject without rounding or writing. |
| Zero | Allow after explicit confirmation. |
| Same as calculated | Reset to null. |
| Existing null override | Calculated price, no note. |
| Reload | Read latest persisted state. |
| Stale tab | Return conflict and do not overwrite. |
| Failed save | Keep editor and persisted view unchanged. |
| Missing snapshot URL | Use existing PDF fallback. |
| Fake/missing R2 PDF object | Ignore; regenerate HTML. |
| Already-open popup after another update | Point-in-time document; reopening uses refreshed state. |
| Unauthorized direct update | Server guard and RLS both reject. |

The current lifecycle has no quotation-item or calculated-total update after link generation. Preserve that immutability. Any future recalculation must atomically replace snapshot/items/total and clear all negotiation fields, requiring renegotiation.

## 10. Data Flows

Client draft: visualization session -> existing pricing engine -> V1 draft -> view model -> shared HTML -> preview/print.

Persistence: V1 draft -> signed-link action -> auth/schema/arithmetic validation -> snapshot upload and server identity -> V1 persisted with items -> returned identity.

Admin: booking query -> V1 or legacy mapper -> derived pricing -> shared HTML -> preview/print.

Negotiation: input -> client validation -> server action -> permission and Zod -> concurrency check -> RLS update -> returned pricing -> reducer and refresh -> regenerated HTML.

Public: code -> public read -> persisted pricing -> effective price and transparency -> page.
