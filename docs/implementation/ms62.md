## 1. Outcome and Scope

The Paper Detection Confirmation Modal (`PaperDetectionConfirmationModal.tsx`) remains the gate between image upload and a metric paper-calibrated workspace. MS53 through MS61 established that a detected quadrilateral, an aspect-ratio suggestion, edge contrast, and a candidate score are evidence only. They do not establish the physical paper format, physical edge correspondence, or coplanar placement.

MS62 improves the presentation and interaction layer without changing calibration mathematics, provenance, eligibility, or the meaning of a user declaration:

1. Remove checkbox controls while retaining explicit, accessible action controls for paper format, edge correspondence, and paper placement.
2. Make automatic suggestions visible but non-promoting. A suggestion becomes a declaration only after the customer actively selects the visible control.
3. Replace distracting non-selected blue candidate outlines with neutral low-emphasis outlines and an evidence-labeled, ranked candidate selector.
4. Consolidate orientation into the paper-standard HUD as a compact explicit two-option selector.
5. Replace the dense control bar with a structured card and progressive disclosure that keeps all recovery choices available.
6. Improve discrete snap-settlement feedback without adding latency to continuous corner dragging.

This milestone does not change FastAPI detection, edge-fitting mathematics, `confirmPaperReference()`, plane eligibility, session provenance, model sizing, quotation dimensions, or database schema.

## 2. Contract-Preserving Interaction Model

| Evidence or declaration | Presentation | State and eligibility behavior | Prohibited behavior |
|---|---|---|---|
| Paper standard | Existing Short Bond, A4, and Long Bond pills. A high-confidence aspect-ratio result is marked `Suggested`. | A customer selecting a pill explicitly sets `formatConfirmed` to `true`. A pre-existing `paperStandardConfirmed` prop remains valid for a recalibration session until the customer changes standard. | Never set confirmation from a suggestion alone. |
| Physical edge correspondence | Compact 44px segmented control in the HUD: `Edge 1-2: Short` and `Edge 1-2: Long`, with dimensions and the recommended option visible. | Selecting either option sets `firstEdge` and `orientationConfirmed` to `true`. Changing paper standard resets orientation confirmation. | Never treat `recommendedFirstEdge` as confirmed without the customer selecting it. |
| Paper placement | Collapsed `Paper placement` section with action controls for `Flat on the installation wall`, `Held or offset`, `Unsure`, and `Corners obscured or paper curled`. | Selecting `Flat` sets `placement` to `user_confirmed_same_plane` and clears `boundaryUnsafe`. The other choices retain their current recovery provenance and disable metric confirmation. | Never infer coplanarity, safety, or a placement declaration from detector score, aspect ratio, or edge-fit quality. |
| Edge-fit quality | Read-only `Sharp edge alignment`, `Moderate edge contrast`, or `Manual alignment recommended` badge. Yellow or muted quality expands the placement section and shows retake guidance. | Advisory only. It may guide review but cannot alter `placement`, `boundaryUnsafe`, `samePlaneConfirmed`, or `canConfirm`. | Never promote a reference or remove risk reasons based on a green badge. |
| Candidate score | Candidate pills use `Boundary evidence NN%`, not `Match NN%` or a physical-accuracy claim. | Rank by `score` descending then `id` ascending after excluding rejected and cropped candidates. Keep the active selection visible even if it falls outside the initial three. | Never represent boundary-evidence score as paper identity, physical accuracy, or calibration confidence. |

The required calibration path is therefore four explicit customer actions: choose the actual paper format, choose the physical edge correspondence, declare the sheet flat on the installation wall, and confirm. The automatic recommendation reduces search effort but does not replace evidence required by PRD-F3, PRD-F4, PRD-F6, IMP-MS53, IMP-MS54, and IMP-MS55.

## 3. Non-Negotiable Invariants

1. All MS53 through MS61 calibration accuracy, corner localization, homography projection, metric sizing, plane eligibility, and quotation provenance behavior remains mathematically identical.
2. `PaperReviewResult` continues to pass `paperStandardConfirmed`, `samePlaneConfirmed`, `firstEdge`, `orientationConfirmed`, `placementAssessment`, and `placementRiskReasons` to `onConfirm()` unchanged in meaning.
3. `confirmPaperReference()` and its explicit validation guard remain unchanged. This milestone must satisfy that guard rather than bypass it.
4. All interactive controls meet a 44 by 44 CSS pixel minimum target. Candidate selection, the disclosure control, and both orientation segments must be keyboard-operable and expose an accessible name and selected state.
5. No new dependency, API endpoint, persistence field, database migration, RLS policy, or calibration algorithm is introduced.
6. Existing QAD-TC66, QAD-TC68 through QAD-TC71, and QAD-TC73 through QAD-TC76 remain valid. Tests that assert checkbox markup are updated to assert the equivalent explicit declaration controls and domain outcomes.

## 4. Redesigned Modal Layout

| Zone | Required implementation |
|---|---|
| Header card | Preserve title, detection status, close behavior, focus containment, focus restoration, and edge-alignment status. The quality badge is visible at all breakpoints. |
| Paper standard HUD | Keep the existing standard pills. Add the `Edge 1-2` segmented orientation selector after them. Show current dimensions in the selected control and the recommendation as supporting text. Both orientation choices are buttons with `aria-pressed`. |
| Snap guidance banner | Preserve existing tap-to-snap and manual-corner guidance. It does not assert physical accuracy or eligibility. |
| Review card | Section A, `Paper outline`, is open by default. Section B, `Paper placement`, is collapsed by default unless quality is yellow or muted, a risk is already recorded, or the user opens it. Section B must remain available by keyboard. |
| Canvas viewport | Keep active emerald boundary, guide lines, loupe, touch proxies, click-guided snapping, and manual correction. Render non-selected valid candidate polygons in white at 25% opacity with a 1.2px dashed stroke. Hover and keyboard selection raise visual opacity to 55%. |
| Footer | Retain all existing handlers. Labels become `Map Corners Manually`, `Skip Calibration`, and `Confirm and Enter Workspace`. The primary action remains disabled until every existing eligibility condition is met. |

### 4.1 Candidate Selector

Create a derived candidate list with this exact order: exclude `rejectedIds` and candidates with `cropped_boundary`; sort by descending `score`, then ascending `id`; render the first three plus the selected candidate if absent; and expose a `Show all candidates` toggle when additional candidates exist. Each candidate button must use `aria-pressed`, show `Boundary evidence ${Math.round(score * 100)}%`, and preserve the existing `selectCandidate()` handler.

### 4.2 Placement Disclosure and Recovery

`Paper placement` must contain action buttons, not checkboxes or radio inputs. The `Flat on the installation wall` action is the only positive metric-eligibility declaration. `Held or offset`, `Unsure`, and `Corners obscured or paper curled` must preserve the applicable current `placementAssessment` and `placementRiskReasons`, show existing recovery guidance, and leave Confirm disabled. Retake Photo and Skip Calibration remain available in every non-eligible state.

## 5. Step-by-Step Implementation Plan

### Task 5.1: Preserve Explicit Confirmation State with Checkbox-Free Controls

**Target file:** `src/features/visualization/components/PaperDetectionConfirmationModal.tsx`

1. Keep `formatConfirmed`, `orientationConfirmed`, `placement`, `boundaryUnsafe`, `firstEdge`, and the existing `recoveryReview` mapping. Remove only their checkbox and radio presentation controls.
2. When a standard pill is selected, set `formatConfirmed` to `true`; retain the existing reset of `orientationConfirmed` after a standard change.
3. Replace the standalone swap button and orientation checkbox with the HUD segmented selector. Each explicit segment activation sets `firstEdge` and `orientationConfirmed` to `true`.
4. Keep `matchResult.recommendedFirstEdge` as a visual recommendation and initial orientation only. It must not set `orientationConfirmed`.
5. Replace placement inputs with the four action controls defined in Section 4.2. Only the explicit Flat action may create `user_confirmed_same_plane` with `boundaryUnsafe = false`.
6. Keep the confirmation guard equivalent to the current domain contract: `formatConfirmed && orientationConfirmed && samePlane && boundaryReviewed && isValidQuad && liveScale !== null && liveScale.scaleCmPerPx > 0`. Do not test `selectedStandard !== null`, because its state type is non-nullable.
7. Preserve the unchanged `onConfirm()` payload, including `orientationConfirmed: true` only after the explicit orientation action and `samePlaneConfirmed: true` only after the explicit Flat action.
8. Trace: `PRD-F3`, `PRD-F4`, `PRD-F6`, `SDD-C3`, `DSD-UI3`, `DSD-UI4`, `QAD-TC68`, `QAD-TC69`, `QAD-TC70`.

### Task 5.2: Candidate Visuals and Accessible Ranking

**Target file:** `src/features/visualization/components/PaperDetectionConfirmationModal.tsx`

1. Implement the deterministic derived candidate list in Section 4.1 with local boolean state for `showAllCandidates`.
2. Replace `Outline N` with `Boundary evidence NN%`. Do not use the words `match`, `confidence`, `accurate`, or `guaranteed` in the candidate score label.
3. Change non-selected SVG polygon stroke to `#ffffff`, `strokeWidth={1.2}`, `strokeOpacity={0.25}`, and `strokeDasharray="6 4"`.
4. Add a pointer and keyboard-visible selected or hover state that raises only the applicable non-selected outline to 55% opacity. Preserve selected-candidate click behavior and every rejection exclusion.
5. Trace: `PRD-F4`, `DSD-UI3`, `BRD-M4`, `QAD-TC68`, `QAD-TC77.2`.

### Task 5.3: Structured Review Card

**Target file:** `src/features/visualization/components/PaperDetectionConfirmationModal.tsx`

1. Replace the flat scrollable control bar with a `rounded-[16px] bg-white shadow-md` card containing the Paper Outline and Paper Placement sections.
2. Use existing repository typography and neutral tokens. Do not add a UI library or global design token.
3. Keep the card within `max-h-32` with internal scroll only when expanded content exceeds its height. The disclosure control reports expanded state with `aria-expanded` and references its section with `aria-controls`.
4. Automatically open placement only for advisory review states described in Section 4. Do not mutate declarations when opening it.
5. During active drag, visually reduce the card to 30% opacity and use `pointer-events-none`; preserve focus semantics by returning normal interaction on pointer release or cancellation.
6. Trace: `DSD-UI3`, `DSD-UI4`, `BRD-M4`, `QAD-TC70`, `QAD-TC77.5`.

### Task 5.4: Snap-Settlement Feedback Without Drag Latency

**Target file:** `src/features/visualization/components/PaperDetectionConfirmationModal.tsx`

1. Do not transition `cx` or `cy` during pointer movement. Corner coordinates must follow every pointer update without easing.
2. Add a monotonic `snapPulseId` when a corner changes from unsnapped to snapped. Use it to render a 200ms scale-and-emerald-ring settlement cue at the snapped corner or active polygon perimeter.
3. Apply the cue only to the discrete snap transition. Do not claim all four corners are individually green because the current edge-fit signal is aggregate.
4. Use existing Tailwind motion-safe and motion-reduce variants so the cue is disabled for `prefers-reduced-motion` users.
5. Maintain the MS59 performance budget of at least 55 FPS and Sobel work below 2ms per drag event.
6. Trace: `PRD-F4`, `PRD-F6`, `DSD-UI4`, `QAD-TC74`, `QAD-TC77.4`.

### Task 5.5: Footer Labels

**Target file:** `src/features/visualization/components/PaperDetectionConfirmationModal.tsx`

1. Rename the manual action to `Map Corners Manually`.
2. Rename the approximate path to `Skip Calibration`.
3. Rename the primary action to `Confirm and Enter Workspace`.
4. Do not change any handler, recovery payload, or disabled-state semantics.
5. Trace: `DSD-UI3`, `PRD-F4`, `QAD-TC66`, `QAD-TC77.1`.

### Task 5.6: Tests and QA Registration

**Target files:** `tests/unit/paperReferenceSelection.test.ts`, `tests/unit/planeEligibility.test.ts`, `docs/qad-glassfit.md`

1. Update static-modal assertions to require no checkbox or radio input, accessible standard, orientation, and placement declaration controls, recovery actions, and disabled initial confirmation.
2. Retain domain assertions that reject absent paper format, absent orientation, absent same-plane declaration, handheld placement, unsure placement, and obscured or curled paper for metric promotion.
3. Add QAD-TC77 exactly as registered in `docs/qad-glassfit.md`. TC77 is additive and does not replace QAD-TC68 through QAD-TC76.
4. Run `npm run test:ms53`, `npm run test:ms54`, `npm run test:ms55`, `npm run test:ms58`, `npm run test:ms59`, `npm run test:ms60`, and `npm run test:ms61`, then `npm run lint`, `npx tsc --noEmit`, and `npm run build`.

## 7. Risks and Rollout Strategy

| Risk | Mitigation |
|---|---|
| A customer overlooks an automatic recommendation | Suggestions remain distinct from selections, and the disabled primary action names the missing declaration. |
| A wall-mounted or visible sheet is not coplanar with the installation plane | Explicit placement declaration and existing MS55 eligibility remain the only metric-promotion path. Edge quality is advisory only. |
| Low-contrast imagery hides white inactive outlines | Candidate pills remain the primary selection mechanism, and focus or hover raises outline opacity without implying evidence quality. |
| Motion affects low-end devices or motion-sensitive users | Pulse animation is discrete, uses existing motion-reduction support, and is tested against the MS59 mobile performance gate. |
| UI refactor weakens provenance | No domain contract, payload field, or eligibility code is changed. Existing MS53 through MS61 test suites remain release gates. |
