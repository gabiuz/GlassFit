## 1. Approved Outcome and Scope

The visualization flow has two user-facing measurement calibration modes. Automatic Detection must restore the original paper-free workflow. Paper detection belongs exclusively to Paper Reference Calibration.

| Mode | Analysis and upload flow | Workspace behavior |
|---|---|---|
| Automatic Detection (`auto_detect`, default) | Upload photo, run existing image analysis, show `ImageSuccessModal`, then enter the workspace through its existing action | Approximate preview using existing non-paper signals and sizing fallbacks. No paper detection, confirmation, pinning, standard selection, or marker adjustment |
| Paper Reference Calibration (`paper_fiducial`) | Select paper standard, upload photo, detect paper, show `PaperDetectionConfirmationModal`, then confirm or skip into the workspace | Preserve paper review, candidate selection, click-guided snapping, manual corners, geometry and plane eligibility, marker adjustment, and approximate fallback |

Apply this contract to both the product-specific upload page and the direct visualization page. Keep their existing workspace entry behavior: product-specific navigation opens the selected product workspace; direct visualization activates its inline workspace and retains product selection.

Preserve brightness, lighting, segmentation, optional depth and scene analysis, existing heuristic sizing, product placement, manual tape measurements, and quotation confirmation. Do not add a measurement algorithm, change detector accuracy thresholds, rename either mode, add a third visible mode, or introduce a new UI library, dependency, database migration, or continuous camera tracking.

The legacy API mode `standard` remains supported as paper-free approximate preview. It is not a third selector option.

### 1.1 Requirement precedence

MS62 supersedes the default automatic paper-localization requirement in MS48/MS51/MS53 and the related PRD-F3/F4, DSD-UI3, and QAD-TC63/66/68 intake expectations. It also supersedes QAD-TC60's old selector labels and `standard` default dispatch; the current two labels and `auto_detect` default remain. Paper-detection and review requirements continue under `paper_fiducial`.

The reconciled PRD, SDD, DSD, QAD, index, and milestone entries describe the target behavior, with implementation evidence recorded in section 9. Existing MS54-MS61 geometry, eligibility, quotation provenance, and empirical release requirements remain in force. MS61 `MOD-AUTO` means automatic localization within the paper benchmark; it is not the user-facing `auto_detect` intake mode.

BRD objectives and ERD/BUILD contracts remain applicable without changes: this milestone adds no persistence entity, migration, secret, environment variable, or deployment service.

## 3. Non-Negotiable Invariants

1. Successful automatic or standard analysis never invokes `detect_paper_fiducial`, including when paper is visible or extra paper parameters arrive.
2. A valid paper-mode analysis invokes the detector. No-paper, ambiguous, malformed-evidence, and detector-error responses retain manual review or skip recovery.
3. Request mode controls a fresh session. Response metadata, incidental corners/candidates, or selector changes cannot promote an automatic request to paper mode.
4. Automatic sessions never show a paper modal or paper action in either upload flow or the workspace.
5. Preserve both scale aliases and existing non-paper signals. Missing EXIF, no object anchors, disabled depth/scene, or model unavailability may produce an approximate fallback; these are not failures introduced by MS62.
6. Paper-mode confirmation, placement declarations, metric eligibility, and measurement/quotation trust rules remain unchanged. Paper review alone does not certify physical accuracy.
7. Normalize mode before storing or restoring workspace state. Normalization must be idempotent and preserve user-entered dimensions and historical saved quotation snapshots.

## 4. Implementation Contract

### 4.1 Backend request and response

Keep the endpoint, multipart field names, supported mode values, and default `auto_detect`. Gate the detector exclusively on `calibration_mode == "paper_fiducial"`. Keep current request validation and errors, including paired/finite seed validation; this change does not relax invalid-input handling.

For valid `auto_detect` and `standard` requests, retain the existing `PaperCalibrationResult` envelope and workspace-coordinate metadata:

| Field | Required value |
|---|---|
| `paper_calibration.status` | `not_requested` |
| `paper_calibration.candidates` | Empty array |
| Paper standard, suggested standard, unwarped aspect ratio, selected candidate, reference source, detected corners, scale, homography | Null |
| Confidence and aspect-ratio match confidence | Zero |
| Paper standard confirmation and user verification, when present | False |
| `calibration_meta.mode` | Request mode |
| `calibration_meta.status` | `heuristic_fallback` |
| `calibration_meta` paper evidence fields | Null/zero/false as above; no metric reference |

Preserve the existing empty `detection_outcome` representation (`not_found`), coordinate image identity, dimensions, and mapping envelope. `not_requested` is the authoritative paper status; it must not be replaced by `heuristic_fallback` in `paper_calibration`.

Keep non-paper analysis and `scale_estimation` generation unchanged. The backend builds object anchors, optionally corrected by depth, and attaches EXIF fields separately. It does not guarantee EXIF or scene entries in the anchor array.

### 4.2 Frontend normalization

Pass captured request mode from `analyzeImage` into `toSpaceImageSession`. Do not decide normalization from `payload.calibration_meta.mode`. Keep default requests explicit as `auto_detect`. Serialize `paper_standard` and seed coordinates only for paper-mode requests.

For automatic and standard requests:

1. Skip `validatePaperDetection`; do not let its manual-pin fallback run.
2. Set both `paperCalibration` and `paper_calibration` to `undefined`. These optional TypeScript fields do not require widening to accept null.
3. Construct fresh `calibrationMeta`, rather than spreading backend metadata: request mode, `status="heuristic_fallback"`, `paperStandard=null`, `confidence=0`, `homographyMatrix=null`, `detectedCorners=null`, `user_verified=false`, `verified_corners=null`, `verified_scale_cm_per_px=null`, and `paperStandardConfirmed=false`.
4. Omit optional paper suggestions, aspect-ratio fields in either naming convention, candidate IDs, reference source, placement review, same-plane declarations, and metric reference. Never retain them from incidental payloads.
5. Keep existing rejection of paper/calibrated scale methods: method names containing `paper` or `calibrat` are rejected. For these stale signals, set `best_scale_cm_per_px=null`, `confidence=0`, `method="none"`, and `anchors=[]`; remove `reference_confirmed` and preserve EXIF fields. Construct this result from the declared signal fields so incidental metric evidence is not spread forward. Preserve legitimate non-paper signals exactly, including empty anchors, and synchronize `scaleEstimation` and `scale_estimation`. During restoration, prefer the camelCase signal when present, otherwise its snake_case alias; fresh mapping uses the single backend signal.

For paper requests, retain validation, candidate mapping, aliases, and fallback behavior. Normalize `calibrationMeta.mode` to `paper_fiducial` even if response mode is absent or contradictory. Missing/invalid paper data yields `manual_pin_required`, allowing manual corners or skip. Never treat response verification claims as user confirmation.

Use a shared pure non-paper session normalizer, exported from `src/lib/imageApi.ts`, for fresh mapping and session restoration so both paths enforce the same field clearing. Keep existing interfaces and dependencies.

### 4.3 Upload routing and workspace gating

In both upload pages, use the normalized pending session's mode as the paper-review gate: `pendingSession?.calibrationMeta?.mode === "paper_fiducial"`. Do not require corners or candidates. Paper mode must open review even when no paper was detected.

An automatic result opens `ImageSuccessModal`; its existing action enters the workspace. Preserve loading, cancellation, retry, request-ID protection, errors, and focus handling. Capture mode for each request so later selector state cannot reinterpret an outstanding response; a cancelled/replaced request cannot open either result modal.

In `ProductModelWorkspace`, require paper mode when initializing the pin prompt, rendering paper review, and exposing Pin Paper or Adjust Marker. Keep verification/status checks inside that mode gate. Automatic mode keeps approximate or manual tape wording and must not display paper guidance in its HUD tooltip. A paper session that skips review remains paper mode with heuristic fallback, preserving voluntary Pin Paper recovery.

### 4.4 Existing session compatibility

The image API mapper cannot migrate `sessionStorage`. Apply this policy inside `readStoredVisualizationSession` before `validateSessionPlaneEligibility` and before workspace UI consumes restored state:

| Stored state | Restoration policy |
|---|---|
| Explicit `paper_fiducial` | Preserve paper workflow and run existing geometry/eligibility validation |
| `auto_detect` with explicit user review (`calibrationMeta.user_verified === true` or `calibrationMeta.status === "verified_calibrated"`) | Relabel session mode to `paper_fiducial`, preserving previously reviewed work; existing validators still decide eligibility |
| `auto_detect` without explicit review, including `manual_pin_required` or incidental candidates | Apply non-paper normalizer; no paper prompt or retained paper metric evidence |
| `standard` | Apply non-paper normalizer and retain `standard` |
| Missing/unrecognized mode with the same explicit review evidence | Restore as `paper_fiducial`, then run existing validators |
| Missing/unrecognized mode without review evidence | Restore as `auto_detect` and apply non-paper normalizer |

Detector confidence, `detected`/`calibrated` status alone, or a standard value is not explicit user review. Relabeling reviewed legacy work does not validate geometry or automatically open a dialog.

Normalize in-memory restored state and let existing persistence write it on subsequent saves. Repeated reloads must yield the same result. Retain product selections, placements, assets, numeric dimensions, and manual tape provenance. Revalidate draft paper-derived eligibility after evidence removal through the existing plane validator; stale paper-derived labels/provenance cannot remain eligible. Do not rewrite saved server quotation snapshots or remeasure/reprice historical records.

Product add/change transitions and quotation return must preserve the resulting mode without resurrecting paper metadata or reopening paper prompts in automatic mode.

### 4.5 Copy and UI reuse

Keep both labels, default selection, selector layout, design tokens, badges, and paper-mode instructions. Replace the Automatic Detection description with:

> Upload a space photo and enter the workspace with an approximate preview. No paper reference required.

Keep its `Requires no markers` footer. Automatic upload guidance and workspace tooltip must describe approximate preview without requesting paper. Retain the existing success modal; do not add an entry screen or calibration dialog.

## 8. Rollout and Completion Boundary

Ship backend and frontend together. New frontend normalization must tolerate old backend paper payloads. A new backend with an old frontend can still trigger paper prompts because old clients treat `not_requested` as manual fallback; a backend-only deployment does not complete MS62. Reload the updated frontend before acceptance.

Legacy reviewed work is retained under Paper Reference Calibration; unreviewed automatic sessions become paper-free. This avoids treating previous user confirmation as incidental detector output.

Implementation is recorded separately from browser and physical acceptance. Automated checks do not certify physical measurement accuracy.
