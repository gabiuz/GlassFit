## 1. Executive Summary & Problem Context

The GlassFit asynchronous photo-based space visualization workflow begins at the client photo dropzone (`/visualize/[productId]/upload` or `/visualization`). A customer captures a photo of their physical room opening (such as a patio doorway, window aperture, or shower enclosure) and uploads it to serve as the real-world backdrop for interactive 3D fenestration placement, lighting estimation, and foreground occlusion.

### 1.0 Confirmed Initial Requirement

The approved customer requirement is: when uploading an image of the client's space, GlassFit must accept WebP and HEIC/HEIF in addition to the currently supported JPG and PNG formats. This milestone is limited to safe ingestion, preview behavior, server decoding, normalization, and regression verification. It does not alter the visualization workflow or final workspace image contract.

### 1.1 The Business Need & Modern Format Proliferation

Since Apple introduced iOS 11, iPhones and iPads capture photos in High Efficiency Image File Format (HEIF/HEIC) by default. In the Philippine consumer market, where iPhone adoption across commercial and residential property owners is substantial:
1. **Apple iOS Default Format (HEIC):** When customers use mobile Safari or AirDrop photos to their desktop computers, images commonly retain `.heic` or `.heif` extensions. Under the current implementation, every iPhone customer uploading a standard space photo receives an immediate error rejecting the file.
2. **Modern Web Format (WebP):** Modern digital cameras, Android devices, and web-optimized asset repositories increasingly store images in WebP format due to superior compression (25-35% smaller file size compared to JPEG at equivalent visual quality).
3. **Customer Friction & Drop-Off:** Forcing non-technical clients to search for third-party file converters or screenshot their photos creates immediate friction, degrading user conversion (`BRD-M3`) and violating the usability baseline (`BRD-M4`).

### 1.2 Current Architectural Limitations & Format Rejection

Under the current implementation across frontend and microservice layers:

1. **Frontend Dropzone MIME Whitelist:** In [`src/features/visualization/components/UploadImage.tsx`](file:///Users/gab/Developer/glassfit/src/features/visualization/components/UploadImage.tsx#L168), the hidden file input specifies `accept="image/jpeg,image/png"`. The operating-system file picker disables WebP and HEIC files by default.
2. **Client Validation Rejection:** In [`src/lib/imageApi.ts`](file:///Users/gab/Developer/glassfit/src/lib/imageApi.ts#L3), `ACCEPTED_IMAGE_TYPES` is hardcoded to `["image/jpeg", "image/png"]`. If a user bypasses the file picker filter (via drag-and-drop), `validateImageFile()` immediately returns `"Upload a JPG, JPEG, or PNG image."`.
3. **FastAPI Microservice Rejection:** In [`fastapi-service/main.py`](file:///Users/gab/Developer/glassfit/fastapi-service/main.py#L31), `ALLOWED_CONTENT_TYPES` is hardcoded to `{"image/jpeg", "image/png"}`. If a request reaches the microservice with `image/webp` or `image/heic`, FastAPI returns an HTTP 400 Bad Request exception.
4. **FastAPI Suffix Generation:** In [`fastapi-service/main.py`](file:///Users/gab/Developer/glassfit/fastapi-service/main.py#L133), the file extension suffix is hardcoded with binary logic: `suffix = ".png" if image.content_type == "image/png" else ".jpg"`. WebP and HEIC files are mislabeled with `.jpg` extensions.

### 1.3 Format Incompatibilities & Technical Hurdles

While WebP integration is straightforward, HEIC presents three significant technical challenges across web browsers and Python runtimes:

| Challenge Domain | WebP Behavior | HEIC/HEIF Behavior | Technical Consequence & Resolution Strategy |
|---|---|---|---|
| **Browser Native Decoding** | Supported by the target Chrome, Edge, Firefox, and Safari versions through `HTMLImageElement`. | Supported by Safari 17 or later and not assumed in Chromium or Gecko. | The client must attempt to decode the selected file itself. A successful decode uses the native preview; a failed HEIC/HEIF browser decode uses a metadata card and delegates authoritative validation to the server. |
| **MIME Type Reporting** | Consistently reported as `image/webp`. | Inconsistent across platforms. Windows and Android browsers frequently report empty string `""` or `application/octet-stream` for `.heic` files. | Validation logic cannot rely solely on `file.type`. It must inspect both MIME type and filename extension (`.heic`, `.heif`). |
| **Python Pillow Decoding** | Supported natively by standard Pillow wheels (compiled with `libwebp`). | Not supported by standard Pillow. Calling `Image.open("photo.heic")` raises `PIL.UnidentifiedImageError`. | Must introduce `pillow-heif` in `fastapi-service/requirements.txt` and invoke `pillow_heif.register_heif_opener()` at startup. |
| **OpenCV Decoding (`cv2.imread`)** | Supported natively by OpenCV headless wheels. | Not supported. Calling `cv2.imread("photo.heic")` returns `None`. | In `main.py`, `analyze_brightness`, `analyze_lighting`, and line 191 (`image_bgr = cv2.imread(str(upload_path))`) will crash. `save_oriented_upload()` must normalize HEIC files into high-quality JPEG or PNG before OpenCV consumption. |

### 1.4 Required System Behavior & Format Normalization Topology

To fulfill `IMP-MS35`, the system must implement the following ordered pipeline:

| Stage | Required Behavior |
|---|---|
| 1. File selection | Accept one static JPG, JPEG, PNG, WebP, HEIC, or HEIF file with a maximum compressed size of 12 MB. |
| 2. Client pre-flight | Reconcile MIME and extension, reject recognized conflicts, and decode JPG, PNG, and WebP through `HTMLImageElement`. Attempt the selected HEIC/HEIF file directly and use a fallback card when the browser cannot decode it. |
| 3. FastAPI ingress | Resolve generic MIME values only through an approved extension, save raw bytes using the resolved suffix, and reject declared-format conflicts. |
| 4. Authoritative decode | Open through Pillow with the required HEIF plugin, verify the decoded format, reject animation or multiple frames, enforce the 40,000,000-pixel limit before full RGB conversion, and map all expected decoder failures to HTTP 400. |
| 5. Normalization | Preserve JPG, PNG, and WebP intermediates; convert HEIC/HEIF to an upright high-quality JPEG that OpenCV can read. |
| 6. CV inference | Run brightness, lighting, segmentation, depth, and scene analysis on the normalized intermediate. |
| 7. Workspace delivery | Continue producing `session_dir/workspace.webp` for the existing visualization workspace without changing its consumer contract. |

### 1.5 Scope Boundaries & Non-Goals

- **Non-Goal (Heavy Client-Side WebAssembly HEIC Transcoding):** Bundling large client-side WebAssembly decoders (such as `heic2any` or `libheif-js`, which add 1.5 MB to 2.5 MB of JavaScript to the initial bundle) is rejected. Server-side transcoding via native C `libheif` in Python runs faster, avoids mobile browser memory strain, and keeps client bundles lean.
- **Non-Goal (Video or Animation Ingestion):** Animated WebP, APNG, GIF, or video formats (MP4, MOV) remain unsupported. Only static single-frame photographs are permitted.
- **Non-Goal (Increasing Maximum File Size):** The 12 MB file size limit (`MAX_UPLOAD_BYTES = 12 * 1024 * 1024`) remains active across all formats to preserve memory limits on container environments.
- **Non-Goal (Modifying Downstream Workspace Image Format):** The workspace image format remains `workspace.webp`. All inputs (JPEG, PNG, WebP, HEIC, and HEIF) converge to this uniform web standard for the 3D canvas viewport.

## 3. Format Ingestion & Transformation Architecture

### 3.1 WebP Ingestion Flow

WebP is natively supported across all modern web browsers and Python libraries:
1. **User Action:** Customer selects a `.webp` file (`image/webp`).
2. **Client Pre-Flight:** `validateImageFile()` verifies MIME, extension, and size. `validateImageDecode()` loads the selected blob into `new window.Image()` and returns image preview mode after successful decode.
3. **Dropzone Preview:** `UploadImage.tsx` renders the local blob with the existing Next.js `Image` component in unoptimized mode.
4. **Network Payload:** Browser sends `POST /analyze-image` with `Content-Type: multipart/form-data`.
5. **FastAPI Processing:** 
   - `image.content_type` matches `"image/webp"`.
   - Raw bytes saved to `upload_id_raw.webp`.
   - `save_oriented_upload()` decodes via Pillow, transposes orientation, and saves to `upload_id.webp`.
   - `analyze_brightness()` and `analyze_lighting()` read `upload_id.webp` directly via `cv2.imread()`.
   - `analyze_objects()` runs YOLO inference on `upload_id.webp`.
   - `prepare_workspace_image()` resizes and saves `workspace.webp`.

### 3.2 HEIC/HEIF Ingestion Flow

HEIC requires dual-stage handling due to browser and OpenCV decoding constraints:
1. **User Action:** Customer selects an iPhone `.heic` or `.heif` photo.
2. **Client Pre-Flight:** 
   - `validateImageFile()` accepts empty or generic MIME through an approved extension, but rejects conflicts between recognized MIME and extension values.
   - `validateImageDecode()` attempts the selected file. Successful browser decode returns image mode; failed HEIC/HEIF decode returns file-card mode and delegates authoritative validation to the server.
3. **Dropzone Preview:** 
   - If selected-file decode succeeds, the Next.js `Image` component renders the blob URL in unoptimized mode.
   - If selected-file decode fails for HEIC/HEIF, `UploadImage.tsx` renders a GlassFit-styled metadata card showing filename, formatted file size, a HEIC/HEIF badge, and a camera icon.
4. **Network Payload:** Raw HEIC binary transmitted directly to FastAPI `/analyze-image`.
5. **FastAPI Processing:**
   - Ingress identifies HEIC via content-type or filename extension.
   - Raw bytes saved to `upload_id_raw.heic`.
   - `extract_exif_camera_info()` reads camera metadata via Pillow + `pillow-heif` (extracting Apple iPhone model, focal length, etc.).
   - `save_oriented_upload()` decodes the display-oriented primary HEIC image via `pillow-heif` and **normalizes the output file to high-quality JPEG (`upload_id.jpg`, quality 95)** without applying the informational HEIF EXIF orientation twice.
   - Downstream OpenCV functions (`cv2.imread`), brightness analysis, lighting analysis, and YOLOv8 instance segmentation read `upload_id.jpg` without compatibility errors.
   - `prepare_workspace_image()` outputs the standardized `workspace.webp`.
6. **Workspace Delivery:** Downstream 3D visualization canvas loads `workspace.webp`, which displays identically across all desktop and mobile browsers.

## 4. Detailed Technical Specifications

### 4.1 Client Pre-Flight Validator & Type Definitions (`src/lib/imageApi.ts`)

In [`src/lib/imageApi.ts`](file:///Users/gab/Developer/glassfit/src/lib/imageApi.ts), the constants and validation functions must be enhanced to accept WebP and HEIC/HEIF while handling OS-level MIME reporting anomalies:

```typescript
export const ACCEPTED_IMAGE_TYPES = [
  "image/jpeg",
  "image/png",
  "image/webp",
  "image/heic",
  "image/heif",
];

export const ACCEPTED_IMAGE_EXTENSIONS = [
  ".jpg",
  ".jpeg",
  ".png",
  ".webp",
  ".heic",
  ".heif",
];

export const MAX_UPLOAD_BYTES = 12 * 1024 * 1024;

/**
 * Checks whether a given file is a HEIC or HEIF image based on MIME type or extension.
 */
export function isHeicFile(file: File): boolean {
  const mime = file.type.toLowerCase();
  if (mime === "image/heic" || mime === "image/heif") {
    return true;
  }
  const name = file.name.toLowerCase();
  return name.endsWith(".heic") || name.endsWith(".heif");
}

export type ImagePreviewMode = "image" | "file-card";

const GENERIC_IMAGE_TYPES = new Set(["", "application/octet-stream"]);

const MIME_EXTENSIONS: Readonly<Partial<Record<string, readonly string[]>>> = {
  "image/jpeg": [".jpg", ".jpeg"],
  "image/png": [".png"],
  "image/webp": [".webp"],
  "image/heic": [".heic", ".heif"],
  "image/heif": [".heic", ".heif"],
};

/**
 * Validates file MIME type, extension, and file size.
 */
export function validateImageFile(file: File): string | null {
  const fileType = file.type.toLowerCase();
  const fileName = file.name.toLowerCase();

  const extension = ACCEPTED_IMAGE_EXTENSIONS.find((candidate) =>
    fileName.endsWith(candidate)
  );
  const allowedExtensions = MIME_EXTENSIONS[fileType];

  if (GENERIC_IMAGE_TYPES.has(fileType)) {
    if (!extension) {
      return "Upload a JPG, PNG, WebP, or HEIC/HEIF image.";
    }
  } else if (!allowedExtensions || !extension || !allowedExtensions.includes(extension)) {
    return "The file type and filename extension do not match.";
  }

  if (!ACCEPTED_IMAGE_TYPES.includes(fileType) && !GENERIC_IMAGE_TYPES.has(fileType)) {
    return "Upload a JPG, PNG, WebP, or HEIC/HEIF image.";
  }

  if (file.size > MAX_UPLOAD_BYTES) {
    return "Upload an image smaller than 12 MB.";
  }

  return null;
}

/**
 * Validates browser decode integrity and returns the required preview mode.
 * A failed HEIC/HEIF browser decode is delegated to the authoritative server decoder.
 */
export async function validateImageDecode(file: File): Promise<ImagePreviewMode> {
  const objectUrl = URL.createObjectURL(file);

  try {
    await new Promise<void>((resolve, reject) => {
      const image = new window.Image();
      image.onload = () => {
        if (image.naturalWidth <= 0 || image.naturalHeight <= 0) {
          reject(new Error("Uploaded image has invalid dimensions."));
          return;
        }
        resolve();
      };
      image.onerror = () =>
        reject(new Error("Uploaded image could not be decoded."));
      image.src = objectUrl;
    });
    return "image";
  } catch (error) {
    if (isHeicFile(file)) {
      return "file-card";
    }
    throw error;
  } finally {
    URL.revokeObjectURL(objectUrl);
  }
}
```

2. **Robust Format Detection Function:**
   ```python
   def _resolve_image_format(
       content_type: str | None,
       filename: str | None,
   ) -> tuple[str, str]:
       """
       Returns the original approved suffix and declared format family.
       Generic MIME values may fall back to extension. Recognized MIME and
       extension values must agree.
       """
       ct = (content_type or "").lower().strip()
       ext = Path(filename or "").suffix.lower()

       extension_format = EXTENSION_FORMATS.get(ext)
       if extension_format is None:
           raise HTTPException(400, "Upload a JPG, PNG, WebP, or HEIC/HEIF image.")

       if ct in GENERIC_CONTENT_TYPES:
           return ext, extension_format

       mime_contract = MIME_FORMATS.get(ct)
       if mime_contract is None:
           raise HTTPException(400, "Upload a JPG, PNG, WebP, or HEIC/HEIF image.")

       declared_format, allowed_extensions = mime_contract
       if ext not in allowed_extensions:
           raise HTTPException(400, "The file type and filename extension do not match.")

       return ext, declared_format

   def _assert_decoded_format(declared_format: str, decoded_format: str) -> None:
       normalized_decoded = decoded_format.lower()
       compatible = normalized_decoded == declared_format or (
           declared_format == "heif" and normalized_decoded in {"heic", "heif"}
       )
       if not compatible:
           raise HTTPException(
               status_code=400,
               detail="The uploaded image contents do not match its declared format.",
           )
   ```

### 4.4 Image Preparation & Decoding Adapter (`fastapi-service/image_preparation.py`)

In [`fastapi-service/image_preparation.py`](file:///Users/gab/Developer/glassfit/fastapi-service/image_preparation.py):

1. **Register the Required HEIF Opener at Module Import:**
   ```python
   from pathlib import Path
   from typing import TypedDict
   
   from PIL import Image, ImageOps, UnidentifiedImageError
   from pillow_heif import register_heif_opener
   ```

   Import or registration failure is a startup failure. It must not be swallowed because the service contract declares HEIC/HEIF support. The existing `/health` response remains `{"status": "ok"}` and can only become available after successful application import and decoder registration.
2. **Enhance `save_oriented_upload()` for Format Normalization:**
   ```python
   DECODER_ERRORS = (
       UnidentifiedImageError,
       OSError,
       ValueError,
       EOFError,
       SyntaxError,
       RuntimeError,
   )

   def _open_validated_image(input_path: Path) -> tuple[Image.Image, str]:
       image: Image.Image | None = None
       try:
           image = Image.open(input_path)
           source_format = (image.format or "").lower()
           _validate_dimensions(image.width, image.height)
           if getattr(image, "n_frames", 1) != 1 or getattr(image, "is_animated", False):
               image.close()
               raise ImagePreparationError("Animated or multi-frame images are not supported.")
           return image, source_format
       except ImagePreparationError:
           if image is not None:
               image.close()
           raise
       except Image.DecompressionBombError as exc:
           if image is not None:
               image.close()
           raise ImagePreparationError("Uploaded image is too large to process safely.") from exc
       except DECODER_ERRORS as exc:
           if image is not None:
               image.close()
           raise ImagePreparationError("Uploaded image could not be decoded.") from exc

   def save_oriented_upload(input_path: Path, output_path: Path) -> ImageMetadata:
       source, source_format = _open_validated_image(input_path)
       try:
           # The HEIF decoder returns the display-oriented primary image.
           # Do not apply raw HEIF EXIF orientation a second time.
           oriented = source.copy() if source_format in {"heic", "heif"} else ImageOps.exif_transpose(source)
           try:
               image = oriented.convert("RGB") if oriented.mode != "RGB" else oriented.copy()
           finally:
               oriented.close()
       finally:
           source.close()

       target_format = output_path.suffix.lstrip(".").lower()
       width, height = image.size
       try:
           output_path.parent.mkdir(parents=True, exist_ok=True)
           if target_format in {"jpg", "jpeg"}:
               image.save(output_path, "JPEG", quality=95, optimize=True)
           elif target_format == "webp":
               image.save(output_path, "WEBP", quality=95, method=4)
           elif target_format == "png":
               image.save(output_path, "PNG", optimize=True)
           else:
               raise ImagePreparationError("Unsupported normalized image format.")
       finally:
           image.close()

       return {
           "width": width,
           "height": height,
           "format": target_format,
           "source_format": source_format,
       }
   ```
3. **Decode Safety and Orientation Integrity:**
   - Validate dimensions before `copy()`, `convert()`, or any other operation that forces full pixel decode. This makes the 40,000,000-pixel limit an actual memory guard rather than a post-decode check.
   - Reject every input with `n_frames != 1` or `is_animated == true`, including animated WebP, APNG, and multi-image HEIF containers.
   - Treat the HEIF decoder's primary image as already display-oriented. Do not rotate again from the informational raw HEIF EXIF orientation tag.
   - Test portrait, landscape, mirrored JPEG, and iPhone HEIC fixtures with known dimensions and visual orientation.
