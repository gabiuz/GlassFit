# Implementation Specification: Quotation Preview and Browser-Saved PDF Reliability (IMP-MS38)

**Project:** GlassFit (Web-Based Client-Space Visualization System for Customized Glass & Aluminum)  
**Document ID:** IMP-MS38  
**Document Function:** Implementation-ready specification for repairing quotation preview layout defects and browser-saved PDF output  
**Version:** 1.1.0  
**Date:** October 1, 2026  
**Owner:** Reynard John B. Rabanal (Lead Product / Systems Architect) & GlassFit Capstone Team (PUP CCIS)  
**Status:** Ready for Implementation  
**Primary Traceability:** `BRD-M3`, `BRD-M5`; `PRD-F10`, `PRD-F11`; `SDD-C7`; `DSD-UI16`; `ERD-E13`, `ERD-E14`; `QAD-TC10`, `QAD-TC11`, `QAD-TC30`, `QAD-TC53`

---

## 1. Authorized Requirement

Repair the quotation preview and the PDF produced through the browser's native Print or Save as PDF flow. The completed implementation must preserve quotation content and pricing while resolving these observed defects:

1. Page 1 of some browser-saved PDFs loses text and foreground graphics while retaining boxes and background fills.
2. A multi-fixture quotation displays Fixture 1 specifications in the project-level header.
3. A fixture title and specifications can be separated from its final item price by a page break.
4. Currency values can wrap within the number.
5. Some browser and PDF viewer combinations render vertical glyph stems with inconsistent weight.
6. Native print headers can expose an administrative route when browser headers and footers are enabled.

No database migration, pricing rule change, CV microservice change, or new dependency is authorized. The implementation must preserve the customer-safe disclosure contract in `PRD-F11`, including one effective final price per product item, a reconciling grand total, and no internal BOM rates, margin, original price, or negotiation notes.

## 2. Verified Current State

### 2.1 Confirmed Repository Findings

1. `public/Logo.svg` is a 408 KB SVG wrapper around an embedded base64 PNG. It uses `<pattern>`, `<use>`, `xlink:href`, and an affine `matrix(...)` transform.
2. Every current quotation surface supplies `/Logo.svg` to the document view model:
   - `src/features/booking/components/BookingFlow.tsx`
   - `src/features/admin/bookings/BookingsContent.tsx`
   - `src/app/api/quotations/download/route.ts`
3. `src/app/api/quotations/download/route.ts` returns `text/html`. The current product does not generate PDF bytes on the server. The PDF named in this milestone is the file produced by the browser's native print dialog.
4. Canonical documents recursively pass through `canonicalToLegacy`. That adapter uses the first fixture to construct placeholder metadata and omits canonical fixture count. The shared renderer therefore treats a multi-fixture document as a single fixture and emits Fixture 1 data in the project-level specifications block.
5. The canonical branch later replaces the itemized section with canonical fixture cards. This replacement does not remove the already-rendered project-level specifications block.
6. The print stylesheet applies `break-after: avoid` to the fixture header but intentionally allows `.item-card` to fragment. The existing unit test explicitly asserts that `.item-card` does not use `break-inside: avoid`.
7. The document body uses `overflow-wrap: anywhere`, while currency cells and item totals have no non-breaking rule.
8. `quotationPreviewWindow.ts` already waits for document load, fonts, image decoding, two animation frames, or a bounded five-second timeout before automatic printing.
9. The generated HTML already contains a quotation-specific `<title>`. Setting the document title again is not a proven fix for missing page content or native browser headers.
10. `SNAPSHOT_FALLBACK_DATA_URL` already uses direct `<rect>`, `<path>`, and `<circle>` geometry with no pattern or transform. It requires regression coverage, not redesign.
11. Administrator item-price, legacy final-price, and labor save actions persist their values and update local booking state. The administrator preview currently passes the saved negotiated total and item overrides into `createQuotationDocumentViewModel`, but it does not pass `adminLaborCharge` directly. The PDF generator can infer labor from the difference between product subtotal and saved grand total, but MS38 must replace that implicit dependency with explicit saved labor wiring.

### 2.2 Evidence-Gated Root Cause

The repository proves that the logo asset is unusually complex for print output, but it does not prove that the asset corrupts a Cairo or Skia graphics state. The implementation must not encode that browser-engine explanation as fact.

Before changing the global brand asset, reproduce the Page 1 failure with a fixed quotation fixture and run this isolation sequence in the affected browser:

1. Export with the current `/Logo.svg`.
2. Export the same HTML with the logo omitted.
3. Export the same HTML with a dedicated print-safe raster logo.
4. Keep all other data, styles, browser settings, and page scale unchanged.

If steps 2 or 3 restore Page 1, use the dedicated print-safe asset only in the quotation pipeline. Do not replace the site-wide `public/Logo.svg` unless a separate visual regression proves the replacement is safe across all existing consumers.

If the logo isolation does not restore Page 1, continue with a controlled one-variable-at-a-time reduction of Page 1. Test the customer snapshot, print color adjustment, flex and grid containers, backgrounds, overflow rules, and the document header independently. The implementation must select the smallest verified repair and record the eliminated hypotheses. It must not apply the asset change as an unsupported fix.

The bold stem artifact must also be classified before remediation. Compare the same PDF in the browser viewer and macOS Preview, with viewer enhancement settings recorded. CSS font smoothing and `text-rendering` are hints and are not acceptance evidence by themselves.

### 2.3 Native Print Boundary

Browser-added headers and footers are controlled by the native print dialog. Application CSS and `<title>` cannot guarantee their removal in every browser. IMP-MS38 therefore requires both of the following:

1. The quotation HTML must never render an administrative URL as document content.
2. The preview must provide concise guidance to disable native headers and footers when the selected browser exposes that option.

A guarantee that no browser-generated URL can ever appear would require a separate server-generated PDF architecture. That architecture is not authorized by this milestone.

## 3. Scope

### 3.1 In Scope

1. A print-safe quotation logo asset and consistent use of that asset across customer, administrator, and download-route document generation.
2. Canonical single-fixture and multi-fixture project-header specification rules.
3. Bounded print fragmentation rules that keep compact canonical fixture cards intact without reintroducing clipping risks for oversized legacy content.
4. Non-breaking currency and dimension formatting.
5. Print typography normalization using approved, already-present assets and system fonts only.
6. Preview guidance for native print headers and footers.
7. Unit regression coverage plus a mandatory manual browser-saved PDF verification matrix.
8. Preservation of quotation arithmetic, customer-safe disclosure, terms, signatures, structural waiver notices, and legacy quotation behavior.

### 3.2 Out of Scope

1. Server-side PDF byte generation.
2. Puppeteer, Playwright, wkhtmltopdf, PDF libraries, or any other new dependency.
3. Database schema or data mutation.
4. Pricing, BOM, negotiation, labor, or quotation persistence changes.
5. Booking workflow stage changes.
6. Site-wide logo replacement without a separately verified need.
7. Claims that application code can disable native browser headers and footers.

## 4. Functional Contracts and Acceptance Criteria

### 4.1 Document Content Contract

| Document case | Required project-level specifications behavior | Required item behavior |
|---|---|---|
| Canonical single fixture | Show one project-level specifications block | Show one item card with the effective final item price |
| Canonical multiple fixtures | Do not show project-level fixture specifications | Show each fixture exactly once with its own specifications, quantity, and effective final item price |
| Reconstructed legacy quotation | Preserve current supported legacy content | Preserve customer-safe disclosure and grand-total reconciliation |

The renderer must derive multi-fixture behavior from the canonical view model itself. It must not fabricate `ItemizedProductQuotation` values or a `ConsolidatedQuotationSummary` solely to influence template branching.

### 4.2 Pricing and Disclosure Contract

For every canonical quotation:

1. The sum of effective final item prices plus the displayed administrator-confirmed labor charge, when present, must equal the displayed grand total to the centavo.
2. Existing negotiated item values must remain authoritative.
3. No component cost, material rate, contractor margin, original calculated price, or negotiation metadata may appear in the customer document.
4. The Page 1 repair must not change any value produced by `quotationDocument.ts` or the pricing engine.
5. After an administrator saves an item price, legacy final price, or labor fee, the next preview must use the returned persisted values without requiring a second edit or manual recalculation.
6. Administrator preview construction must pass the saved `adminLaborCharge` explicitly. Difference-based labor inference may remain only as a compatibility fallback for older callers.

### 4.3 Asset Contract

| Asset | Required contract |
|---|---|
| Quotation logo | Dedicated same-origin print-safe raster PNG or direct-path SVG with explicit intrinsic dimensions and no `<pattern>`, `<use>`, embedded SVG image, or matrix transform |
| Snapshot fallback | Preserve the current direct-geometry data URL and verify that it contains no pattern, use, or transform element |
| Customer snapshot | Preserve existing origin allow-list validation, aspect ratio, and `object-fit: contain` behavior |

The preferred implementation is a dedicated quotation asset such as `public/quotation-logo.png`, produced from an approved GlassFit source. The implementation must update all three quotation entry points. It must not reuse `public/send-booking/pdf_icon.svg` as a brand logo.

### 4.4 Fragmentation Contract

| Element | Required behavior |
|---|---|
| Compact canonical fixture card | Apply a dedicated class such as `.item-card--compact` with `break-inside: avoid` and `page-break-inside: avoid` |
| Oversized or legacy item content | Remain fragmentable so content is never clipped or pushed beyond a printable page |
| Fixture header | Retain `break-after: avoid` and `page-break-after: avoid` |
| Total table | Keep the complete reconciliation block together |
| Signature block | Keep each signature line, printed name, and date together |
| Terms appendix | Start on a new page and preserve current paragraph behavior |

The implementation must update the prior unit assertion that globally forbids item-card break avoidance. A blanket rule on every `.item-card` is not authorized because earlier tests intentionally protected long-card fragmentation.

### 4.5 Wrapping and Typography Contract

1. Currency values, quantities paired with prices, and grand totals must use `white-space: nowrap` and `font-variant-numeric: tabular-nums`.
2. Dimension values may remain on one line when space permits, but labels and long customer text must still wrap without horizontal overflow.
3. Remove global `overflow-wrap: anywhere`. Apply an explicit wrapping utility only to untrusted long strings such as email addresses and shareable URLs.
4. Use an explicit regular-weight system font stack for print. Do not introduce or embed a new font.
5. Font smoothing may be included as a best-effort enhancement, but manual rendered-output comparison is the acceptance gate.

### 4.6 Surface Parity Contract

The same canonical quotation must render equivalent document content from:

1. Customer booking preview in `BookingFlow.tsx`.
2. Administrator booking preview in `BookingsContent.tsx`.
3. The HTML response from `/api/quotations/download`.

Differences are limited to runtime data that is legitimately surface-specific, such as estimator identity or the current shareable origin.

## 5. Authorized Implementation Plan

### Phase 1: Reproduce and Isolate

1. Create fixed manual fixtures for one fixture, two fixtures, long customer data, missing snapshot, structural waiver, and reconstructed legacy data.
2. Reproduce the Page 1 failure before code changes and record browser version, operating system, print scale, paper size, headers and footers setting, and PDF viewer.
3. Run the logo isolation sequence in Section 2.2.
4. If logo isolation is negative, run the controlled Page 1 reduction defined in Section 2.2 until one minimal cause is verified.
5. Record whether the glyph issue exists in the PDF data across viewers or only under a viewer enhancement setting.

### Phase 2: Print-Safe Asset Wiring

1. Add one approved dedicated quotation logo asset under `public/` only if the isolation result implicates the current logo.
2. Update `BookingFlow.tsx`, `BookingsContent.tsx`, and `src/app/api/quotations/download/route.ts` to use the same print-safe asset.
3. Preserve the current snapshot source sanitization and fallback artwork.
4. Add asset-level tests that reject pattern, use, embedded SVG image, and matrix-transform constructs in the print logo and fallback asset.

### Phase 3: Canonical Rendering Repair

1. Refactor the shared HTML shell so canonical rendering passes an explicit document context containing fixture count and project-header specification visibility.
2. Do not map canonical items into legacy pricing types merely to make `isMulti` true.
3. Give the project-level specifications block a distinct semantic class so tests can distinguish it from fixture-card specifications.
4. Preserve the existing canonical effective-price lookup and labor reconciliation logic.
5. Pass `selectedBooking.quotation.adminLaborCharge` explicitly when constructing the administrator quotation view model.
6. Confirm single-fixture and legacy rendering remain unchanged except for authorized styling repairs.

### Phase 4: Print Layout and Typography

1. Add compact-only card break avoidance, total-table break avoidance, and signature-block break avoidance.
2. Add non-breaking numeric selectors without preventing long labels from wrapping.
3. Replace global arbitrary wrapping with targeted long-string wrapping.
4. Use explicit regular font weight and the approved system stack in print CSS.
5. Add native print guidance near the preview controls. Do not claim the application disabled browser headers and footers.

### Phase 5: Tests and Verification

1. Extend `tests/unit/quotationPdfGenerator.test.ts` for `QAD-TC53`.
2. Preserve and extend `tests/unit/unifiedQuotationDocument.test.ts` and `tests/unit/adminLaborReconciliation.test.ts` coverage.
3. Update `quotationPreviewWindow` tests only if the implementation changes its public port or guidance lifecycle.
4. Run the focused test command, full tests, lint, typecheck, and production build.
5. Complete the manual browser-saved PDF matrix. Automated HTML assertions alone cannot close the Page 1 PDF defect.

## 7. Quality Assurance Specification (QAD-TC53)

### 7.1 Automated Assertions

1. A two-fixture canonical document has no project-level specifications block.
2. Each canonical fixture appears exactly once with its own product name, dimensions, quantity, and effective final item price.
3. A single-fixture canonical document retains the project-level specifications block.
4. Compact canonical item cards, total tables, and signature blocks contain the authorized fragmentation rules.
5. Legacy or explicitly oversized content remains fragmentable.
6. Currency selectors contain both non-breaking and tabular-numeral rules.
7. Long email and URL values receive targeted wrapping without global `overflow-wrap: anywhere`.
8. The print logo and snapshot fallback satisfy the asset contract.
9. Existing terms, consumer notice, waiver, signature, effective product subtotal, labor, and grand-total tests remain green.
10. No generated document exposes internal component costs, rates, margin, original price, or negotiation notes.
11. A saved item-price override plus a saved labor fee appears in the next administrator preview and reconciles exactly to the displayed grand total.

### 7.2 Manual Browser-Saved PDF Matrix

| Environment | Required cases | Pass criteria |
|---|---|---|
| Firefox on macOS | Single fixture and two fixtures | Every page retains text and foreground graphics; compact fixture cards and prices stay together; no mid-number wrap |
| Chromium on macOS | Single fixture, two fixtures, long customer data | Same content and price totals as preview; no Page 1 loss; no horizontal overflow |
| Chromium on Windows | Two fixtures and structural waiver | Cards, waiver, signatures, and totals remain readable and correctly paginated |
| Safari on macOS | Single fixture, missing snapshot, and long text | Fallback artwork, typography, signatures, and totals render without overlap |
| macOS Preview and one browser PDF viewer | The same exported file | Text remains present and glyph weight is acceptably consistent; any viewer-only enhancement artifact is documented |

For each desktop browser, run one export with native headers and footers disabled. Also run one diagnostic export with them enabled to confirm that any URL is browser chrome rather than quotation HTML.

### 7.3 Required Commands During Implementation


The CV health check remains part of the repository release protocol, but IMP-MS38 does not authorize or require a CV service change.

## 8. Definition of Done

IMP-MS38 is complete only when all of the following are true:

1. The fixed reproduction no longer loses Page 1 text or foreground graphics in the affected environment.
2. Customer, administrator, and download-route surfaces use equivalent canonical document content.
3. Multi-fixture project headers do not leak Fixture 1 specifications.
4. Compact fixture cards do not orphan their price while oversized legacy content remains readable.
5. Currency values do not wrap within the number.
6. Pricing, labor reconciliation, terms, signatures, waivers, and customer-safe disclosure remain correct.
7. Automated tests and all required repository verification commands pass.
8. The manual browser-saved PDF matrix is completed with recorded evidence.
9. Native browser header limitations are described accurately in the UI and release notes.
10. No application implementation begins until this specification is approved.
