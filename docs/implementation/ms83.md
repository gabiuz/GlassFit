## 1. Required Outcome

The customer's fit selection uses the **outer left and right sides of the assembled host frame** as the product's horizontal width reference. The optional projecting sill is visible when enabled, but its horizontal extent must not determine the fitted frame's width or horizontal position. Turning **Include Window Sill** on or off after a fit leaves the frame's left and right edges aligned to the same selected opening. The selected corners and configured physical dimensions remain unchanged. Sill visibility and its expected price difference remain available. This milestone leaves the existing vertical fit behavior unchanged; it does not exclude the sill's height from that behavior.

The supplied screenshots show the same cyan fit quadrilateral with the sill enabled in the first image and disabled in the second. The visible frame is narrower with the sill enabled. These are user-provided observations, not measured geometry. The workspace labels this example **Heuristic Scale: Ballpark Preview**; this milestone targets visual fit consistency relative to the selected opening, not a new claim of physical measurement accuracy.

This is a plan only. It does not authorize a code change, data migration, or deployment.

## 2. Verified Starting Point and Diagnosis to Complete

| Current path | Evidence in code | Risk to investigate |
|---|---|---|
| Model assembly | `parametricProductBuilder.ts` conditionally includes the removable sill. Its natural-assembly host measurement already excludes sill components, and add-on mounting has a separate projecting-sill exclusion. | The fit renderer may use a broader set of meshes than the builder's installation reference. Cover legacy and natural-assembly paths. |
| Planar camera | `modelRenderer.ts` `render(..., isPlanarFit)` uses `computeFitFrameBounds(modelGroup) ?? computeHostProductBounds(modelGroup)` for camera center and projection. | `computeFitFrameBounds` accepts broad frame/category metadata and does not explicitly reject a removable sill. The host fallback also includes it. Confirm the actual scene graph and dimensions for the pictured product before changing the selector. |
| Fitted bitmap | With neutral yaw and pitch, `modelRenderer.ts` calls `getVisibleAlphaBounds` and stretches the full visible image to the fitted canvas. | A wide sill can enlarge the horizontal visible-alpha bounds even after camera bounds are corrected. Cropping all visible pixels to the fit rectangle can still narrow the frame. Test the complete camera-to-bitmap-to-homography path without changing vertical normalization. |
| Workspace placement | `ProductModelWorkspace.tsx` warps the rendered canvas into `perspectiveCorners` and saves rendered layers for placed products. | Active display, saved layers, editing, and snapshots must share one fit reference. Existing corners must not be rewritten when the sill changes. |
| Existing tests | `tests/unit/customerAddonWorkspace.test.ts` checks add-on fit-bound invariance and visible-alpha behavior. | There is no equivalent sill-on/off invariant for camera framing and final fitted pixels. |

Before implementation, reproduce the pictured product with identical dimensions, corners, viewport, and yaw/pitch. Record the assembled host frame and sill world-space bounds, the selected fit bounds, camera center/projection, pre-crop alpha bounds, final frame pixel bounds, and the saved composite. This evidence determines which stages require correction.

## 3. Fit Reference Contract

1. Define a deterministic **host frame horizontal reference** from the actual outer frame or equivalent installation edges. Its world-space left and right bounds determine horizontal fitting independently of `includeSill` and other optional protrusions.
2. Exclude the removable/projecting sill, add-on attachments, and protruding handles or hardware when selecting these horizontal bounds. Keep permanent bottom rails or sill rails that are part of the installation frame. Identify parts from explicit component metadata and known bay roles where possible; do not exclude every key containing `sill`, since `OUTER_SILL` can be structural.
3. Use the host frame reference for projection width and horizontal center only. Preserve the existing vertical bounds, vertical camera center, and height normalization. The product's configured width and height remain the physical dimension inputs. No sill width may be substituted for the product width.
4. Preserve the entire visible sill when enabled. If it projects beyond the frame's left or right edge, keep that horizontal overhang visible through render padding or a compositing transform. Do not stretch the complete horizontal alpha bounds, including the sill, to the selected width. Keep the current vertical alpha treatment and top/bottom fit behavior. If the current single-canvas layout cannot show horizontal overhang without clipping, plan the minimal renderer and workspace coordinate change needed to anchor only the frame's horizontal span to the selected opening.
5. Where no reliable host frame width can be found, use an explicit, deterministic width reference from the structural definition or fixed-model metadata. If neither exists, surface an actionable diagnostic and preserve the current placement instead of silently switching between sill-inclusive and sill-exclusive widths. Verify the fallback on products without removable sills.
6. A sill toggle may alter geometry, pixels, and BOM price. It must not alter fit corners, product dimensions, overlay position, the frame's horizontal span or horizontal center on the photo, or calibrated measurement evidence. This milestone does not require the rendered frame's vertical span or vertical center to remain invariant across the toggle. Existing add-on fit invariance must remain intact.

## 7. Scope Boundary

This milestone changes only the horizontal visual reference used to fit a product into a user-selected opening. The vertical fit calculation and treatment of sill height retain their existing behavior. The sill option, manufactured geometry, quotation formulas, calibrated photo measurement, customer-selected corners, and product configuration schema remain outside this change. A heuristic room photo does not yield verified physical dimensions.
