## 1. Problem Context & Motivation

GlassFit uses YOLOv8s-seg object masks to place detected furniture and other foreground objects in front of an active product model. MS-01 extended this behavior to architectural protrusions that are not part of the COCO-80 class set, including wall columns, piers, partitions, soffits, and beams.

MS-01 selected freehand brush painting as the manual input method. In practical use, brush painting requires the user to trace long, straight architectural edges with high precision. Small pointer movements, finger occlusion on touch screens, and mismatched brush sizes can create gaps or overpainted areas. These inaccuracies are especially visible where a product frame meets the edge of a column.

**Critical distinction:** The target remains the protruding foreground structure, not the full wall surface. The back wall where the product is installed must remain unmasked. Only image regions that physically stand in front of the product require manual occlusion.

**Approach selected:** Interactive point-based polygon masking. The user clicks or taps around the visible boundary of a foreground structure, adjusts draggable point handles, and explicitly finishes the region. The user may add multiple independent polygons for separate columns, beams, or other protrusions. The application rasterizes the completed polygons into the same white-on-transparent PNG mask used by the existing live rendering and snapshot compositor.

This approach:
- Produces straight, stable boundaries between selected points.
- Supports multiple separate and irregular foreground regions.
- Allows point handles to be repositioned without repainting the full mask.
- Stores normalized geometry so regions remain editable after responsive resizing.
- Reuses the point placement and drag interaction established by MS-02.
- Preserves the existing raster-mask rendering and snapshot compositing pipeline.
- Requires no computer vision retraining, backend service, database migration, or new dependency.

**Supersession statement:** MS-03 supersedes the brush, eraser, brush-size, and painted-mask editing interface specified by MS-01. MS-01 remains authoritative for the purpose of manual architectural occlusion and its foreground compositing order. Existing raster masks created under MS-01 remain supported as legacy configuration data.

## 4. Technical Specification

### 4.1 Type Additions

**File:** `src/lib/visualization/types.ts`

Add explicit normalized polygon types and extend `ProductConfigurationSnapshot`:

```typescript
export type ManualOcclusionPolygon = Point2D[];

export type ManualOcclusionMaskResult = {
  polygons: ManualOcclusionPolygon[];
  maskDataUrl: string | null;
};

export type ProductConfigurationSnapshot = {
  // Existing configuration fields remain unchanged.
  activeOcclusionIds?: string[];
  manualOcclusionMaskDataUrl?: string | null;
  manualOcclusionPolygons?: ManualOcclusionPolygon[];
  perspectiveFitCorners?: QuadrilateralCorners | null;
};
```

Every point in `manualOcclusionPolygons` uses normalized image coordinates where `x` and `y` are within `0.0` and `1.0`. A polygon contains at least three points in boundary order. The closing edge from the final point to the first point is implicit and must not be duplicated in persisted data.

`manualOcclusionMaskDataUrl` remains the rendering artifact used by CSS masks and snapshot composition. `manualOcclusionPolygons` becomes the editable source geometry for masks created under MS-03.

### 4.2 Polygon Geometry Module

**File:** `src/lib/visualization/occlusionPolygon.ts` (NEW)

Implement pure TypeScript helpers with no external dependencies:

| Function | Purpose |
|---|---|
| `normalizeOcclusionPolygon(points, width, height)` | Converts canvas-space points into normalized coordinates clamped to the image boundary |
| `denormalizeOcclusionPolygon(points, width, height)` | Converts normalized points into pixel coordinates for the current viewport or export canvas |
| `getPolygonSignedArea(points)` | Computes polygon area using the shoelace formula |
| `hasSelfIntersections(points)` | Detects intersections between non-adjacent polygon edges |
| `validateOcclusionPolygon(points)` | Rejects incomplete, non-finite, duplicate-only, zero-area, or self-intersecting polygons |
| `rasterizeOcclusionPolygons(polygons, width, height)` | Produces a white-on-transparent PNG data URL containing the union of all valid regions |

Validation returns a discriminated result rather than throwing for normal user input:

```typescript
export type OcclusionPolygonValidation =
  | { valid: true }
  | {
      valid: false;
      reason: "too_few_points" | "non_finite" | "duplicate_points" | "zero_area" | "self_intersection";
    };
```

Points must be finite and clamped to image bounds during coordinate conversion. Completed polygons require at least three distinct points. Adjacent edges and the shared first and final vertices are excluded from self-intersection checks.

### 4.3 ManualOcclusionPointPicker Component

**File:** `src/features/visualization/components/ManualOcclusionPointPicker.tsx` (NEW)

Use the modal structure, responsive image viewport, SVG overlay, pointer interaction, and marker presentation established by `PerspectivePlanePicker.tsx`.

```typescript
interface ManualOcclusionPointPickerProps {
  backgroundImageUrl: string;
  canvasWidth: number;
  canvasHeight: number;
  initialPolygons?: ManualOcclusionPolygon[];
  legacyMaskDataUrl?: string | null;
  onSave: (result: ManualOcclusionMaskResult) => void;
  onCancel: () => void;
}
```

The component maintains:

```typescript
type ManualOcclusionEditorState = {
  completedPolygons: Point2D[][];
  activePoints: Point2D[];
  selectedPolygonIndex: number | null;
  activeDrag: { polygonIndex: number | "active"; pointIndex: number } | null;
  isReplacingLegacyMask: boolean;
};
```

Editor coordinates use source-image pixel space internally. Props and saved configuration use normalized coordinates. This matches the MS-02 persistence convention and prevents responsive layout changes from shifting saved boundaries.

### 4.4 Region Creation Workflow

1. Opening a new editor starts with an empty active region and displays the room photograph.
2. Each click or tap on unoccupied image space appends one point to the active region.
3. SVG lines connect active points in placement order. A temporary line connects the latest point to the current pointer position on pointer-capable devices.
4. After three valid points exist, the **Finish Region** action becomes available.
5. **Finish Region** validates the polygon. A valid polygon moves into `completedPolygons`; an invalid polygon remains active and displays its validation message.
6. After finishing a region, the user selects **Add Region** before placing another independent polygon.
7. **Apply Mask** is enabled only when at least one valid completed polygon exists and no unfinished active region contains points.
8. Applying normalizes the completed polygons, rasterizes their union at source-image dimensions, and calls `onSave` with both geometry and the PNG data URL.

The editor does not close a polygon by tapping its first point. Region completion is always explicit through **Finish Region**, preventing accidental closure on small touch targets.

### 4.5 Point and Region Editing

| Capability | Required Behavior |
|---|---|
| Drag point | Pointer down on a marker captures the pointer; movement clamps the point to image bounds; pointer up commits the position |
| Select region | Clicking a completed polygon fill or one of its handles marks that region as selected |
| Delete region | Removes only the selected completed polygon after it has been selected |
| Undo | Restores the previous editor state for point addition, point movement, region completion, region deletion, or clear |
| Clear all | Removes all point-created regions from the editor after recording an undo state |
| Cancel | Discards all editor changes and leaves the saved configuration unchanged |
| Escape | Performs the same behavior as Cancel |

All visible point handles remain draggable after a region is completed. The selected polygon uses a stronger fill and stroke treatment than unselected polygons. Point numbers restart at 1 for each region and are visual guidance only.

### 4.6 Polygon Preview Rendering

The interactive layer is SVG aligned to the displayed room image:

- Point markers use teal `#07b6d3`, a 2px white stroke, and centered white numbering.
- Active edges use a solid teal stroke.
- Completed polygons use a translucent cyan fill and teal outline.
- Invalid active geometry uses the existing error color treatment and an inline guidance message.
- SVG uses the source image dimensions as its `viewBox` so pointer and geometry coordinates share one coordinate system.
- The image and SVG must use the same contain sizing and aspect ratio to prevent alignment drift.

### 4.7 Raster-Mask Generation

`rasterizeOcclusionPolygons` creates an offscreen canvas at the source image dimensions. For every completed polygon:

1. Denormalize its points to output pixel coordinates.
2. Begin a new path at the first point.
3. Add straight line segments through the remaining points.
4. Close the path.
5. Fill with `rgba(255, 255, 255, 1)` using `source-over` composition.

The canvas remains transparent outside selected regions. Multiple polygons are drawn into the same canvas, producing their union. Overlapping polygons remain fully opaque without increasing alpha beyond 255. The result is exported with `canvas.toDataURL("image/png")`.

The generated mask must remain compatible with:

```typescript
drawMaskedBackgroundLayer({
  outputWidth,
  outputHeight,
  context,
  backgroundImage,
  maskUrl: manualOcclusionMaskDataUrl,
});
```

### 4.8 ProductModelWorkspace Integration

Replace brush-specific component state with point-editor state while preserving the existing mask data URL:

```typescript
const [manualOcclusionPolygons, setManualOcclusionPolygons] = useState<
  ManualOcclusionPolygon[]
>(initialConfiguration?.manualOcclusionPolygons ?? []);

const [manualMaskDataUrl, setManualMaskDataUrl] = useState<string | null>(
  initialConfiguration?.manualOcclusionMaskDataUrl ?? null,
);

const [showOcclusionPointPicker, setShowOcclusionPointPicker] = useState(false);
```

The current configuration includes both fields:

```typescript
manualOcclusionMaskDataUrl: manualMaskDataUrl,
manualOcclusionPolygons,
```

On save:

```typescript
onSave={({ polygons, maskDataUrl }) => {
  setManualOcclusionPolygons(polygons);
  setManualMaskDataUrl(maskDataUrl);
  setShowOcclusionPointPicker(false);
}}
```

The Object Aware Occlusion accordion replaces paint terminology with point-selection terminology:

- Section label remains **Manual Occlusion Mask**.
- Helper text becomes: "Outline protruding columns, piers, or beams that should appear in front of the product."
- Empty-state action becomes **Select Occlusion Areas**.
- Existing point geometry action becomes **Edit Occlusion Areas**.
- Raster-only legacy action becomes **Replace Legacy Mask**.
- Existing **Remove Mask** behavior clears both `manualOcclusionMaskDataUrl` and `manualOcclusionPolygons`.

### 4.9 Legacy Raster-Mask Compatibility

A legacy configuration is identified when `manualOcclusionMaskDataUrl` is present and `manualOcclusionPolygons` is empty or absent.

Legacy behavior:

1. The existing raster mask continues to render in the live workspace.
2. The existing raster mask continues to participate in snapshot export.
3. Opening the editor shows the legacy mask as a read-only tinted preview with guidance that its original brush geometry cannot be converted into editable points.
4. **Replace Legacy Mask** starts a new empty point selection without mutating saved state.
5. Applying at least one completed polygon replaces the legacy PNG and stores new normalized geometry.
6. Canceling replacement leaves the legacy PNG unchanged.
7. Removing the mask clears the legacy PNG and any point geometry together.

The implementation must not attempt automatic raster-to-vector tracing because that would introduce nondeterministic geometry and unnecessary complexity.

### 4.10 Existing Picker Isolation

`PerspectivePlanePicker.tsx` remains behaviorally unchanged. MS-03 reuses its interaction conventions and visual patterns, but does not generalize or modify its fixed four-corner perspective contract. This avoids regression risk in MS-02 perspective fitting.

## 5. Compositing Pipeline (Preserved)

MS-03 changes how a manual mask is authored and edited. It does not change how the final raster mask is layered.

| Layer Order | Source | Compositing Strategy |
|---|---|---|
| 1 | Background room photograph | Drawn as the base image using object-contain alignment |
| 2 | Placed product overlays | Drawn from cached flattened product layers |
| 3 | Active product overlay | Drawn using free placement or MS-02 perspective fitting |
| 4 | Auto-detected YOLO occlusion masks | Background pixels are clipped through each active object mask |
| 5 | Manual polygon-derived occlusion mask | Background pixels are clipped through `manualOcclusionMaskDataUrl` |
| 6 | Interactive 3D controls in the live DOM only | Rendered above occlusion and excluded from snapshot output |

### 5.1 Live DOM Rendering

The polygon-derived PNG uses the existing CSS mask layer:

```tsx
{selectedProduct && manualMaskDataUrl && (
  <img
    src={bgImage}
    alt=""
    aria-hidden="true"
    style={{
      WebkitMaskImage: `url(${manualMaskDataUrl})`,
      maskImage: `url(${manualMaskDataUrl})`,
      WebkitMaskPosition: "center",
      maskPosition: "center",
      WebkitMaskRepeat: "no-repeat",
      maskRepeat: "no-repeat",
      WebkitMaskSize: "100% 100%",
      maskSize: "100% 100%",
    }}
  />
)}
```

The manual mask remains inside the `foreground-occlusion` layer. Product controls remain inside the higher `product-controls` layer so polygon-derived foreground pixels never cover the toolbar or transform handles.

### 5.2 Snapshot Export

`captureWorkspaceSnapshot` continues passing `manualMaskDataUrl` to `drawMaskedBackgroundLayer` after all product layers and automatic object masks have been drawn. Polygon points are configuration metadata and are not drawn directly into the exported snapshot.

### 5.3 Alignment Contract

Point editing, raster generation, live CSS masking, and snapshot masking must all use the same source image aspect ratio and object-contain convention. Responsive viewport dimensions may change, but normalized polygon coordinates and source-ratio rasterization must produce the same selected image regions.

- Toolbar icon buttons include visible text or an `aria-label` and title.

## 7. Definition of Done (Exit Criteria)

1. `ManualOcclusionPointPicker.tsx` replaces the brush-based manual-mask editor.
2. Users can create multiple independent polygon regions with three or more points per region.
3. **Finish Region** explicitly closes and validates the active polygon.
4. Completed polygon point handles remain draggable for precise adjustment.
5. Users can select and delete one region without removing other regions.
6. Undo restores the previous state for point placement, dragging, completion, deletion, and clear actions.
7. Invalid, zero-area, and self-intersecting polygons cannot be applied.
8. **Apply Mask** is unavailable while an unfinished region contains points.
9. Polygon coordinates persist as normalized values in `manualOcclusionPolygons`.
10. Reopening a point-created mask restores all regions and draggable handles.
11. Rasterization produces a white-on-transparent PNG compatible with the existing CSS and Canvas 2D mask paths.
12. Multiple polygons produce a single union mask without gaps introduced by brush movement.
13. Live workspace occlusion renders polygon-selected architectural regions above the product model.
14. The product toolbar, rotation handles, resize handles, and movement handle remain above all occlusion layers.
15. "Apply Changes" snapshot export includes the polygon-derived manual mask.
16. Existing raster-only MS-01 masks continue rendering and exporting without data loss.
17. Replacing a legacy mask stores new point geometry and a newly generated PNG.
18. Canceling the editor does not mutate the current saved mask or polygon geometry.
19. Removing a manual mask clears both geometry and raster fields.
20. MS-02 perspective-fitted products remain compatible with manual polygon occlusion.
21. No Supabase migration, FastAPI change, or new dependency is introduced.
22. Unit tests cover polygon validation, coordinate conversion, multiple regions, persistence, legacy compatibility, and layer order.
23. `npm run lint` reports zero new errors in changed files.
24. `npx tsc --noEmit` passes with zero type errors.
25. `npm test` passes, including QAD-TC8 regression coverage.
26. `npm run build` succeeds.
27. `GET http://localhost:8000/health` continues returning `{"status":"ok"}` when the CV service is running.
28. No em-dashes appear in code comments or documentation (BAN-PUNCT-01).
29. No `any` types appear in new TypeScript code (BAN-TYPE-05).
30. No foreign UI library or ad-hoc design system is introduced (BAN-UI-09).

## 8. Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| User places points in an order that crosses polygon edges | Medium | Medium | Show the connecting outline immediately, detect self-intersections, and keep **Finish Region** disabled with corrective guidance |
| User leaves a narrow gap between the polygon and the visible structure edge | Medium | Medium | Keep all completed point handles draggable and show a translucent fill over the exact selected region |
| Small point handles are difficult to drag on mobile | Medium | Medium | Use enlarged transparent touch targets while preserving the established visible marker size |
| User accidentally starts a second region before completing the first | Medium | Low | Require **Finish Region** before **Add Region** becomes available |
| Multiple regions make selection ambiguous | Low | Medium | Highlight the selected polygon and scope delete actions to the selected region only |
| Polygon geometry shifts after responsive resizing | Low | High | Persist normalized coordinates and use a shared source-image coordinate system for SVG and raster output |
| Legacy brush masks cannot recover editable source points | High | Low | Continue rendering legacy PNGs, identify them clearly, and provide an explicit replacement workflow without automatic tracing |
| Raster output and live preview use different image alignment | Low | High | Enforce one source aspect ratio and object-contain alignment contract across editor, CSS mask, and snapshot compositor |
| Large point collections increase interaction complexity | Low | Low | Encourage concise boundary selection through guidance and allow per-region editing instead of requiring dense tracing |
| Refactoring the fixed four-point perspective picker introduces regressions | Low | High | Keep `PerspectivePlanePicker.tsx` isolated and reuse its conventions without changing its contract |
