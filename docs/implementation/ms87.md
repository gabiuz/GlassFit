## 1. Outcome and Problem Context

In Philippine residential and commercial fenestration, architectural operating mechanisms (such as jalousie window rotary operators, awning window cam latches, casement window push handles or espagnolettes, and sliding sash flush pulls) are installed exclusively on the **interior room side** of the window fixture. Building occupants operate these mechanisms from inside the room.

When an add-on attachment (such as an insect screen or a security grille) is mounted on the **interior face** (`back` / interior), it forms a physical barrier situated between the room occupant and the window operating hardware:
1. **Insect Screens on Interior:** Because insect mesh blocks physical hand reach, an operable wicket access hatch (door) aligned with each operating mechanism is necessary for the occupant to open or close the window sashes.
2. **Security Grilles on Interior:** Because rigid aluminum bars block hand entry, a framed rectangular clearance opening aligned with each handle is necessary for the occupant's wrist to reach through and operate the window.

Conversely, when an add-on attachment is mounted on the **exterior face** (`front` / exterior):
1. **Direct Interior Hardware Accessibility:** The room occupant is already on the interior side with unhindered, direct access to all cranks, cam latches, and handles. The screen or grille is positioned outside the glass plane.
2. **Physical Impossibility and Security Breach on Exterior:**
   - Placing an access hatch on an exterior insect screen is functionally useless for room occupants and introduces unnecessary perimeter sealing gaps where mosquitoes can enter.
   - Placing a handle clearance opening on an exterior security grille is dangerous: it creates an empty hole on the outside face of the building, providing external intruders with reach-in leverage or direct access to defeat window latching mechanisms, completely compromising physical security.
   - Interior operating hardware does not project outward toward the exterior. Aligning exterior openings or hatches to interior handle coordinates is physically contradictory.

### Current Architectural Defect in Repository
In the current GlassFit implementation (introduced across `IMP-MS80` and extended in `IMP-MS86`):
1. **Admin Setup Wizard (`AddonInheritanceSection.tsx`):** The "Operator Hatch Alignment Targets" checklist and the security grille opening target dock remain fully visible and configurable even when the administrator selects "Front (Exterior) Only" mounting.
2. **Customer Workspace (`ProductModelWorkspace.tsx`):** When a customer switches the add-on mounting side toggle from "Interior (Back)" to "Exterior (Front)", the state variable `effectiveHatchTargetKeys` continues to supply target keys, `effectiveHatchCount` remains greater than zero, and the customer badge continues to proclaim `"with 2x Operator Access Hatches"` on an exterior-mounted screen.
3. **3D Visualization Assembly (`parametricProductBuilder.ts`):** `buildScreenAssembly` and `buildGrillAssembly` inspect `options.hatchTargetComponentKeys` without checking the resolved `addonMountingSide`. Consequently, Three.js instantiates access hatches or clips grille bars on the exterior front mesh, rendering nonsensical exterior openings.
4. **Parametric BOM & Quotation (`pricingEngine.ts`, `addonPricingEngine.ts`, `ProductSummary.tsx`, `quotationPdfGenerator.ts`):** The pricing engine charges customers for screen hatch hardware (₱180.00 per hatch set) and grille opening framing extrusions regardless of whether the attachment is mounted on the front exterior or back interior. The quotation summary and consultation PDF print contradictory specifications such as `"Insect Screen (Front / Exterior, with 2x Operator Access Hatches)"`.

### Required Engineering Outcome
1. **Strict Interior-Only Alignment Target Availability:** Operator alignment targets (both screen access hatches and grille handle openings) must be strictly restricted to interior mounting (`back`).
2. **Total Exterior Suppression:** When an add-on is mounted on the exterior (`front`), all alignment targets, access hatches, clearance cutouts, and associated hardware costs must be completely suppressed across the admin wizard, 3D viewport, BOM engine, customer workspace, quotation summary, and consultation PDF exports.
3. **Transparent Configuration Feedback:** When an administrator or customer configures an exterior mounting side, the interface must provide clear, professional contextual guidance explaining that alignment targets apply solely to interior attachments.

## 3. Technical Contract and Architectural Design

### 3.1 Domain Invariant Matrix

The fundamental physical invariant governing add-on alignment targets is formalized as follows:

| Add-on Type | Configured Placement Side | Operator Targets Available? | 3D Geometry Generated | Parametric BOM Billing | Customer / PDF Disclosure |
|---|---|---|---|---|---|
| Insect Screen | Interior (`back`) | YES (if host has operators) | Hinged / sliding wicket hatches at target centroids | ₱180.00 per hatch hardware added to BOM | `"Insect Screen (Interior, with Nx Operator Access Hatches)"` |
| Insect Screen | Exterior (`front`) | NO (strictly suppressed) | Continuous uniform insect mesh plane; zero hatches | ₱0.00 hatch hardware; standard screen framing only | `"Insect Screen (Exterior)"` |
| Security Grille | Interior (`back`) | YES (if host has operators) | Framed rectangular clearance collars with empty interiors | Collar extrusions ($2W + 2H$) and corner cleats billed | `"Security Grille (Interior, with Nx Handle Clearance Openings)"` |
| Security Grille | Exterior (`front`) | NO (strictly suppressed) | Continuous pickets spanning sill to head; zero cutouts | Standard picket linear meters only; zero collar cuts | `"Security Grille (Exterior)"` |

### 3.2 Admin Setup Wizard Interior Guardrail Contract (`AddonInheritanceSection.tsx`)

In Step 4 (Compatible Add-ons) of the Admin Product Setup Wizard:

#### 3.2.1 Screen Add-on Configuration
1. **Front (Exterior) Only Mode:**
   - When the administrator selects `screenAllowedSides === "front"`, the Operator Hatch Alignment Targets dock is suppressed from interactive selection.
   - In its place, render a clean informative advisory card using existing design tokens:
     - Icon: `Info` or `ShieldAlert` (amber/teal styled)
     - Title: "Alignment Targets Unavailable for Exterior Placement"
     - Body: "Window operating mechanisms (jalousie operators, cam handles) are located on the room interior. Because an exterior screen is mounted outside the glass plane, room occupants reach handles directly without obstruction. Operator access hatches are not applicable to exterior attachments."
   - If previous target keys existed in state, they are retained in memory or cleared upon save, but disabled from activation.
2. **Back (Interior) Only Mode:**
   - The Operator Hatch Alignment Targets dock is fully active.
   - Header badge indicates: "Active (Interior Attachment)".
3. **Both Sides Mode:**
   - The dock is active, allowing administrators to configure alignment targets for when the customer chooses interior placement.
   - An explicit contextual note is appended:
     - "Notice: These alignment targets will apply exclusively when this screen is mounted on the Interior (Back). If a customer selects Exterior (Front) mounting during quotation, access hatches will be automatically suppressed."

#### 3.2.2 Security Grille Add-on Configuration
The same contract applies symmetrically to Security Grilles:
1. When `grillAllowedSides === "front"`, handle opening alignment controls are suppressed with the advisory:
   - "Handle clearance openings are only available for Interior (Back) mounting. Exterior security grilles require unbroken bar barriers for structural security and do not support operator clearance cutouts."
2. When `grillAllowedSides === "both"`, the interface notes that clearance openings generate only when interior mounting is chosen.

### 3.6 Parametric BOM and Pricing Engine Contract (`pricingEngine.ts` & `addonPricingEngine.ts`)

#### 3.6.1 Add-on Pricing Engine (`addonPricingEngine.ts`)
```typescript
export function calculateAddonPricing(input: AddonPricingInput): AddonPricingResult {
  const isInterior = input.mountingSide === "back";
  const effectiveHatchCount = isInterior ? (input.hatchCount ?? 0) : 0;
  
  let hardwareSubtotal = 0;
  const hardwareItems: BreakdownItem[] = [];

  // Hatch hardware is strictly billed for interior mounting
  if (effectiveHatchCount > 0) {
    const hatchHardwareUnitPrice = 180.0;
    const hatchHardwareSubtotal = effectiveHatchCount * hatchHardwareUnitPrice;
    hardwareSubtotal += hatchHardwareSubtotal;
    hardwareItems.push({
      item: `Screen Access Hatch Hardware (${effectiveHatchCount}x operator ${effectiveHatchCount === 1 ? "hatch" : "hatches"})`,
      quantity: effectiveHatchCount,
      unit: "set",
      unitPrice: hatchHardwareUnitPrice,
      subtotal: hatchHardwareSubtotal,
    });
  }
  // ...
}
```

## 4. Database Schema and Persistence Architecture

The relational schema established in migrations `024_addon_mounting_side_and_hatch_alignment.sql` and `026_addon_mounting_side_and_hatch_alignment.sql` already provides the necessary columns on `product_compatible_addons`:

- `hatch_target_component_keys text[] DEFAULT NULL`
- `hatch_alignment_config jsonb DEFAULT NULL`
- `grille_opening_target_component_keys text[] DEFAULT NULL`
- `grille_opening_config jsonb DEFAULT NULL`

- If `allowedSides === "front"`, enforce that `hatch_target_component_keys` and `grille_opening_target_component_keys` are sanitized to `null` or empty array before database write, preventing orphaned target associations on exterior-only add-ons.

1. **In Scope:**

   - Altering OpenCV fiducial paper detection microservice or space image processing.
