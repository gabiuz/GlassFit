## 1. Problem and Intended Outcome

Following the implementation of [IMP-MS89](ms89.md) (Context-Aware Visualization Onboarding and First Placement Guidance), first-time customers arriving on the Comparison page and administrators adopting the back-office portal still encounter high-density workflows with non-obvious controls. At the same time, blanket automatic blocking tours on low-complexity or high-frequency screens create modal fatigue and risk interrupting customer booking conversion (`BRD-M3`).

This milestone extends the MS89 guidance architecture using a differentiated, surface-appropriate onboarding model:
1. **Client Comparison (`/comparison`):** Retain a short automatic first-use spotlight tour covering comparison/view mode switching, dual-panel aluminum finish selection (including mutual exclusion and multi-product overlay selection), and proceeding to price estimation.
2. **Client Conversion & Browsing Routes (`/quotation`, `/send-booking`, `/product`, `/product-details/[id]`, `/my-requests`, `/profile`):** Keep completely free of popup tours; preserve existing inline copy and stepper UI.
3. **Admin Product Setup Wizard (`/admin/products/[productId]/setup`):** Provide automatic phase-contextual guidance driven by semantic `StepKey`, product role (`standard`, `addon`, `accessory`), active sub-tab, and mounted controls, paired with a persistent `Help` trigger across all wizard phases.
4. **Admin Consultation Bookings (`/admin/bookings`):** Provide a short automatic orientation to queue search and status filtering, followed by inspector guidance that adapts to the selected quotation's actual capabilities (`supportsItemNegotiation` per-item overrides vs. legacy whole-total negotiation, installation labor fee, external window PDF preview, and status save vs. hard-delete discard).
5. **Admin Raw Materials (`/admin/materials`) and Products Catalog (`/admin/products`):** Provide concise automatic first-use onboarding focused on creation entry points, bulk/individual material entry, and the downstream consequences of pricing, status, and deletion actions.
6. **Admin Dashboard (`/admin`):** Present a non-blocking welcome cue (or optional `Help`-initiated tour) aligned with the actual rendered KPI cards and shortcuts rather than an automatic blocking backdrop.
7. **Admin Staff (`/admin/staff`) and Settings (`/admin/settings`):** Provide optional, role-aware contextual `Help` (triggered explicitly by the administrator) rather than automatic page-wide tours.

All guidance is presentation-only. Tour progression, skipping, or replay never mutates domain records, triggers server actions, or alters quotation pricing. Reuse the repository's existing `OnboardingTourPopup` primitive (`bg-black/60 backdrop-blur-xs` spotlight cutout, `rounded-[20px]` desktop popover, and compact `max-h-[45dvh]` mobile bottom-sheet card with `min-h-11` touch targets). No new third-party dependency, database migration, or FastAPI change is required.

## 3. Preference, Account Isolation, and Lifecycle Contract

### 3.1 Preservation of Existing MS89 Storage Contracts

Preserve the existing MS89 constants and schemas in `src/features/visualization/onboarding/storage.ts` without modification:
- `GUIDE_PREFERENCE_STORAGE_KEY = "glassfit.onboarding.preference.v1"` storing `GuidePreferenceRecord` (`{ version: 1, status: "unseen" | "completed" | "dont_show_again" }`).
- `GUIDE_PROGRESS_STORAGE_KEY = "glassfit.onboarding.progress.v1"` storing `GuideSessionProgressRecord`.

Completing, skipping, or opting out of the MS89 visualization workspace tour never suppresses the Comparison tour or any Admin surface guide, and vice versa.

### 3.2 Scoped Storage Keys and Account-Scoped Admin State

Keep all onboarding persistence browser-local (`localStorage` for durable preferences, `sessionStorage` for per-session skip/progress state, and an in-memory map fallback when storage is unavailable). No database table or migration is introduced.

#### Client Comparison Preference Key
- **Durable key (`localStorage`):** `glassfit.onboarding.comparison.preference.v1`
- **Schema:** `{ version: 1, status: "unseen" | "completed" | "dont_show_again" }`
- **Session skip key (`sessionStorage`):** `glassfit.onboarding.comparison.session.v1` storing `{ version: 1, runSkipped: boolean }`

#### Account-Scoped Admin Preference and Wizard Phase Storage
On shared workshop or office browsers, multiple administrators (`Owner`, `Manager`, `Staff`) may sign in at different times. Scope all admin onboarding records to the authenticated administrator's `profileId` from `useAdminSession().profileId` (`AdminContext.profileId`, which matches `auth.uid()`):

- **Durable key (`localStorage`):** `glassfit.onboarding.admin.preference.v1.<profileId>`
- **Session key (`sessionStorage`):** `glassfit.onboarding.admin.session.v1.<profileId>`

```ts
export type AdminOnboardingSurfaceId =
  | "dashboard"
  | "bookings"
  | "products"
  | "product_setup"
  | "materials"
  | "staff"
  | "settings";

export type WizardPhaseGuideId =
  | "basic"
  | "strategy"
  | "assets"
  | "components_intake"
  | "components_inspector"
  | "parameters_dimensions"
  | "parameters_rules"
  | "parameters_addons"
  | "validation_sandbox"
  | "validation_materials"
  | "review";

export type BookingsSubGuideId =
  | "queue_orientation"
  | "inspector_negotiation";

export interface AdminOnboardingPreferenceRecord {
  version: 1;
  profileId: string;
  /** Surface-level status: controls automatic entry tours and surface-wide dont_show_again opt-out. */
  surfaces: Partial<Record<AdminOnboardingSurfaceId, GuidePreferenceStatus>>;
  /** Granular completion for Product Setup Wizard phases so completing one phase does not silence later phases. */
  wizardPhases: Partial<Record<WizardPhaseGuideId, "unseen" | "completed">>;
  /** Granular completion for Bookings orientation vs. selected-quotation inspector guidance. */
  bookingsPhases: Partial<Record<BookingsSubGuideId, "unseen" | "completed">>;
}

export interface AdminOnboardingSessionRecord {
  version: 1;
  profileId: string;
  skippedSurfaces: Partial<Record<AdminOnboardingSurfaceId, boolean>>;
  skippedWizardPhases: Partial<Record<WizardPhaseGuideId, boolean>>;
  skippedBookingsPhases: Partial<Record<BookingsSubGuideId, boolean>>;
}
```

### 3.3 Separation of Wizard Phase Completion vs. Surface-Wide Opt-Out

1. **Surface-Wide Opt-Out (`surfaces.product_setup === "dont_show_again"`):**
   - Clicking **Don't show again** during any Product Setup Wizard phase sets `surfaces.product_setup = "dont_show_again"` for that `<profileId>`. This suppresses automatic popup tours across **all** wizard phases (`basic`, `components_intake`, `components_inspector`, `parameters_*`, `validation_*`, `review`), while keeping the header `Help` button available on every step.
2. **Per-Phase Completion (`wizardPhases[phaseId] === "completed"`):**
   - Clicking **Got it** at the end of a wizard phase tour marks only `wizardPhases[phaseId] = "completed"`. When the administrator advances to a subsequent phase whose status is still `"unseen"` (for example, moving from `components_inspector` to `parameters_dimensions` or `validation_sandbox`), that new phase's contextual tour still opens automatically (provided `surfaces.product_setup !== "dont_show_again"`).
   - `surfaces.product_setup` transitions from `"unseen"` to `"completed"` only when all automatic phases applicable to the current product role have been completed, or when the administrator completes the final `validation_sandbox` automatic tour.
3. **Bookings Two-Stage Progression (`bookingsPhases`):**
   - On `/admin/bookings`, `bookingsPhases.queue_orientation` tracks the 2-step queue/filter orientation, and `bookingsPhases.inspector_negotiation` tracks the 2-step selected-booking inspector guide. If an admin first opens `/admin/bookings` when the queue is empty (`!selectedBooking`), completing the queue orientation marks only `queue_orientation = "completed"`, so `inspector_negotiation` still runs automatically the first time they view a populated booking (unless `surfaces.bookings === "dont_show_again"`).

### 3.4 Lifecycle Rules: Skip, Route Changes, Refresh, Manual Replay, Opt-Out Precedence, and Storage Resilience

| Lifecycle Aspect | Normative Contract |
|---|---|
| **Automatic Display Eligibility** | Automatic tours run only on surfaces designated for automatic onboarding (`/comparison`, `/admin/products/[productId]/setup` automatic phases, `/admin/bookings`, `/admin/materials`, `/admin/products`) when the surface status is `"unseen"` (not `"completed"` and not `"dont_show_again"`), the specific phase (if phased) is `"unseen"`, and the surface/phase is not marked `skipped` in the current session record. |
| **Skip Duration** | Clicking **Skip** (or pressing `Escape` while a tour popup is open) records `runSkipped = true` for the active surface (or active `WizardPhaseGuideId` / `BookingsSubGuideId`) in `sessionStorage` and in-memory state. It hides the tour for the remainder of the current browser tab session across client-side route changes and page refreshes, without writing `"dont_show_again"` or `"completed"` to `localStorage`. In the Setup Wizard, skipping `components_inspector` suppresses only `components_inspector` for the current session; advancing to `parameters_dimensions` or `validation_sandbox` still shows those unseen phase guides. |
| **Route Changes & Refresh** | Navigating away from a surface pauses/unmounts its tour popup immediately without marking it completed or skipped. Refreshing the page or returning via client navigation re-evaluates eligibility after hydration using persisted `localStorage` and `sessionStorage` state. |
| **Manual Replay (`Help`)** | Clicking the header **Help** button starts a manual run (`isManualRun = true`) from Step 1 of the current surface (or the active `WizardPhaseGuideId` matching the current `StepKey`, sub-tab, and mounted state). Manual replay works regardless of whether the stored status is `"unseen"`, `"completed"`, or `"dont_show_again"`, and clears `runSkipped` for that active run. |
| **Opt-Out Precedence** | `"dont_show_again"` has strict precedence over `"completed"` and `"unseen"`. If a surface's stored status is already `"dont_show_again"` and the user launches a manual replay via **Help** and clicks **Got it** at the end, the stored status **must remain `"dont_show_again"`** (never overwritten to `"completed"`). Clicking **Got it** writes `"completed"` only when the prior surface status was `"unseen"`. |
| **Malformed or Version-Incompatible Records** | If `localStorage.getItem` or `sessionStorage.getItem` returns unparseable JSON, a non-object, a record where `version !== 1`, a record where `profileId` does not match the active `AdminContext.profileId`, or unknown enum values, ignore the invalid fields safely and default missing entries to `"unseen"` without throwing or clearing unrelated keys. |
| **Unavailable Storage** | If `window.localStorage` or `window.sessionStorage` is unavailable or throws `SecurityError` / `QuotaExceededError`, read and write operations fall back to a module-scoped in-memory store keyed by storage key for the lifetime of the browser document. |

#### 4.2.2 Detailed Wizard Phase & Tab Contracts

##### Phase A: `StepKey === "basic"` (`WizardPhaseGuideId = "basic"`)
- **Trigger:** Automatic once when `isDraft === true` (creating a new product) and `wizardPhases.basic === "unseen"`; always available via `Help`.
- **Target (`admin-setup-basic-role`):** Product Role selector cards (`Standard Fixture`, `Add-on Accessory`, `Hardware Accessory`) and form fields in `BasicInfoSection.tsx`.
- **Guidance Copy:**
  - **Step 1 of 1 ("Select Product Role & Basic Details"):** "Choose **Standard Fixture** (7-step setup for windows, doors, cabinets, and enclosures), **Add-on Accessory** (5-step setup for insect screens and security grilles), or **Hardware Accessory** (4-step setup for handles, locks, hinges, and rollers). ### 5.4 Focus Ownership, `Escape` Behavior, Focus Restoration, and Spotlight Accessibility

1. **Focus Ownership & Spotlight Interaction:** When `OnboardingTourPopup` opens with `blocking={true}`, the 4-quadrant backdrop (`bg-black/60 backdrop-blur-xs`) leaves the `targetSelector` bounding box uncovered (`pointer-events: none` on the cutout region) so the user can either click/tab into the highlighted control directly or use the popup's `Next` / `Got it`, `Skip`, and `Don't show again` buttons.
2. **`Escape` Key Isolation:** Pressing `Escape` while `OnboardingTourPopup` is open invokes `onSkip()` and calls `event.stopPropagation()` so it dismisses only the tour popup and never closes an underlying inline editor or triggers a destructive cancel action. When a domain modal (`DiscardBookingModal`, `MaterialModal`, `DeleteProductModal`, etc.) is open, the tour popup is unmounted (`isOpen={false}`) so `Escape` is handled exclusively by the domain modal.
3. **Focus Restoration:** When the tour closes via `Got it`, `Skip`, or `Don't show again`, restore focus to the surface's header `Help` button (or the last active interactive target if still mounted and enabled) without scrolling the page unexpectedly.
4. **Missing Target Safety Invariant:** If `document.querySelector(targetSelector)` returns `null` (or a zero-size hidden element) after mount/layout measurement, `OnboardingTourPopup` must never render a full-screen pointer-blocking curtain that traps the page; it either falls back to a centered/bottom card with working `Next` / `Got it` / `Skip` buttons or the surface resolver skips/adapts that step automatically.
