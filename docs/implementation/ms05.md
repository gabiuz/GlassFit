## 1. Problem Context & Motivation

GlassFit has established a functional parametric pricing foundation in `src/lib/pricing/pricingEngine.ts`:
- Pure parametric Bill-of-Materials (BOM) calculation executes 1D linear extrusion formulas, 2D glazing area formulas, fixed hardware rates, 12% aluminum offcut scrap, 10% glass handling scrap, workshop fabrication labor floors (`max(PHP 750.00, 0.25 * Materials)`), and contractor gross margin (25%).
- Milestone 7 established single-product quotation summaries and HTML-based consultation PDF rendering in `src/lib/pricing/quotationPdfGenerator.ts`.

However, when users design realistic client spaces containing **multiple architectural products** (such as placing a 2-panel sliding window alongside an awning window, or combining a glass partition with modular cabinets), the pricing and quotation workflow exhibits three critical deficiencies:

1. **Workspace Price Ambiguity (Editing vs. Applied Scene Total):**
   - In `ProductModelWorkspace.tsx`, the Price Card currently computes and displays only the active product configuration (`realtimePricing`).
   - When a user finishes tweaking an active product and clicks **"Apply Changes"**, the scene contains multiple placed products (`placedOverlays`), but the Price Card continues to show only the single active product cost. The user has no immediate feedback on the total financial commitment of their combined room configuration.
   - **Target Behavior:** While editing is ON (`isEditingProduct = !isSnapshotApplied`), the Price Card displays the live, reactive price of the specific product currently being manipulated. Once the user clicks **"Apply Changes"** (`isSnapshotApplied = true`), the Price Card immediately updates to display the **sum of all products present on the canvas** (all placed overlays plus the confirmed active product). Returning to edit mode restores single-product pricing.

2. **Single-Product Quotation Limitation (Missing Multi-Product Itemization):**
   - On the `/quotation` page (`ProductSummary.tsx`), the view calculates only a single `createProductSummaryItem` from `structuralDefinition` and `productConfiguration`. Any products placed into `placedOverlays` are ignored.
   - SME fabricators require an itemized breakdown for each distinct fixture installed in the client room opening, followed by a consolidated total.
   - **Target Behavior:** The quotation view must generate a dedicated, independent quotation section for **each product present in the scene**. Each product card displays its own thumbnail snapshot, aperture dimensions, material finishes, sill toggle status, NSCP 2015 structural waiver badge (if applicable), unit rate, quantity, and itemized 4-group BOM breakdown (Framing, Glazing, Hardware, Labor). Following all individual product cards, the system renders a **Consolidated Grand Quotation Summary** displaying the combined BOM totals and overall project price.

3. **Single-Product PDF Document Bottleneck:**
   - In `src/lib/pricing/quotationPdfGenerator.ts`, `QuotationPdfMetadata` accepts only a single `bomResult: CalculatedBOMResult`.
   - In `BookingFlow.tsx`, the preview and save PDF actions pass only the active product parameters, omitting all other placed products in the session.
   - **Target Behavior:** The consultation PDF generator must accept an array of itemized product quotations (`items: QuotationProductItemPdf[]`) alongside the aggregated grand total. The resulting formal consultation PDF document renders each individual fixture in an itemized schedule, flags per-product structural waivers, and concludes with the consolidated bill-of-materials summary table, consumer protection disclaimers (RA 7394), and contractor signature blocks.

### 4.2 Workspace Pricing Dynamic (Requirement 1)

#### 4.2.1 Problem Analysis in Workspace
In `src/features/visualization/components/ProductModelWorkspace.tsx`:
- State `isSnapshotApplied` tracks whether changes are active or committed.
- `isEditingProduct = !isSnapshotApplied;`
- Currently:
  - Line 417 calculates `realtimePricing` based exclusively on `structuralDefinition` and slider parameters.
  - Line 2495 renders `{formattedPrice}` which points directly to `realtimePricing.totalPrice`.
  - When the user clicks "Apply Changes", `isSnapshotApplied` becomes `true`, but the price card retains only the active product cost.

#### 4.2.2 Dual-Mode Pricing Logic
The workspace price card must dynamically toggle between:
1. **Editing State (`!isSnapshotApplied` / `isEditingProduct === true`):**
   - Focus: The single product currently being configured by the user.
   - Price shown: `activeProductPrice = realtimePricing.totalPrice`.
   - Card Header: `Price:` (with single-product quantity pill and unit rate).
2. **Applied State (`isSnapshotApplied === true` / `isEditingProduct === false`):**
   - Focus: All products currently placed in the room aperture.
   - Price shown: `totalScenePrice = sum(placedOverlays.totalPrice) + activeProductPrice`.
   - Card Header: `Total Estimated Price (N items):`
   - Subtitle: `Includes all products placed on canvas. Click 'Edit' to adjust this item.`

#### 4.2.3 Implementation Code Specification for Workspace Pricing

```typescript
// 1. Calculate placed overlays subtotal
const placedOverlaysTotalPrice = useMemo(() => {
  return placedOverlays.reduce((sum, overlay) => {
    const price = overlay.totalPrice ?? (overlay.bomResult?.finalQuotation ? overlay.bomResult.finalQuotation * (overlay.configuration.quantity ?? 1) : 0);
    return sum + price;
  }, 0);
}, [placedOverlays]);

// 2. Compute effective display price based on editing state
const effectiveDisplayPricing = useMemo(() => {
  const activePrice = realtimePricing.totalPrice;
  const totalScenePrice = placedOverlaysTotalPrice + activePrice;
  const totalItemCount = placedOverlays.length + (selectedProduct ? 1 : 0);

  if (!isSnapshotApplied) {
    // Mode A: User is actively tweaking sliders - show current product price
    return {
      title: "Price:",
      totalAmount: activePrice,
      unitAmount: realtimePricing.unitPrice,
      isSceneTotal: false,
      itemCount: quantity,
      badgeText: quantity > 1 ? `Qty: ${quantity}` : null,
      footnote: quantity > 1 ? `${formattedUnitPrice} each` : "Configuring selected item",
    };
  }

  // Mode B: User clicked 'Apply Changes' - show combined sum of all products
  return {
    title: totalItemCount > 1 ? `Total Price (${totalItemCount} products):` : "Price:",
    totalAmount: totalScenePrice,
    unitAmount: null,
    isSceneTotal: totalItemCount > 1,
    itemCount: totalItemCount,
    badgeText: totalItemCount > 1 ? `${totalItemCount} Items Applied` : `Qty: ${quantity}`,
    footnote: totalItemCount > 1 ? "Combined total of all placed fixtures" : "excl. install, final after consultation",
  };
}, [
  isSnapshotApplied,
  realtimePricing.totalPrice,
  realtimePricing.unitPrice,
  placedOverlaysTotalPrice,
  placedOverlays.length,
  selectedProduct,
  quantity,
  formattedUnitPrice,
]);
```

### 4.3 Multi-Product Itemized Quotation Architecture (Requirement 2)

#### 4.3.1 Aggregation Engine (`src/lib/pricing/pricingEngine.ts`)
Create a pure domain utility function `aggregateMultiProductBOM` that aggregates individual product calculation results into a single project summary:

```typescript
export function aggregateMultiProductBOM(
  items: ItemizedProductQuotation[]
): ConsolidatedQuotationSummary {
  let totalQuantity = 0;
  let totalFramingMeters = 0;
  let totalFramingCost = 0;
  let totalGlazingSqm = 0;
  let totalGlazingCost = 0;
  let totalHardwareCost = 0;
  let totalConsumablesCost = 0;
  let totalDirectMaterialsCost = 0;
  let totalLaborCost = 0;
  let totalDirectCost = 0;
  let totalContractorMargin = 0;
  let finalGrandTotal = 0;

  for (const item of items) {
    const qty = Math.max(1, item.quantity);
    const bom = item.bomResult;

    totalQuantity += qty;
    totalFramingMeters += bom.totalLinearMetersFraming * qty;
    totalFramingCost += bom.effectiveFramingCost * qty;
    totalGlazingSqm += bom.glazingAreaSqm * qty;
    totalGlazingCost += bom.effectiveGlazingCost * qty;
    totalHardwareCost += bom.hardwareSubtotal * qty;
    totalConsumablesCost += bom.consumablesSubtotal * qty;
    totalDirectMaterialsCost += bom.directMaterialsSubtotal * qty;
    totalLaborCost += bom.fabricationLaborCost * qty;
    totalDirectCost += bom.totalDirectCost * qty;
    totalContractorMargin += bom.contractorMargin * qty;
    finalGrandTotal += item.totalPrice;
  }

  return {
    items,
    totalQuantity,
    totalFramingMeters: round2(totalFramingMeters),
    totalFramingCost: round2(totalFramingCost),
    totalGlazingSqm: round2(totalGlazingSqm),
    totalGlazingCost: round2(totalGlazingCost),
    totalHardwareCost: round2(totalHardwareCost),
    totalConsumablesCost: round2(totalConsumablesCost),
    totalDirectMaterialsCost: round2(totalDirectMaterialsCost),
    totalLaborCost: round2(totalLaborCost),
    totalDirectCost: round2(totalDirectCost),
    totalContractorMargin: round2(totalContractorMargin),
    finalGrandTotal: round2(finalGrandTotal),
  };
}
```

#### 4.3.2 Product Summary Reconciliation (`src/features/quotation/components/ProductSummary.tsx`)
Update `ProductSummary.tsx` to read both `placedOverlays` and the primary `productConfiguration`:
1. If `placedOverlays` contains items, map each overlay into an `ItemizedProductQuotation`.
2. If the active product (`structuralDefinition` + `productConfiguration`) is not already in `placedOverlays`, include it as an item.
3. If no placed overlays exist, fall back cleanly to the single active product.
4. Render a sequence of `<PriceCard>` components, one for each product item, with an index indicator (e.g., *"Item 1 of 3: Main Sliding Window"*, *"Item 2 of 3: Awning Window"*).
5. Render the **Final Consolidated Quotation Card** at the bottom:
   - Summary of total linear aluminum meters across all fixtures.
   - Summary of total daylight glass area in square meters.
   - Consolidated 4-group direct cost breakdown table.
   - Prominent, final grand total estimate (`formattedGrandTotal`).

```tsx
// Quotation items mapping structure in ProductSummary.tsx
const quotationItems = useMemo<ItemizedProductQuotation[]>(() => {
  const list: ItemizedProductQuotation[] = [];

  // Add all placed overlays
  for (const overlay of placedOverlays) {
    list.push(createQuotationItemFromOverlay(overlay));
  }

  // If active product exists and is not represented in overlays, append it
  if (structuralDefinition && !placedOverlays.some((o) => o.overlayId === activeOverlayId)) {
    list.push(
      createQuotationItemFromActive(
        structuralDefinition,
        productConfiguration,
        finalSnapshotDataUrl
      )
    );
  }

  return list;
}, [placedOverlays, structuralDefinition, productConfiguration, finalSnapshotDataUrl, activeOverlayId]);

const consolidatedSummary = useMemo(
  () => aggregateMultiProductBOM(quotationItems),
  [quotationItems]
);
```

#### 4.4.2 Document Markup Specification (`generateQuotationPdfHtml`)
The generated HTML template for printing and archiving is structured into 4 sequential sections:

1. **Document Header & Client Space Snapshot:**
   - Brand logo (GlassFit) and document metadata (Quotation Number, Reference Code, Date, Expiry).
   - Customer and installation site summary grid.
   - High-resolution photographic composited snapshot showing all placed products in the client space.

2. **Itemized Product Schedule (Separate Section for Each Product):**
   - Loops through `items: QuotationPdfItem[]`.
   - Each item features:
     - Item heading: `Item 1: [Product Name] - Qty: [X]`
     - Specifications bar: Aperture size ($W \times H$), Series 798 configuration, panel count, sill condition, profile finish, and glass specification.
     - Per-Item Structural Waiver Banner: If this specific item has $W \ge 2400\text{mm}$ under 2 panels, display the NSCP 2015 Structural Span Waiver warning specifically for this fixture.
     - Per-Item 4-Group BOM Table:
       - Aluminum Framing (linear meters, scrap allowance, subtotal).
       - Glass Infill (daylight area, scrap allowance, subtotal).
       - Hardware & Accessories (rollers, latches, guides, sealants, subtotal).
       - Workshop Fabrication Labor (floor or 25% allowance).
     - Item Subtotal line in PHP.

3. **Consolidated Bill-of-Materials & Final Quotation Summary Table:**
   - Appears after all individual products.
   - Consolidates all line items:
     - Total linear meters of aluminum across all fixtures.
     - Total daylight glazing surface area in square meters.
     - Total hardware subtotal.
     - Total consumables subtotal.
     - Total direct materials cost.
     - Total workshop fabrication labor.
     - Total contractor gross margin (25%).
     - **FINAL ESTIMATED GRAND QUOTATION (PHP)** prominently displayed in double-bordered summary box.

4. **Legal Compliance & Consumer Notice Section:**
   - Preliminary Estimate Disclaimer: Notice that dimensions are client-supplied and subject to physical on-site ocular verification of opening squareness and wall plumbness.
   - RA 7394 (Consumer Act of the Philippines) standard terms.
   - 7-day price validity clause.
   - Client and SME Fabricator signature acceptance lines.

- **Setup:** User places Product A (Series 798 2-Panel, $1500\text{mm} \times 1200\text{mm}$, calculated cost PHP 12,450.00). User then clicks "Add Product" and selects Product B (Series 798 3-Panel, $2600\text{mm} \times 1500\text{mm}$, calculated cost PHP 22,100.00).
- **While Editing Product B:**
  - Price Card displays: `PHP 22,100` (Product B only).
  - Primary button displays: `Apply Changes`.
- **Upon Clicking "Apply Changes":**
  - Price Card displays: `PHP 34,550` (PHP 12,450 + PHP 22,100).
  - Price Card header displays: `Total Price (2 products):`.
  - Primary button displays: `Edit`.
- **Upon Clicking "Edit":**
  - Price Card returns to: `PHP 22,100`.

### Scenario 2: Quotation Page Multi-Product Breakdown
- **Setup:** Same 2-product session from Scenario 1 navigates to `/quotation`.
- **Verification:**
  - Price Card 1 displays: Product A specifications, dimensions ($1500 \times 1200$), unit price PHP 12,450, and 4-group BOM breakdown.
  - Price Card 2 displays: Product B specifications, dimensions ($2600 \times 1500$), unit price PHP 22,100, and 4-group BOM breakdown.
  - Bottom Estimated Total Card displays: `Php 34,550`.
  - Both cards allow independent expanding and collapsing of detailed BOM summaries.

### Scenario 3: Per-Product Structural Waiver Isolation
- **Setup:** Product A is $1800\text{mm}$ (within standard 2-panel limits). Product B is $2500\text{mm}$ under a 2-panel configuration (triggers NSCP 2015 structural waiver).
- **Verification:**
  - Product A card displays no waiver banner.
  - Product B card displays the amber `⚠️ Structural Span Limit Waiver Acknowledged` banner.
  - The consultation PDF shows the waiver alert solely under Item 2's schedule, leaving Item 1 clean.

### Scenario 4: Consultation PDF Multi-Item Parity
- **Setup:** User generates consultation PDF from `/send-booking`.
- **Verification:**
  - PDF document contains separate schedules for Item 1 and Item 2.
  - Item 1 subtotal equals PHP 12,450.00.
  - Item 2 subtotal equals PHP 22,100.00.
  - Consolidated Grand Summary table shows total PHP 34,550.00.
  - Centavo precision matches between the live web UI and the PDF document (QAD-TC11).

## 7. Risk Assessment & Mitigation Matrix

| Risk Event | Severity | Likelihood | Mitigation Strategy |
|---|---|---|---|
| Placed overlay BOM result lost during page reload | High | Low | Persist the computed `bomResult` and `pricing` directly inside `PlacedOverlay` and save to `sessionStorage` in `visualizationSession.tsx`. |
| Rounding discrepancies between individual items and consolidated total | Medium | Low | Perform all line-item calculations using standard `round2(cents)` arithmetic in `pricingEngine.ts`. The grand total is the sum of rounded item subtotals. |
| Memory bloat in session storage from storing detailed BOM JSON | Low | Low | Store only lightweight numeric subtotals and material identifiers in `PlacedOverlay`; exclude heavy raw vertex arrays. |
| Legacy sessions lacking `bomResult` in `placedOverlays` | Low | Medium | Provide backward-compatible fallback in `ProductSummary.tsx`: if `overlay.bomResult` is missing, recalculate dynamically using `calculateBOMFromStructuralDefinition` or default template rates. |
| PDF page overflow for sessions with 4+ fixtures | Medium | Low | Apply clean CSS print page-break rules (`page-break-inside: avoid;`) to each product item schedule in `quotationPdfGenerator.ts`. |
