## 1. Executive Summary & Problem Context

In GlassFit, administrators create and configure architectural products (sliding windows, awning windows, glass doors, and interior partitions) via the multi-step Product Setup Wizard at `/admin/products/[productId]/setup`. Step 3 of this wizard (`CatalogAssetsSection.tsx`) handles the ingestion of two foundational marketing and inspection assets:
1. The **Catalog Image** (2D raster image: JPG, PNG, or WebP) utilized across the customer product catalog grid and configuration previews.
2. The **Whole 3D Preview** (glTF 2.0 binary `.glb` model) used for 360-degree customer inspection prior to entering the parametric visualization workspace.

### 1.1 The Current State and Visual Blindness
In the current implementation of `CatalogAssetsSection.tsx`:
- When an administrator uploads or drags a 2D image, the UI renders a gray container (`bg-[#f5f5f5]`) containing only the text string of `imageAsset.file_name`, file size in kilobytes, and a green success label (`✓ Uploaded successfully`). No visual thumbnail or image bitmap is rendered.
- When an administrator uploads a 3D model, the UI displays a generic static icon (`/upload.svg`), the text string of `previewAsset.file_name`, file size in megabytes, and a success label. No 3D WebGL viewport or geometry preview is initialized.

This creates significant operational friction for administrative and workshop staff:
- Administrators cannot verify whether the uploaded image is correctly framed, has transparent padding, or is corrupted without opening a separate operating system file browser.
- Administrators cannot inspect the 3D model orientation, verify component assembly, or evaluate surface normal integrity before proceeding to Step 4 (Structural Components) or Step 6 (Validation Workspace).
- If an existing product draft is reloaded from Supabase (`initialData`), the user only sees string filenames rather than visual proof of persisted assets.

### 1.2 Core Architectural Directives
1. **Interactive 2D Image Preview:**  
   Replace the text card with a responsive image viewport utilizing Next.js `Image` or an optimized HTML `<img>` element. The component must support both in-flight local file uploads via temporary object URLs (`URL.createObjectURL(file)`) and persisted remote assets retrieved from Cloudflare R2 (`getR2AssetUrl(objectKey)`). Provide hover controls for removal, replacement, and full-resolution lightbox inspection.
2. **Hardware-Accelerated 3D WebGL Canvas Preview:**  
   Replace the static SVG placeholder with an embedded, performant Three.js WebGL canvas utilizing `@react-three/fiber` and `@react-three/drei` primitives (`OrbitControls`, `Stage`), consistent with the 3D rendering architecture established in `StructuralComponentsSection.tsx` and `ProductModel3D.tsx`.
3. **Automated Geometry Framing & Normalization:**  
   Automatically compute bounding boxes (`THREE.Box3`), recenter model origins to the geometric center, and normalize camera distance so that models of any scale (from small awning window handles to 3-meter glass partitions) fit comfortably inside the square preview viewport.
4. **Memory Safety & Resource Lifecycle Management:**  
   Ensure all generated object URLs are revoked (`URL.revokeObjectURL`) when files change or components unmount. Manage Three.js geometries, materials, textures, and WebGL contexts cleanly to prevent memory leaks and browser context loss across wizard step transitions (`BAN-UI-09`).
5. **Zero Hallucinated Dependencies & Zero `any`:**  
   Strictly reuse existing repository dependencies (`three`, `@react-three/fiber`, `@react-three/drei`, `lucide-react`, `next/image`) and enforce strict TypeScript typing across all component interfaces (`BAN-TYPE-05`).

### 3.3 Public R2 Asset Resolution Contract
When loading persisted assets from `initialData`, the R2 object key must resolve to a valid browser-accessible URL. The helper `getR2AssetUrl` in `src/lib/r2.ts` provides the authoritative edge URL:
```typescript
import { getR2AssetUrl } from "@/lib/r2";

export function resolveAssetUrl(asset: CatalogAssetRecord | null | undefined): string | null {
  if (!asset) return null;
  if (asset.file_url) return asset.file_url;
  if (asset.r2_object_key) {
    return getR2AssetUrl(asset.r2_object_key);
  }
  return null;
}
```

## 5. Technical Implementation Details & Code Blueprints

### 5.1 Dynamic GLB Parser for Local In-Memory Files
When an administrator drops a `.glb` file before uploading to R2, the system must generate a preview without waiting for network roundtrips. The parser reads the file as an `ArrayBuffer` and feeds it to `GLTFLoader`:

```typescript
import * as THREE from "three";
import { GLTFLoader } from "three/addons/loaders/GLTFLoader.js";

export async function parseLocalGlbFile(file: File): Promise<THREE.Group> {
  const arrayBuffer = await file.arrayBuffer();
  const loader = new GLTFLoader();

  return new Promise<THREE.Group>((resolve, reject) => {
    loader.parse(
      arrayBuffer,
      "",
      (gltf) => {
        const root = gltf.scene;
        recenterAndNormalizeGroup(root);
        resolve(root);
      },
      (error) => {
        console.error("Failed to parse local GLB:", error);
        reject(new Error("The uploaded 3D file is not a valid GLB binary model."));
      }
    );
  });
}

export function recenterAndNormalizeGroup(group: THREE.Group): void {
  group.updateMatrixWorld(true);
  const box = new THREE.Box3().setFromObject(group);
  const center = new THREE.Vector3();
  box.getCenter(center);
  group.position.sub(center);
  group.updateMatrixWorld(true);
}
```

### 5.2 Embedded WebGL Canvas Component Blueprint
The 3D model canvas component implements clean memory lifecycle and stage rendering:

```typescript
"use client";

import React, { Suspense, useRef, useState, useEffect } from "react";
import { Canvas } from "@react-three/fiber";
import { OrbitControls, Stage } from "@react-three/drei";
import * as THREE from "three";
import { GLTFLoader } from "three/addons/loaders/GLTFLoader.js";
import { RotateCw, RefreshCw, X, Loader2, Eye } from "lucide-react";

interface ModelPreviewCanvasProps {
  modelSource: string | File;
  fileName: string;
  fileSizeBytes: number;
  onRemove: () => void;
  onExpand?: () => void;
}

function LoadedModel({ source }: { source: string | File }) {
  const [scene, setScene] = useState<THREE.Group | null>(null);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    let isCancelled = false;
    const loader = new GLTFLoader();

    if (typeof source === "string") {
      // Remote R2 URL
      loader.load(
        source,
        (gltf) => {
          if (!isCancelled) {
            const root = gltf.scene;
            recenterAndNormalizeGroup(root);
            setScene(root);
          }
        },
        undefined,
        (err) => {
          if (!isCancelled) setError("Failed to load remote 3D model.");
        }
      );
    } else {
      // Local File object
      source.arrayBuffer().then((buf) => {
        if (isCancelled) return;
        loader.parse(
          buf,
          "",
          (gltf) => {
            if (!isCancelled) {
              const root = gltf.scene;
              recenterAndNormalizeGroup(root);
              setScene(root);
            }
          },
          (err) => {
            if (!isCancelled) setError("Invalid 3D model file format.");
          }
        );
      }).catch(() => {
        if (!isCancelled) setError("Could not read local file buffer.");
      });
    }

    return () => {
      isCancelled = true;
      if (scene) {
        scene.traverse((obj) => {
          if (obj instanceof THREE.Mesh) {
            obj.geometry.dispose();
            if (Array.isArray(obj.material)) {
              obj.material.forEach((m) => m.dispose());
            } else if (obj.material) {
              obj.material.dispose();
            }
          }
        });
      }
    };
  }, [source]);

  if (error) {
    throw new Error(error);
  }

  if (!scene) {
    return null;
  }

  return <primitive object={scene} />;
}

export function ModelPreviewCanvas({
  modelSource,
  fileName,
  fileSizeBytes,
  onRemove,
  onExpand,
}: ModelPreviewCanvasProps) {
  const [autoRotate, setAutoRotate] = useState(false);
  const controlsRef = useRef<React.ComponentRef<typeof OrbitControls>>(null);

  const handleResetCamera = () => {
    if (controlsRef.current) {
      controlsRef.current.reset();
    }
  };

  return (
    <div className="relative w-full aspect-square bg-[#0f1422] rounded-[16px] border border-neutral-200 overflow-hidden group">
      <Canvas
        shadows
        camera={{ position: [0, 1.5, 3], fov: 45 }}
        gl={{ antialias: true, alpha: true }}
        className="w-full h-full cursor-grab active:cursor-grabbing"
      >
        <Suspense fallback={null}>
          <Stage environment="city" intensity={0.6} adjustCamera={1.2}>
            <LoadedModel source={modelSource} />
          </Stage>
        </Suspense>
        <OrbitControls
          ref={controlsRef}
          autoRotate={autoRotate}
          autoRotateSpeed={2.0}
          enableDamping
          dampingFactor={0.05}
          maxPolarAngle={Math.PI / 1.8}
        />
      </Canvas>

      {/* Top Toolbar Controls */}
      <div className="absolute top-3 left-3 flex items-center gap-1.5 z-10">
        <button
          type="button"

        </button>
        <button
          type="button"
          onClick={() => setAutoRotate(!autoRotate)}
          title={autoRotate ? "Pause Turntable" : "Start Turntable"}
          className={`p-1.5 rounded-md backdrop-blur-sm transition-colors border ${
            autoRotate
              ? "bg-[#07b6d3] text-white border-[#07b6d3]"
              : "bg-black/60 hover:bg-black/80 text-white border-white/10"
```

## 6. Edge Cases, Performance & Security Safeguards

1. **Object URL Memory Leaks:**  
   Every invocation of `URL.createObjectURL(file)` allocates an entry in the browser heap that persists until document unload unless revoked. When an administrator replaces or removes an image, or when `CatalogAssetsSection` unmounts, all active object URLs must be explicitly passed to `URL.revokeObjectURL(url)`.
2. **WebGL Context Exhaustion:**  
   Standard mobile and desktop browsers restrict active WebGL contexts to between 8 and 16 concurrent instances. Unmounted Three.js canvases must explicitly dispose of geometries, materials, and textures, and call `gl.dispose()` upon teardown to prevent context loss across wizard tab switching.
3. **Corrupted or Malformed GLB Files:**  
   If an administrator uploads an invalid 3D model (e.g. an ASCII glTF renamed as `.glb` or an incomplete export), `GLTFLoader.parse` rejects with a parser exception. The canvas wraps parsing inside a React Error Boundary (`ModelErrorBoundary`), displaying an informative error banner with a one-click action to clear the corrupt file rather than crashing the Next.js wizard island.
4. **Extreme Aspect Ratio Models:**  
   Tall glass railings or wide 4-panel sliding doors have non-square aspect ratios. Standard stage framing uses `THREE.Box3` bounding spheres to dynamically calculate camera distance:
   ```typescript
   const radius = box.getBoundingSphere(new THREE.Sphere()).radius;
   const distance = radius / Math.sin((camera.fov * Math.PI) / 360);
   camera.position.set(0, 0, distance * 1.2);
   ```
5. **Image File Size and Dimension Limits:**  
   Strict client-side pre-flight checks enforce a 5MB maximum limit for 2D catalog images and 25MB for 3D GLB preview meshes before requesting R2 presigned URLs.

## 8. Migration, Backward Compatibility, and Rollback Strategy

1. **Database Schema Parity:**  
   `IMP-MS22` does not require any database DDL mutations or schema migrations. The existing `public.product_assets` table (`ERD-E8`) already stores `Catalog Image` and `Catalog 3D Preview` asset records with full R2 storage keys and metadata.
2. **Backward Compatibility:**  
   Existing products with previously uploaded assets stored in Supabase will automatically render visual previews upon loading Step 3 because `resolveAssetUrl` resolves `r2_object_key` to public R2 CDN URLs.
3. **Rollback Safety:**  
   If issues arise with WebGL rendering on specific legacy browsers, the component can cleanly fall back to the previous placeholder card layout by toggling an internal flag without corrupting stored database records.
