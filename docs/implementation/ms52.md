## 1. Outcome and Scope

The core objective of paper fiducial calibration is to guarantee that the physical width and height of parametric 3D models placed into client room photos match real-world installation openings with precision accuracy (within 2% to 5% error tolerance), completely eliminating heuristic guesswork.

While `IMP-MS51` establishes the pre-workspace confirmation gateway to ensure the customer verifies or adjusts the detected paper boundaries before entering the editor, `IMP-MS52` establishes the **mathematical and visual grounding pipeline** inside the 3D workspace:

1. **Immediate Verified Scale Grounding:** When the customer enters the workspace from `IMP-MS51` with `status === "verified_calibrated"`, the parametric 3D model does not initialize with arbitrary static dimensions (e.g. 210cm x 150cm) or uncalibrated heuristic heights. Instead, the model's physical width and height are directly calculated from the verified metric scale factor ($S_{\text{cm/px}}$) and the aperture target overlay.
2. **Real-Time Physical Dimension Callouts (Canvas HUD):** As the customer moves, scales, or perspective-fits the 3D fixture against the wall opening, real-time measurement tags (in millimeters and centimeters) render directly on the active overlay boundary (e.g. "Width: 1,450 mm | Height: 2,120 mm" accompanied by an emerald verified trust badge). This gives the customer immediate visual feedback that the 3D model conforms to their physical room geometry.
3. **Hot Workspace Synchronization on Marker Re-Adjustment:** If the customer decides while inside the workspace that they want to refine the paper marker (via the top-left HUD "Calibrated (Verified)" badge), updating the marker immediately recomputes the scale factor and dynamically rescales all placed 3D models and perspective quad dimensions in the scene in real time, without resetting custom finishes, glass selections, or quotation state.
4. **Perspective Quad Direct Physical Mapping:** When the user fits a 4-point perspective quadrilateral around an opening, the opening's pixel spans convert directly into metric centimeters using the verified coplanar scale factor, dynamically extruding Three.js aluminum frames, mullions, and glass infill to match the physical opening.
5. **Fabricator Quotation Audit Parity:** When generating quotation items in `MeasurementConfirmationModal.tsx`, dimensions verified against paper markers are permanently labeled with `pricing_details.dimension_source = "verified_calibrated_visual"`, building trust with fabricator estimators and suppressing on-site measurement revisits (`BRD-M5`, `BRD-M6`).

### 1.1 Non-Negotiable Invariants

1. **Pure Coplanar Weighting:** Calibrated sessions must assign 100% mathematical weight to the verified scale factor (`scale_cm_per_px`). Heuristic blending with template default heights (e.g. 120cm for windows, 210cm for doors) is strictly forbidden for verified calibrated sessions.
2. **Real-Time Rescaling Integrity:** Re-adjusting the paper marker from within the workspace must never wipe the customer's active scene, selected product variations, or quotation items. All placed fixtures must synchronously update their dimensions.
3. **Manufacturing Safety Clamping:** All computed physical dimensions are strictly clamped within architectural fabrication limits: width in [30cm, 600cm] and height in [30cm, 400cm].
4. **Style Consistency:** All measurement badges, HUD pills, and dimension callouts must strictly conform to existing design tokens in `src/app/globals.css` and established component conventions (`BAN-UI-09`).
5. **No Em-Dashes:** In compliance with `BAN-PUNCT-01`, all documentation, code comments, and copy must use hyphens, colons, or parentheses.
6. **No Box Diagrams in Code Blocks:** All UI tables, dimension formulas, and state flows must use standard Markdown tables and ordered prose (`BAN-DIAG-03`).
7. **Strict Type Safety:** Zero usage of `any` across TypeScript interfaces and calculation utilities (`BAN-TYPE-05`).

## 3. Grounded Dimension Formulation & Scaling Architecture

### 3.1 Direct Coplanar Mathematical Formulation

Given:
- Opening pixel width: $W_{\text{px}}$ (derived from target overlay or 4-point perspective quadrilateral)
- Opening pixel height: $H_{\text{px}}$
- Verified coplanar scale factor: $S = \text{verified\_scale\_cm\_per\_px}$ (in centimeters per pixel)

When `session.calibrationMeta.status === "verified_calibrated"`:

$$W_{\text{cm}} = \text{round}(W_{\text{px}} \cdot S)$$
$$H_{\text{cm}} = \text{round}(H_{\text{px}} \cdot S)$$

$$W_{\text{grounded}} = \max(30, \min(600, W_{\text{cm}}))$$
$$H_{\text{grounded}} = \max(30, \min(400, H_{\text{cm}}))$$

Zero depth corrections or template height ratios are applied. Because the verified fiducial paper lies on the exact same wall surface plane as the opening, the scale factor is planar and mathematically exact across that entire wall plane.

### 3.2 Enhanced Initial Sizing Implementation

In `src/lib/visualization/scaleEstimation.ts`:

```typescript
export function getVerifiedScaleInitialDimensions(
  verifiedScaleCmPerPx: number,
  canvasWidthPx: number,
  canvasHeightPx: number,
  defaultOverlayWidthPx?: number,
  defaultOverlayHeightPx?: number,
  photoWidthPx?: number,
  photoHeightPx?: number,
): { widthCm: number; heightCm: number } {
  const canvasToPhotoW =
    photoWidthPx && photoWidthPx > 0 && canvasWidthPx > 0
      ? photoWidthPx / canvasWidthPx
      : 1;
  const canvasToPhotoH =
    photoHeightPx && photoHeightPx > 0 && canvasHeightPx > 0
      ? photoHeightPx / canvasHeightPx
      : 1;

  const basePxW = defaultOverlayWidthPx || Math.round((canvasWidthPx || 636) * 0.35);
  const basePxH = defaultOverlayHeightPx || Math.round((canvasHeightPx || 579) * 0.35);

  const targetPxW = basePxW * canvasToPhotoW;
  const targetPxH = basePxH * canvasToPhotoH;

  const widthCm = Math.round(targetPxW * verifiedScaleCmPerPx);
  const heightCm = Math.round(targetPxH * verifiedScaleCmPerPx);

  return {
    widthCm: Math.max(30, Math.min(600, widthCm)),
    heightCm: Math.max(30, Math.min(400, heightCm)),
  };
}
```

## 5. Hot Workspace Synchronization & Multi-Product Scenes

### 5.1 HUD Marker Re-Adjustment Action

In the workspace top-left HUD, the calibration pill displays:

1. **Status Readout:** "Calibrated (Verified: A4) - 0.0418 cm/px" with an emerald checkmark.
2. **Re-Adjustment Action:** "Adjust Marker" button.
3. **Execution:**
   - Clicking "Adjust Marker" re-opens `PaperDetectionConfirmationModal` populated with the current verified corners.
   - The customer can adjust corner handles or switch paper standards.
   - When the customer confirms, `updateSessionCalibration()` is invoked.
   - **Hot Rescaling:** All active fixtures in the scene immediately update their physical dimensions ($W = \text{round}(W_{\text{px}} \cdot S_{\text{new}})$ and $H = \text{round}(H_{\text{px}} \cdot S_{\text{new}})$) and trigger a parametric Three.js mesh extrusion update without reloading the page or losing custom materials.

### 5.2 Multi-Product Inheritance

When the customer adds a secondary fixture into the room (e.g. adding a sliding window beside a sliding door):

1. The secondary fixture reads the active session's `verified_scale_cm_per_px`.
2. Initial dimensions for the added fixture are computed using `getVerifiedScaleInitialDimensions()`.
3. The newly placed 3D mesh instantiates at proper real-world scale relative to the primary fixture and room background, eliminating mismatched visual proportions.

## 6. Quotation Integrity & Fabricator Audit Parity

### 6.1 Measurement Confirmation Modal

In `MeasurementConfirmationModal.tsx`, when the session has `status === "verified_calibrated"`:

1. Displays a primary Choice Card with an emerald trust theme:
   - Header: "Keep User-Verified Calibrated Dimensions" with "±2-5% Precision" tag.
   - Monospace Readout: e.g. "1,450 mm Width x 2,120 mm Height".
   - Subtitle: "Calibrated from verified [A4 / Short / Long] paper marker on installation wall plane".
2. Manual tape-measure override is retained as an alternative choice card for customers who have physical tape measurements.

### 6.2 Supabase Quotation Line Item Payload

```typescript
const quotationItemPayload = {
  // ...
  pricing_details: {
    // ...
    dimension_source: isVerifiedCalibrated
      ? "verified_calibrated_visual"
      : isPaperCalibrated
      ? "calibrated_visual"
      : "manual_tape",
    paper_standard: activeCalibrationMeta?.paperStandard ?? null,
    calibration_scale_cm_per_px: activeScaleSignal?.best_scale_cm_per_px ?? null,

  },

```

This persistent audit trail certifies to fabricator estimators that the customer verified the reference paper boundary, suppressing ocular measurement overhead and reducing on-site scrappage (`BRD-M5`, `BRD-M6`).

## 10. Risks and Mitigations

| Risk | Severity | Mitigation |
|---|---|---|
| Severe perspective tilt causes opposite paper edges to exhibit trapezoidal distortion | Medium | Homography matrix projection rectifies planar projective distortion; scale is derived from geometric mean of opposite edges. |
| Customer places fiducial paper on an adjacent wall on a different plane | Medium | Intake guideline cards and pre-workspace confirmation copy explicitly remind the customer: "Ensure paper is mounted on the exact same wall plane as the installation opening." |
| Overlapping HUD dimension badges on small mobile screens | Low | Responsive CSS media queries hide secondary centimeter units on mobile viewports (<640px), showing compact millimeter labels only. |
