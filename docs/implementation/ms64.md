## 1. Outcome and Scope

In the current GlassFit administrative setup (Step 4 of `/admin/products/[id]/setup`, implemented in `src/features/admin/products/setup/StructuralComponentsSection.tsx` and `PartInspectorDrawer.tsx`), an administrator maps each 3D `.glb` component mesh to exactly one raw material using a single dropdown select (`rawMaterialId: string | null`) that writes to `product_components.raw_material_id`.

In real-world Philippine glass and aluminum fabrication, architectural openings are rarely restricted to a single rigid material specification. For example:
1. **Framing Profiles:** A sliding window frame or sash rail can be manufactured from Series 798 aluminum extrusions in either Analok (dark bronze anodized) or Powder Coated White finish.
2. **Glazing Infills:** A fixed or sliding glass panel can accept 6mm Annealed Float Clear, 6mm Tinted Bronze, or 6mm Safety Tempered Clear glass.
3. **Hardware:** Rollers and flush locks may offer standard nylon/POM variants or premium stainless steel configurations.

When an administrator configures a product template, restricting each part to a single material forces fabricators to create duplicate product templates for every finish combination (e.g., "Series 798 Window - Analok" versus "Series 798 Window - Powder Coated White"). This duplicates 3D assets, fragments catalog management, and prevents dynamic material customization during visualization and quotation.

`IMP-MS64` resolves this fundamental limitation at the persistence and administrative authoring layer:
- **Relational Multi-Material Binding:** Establishes a relational junction entity (`product_component_materials`) linking a component part to multiple permitted raw materials, with one explicitly designated default material.
- **Interactive Checkbox-Based Assignment:** Replaces the single select dropdown in the Part Inspector Drawer with a categorized checkbox list of candidate materials, paired with a clear default material radio/badge selector.
- **Default Material Integrity:** Enforces that whenever materials are assigned to a part, exactly one material must be designated as the active default.
- **Backward Compatibility Guarantee:** Keeps `product_components.raw_material_id` synchronized with the designated default material via automated trigger and mutation logic, preventing regressions in legacy queries and existing pricing endpoints.
- **Batch Assignment for Symmetrical Members:** Enables simultaneous multi-material configuration across multiple selected parts (such as all sash rails or both vertical jambs).

This document covers the relational schema migration, TypeScript data contracts, server mutation actions, and Admin Step 4 Part Inspector UI. Testing in the pre-activation validation sandbox is specified in `IMP-MS65`, and customer-facing visualization selection is specified in `IMP-MS66`.

## 3. Non-Negotiable Invariants

1. **Deterministic Default Material Invariant:** If one or more raw materials are checked for a component part, exactly one material must be designated as `is_default = true`. The system must never permit zero defaults or multiple defaults for a component with assigned materials.
2. **Automatic Default Promotion:** When an admin checks the first material for an unassigned component, that material must automatically become the default. If the current default material is unchecked, the default status must automatically transfer to the first remaining checked material. If all materials are unchecked, the component returns to unassigned status (`defaultRawMaterialId = null`).
3. **Database Referential Integrity:** Deleting a `product_component` cascades to its `product_component_materials` junction rows (`ON DELETE CASCADE`). Deleting a `raw_materials` record that is linked to active components is strictly rejected (`ON DELETE RESTRICT`) per `BAN-MIGR-06`.
4. **Backward Compatibility Guarantee:** The column `product_components.raw_material_id` must always mirror the ID of the material where `is_default = true`. Legacy queries, older migrations, and standalone scripts that query `product_components.raw_material_id` must continue to return the default material without modifications.
5. **Tenant Isolation and RLS Policies:** All reads from `product_component_materials` follow public read permissions for active products. All insert, update, and delete mutations require authenticated admin authorization via `public.has_admin_permission('manage_products') or public.is_admin()` per `BAN-RLS-07`.
6. **No Foreign UI Libraries or Ad-Hoc Styling:** All checkboxes, radio badges, pills, and layout panels must strictly reuse Tailwind CSS tokens from `src/app/globals.css` and established component conventions in `src/features/admin/products/setup/` per `BAN-UI-09`.
7. **Zero Em-Dashes:** In strict compliance with `BAN-PUNCT-01`, all documentation, user interface labels, helper text, and code comments must use hyphens, colons, or parentheses. Never use em-dashes.
8. **No Type Any:** All TypeScript schemas, interfaces, and function signatures must use explicit types, interfaces, or unknown per `BAN-TYPE-05`.

## 4. Relational Persistence & Schema Migration

### 4.1 Migration SQL: `015_multi_material_component_bindings.sql`

Create migration file `supabase/migrations/015_multi_material_component_bindings.sql`:

```sql
-- Migration: 015_multi_material_component_bindings.sql
-- Function: Support multi-material candidate bindings per product component with explicit default selection
-- Upstream Traceability: ERD-E6 (product_components), ERD-E17 (raw_materials), PRD-F14, SDD-C9

-- 1. Create junction table public.product_component_materials
create table if not exists public.product_component_materials (
  id uuid primary key default gen_random_uuid(),
  product_component_id uuid not null references public.product_components(component_id) on delete cascade,
  raw_material_id uuid not null references public.raw_materials(id) on delete restrict,
  is_default boolean not null default false,
  display_order integer not null default 0,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  constraint uq_component_material unique (product_component_id, raw_material_id)
);

-- Indexes for performance
create index if not exists idx_pcm_component_id on public.product_component_materials(product_component_id);
create index if not exists idx_pcm_material_id on public.product_component_materials(raw_material_id);
create index if not exists idx_pcm_default on public.product_component_materials(product_component_id) where is_default = true;

-- 2. Ensure exactly one default per component when bindings exist
create unique index if not exists uq_component_single_default 
  on public.product_component_materials(product_component_id) 
  where is_default = true;

-- 3. Row-Level Security (RLS) Policies
alter table public.product_component_materials enable row level security;

drop policy if exists pcm_public_read on public.product_component_materials;
create policy pcm_public_read
  on public.product_component_materials for select
  using (
    exists (
      select 1 from public.product_components pc
      join public.products p on p.id = pc.product_id
      where pc.id = product_component_materials.product_component_id
        and (p.status = 'active' or public.is_admin())
    )
  );

drop policy if exists pcm_admin_insert on public.product_component_materials;
create policy pcm_admin_insert
  on public.product_component_materials for insert to authenticated
  with check (public.has_admin_permission('manage_products') or public.is_admin());

drop policy if exists pcm_admin_update on public.product_component_materials;
create policy pcm_admin_update
  on public.product_component_materials for update to authenticated
  using (public.has_admin_permission('manage_products') or public.is_admin())
  with check (public.has_admin_permission('manage_products') or public.is_admin());

drop policy if exists pcm_admin_delete on public.product_component_materials;
create policy pcm_admin_delete
  on public.product_component_materials for delete to authenticated
  using (public.has_admin_permission('manage_products') or public.is_admin());

-- 4. Trigger Function: Sync product_components.raw_material_id with default material
create or replace function public.sync_component_default_material()
returns trigger
language plpgsql
as $$
declare
  target_component_id uuid;
  default_mat_id uuid;
begin
  if (tg_op = 'DELETE') then
    target_component_id := old.product_component_id;
  else
    target_component_id := new.product_component_id;
  end if;

  select raw_material_id into default_mat_id
  from public.product_component_materials
  where product_component_id = target_component_id
    and is_default = true
  limit 1;

  update public.product_components
  set raw_material_id = default_mat_id,
      updated_at = now()
  where id = target_component_id;

  return null;
end;
$$;

drop trigger if exists trg_sync_component_default_material on public.product_component_materials;
create trigger trg_sync_component_default_material
  after insert or update of is_default, raw_material_id or delete on public.product_component_materials
  for each row execute function public.sync_component_default_material();

-- 5. Seed backfill: Populate product_component_materials from existing product_components.raw_material_id
insert into public.product_component_materials (product_component_id, raw_material_id, is_default, display_order)
select id, raw_material_id, true, 0
from public.product_components
where raw_material_id is not null
on conflict (product_component_id, raw_material_id) do update set
  is_default = true;
```

### 5.3 Server Mutation Action Contract (`src/lib/admin/products/componentMutations.ts`)

```typescript
export interface UpsertComponentPayload {
  id?: string;
  productId: string;
  componentKey: string;
  componentName: string;
  componentType: ComponentType;
  assemblyGroup: string;
  baseQuantity: number;
  rawMaterialId: string | null;
  dimensionBinding: DimensionBinding;
  spanRatio: number;
  isRemovable: boolean;
  togglePropertyKey?: string | null;
  presentationCategory: PresentationCategory;
  glbFileUrl?: string | null;
  materialBindings?: Array<{
    rawMaterialId: string;
    isDefault: boolean;
    displayOrder?: number;
  }>;
}

export async function upsertProductComponentWithMaterials(
  payload: UpsertComponentPayload
): Promise<{ success: boolean; componentId: string; error?: string }>;
```

The mutation executes inside an atomic Supabase client call:
1. Validates payload invariants: if `materialBindings` is non-empty, exactly one item must have `isDefault: true`.
2. Upserts `product_components` record with `raw_material_id` set to the default material ID.
3. Deletes existing rows in `product_component_materials` for `product_component_id` that are not in the new payload.
4. Upserts all current `materialBindings` into `product_component_materials`.
5. Returns synchronized component with populated relations.

## 6. UI & Interaction Specification (Admin Step 4)

### 6.1 Part Inspector Multi-Material Selector (`PartInspectorDrawer.tsx`)

In `PartInspectorDrawer.tsx`, replace the single `<select>` with a structured multi-material panel.

#### Visual Layout Structure

The material selection panel contains three sections:
1. **Header & Category Filter:**
   - Label: "Allowed Raw Materials (Catalog)"
   - Sub-label: "Select one or more materials this part can be fabricated with. Designate one material as the default."
   - Quick category tabs matching part presentation category (e.g., "Aluminum Framing", "Glass Infill", "Hardware", "All Materials").
2. **Material Candidate Checklist:**
   - Render a scrollable list of available raw materials.
   - Each row presents:
     - **Selection Checkbox:** Styled with cyan accent (`accent-[#07b6d3]`), checking/unchecking includes or excludes this material from the part's candidate list.
     - **Material Identity:** Material code (mono font), description, finish badge (e.g., Analok, Powder Coated White, Bronze, Clear).
     - **Pricing Summary:** Unit price (PHP/m or PHP/sqm) and effective rate including cutting scrap allowance.
     - **Default Indicator / Selector:**
       - If checked: Displays a radio button or click-to-default badge: `[ (o) Default ]` or `[ ( ) Set as Default ]`.
       - If unchecked: Default selector is hidden or disabled.
3. **Selection Summary Footer:**
   - Displays count: "N materials allowed" (e.g., "2 materials configured: Analok (Default), Powder Coated White").
   - Status badge: Green checkmark when exactly one default is selected; Amber alert if zero materials are assigned ("Unassigned: Free component").

#### Interactive State Rules

| Action | Resulting Component State | Validation & Visual Feedback |
|---|---|---|
| Admin checks an unchecked material (no others checked) | Material is added to `materialBindings`; automatically set as `isDefault = true`. | Green checkmark badge; default radio pre-selected. |
| Admin checks an additional material (other materials already checked) | Material is added to `materialBindings` with `isDefault = false`. | Added as alternative option; existing default remains unchanged. |
| Admin clicks "Set as Default" on a checked material | Target material becomes `isDefault = true`; previous default becomes `isDefault = false`. | Active default radio moves to target material immediately. |
| Admin unchecks the current default material (other checked materials remain) | Target material is removed; default automatically shifts to the first remaining checked material. | Toast notice: "Default shifted to [Next Material Name]". |
| Admin unchecks the sole remaining material | `materialBindings` becomes empty; component becomes unassigned (`rawMaterialId = null`). | Amber badge: "Unassigned component (Free)". |
| Admin attempts to click default on an unchecked row | Checkbox is automatically checked and designated as default in a single gesture. | Ergonomic one-click default assignment. |

### 6.2 Multi-Part Symmetrical Batch Assignment

When an administrator selects multiple components simultaneously in Step 4 (e.g., selecting `rail-top`, `rail-bottom`, `rail-left`, `rail-right`):
1. The drawer header displays: "4 Parts Selected: Framing Members".
2. The material checklist displays:
   - Checkbox with indeterminate state (`-`) if materials are partially assigned across parts.
   - Checking a material applies it across all selected parts.
   - Designating a default material sets that material as default across all selected parts.
3. A "Sync Across Symmetrical Parts" button allows instant propagation of allowed materials and default selection to all parts in the same assembly group.
