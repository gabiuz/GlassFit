## 1. Required Outcome

MS17 delivers two related outcomes:

1. **Customer-facing quotation simplification:** Every customer quotation preview, print view, and saved PDF shows configuration details, quantity, one final price per quotation item, and the grand total. It does not expose BOM groups, material or labor rates, component subtotals, contractor margin, the original calculated price, or a negotiation note.
2. **Admin per-item negotiation:** Authorized booking managers edit the final line price of each canonical quotation item. The grand total is read-only and always equals the sum of effective item line prices.

The client quotation summary page is outside the PDF disclosure change. Its existing expandable BOM breakdown remains unchanged because it is an interactive pre-booking estimate, not the customer quotation document governed by this milestone.

### 1.1 Fixed decisions

- Negotiation targets an item's **line subtotal**, not its unit price. This document uses `negotiatedSubtotal` consistently.
- `QuotationDocumentSnapshotV1` remains immutable and contains calculated values only.
- Per-item overrides are stored in a new server-owned `quotation_estimates.item_price_overrides` JSONB column. Customer-submitted quotation drafts never accept negotiation or audit fields.
- All customer document surfaces use the same simplified renderer. This includes the booking preview, admin View/Download PDF actions, public reference print output, and saved PDF generation where available.
- Canonical quotations use per-item editing only. Legacy quotations without a persisted V1 snapshot retain the existing total-level editor as a compatibility fallback.
- `negotiated_amount`, `negotiated_by`, and `negotiated_at` remain as compatibility and summary fields. New code derives authoritative canonical pricing from item overrides.
- No new third-party dependency is introduced.

### 1.2 Non-goals

- Do not change the pricing engine, BOM calculation, material catalog, margin formula, or calculated quotation values.
- Do not remove calculated BOM groups from persisted snapshots or `quotation_items`.
- Do not add a new admin route, modal, drawer, or iframe.
- Do not expose administrator profile IDs or per-item audit metadata to customer clients.
- Do not enable per-item editing for reconstructed legacy documents.

## 3. Domain and Pricing Invariants

All money derivation operates in integer centavos. Conversion to decimal PHP occurs only at schema and display seams.

### 3.1 Per-item pricing

For each persisted V1 item:

| Value | Rule |
|---|---|
| `calculatedSubtotalCents` | `round(item.calculatedSubtotal * 100)` from the immutable snapshot. |
| `negotiatedSubtotalCents` | Nullable override stored for the item. |
| `effectiveSubtotalCents` | `negotiatedSubtotalCents ?? calculatedSubtotalCents`. |
| `isPriceModified` | An override entry exists and differs from the calculated subtotal. |

An entered value equal to the calculated subtotal is canonicalized to reset and removes that item's override entry. Blank input is invalid and is not a reset. Zero is allowed only after explicit confirmation.

### 3.2 Quotation pricing

| Value | Rule |
|---|---|
| `calculatedFinalPriceCents` | Sum of all calculated item subtotals. It must equal the immutable snapshot total. |
| `effectiveFinalPriceCents` | Sum of all effective item subtotals. |
| `isPriceModified` | At least one item override entry exists. This remains true when offsetting item changes make the effective total equal the calculated total. |
| `negotiatedFinalPrice` | Effective total when at least one override exists; otherwise null. |

The effective grand total must remain within `numeric(12,2)`: 0 through PHP 9,999,999,999.99. A save that would exceed this range is rejected before persistence.

### 3.3 Item identity

- A canonical snapshot must contain unique, nonblank `itemId` values.
- New draft and snapshot validation rejects duplicate item IDs.
- Migration 007 audits persisted V1 snapshots for missing or duplicate item IDs before backfill. It aborts with an actionable error instead of guessing.
- An item update must find exactly one matching snapshot item. Zero matches returns `ITEM_NOT_FOUND`; multiple matches returns `UNSUPPORTED_QUOTATION`.

## 4. Persistence Contract

### 4.1 Immutable calculated snapshot

`quotation_document_snapshot` remains the immutable `QuotationDocumentSnapshotV1`. Do not add negotiation or audit fields to `QuotationDocumentItemSchema`, `QuotationDocumentDraftV1Schema`, or the customer-generated document payload.

This preserves the trust seam:

| Data | Writer | Mutability |
|---|---|---|
| Calculated snapshot and BOM | Authenticated customer flow during quotation creation | Immutable after creation |
| Item price overrides and audit | Authorized `manage_bookings` server action | Mutable through optimistic concurrency |
| Derived customer pricing view | Server/domain derivation | Not persisted as customer input |

### 4.2 New JSONB column

Migration `007_per_item_negotiation.sql` adds this nullable column to `public.quotation_estimates`:

```sql
item_price_overrides jsonb
```

Null means there are no canonical per-item overrides. A non-null value has this application-validated shape:

```typescript
type QuotationItemPriceOverridesV1 = {
  schemaVersion: 1;
  entries: Array<{
    itemId: string;
    negotiatedSubtotal: number;
    negotiatedBy: string;
    negotiatedAt: string;
  }>;
};
```

Required constraints and validation:

- Database check: value is null or a JSON object.
- Application schema: exact version, unique nonblank item IDs, UUID administrator IDs, offset-aware ISO timestamps, finite two-decimal money, and allowed range.
- Entries are stored in snapshot item order for deterministic serialization.
- An empty entries array is canonicalized to SQL null.
- Customer and public read models omit `negotiatedBy` and `negotiatedAt`.

### 4.3 Compatibility summary and audit fields

Every successful canonical item mutation updates the JSONB overrides and compatibility fields in the same `quotation_estimates` row update.

When one or more overrides remain:

- `negotiated_amount` equals the effective grand total, even when it happens to equal `total_estimated_amount` because item changes offset each other.
- `negotiated_by` is the administrator who performed the latest successful item mutation.
- `negotiated_at` is the timestamp of the latest successful item mutation.
- Each override entry retains its own administrator and timestamp.

When no overrides remain, all four values are cleared: `item_price_overrides`, `negotiated_amount`, `negotiated_by`, and `negotiated_at` become null.

New canonical reads determine modification state from override entries, not by comparing quotation totals. Legacy reads continue using `deriveQuotationPricing()` with the total-level columns.

### 4.4 Migration of existing negotiated totals

Migration 007 backfills only rows with a valid persisted V1 snapshot and a non-null `negotiated_amount`.

1. If the negotiated total equals the calculated total in centavos, clear the three legacy negotiation fields and create no overrides.
2. For one item, create an override for that item's line subtotal when it differs from the calculated subtotal.
3. For multiple items with a positive calculated total, allocate the negotiated total proportionally by calculated item subtotal using the largest-remainder method in centavos:
   - Compute each exact proportional share.
   - Assign the floor centavos to each item.
   - Distribute remaining centavos by descending fractional remainder.
   - Break ties by snapshot item order.
4. For a zero calculated total and positive negotiated total, assign the full negotiated total to the first snapshot item and zero to all remaining items.
5. Omit entries whose allocated subtotal equals their calculated subtotal.
6. Copy the existing `negotiated_by` and `negotiated_at` into every created override entry.
7. Recompute `negotiated_amount` from the resulting effective item subtotals and verify it exactly matches the pre-migration negotiated total.

Rows without a valid persisted V1 snapshot remain legacy and are not backfilled. Their existing total-level negotiation fields remain authoritative.

Migration 007 also repairs the known `supabase/migrations/schema.sql` quotation-constraint drift and updates `complete_schema.sql` to match the deployed schema.

### 4.5 Deployment and rollback

- Deploy migration 007 before code that selects `item_price_overrides`.
- The migration is additive and keeps all MS16 columns, so the previous application version can run after an application rollback.
- During rollback, continue maintaining `negotiated_amount`; leave the new JSONB column in place. Do not destructively drop migrated item audit data.
- A later cleanup of compatibility fields requires a separate approved milestone.

## 5. Domain Module Interfaces

The pricing module is the single seam for item and quotation price derivation. UI, PDF, public, and admin callers must not reproduce pricing formulas.

### 5.1 Server-owned schemas and derived views

Add separate schemas and types that are not part of the customer draft schema:

```typescript
type ItemPricingView = {
  itemId: string;
  productName: string;
  quantity: number;
  calculatedSubtotal: number;
  negotiatedSubtotal: number | null;
  effectiveSubtotal: number;
  isPriceModified: boolean;
};

type QuotationPricingView = {
  itemPricing: ItemPricingView[];
  calculatedFinalPrice: number;
  negotiatedFinalPrice: number | null;
  effectiveFinalPrice: number;
  isPriceModified: boolean;
};
```

Required functions in `quotationDocument.ts`:

- `deriveItemPricing(item, override): ItemPricingView`
- `deriveQuotationPricingFromItems(snapshot, overrides): QuotationPricingView`
- Existing `deriveQuotationPricing(calculated, negotiated)` remains for legacy total-level quotations only.

All three functions return values and perform no persistence, authorization, or UI side effects.

### 5.2 Sanitized read models

- Admin reads may receive per-entry audit data separately from the customer pricing view.
- Customer-owned and public reads receive `QuotationPricingView` without administrator IDs or timestamps.
- `QuotationDocumentViewModel` exposes derived pricing under a separate `itemPricing` property for rendering. It does not replace or merge mutable override fields into the immutable snapshot `items` property.
- Admin mapping includes `quotationSource: "canonical-v1" | "legacy-reconstructed"` and `supportsItemNegotiation: boolean` so UI behavior never infers capability from a reconstructed document.

## 6. Server Mutation Contract

Add a dedicated server action and keep the legacy action behind an explicit legacy guard.

```typescript
type UpdateItemNegotiatedPriceInput = {
  quotationId: string;
  itemId: string;
  negotiatedSubtotal: number | null;
  expectedUpdatedAt: string;
};

type UpdateItemNegotiatedPriceResult =
  | {
      ok: true;
      quotationId: string;
      item: ItemPricingView;
      pricing: QuotationPricingView;
      negotiatedBy: string | null;
      negotiatedAt: string | null;
      updatedAt: string;
    }
  | {
      ok: false;
      code:
        | "VALIDATION_ERROR"
        | "NOT_FOUND"
        | "ITEM_NOT_FOUND"
        | "UNSUPPORTED_QUOTATION"
        | "CONFLICT"
        | "PERSISTENCE_ERROR";
      message: string;
    };
```

`updateItemNegotiatedPrice()` must:

1. Call `requirePermission("manage_bookings")` before reading quotation data.
2. Validate UUID, nonblank item ID, ISO timestamp, null or finite two-decimal money, and range.
3. Read the quotation snapshot, overrides, totals, audit fields, and `updated_at` through the authenticated Supabase server client.
4. Reject missing, malformed, reconstructed, or duplicate-item snapshots as `UNSUPPORTED_QUOTATION`.
5. Require exactly one matching item.
6. Canonicalize a value equal to the calculated item subtotal to reset.
7. Derive the complete next override document and quotation pricing through the domain module.
8. Reject aggregate totals outside `numeric(12,2)`.
9. Update `item_price_overrides`, `negotiated_amount`, `negotiated_by`, and `negotiated_at` in one row update filtered by both `quotation_id` and the prior `updated_at`.
10. Treat zero updated rows as `CONFLICT`; never use a read-then-unconditional write.
11. Revalidate booking paths only after successful persistence.
12. Return the sanitized derived pricing view and the new row timestamp.

`updateNegotiatedPrice()` remains available only when `quotation_document_snapshot` is null. It returns `UNSUPPORTED_QUOTATION` for canonical V1 quotations after MS17, preventing new total-level overrides from bypassing item invariants.

## 7. Customer Document Contract

### 7.1 Canonical V1 quotation

For each item, render:

- Product name and quantity
- Dimensions, panel count, finish, glass, sill, and structural-waiver status where applicable
- One label, `Final item price`, using `effectiveSubtotal`

Do not render:

- BOM groups or component descriptions
- Material, hardware, labor, or margin amounts
- Unit-rate columns
- Calculated versus negotiated comparisons
- Original price or negotiation notes

Render one grand-total row using `effectiveFinalPrice`. The rendered item prices must sum exactly to the rendered grand total in centavos.

### 7.2 Legacy quotation

For a quotation without a persisted V1 snapshot, render one `Legacy quotation` summary item using the effective total-level price. Do not expose reconstructed BOM rows. This deliberately preserves arithmetic reconciliation while acknowledging that reliable product-level identity is unavailable.

### 7.3 Shared surfaces

`generateQuotationPdfHtml()` is the one customer-document renderer. The same simplified output is used by:

- Booking flow preview and print
- Admin View PDF and Download PDF
- Public quotation reference print
- Any persisted PDF generation path

Admin-only calculated and negotiated details remain in the booking management card, not in the customer document.

## 8. Admin UI and State Contract

### 8.1 Canonical quotation card

Render a list of quotation items. Each row shows:

| Field | Behavior |
|---|---|
| Product and quantity | Read-only identity from the snapshot. |
| Calculated item price | Read-only calculated line subtotal. |
| Final item price | Effective line subtotal with a Negotiated badge when overridden. |
| Edit Price | Opens the existing inline input pattern for this item. |
| Reset | Removes only this item's override. Disabled without an override. |

Below the list, show calculated grand total and effective grand total. The grand total is never directly editable. Show its Negotiated badge when any item override exists, even if the effective total equals the calculated total.

### 8.2 Editing behavior

- At most one item editor is open at a time.
- Input uses decimal mode and step `0.01`.
- Reject blank, nonnumeric, NaN, Infinity, negative, above-max, and more-than-two-decimal input.
- Zero requires a second explicit confirmation.
- Save, reset, all item edit buttons, and both PDF buttons are disabled while a mutation is pending.
- Cancel discards only local input.
- Success applies the returned `QuotationPricingView`, closes the editor, announces success, and refreshes.
- Conflict keeps the current editor open, reports stale state, refreshes persisted data, and preserves the typed input until the administrator chooses to retry or cancel.
- Use existing repository colors, radii, typography, buttons, focus styles, error patterns, and toast behavior defined by DSD-UI11 and current admin components.

Editing state remains local to `BookingsContent.tsx` unless implementation demonstrates a second consumer. Do not move ephemeral editor state into `bookingState.ts` solely for abstraction. The reducer continues owning persisted booking-list reconciliation.

### 8.3 Legacy quotation card

When `supportsItemNegotiation` is false:

- Show `Per-item editing unavailable for legacy quotation`.
- Preserve the existing total-level inline editor and `updateNegotiatedPrice()` behavior.
- Show a single read-only effective grand total in the generated customer document.

## 11. Required Test Matrix

| Arithmetic | Quantity greater than one; zero; maximum; aggregate overflow; multiple overrides; reset one; reset all; offsetting adjustments whose total equals calculated. |
