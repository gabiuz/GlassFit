## 1. Outcome and Scope

Following initial implementation of the modular add-on subsystem (`IMP-MS67` through `IMP-MS69`), user acceptance testing and architectural inspection revealed four interrelated friction points across the admin authoring portal, the Three.js 3D visualization canvas, and the customer workspace parameter dock:

1. **Admin Add-on Authoring Demands Non-Existent 2D/3D Assets:** Modular add-on products (insect screens and security grills) are 100% procedurally generated via native Three.js geometry algorithms. They have no uploaded static `.glb` files and require no standalone 2D catalog elevation images. However, the admin setup wizard currently forces all products through Step 2 (Visualization Strategy), Step 3 (Assets Upload), and Step 6 (3D Model Validation). Requiring 2D/3D asset uploads for add-ons causes setup validation failures, asset store clutter, and broken preview canvases.
2. **Screen Disappears Behind Window Glass:** When a window model includes glass infill (`glass-panel`), mounting an insect screen behind or coplanar with the glass causes the screen frames and wire mesh to become invisible or severely clipped. In Three.js, `MeshPhysicalMaterial` with optical transmission (`transmission: 0.88`) pre-renders scene objects into an offscreen transmission buffer, intentionally excluding standard transparent objects. Without cut-out alpha testing, opaque frame rail flags, and explicit render ordering, screens vanish behind glass.
3. **Unclickable Base Product Color Variations:** In the customer workspace parameter dock, the base product's aluminum finish swatches (Analok bronze, Powder Coated White, Mill aluminum, Matte Black) are currently unclickable or rendered as static badges when component materials are present. Customers are blocked from changing the framing finish of the main window.
4. **Overcrowded Parameter Dock Hierarchy:** Modular add-on controls were previously placed inside the "Design and Customization Option" accordion, mixing base window properties (dimensions, glass type, sill toggle) with secondary attachments and preventing independent frame color selection for the add-on itself.

`IMP-MS70` provides a unified specification resolving all four areas:
- **Streamlined Admin Add-on Registration with Direct Component Modeling & Validation Preview:** Reconfigures `ProductSetupWizard.tsx` and `wizardSteps.ts` so that when `is_addon = true`, the wizard features a focused 5-step authoring workflow: Step 1 (Basic Info & Addon Type), Step 2 (Components), Step 3 (Parameters & Pricing Rules), Step 4 (Validation Preview), and Step 5 (Review & Publish). Step 2 (Visualization Strategy) is omitted from wizard tabs and defaults automatically to Parametric Frame + Panels (`model_strategy = "Parametric"`, `builder_key = "frame_panels_v1"`). Step 3 (Assets) is omitted, while Step 4 (Validation) is preserved so admins can test-drive and inspect the 3D model before final confirmation and review.
- **Glass-Behind Screen Visibility & Depth Ordering:** Updates `materialClassifier.ts`, `addonGeometryBuilder.ts`, and `parametricProductBuilder.ts` to implement:
  - Alpha-tested cutout shader (`alphaTest: 0.2`, `depthWrite: true`, `depthTest: true`) for insect wire mesh, guaranteeing inclusion in the glass transmission render pass.
  - Opaque, double-sided framing rails (`transparent: false`, `side: THREE.DoubleSide`, `depthWrite: true`) with `preserveMaterial: true`.
  - Deterministic render ordering: framing and add-ons at `renderOrder = 0`, window glass panels at `renderOrder = 1`.
  - Configurable non-coplanar Z-offset (+18mm front or -18mm rear) preventing z-fighting with glass panes.
- **Interactive Base Product Color Variations:** Restores immediate clickability to all aluminum finish options in the customer workspace, updating Three.js PBR shaders in < 16ms, recalculating parametric BOM in < 50ms, and updating `variationRecipe`.
- **Dedicated "Add-on Options" Dropdown Accordion:** Extracts modular add-ons out of "Design and Customization Option" into a new dedicated collapsible accordion: `"Add-on Options"` directly below it. Inside this dedicated section, customers can toggle attachments (`None`, `Insect Screen`, `Security Grille`) and choose an independent frame finish for the add-on itself.

## 3. Non-Negotiable Invariants

1. **Zero 2D/3D Asset Requirement for Add-ons:** When authoring an add-on product (`is_addon = true`), the admin wizard must NEVER demand 2D thumbnail images or standalone fixed 3D `.glb` files. Publication to 'Active' status must complete using components, scalar parameters, and raw material pricing rules.
2. **Deterministic Glass-Behind Visibility:** When an insect screen is mounted behind or viewed through window glass, both the perimeter frame rails and the interior wire mesh MUST remain distinctly visible through the transmissive glass surface under all camera angles.
3. **Alpha-Cutout Transmission Buffer Inclusion:** The screen wire mesh must specify `alphaTest: 0.2` and `depthWrite: true`, enabling solid wire pixels to write to the depth and transmission buffers while transparent openings discard fragments.
4. **Explicit Render Ordering Contract:** All opaque frame profiles, add-on rails, and repeating grill bars must render at `renderOrder = 0`. All transmissive and transparent window glass panels must render at `renderOrder = 1` or higher.
5. **Interactive Base Color Clickability:** Aluminum frame finish options for the base window (Analok, White, Mill, Black) must ALWAYS remain interactive and clickable. Clicking any option must update the 3D model shaders on the canvas in < 16ms without resetting camera position or room photo homography.
6. **Dedicated Accordion Separation:** Modular add-on attachment controls must be rendered in their own dedicated collapsible accordion (`"Add-on Options"`) positioned directly below "Design and Customization Option".
7. **Independent Add-on Finish Customization:** The customer must be able to select the aluminum finish of the add-on frame independently of the host window's frame finish. Changing the add-on finish must not alter the host window finish, and vice versa.
8. **Strict Mutual Exclusion Invariant:** A customer can select either the Screen, the Grill, or neither (`None`), but can never enable both simultaneously. Activating Screen must unmount Grill; activating Grill must unmount Screen.
9. **Zero Em-Dashes:** In strict compliance with `BAN-PUNCT-01`, all user interface labels, option descriptions, tooltips, and code comments must use hyphens, colons, or parentheses. Never use em-dashes.
10. **Strict Type Safety:** Zero usage of `any` across TypeScript interfaces, geometry helpers, state hooks, and builder parameters per `BAN-TYPE-05`.
11. **Design Token Parity:** All buttons, swatches, accordions, and modals must reuse established Tailwind CSS tokens from `src/app/globals.css` (`rounded-[20px]`, `border-[#c3c3c3]`, `bg-[#0f1422]`, `text-[#07b6d3]`) per `BAN-UI-09`.

### 4.1 Streamlined Admin Add-on Authoring Flow (`wizardSteps.ts` and `ProductSetupWizard.tsx`)

In `src/lib/admin/products/wizardSteps.ts`, dynamically resolve wizard step navigation based on whether the product is an Add-on or a Standard product:

```typescript
export type StepKey =
  | "basic"
  | "strategy"
  | "assets"
  | "components"
  | "parameters"
  | "validation"
  | "review";

export interface WizardStepDefinition {
  key: StepKey;
  label: string;
  number: number;
}

export const STANDARD_PRODUCT_STEPS: WizardStepDefinition[] = [
  { key: "basic", label: "Basic Info", number: 1 },
  { key: "strategy", label: "Visualization", number: 2 },
  { key: "assets", label: "Assets", number: 3 },
  { key: "components", label: "Components", number: 4 },
  { key: "parameters", label: "Parameters", number: 5 },
  { key: "validation", label: "Validation", number: 6 },
  { key: "review", label: "Review", number: 7 },
];

/**
 * Streamlined 5-step authoring workflow for Add-on products (IMP-MS70).
 * Preserves structural components for uploading and configuring 3D model parts.
 * Restores 3D validation preview before final review and confirmation.
 * Visualization strategy is defaulted to Parametric Frame + Panels and omitted from tabs.
 * 2D/3D Assets tab is omitted.
 */
export const ADDON_PRODUCT_STEPS: WizardStepDefinition[] = [
  { key: "basic", label: "Basic Info", number: 1 },
  { key: "components", label: "Components", number: 2 },
  { key: "parameters", label: "Parameters & Pricing", number: 3 },
  { key: "validation", label: "Validation", number: 4 },
  { key: "review", label: "Review & Publish", number: 5 },
];

export function getStepsForProduct(isAddon?: boolean): WizardStepDefinition[] {
  return isAddon ? ADDON_PRODUCT_STEPS : STANDARD_PRODUCT_STEPS;
}

export function getNextStepKey(currentKey: StepKey, isAddon?: boolean): StepKey {
  const steps = getStepsForProduct(isAddon);
  const currentIndex = steps.findIndex((s) => s.key === currentKey);
  if (currentIndex >= 0 && currentIndex < steps.length - 1) {
    return steps[currentIndex + 1].key;
  }
  return currentKey;
}
```

In `ProductSetupWizard.tsx`:
- When `productData.is_addon === true`, render `ADDON_PRODUCT_STEPS` in the top step progress bar.
- On completing Step 1 (Basic Info), advance directly to Step 2 (Components).
- On completing Step 2 (Components), advance directly to Step 3 (Parameters & Pricing).
- On completing Step 3 (Parameters & Pricing), advance directly to Step 4 (Validation Preview).
- On completing Step 4 (Validation Preview), advance directly to Step 5 (Review & Publish).
- Visualization strategy automatically defaults to Parametric Frame + Panels (`model_strategy: "Parametric"`, `builder_key: "frame_panels_v1"`).
- The review section validates add-on publication using dimensional rules and pricing formulas, with zero checks for standalone 2D images or fixed 3D GLB assets.

### 4.2 Three.js Glass-Behind Screen Visibility & Depth Pipeline

#### 4.2.1 Alpha-Tested Cutout Screen Mesh Shader (`materialClassifier.ts`)

Reconfigure `createInsectScreenMaterial()` with `alphaTest: 0.2` and `depthWrite: true`:

```typescript
export function createInsectScreenMaterial(
  widthMm?: number,
  heightMm?: number,
  config?: InsectScreenMaterialOptions,
): THREE.MeshStandardMaterial {
  const wirePitchMm = config?.wirePitchMm ?? 2.5;
  const wireColor = config?.wireColor ?? "#181a1d";
  const effectiveWidthMm = widthMm && widthMm > 0 ? widthMm : 1200;
  const effectiveHeightMm = heightMm && heightMm > 0 ? heightMm : 1200;

  const repeatX = Math.max(1, Math.round(effectiveWidthMm / wirePitchMm));
  const repeatY = Math.max(1, Math.round(effectiveHeightMm / wirePitchMm));

  if (typeof document === "undefined") {
    return new THREE.MeshStandardMaterial({
      color: new THREE.Color(wireColor),
      transparent: true,
      alphaTest: 0.2, // Critical: Cutout geometry included in depth & transmission buffers
      depthWrite: true,
      depthTest: true,
      roughness: 0.35,
      metalness: 0.75,
      side: THREE.DoubleSide,
    });
  }

  const canvas = document.createElement("canvas");
  const size = 128;
  canvas.width = size;
  canvas.height = size;
  const ctx = canvas.getContext("2d");
  if (!ctx) {
    return new THREE.MeshStandardMaterial({
      color: new THREE.Color(wireColor),
      transparent: true,
      alphaTest: 0.2,
      depthWrite: true,
      depthTest: true,
      roughness: 0.35,
      metalness: 0.75,
      side: THREE.DoubleSide,
    });
  }

  ctx.clearRect(0, 0, size, size);
  const wireWidth = Math.round(size * (config?.wireThicknessRatio ?? 0.28));
  const halfWire = wireWidth / 2;

  ctx.strokeStyle = wireColor;
  ctx.lineWidth = wireWidth;
  ctx.strokeRect(0, 0, size, size);

  ctx.strokeStyle = "#383d44";
  ctx.lineWidth = Math.max(2, Math.round(wireWidth * 0.25));
  ctx.strokeRect(0, 0, size, size);

  ctx.strokeStyle = "#0d0e10";
  ctx.lineWidth = Math.max(1, Math.round(wireWidth * 0.12));
  ctx.strokeRect(halfWire, halfWire, size - wireWidth, size - wireWidth);

  const texture = new THREE.CanvasTexture(canvas);
  texture.wrapS = THREE.RepeatWrapping;
  texture.wrapT = THREE.RepeatWrapping;
  texture.repeat.set(repeatX, repeatY);
  texture.generateMipmaps = true;
  texture.minFilter = THREE.LinearMipmapLinearFilter;
  texture.magFilter = THREE.LinearFilter;
  texture.needsUpdate = true;

  const material = new THREE.MeshStandardMaterial({
    map: texture,
    alphaMap: texture,
    transparent: true,
    alphaTest: 0.2, // Discards transparent openings; writes solid wire to depth & transmission passes
    depthWrite: true,
    depthTest: true,
    opacity: 0.98,
    roughness: 0.35,
    metalness: 0.75,
    side: THREE.DoubleSide,
  });

  material.userData.repeatX = repeatX;
  material.userData.repeatY = repeatY;
  material.userData.wirePitchMm = wirePitchMm;

  return material;
}
```
