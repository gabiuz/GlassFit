# Implementation Specification: Mobile Visualization Workspace Viewport, Scroll Isolation, and Touch Ergonomics (IMP-MS37)

**Project:** GlassFit (Web-Based Client-Space Visualization System for Customized Glass & Aluminum)  
**Document ID:** IMP-MS37  
**Document Function:** Implementation-ready specification for the mobile photo-based visualization workspace, including a full-viewport editing shell, document scroll isolation, orientation guidance, responsive controls, and thumb-safe four-point interactions  
**Version:** 1.1.0  
**Date:** October 1, 2026  
**Owner:** Reynard John B. Rabanal (Lead Product / Systems Architect) & GlassFit Capstone Team (PUP CCIS)  
**Status:** Ready for Implementation  
**Primary Traceability:** `BRD-M4`; `PRD-F6`; `SDD-C5`; `DSD-UI4`, `DSD-UI15`; `QAD-TC52`

---

## 1. Authorized Requirement

On compact touch viewports, the photo-based visualization workspace is difficult to operate because its canvas is restricted to `55vh`, browser scrolling competes with model gestures, controls can clip or overflow, and four-point controls are hidden by the user's finger.

IMP-MS37 must deliver these outcomes:

1. A compact touch user can enter a full-viewport editing mode that gives the canvas the available space remaining after the editor header and HUD.
2. The underlying page cannot scroll, bounce, or trigger pull-to-refresh while the full-viewport editor or perspective picker is open.
3. Tapping `Done`, cancelling the picker, navigating away, or unmounting restores the exact pre-lock document styles and scroll position.
4. Mobile controls remain reachable without horizontal clipping at 320px through 430px portrait widths and supported phone landscape widths.
5. Four-point handles provide at least a 44px hit area and a visible touch proxy above the finger during touch dragging.
6. Portrait users receive dismissible guidance to rotate to landscape. Portrait remains fully supported and is never blocked.

No database migration, backend CV change, new external dependency, or Screen Orientation API lock is authorized.

## 2. Verified Current State

### 2.1 Workspace canvas and layout

`src/features/visualization/components/ProductModelWorkspace.tsx` currently:

- Limits the canvas wrapper to `maxHeight: "55vh"` and derives width from that height.
- Uses a normal document-flow layout with the canvas above the configuration sidebar below the `lg` breakpoint.
- Renders the canvas action toolbar as a single fixed-gap row containing `Fit`, `Rotate`, `Flip`, `Reset`, and `Remove`.
- Provides no compact full-viewport editing state, re-entry action, or `Done` action.

### 2.2 Gesture isolation

- `PerspectivePlanePicker.tsx` already uses pointer events, pointer capture, and `touchAction: "none"` on its SVG surface.
- `ProductModelWorkspace.tsx` calls `preventDefault()` from transform pointer-down handlers, but the interactive workspace surface has no explicit `touch-action` contract.
- Neither surface locks the root document. The picker is fixed to the viewport, but the page behind it can retain mobile overscroll behavior.
- The workspace can open the perspective picker from inside editing mode. Scroll isolation must therefore support nested lock owners without restoring scroll until the final owner exits.

### 2.3 Four-point controls

- The picker uses an invisible SVG handle radius of `18`, which produces a 36px hit diameter rather than the required 44px minimum.
- The workspace perspective corners and standard overlay corners use visible `size-4` controls with no separate 44px hit target.
- The current picker drag offset preserves the initial grab position, but it does not create a deliberate touch proxy above a finger that lands directly on a handle.

### 2.4 Existing state and save semantics

- Workspace edits already update in-memory configuration state and propagate through the existing configuration callback.
- `Apply Changes`, `Save Snapshot`, and `Continue to Comparison` own existing commit and persistence behavior.
- The new `Done` action must only leave compact full-viewport mode. It must retain current in-memory edits and must not generate a snapshot, apply changes, save a record, or navigate.

### 2.5 Existing reusable conventions

- `ProductModelWorkspace.tsx` and `PerspectivePlanePicker.tsx` are already client components, so browser lifecycle hooks belong in the visualization feature layer.
- `src/app/globals.css`, shared `Button`, existing rounded surfaces, and the `black`, `green`, `light`, `blue`, white, and neutral tokens define the visual language.
- The repository uses Node's test runner through `npx tsx --test` and has no DOM test environment dependency.

## 3. Scope

### 3.1 In scope

- Compact viewport classification based on viewport geometry and orientation, not user-agent strings.
- A full-viewport editor shell inside `ProductModelWorkspace.tsx` with a reserved header, flexible canvas stage, compact HUD, internally scrollable controls drawer, `Done` action, and safe-area padding.
- Automatic first entry on a compact touch viewport while an active product is editable, plus a visible re-entry action after `Done`.
- A nested-safe document scroll lock hook in `src/features/visualization/hooks/`.
- Portrait orientation guidance that can be dismissed for the current workspace mount and auto-dismisses after rotation to landscape.
- Responsive action controls that do not clip and that meet 44px minimum hit targets.
- Touch proxy and hit-area improvements for four-point controls in both the picker and workspace.
- Deterministic pure geometry and viewport classification tests, source contract tests, and manual mobile browser verification.

### 3.2 Out of scope

- The catalog product-detail `ProductModel3D.tsx` inspector, which traces to `PRD-F2` and is not the photo-based workspace addressed by this milestone.
- Forcing device orientation or calling `screen.orientation.lock()`.
- Fullscreen API integration.
- Changes to homography, model rendering, snapshot persistence, pricing, quotation, CV, or Supabase behavior.
- A new swipeable bottom-sheet framework or third-party gesture library.
- Continuous WebXR or AR camera tracking.

## 4. Functional Contract

### 4.1 Compact viewport classification

Classification must be expressed as a pure function and mirrored by `matchMedia` listeners:

| State | Required predicate |
|---|---|
| Compact portrait | `orientation = portrait` and viewport width `< 768px` |
| Compact landscape | `orientation = landscape`, viewport width `< 900px`, and viewport height `< 600px` |
| Non-compact | All other viewport geometries |

The implementation must not inspect user-agent strings. The hook must render a deterministic non-compact server snapshot and update after mount so server rendering and hydration do not disagree.

### 4.2 Full-viewport editor lifecycle

1. If a product is editable when a compact viewport is first detected, open full-viewport mode once for that workspace mount.
2. If the user taps `Done`, close full-viewport mode, retain all in-memory transform and configuration state, restore document scrolling, and focus the re-entry control.
3. After `Done`, show `Open full-screen editor` on the standard canvas card while the viewport remains compact and a product is editable.
4. Rotating or resizing from one compact orientation to another must keep the editor open and reflow it.
5. Resizing to non-compact while the editor is open must close compact mode, restore document scrolling, and use the existing desktop layout.
6. Removing the active product must close compact mode.
7. Browser navigation or component unmount must run the same scroll cleanup path.
8. Opening compact mode must hide the site navbar through the existing `useNavbarVisibility` contract. Closing or unmounting must release that ownership.
9. The fixed editor uses dialog semantics, moves focus into the editor, keeps keyboard focus out of the covered page, and restores focus to the re-entry control on `Done`. Escape follows `Done` only when no nested picker or modal is open.

`Done` is an editor-shell action only. Existing `Apply Changes`, `Save Snapshot`, and comparison actions remain unchanged.

### 4.3 Full-viewport geometry

The compact editor root must be a fixed overlay using `inset: 0`, `height: 100dvh`, and a three-row grid:

| Row | Contract |
|---|---|
| Header | Content-sized, contains title, orientation status, and `Done` |
| Stage | `minmax(0, 1fr)`, contains the aspect-ratio-preserving workspace canvas |
| HUD | Content-sized, contains transform actions and a `Controls` drawer trigger without changing viewport width |

Additional requirements:

- Respect `env(safe-area-inset-top)`, `env(safe-area-inset-right)`, `env(safe-area-inset-bottom)`, and `env(safe-area-inset-left)`.
- The canvas must use the full stage bounds with `max-width: 100%`, `max-height: 100%`, and its existing room-photo aspect ratio.
- Do not assign `85dvh`, `90dvh`, or another independent canvas height that can overflow after header and HUD space is added.
- The full-viewport shell must not change the desktop `55vh` canvas behavior.
- Internal panels that need vertical scrolling use their own `overflow-y: auto`, `overscroll-behavior: contain`, and `touch-action: pan-y` region. The canvas stage itself uses `touch-action: none`.
- In portrait, `Controls` opens the existing configuration inspector as a bottom drawer capped at `45dvh`. In compact landscape, it opens as a right drawer capped at the available editor height and 320px width.
- The drawer is closed by default so the stage receives maximum space. It must reuse the current inspector controls, accordions, input state, and `Apply Changes` action rather than creating a second mobile configuration model.

### 4.4 Document scroll isolation

The scroll lock must be a client hook under `src/features/visualization/hooks/useDocumentScrollLock.ts`. It must not be placed under `src/lib` because that layer is reserved for domain services and pure utilities.

The hook contract is:

1. Acquire one lock owner when `active` transitions to true.
2. On the first owner only, capture:
   - `window.scrollX` and `window.scrollY`.
   - Existing inline `overflow`, `overscrollBehavior`, `position`, `top`, `left`, `right`, `width`, and `paddingRight` values needed for restoration.
3. Apply root overflow and overscroll suppression. Use a fixed-body scroll-position fallback for iOS-compatible isolation.
4. Do not set `touch-action: none` on `body` or `html`, because doing so would also disable intentional scrolling inside the editor's controls. Apply `touch-action: none` only to interactive canvas and SVG surfaces.
5. Release one owner during effect cleanup.
6. Restore styles and call `window.scrollTo(savedX, savedY)` only when the final owner releases.
7. Repeated acquire or cleanup for the same mounted hook instance must be idempotent.

The workspace lock is active only while compact full-viewport mode is active. The perspective picker owns a lock whenever it is open. Nested workspace and picker ownership must not unlock the page when only one closes.

### 4.5 Orientation guidance

- Show the guidance when compact full-viewport mode opens in portrait and it has not been dismissed during the current workspace mount.
- Copy: `Rotate for more room` and `Landscape gives the canvas more space. You can continue in portrait.`
- Provide one action: `Continue in portrait`.
- Auto-dismiss on rotation to landscape.
- Do not block canvas interaction after dismissal and do not persist the choice beyond the current mount.
- Honor `prefers-reduced-motion`; any rotation icon animation must be removed when reduced motion is requested.
- The prompt is advisory. It must not claim to rotate the device and must not call the Screen Orientation API.

### 4.6 HUD and control accessibility

- The compact HUD must fit at 320px width without document-level horizontal overflow.
- `Fit`, `Rotate`, `Flip`, `Reset`, `Remove`, `Done`, and the re-entry action must each expose at least a 44px by 44px hit area.
- The `Controls` trigger must expose its open state with `aria-expanded` and identify the drawer with `aria-controls`.
- The HUD may wrap to two rows or use an internally scrollable horizontal strip. If a strip is used, its scrollbar may use the existing `.scrollbar-none` utility.
- Icon-only controls require accessible names and visible focus treatment.
- Destructive `Remove` styling and behavior remain unchanged.
- Desktop toolbar layout and labels remain unchanged.

### 4.7 Four-point touch ergonomics

Create pure geometry helpers in `src/features/visualization/mobileConfiguratorGeometry.ts`. Pointer mapping must subtract the interactive surface bounds before applying scale:

```text
canvasX = clamp((clientX - bounds.left) * scaleX, 0, canvasWidth)
canvasY = clamp((clientY - bounds.top - offsetCssPx) * scaleY, 0, canvasHeight)
```

`offsetCssPx` is `48` for an active touch proxy and `0` for mouse, pen, and keyboard input.

The two surfaces use the helpers differently:

1. `PerspectivePlanePicker.tsx`
   - Increase each invisible SVG hit target to `r={24}`.
   - Track the active pointer ID and pointer type so a second pointer cannot take over an active drag.
   - For touch corner drags, position the active target through the 48 CSS pixel upward proxy and render a leader line from finger contact to a high-contrast proxy reticle.
   - Clamp after offset conversion and keep the existing convex quadrilateral validation. Invalid geometry remains uncommittable.
2. `ProductModelWorkspace.tsx`
   - Wrap each visible perspective and overlay corner in a separate 44px hit target while preserving the existing 12px to 16px visual handle.
   - On a touch corner drag, render an elevated proxy reticle and leader line 48 CSS pixels above contact.
   - Preserve existing proportional scale and width or height semantics. Do not reinterpret workspace resize handles as direct homography points.

The proxy is rendered only during an active touch drag. Mouse and pen behavior must not change.

## 5. Technical Design and Ownership

### 5.1 State additions in `ProductModelWorkspace.tsx`

Use explicit state for:

- `isCompactViewport`
- `compactOrientation`
- `isMobileEditorOpen`
- `isMobileControlsOpen`
- `hasAutoOpenedMobileEditor`
- `isOrientationPromptDismissed`
- Active touch proxy data, including pointer ID, client contact, and proxy position

The full-viewport shell is presentation state. Product transform state continues to use the existing workspace state and callbacks.

The workspace canvas stage, transform toolbar, and configuration inspector must each be defined once as extracted local JSX or focused child components. Render one standard-layout branch or one compact-layout branch at a time. Do not mount duplicate canvases, duplicate inspector inputs, duplicate IDs, or competing refs.

### 5.2 Hooks

| Hook | Location | Responsibility |
|---|---|---|
| `useCompactViewport` | `src/features/visualization/hooks/useCompactViewport.ts` | Subscribe to the two compact media queries and expose hydrated orientation state |
| `useDocumentScrollLock` | `src/features/visualization/hooks/useDocumentScrollLock.ts` | Acquire and release nested-safe document scroll ownership |

Both files are client-only feature hooks. Neither file may use `any`.

### 5.3 Shared presentation components

- Add `src/features/visualization/components/MobileConfiguratorShell.tsx` as a presentation-only wrapper if keeping fixed layout, dialog focus behavior, safe areas, and the controls drawer in `ProductModelWorkspace.tsx` would make the existing component less maintainable. State and domain callbacks remain owned by the workspace.
- Add `src/features/visualization/components/TouchDragProxy.tsx` only if both workspace and picker need identical proxy markup. It must use existing tokens, remain pointer-transparent, and expose no persistence or domain logic.

### 5.4 Styling

Prefer existing Tailwind utilities and established shared components. Add narrowly named rules to `src/app/globals.css` only when safe-area or dynamic-viewport declarations cannot be expressed clearly with existing utilities. Do not introduce new colors or a new component library.

## 7. Acceptance Criteria (`QAD-TC52`)

### AC-1: Canvas expansion

Given an editable product on a compact touch viewport, when compact full-viewport mode opens, then the editor occupies `100dvh` and the canvas fills the flexible stage remaining after the header, HUD, and safe-area insets without distorting the room-photo aspect ratio.

### AC-2: Scroll isolation

Given the compact editor or perspective picker is open, when the user drags vertically on its interactive surface, then the underlying page does not scroll, bounce, or trigger pull-to-refresh.

### AC-3: Nested cleanup

Given the compact editor and nested perspective picker both own the scroll lock, when the picker closes, then the document remains locked until the compact editor also closes.

### AC-4: Exact restoration

Given the document was scrolled and had pre-existing inline styles before the first lock, when the final lock owner releases through `Done`, cancel, resize to non-compact, navigation, or unmount, then the original inline styles and scroll coordinates are restored.

### AC-5: Done semantics and re-entry

Given the user has transformed a product in compact mode, when `Done` is tapped, then compact mode closes, in-memory edits remain unchanged, no snapshot or persistence action runs, page scrolling resumes, and `Open full-screen editor` can re-enter the mode.

### AC-6: Orientation guidance

Given compact mode opens in portrait, when the prompt appears, then it states that portrait remains usable, can be dismissed for the current mount, auto-dismisses after rotation, and never attempts to force orientation.

### AC-7: No clipped controls

Given viewport widths of 320px, 360px, 375px, 390px, and 430px, when the compact HUD and configuration drawer render, then no control or document content overflows horizontally, the reused inspector scrolls internally, and all required actions remain reachable.

### AC-8: Touch targets and proxy

Given a touch pointer starts a four-point handle drag, when the drag is active, then the control has at least a 44px hit area and a high-contrast proxy reticle appears 48 CSS pixels above contact with a leader line. Mouse and pen behavior remains unchanged.

### AC-9: Geometry safety

Given a touch proxy approaches an image boundary, when its client position is mapped to canvas coordinates, then bounds offsets are subtracted before scaling, coordinates are clamped, and an invalid quadrilateral cannot be confirmed.

### AC-10: Desktop regression safety

Given a non-compact viewport, when the workspace renders and transform controls are used, then the existing desktop layout, `55vh` canvas rule, transform semantics, and persistence actions remain unchanged.

### AC-11: Accessibility and motion

Given keyboard navigation or reduced-motion preference, when the mobile editor is used, then dialog semantics isolate the covered page, controls have visible focus, icon-only buttons have accessible names, the controls trigger exposes its drawer state, focus returns to the re-entry action after `Done`, and decorative orientation or proxy motion is disabled.

### AC-12: Performance

Given a supported mid-tier mobile device, when product transforms are performed in compact mode, then the workspace continues to satisfy `QAD-VG3` at a sustained 55 FPS or better.

## 8. Verification Plan

### 8.1 Automated verification

Run:

```bash
npm run test:ms37
npm run lint
npx tsc --noEmit
npm run build
```

Automated tests must cover:

1. Compact portrait, compact landscape, boundary, and non-compact viewport classification.
2. Pointer mapping with non-zero `bounds.left` and `bounds.top`.
3. CSS-pixel-to-canvas scaling of the 48px touch offset.
4. Clamping at all four image boundaries.
5. Zero offset for mouse and pen.
6. Source contracts for fixed `100dvh` shell, safe-area handling, single-instance canvas and inspector composition, controls drawer semantics, navbar ownership, `Done`, re-entry, nested scroll lock usage, direct-surface `touch-action: none`, `r={24}`, and 44px workspace handle wrappers.
7. Existing perspective validity tests remain green.

Because the repository has no DOM test environment dependency, real scroll restoration, focus behavior, and browser overscroll behavior are mandatory manual browser checks rather than simulated unit claims.

### 8.2 Manual browser matrix

| Browser or device | Portrait | Landscape | Required checks |
|---|---:|---:|---|
| iOS Safari, current supported release | Yes | Yes | Dynamic toolbar, fixed-body scroll lock, safe areas, rotation, Done restoration |
| Android Chrome, current supported release | Yes | Yes | Pull-to-refresh suppression, pointer capture, rotation, HUD fit |
| Chrome DevTools at 320, 360, 375, 390, and 430px widths | Yes | As applicable | No clipping, targets, focus, reduced motion |
| Desktop Chrome or Firefox | N/A | N/A | Existing layout and transform regression |

For each mobile case:

1. Scroll the page before entering and record the position.
2. Enter the compact editor and drag the canvas in every direction.
3. Open and close the perspective picker while the editor remains open.
4. Drag each corner at the center and near every boundary.
5. Rotate portrait to landscape and back.
6. Tap `Done`, confirm the original page position, and re-enter.
7. Remove the active product and navigate away while locked.
8. Verify keyboard focus and reduced-motion behavior in browser emulation.

## 10. Readiness Corrections Applied

This revision resolves the blockers found during readiness review:

- Removed the incorrect `PRD-F4` trace and anchored the milestone to `PRD-F6` and `BRD-M4`.
- Replaced the incorrect `DSD-UI3` perspective-picker claim with a new `DSD-UI15` mobile shell contract.
- Added `QAD-TC52` to the authoritative QA catalog and reconciled the documentation index and milestone roadmap.
- Moved browser hooks from the prohibited `src/lib` location into the visualization feature layer.
- Defined nested scroll ownership so a child picker cannot unlock an active parent editor.
- Removed global `touch-action: none` from `body` and reserved it for interactive surfaces so internal controls can still scroll.
- Replaced conflicting canvas height percentages with one `100dvh` grid contract that reserves header, HUD, and safe-area space.
- Removed unsupported forced-orientation behavior and made landscape guidance advisory.
- Corrected pointer mapping to subtract element bounds before scaling.
- Defined `Done` as a presentation-only exit so it cannot collide with existing apply, snapshot, or persistence semantics.
- Limited the milestone to the photo-based workspace and excluded the separate product-detail inspector.
