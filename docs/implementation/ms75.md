## 1. Outcome and Scope

When administrators upload a standard architectural fixture (such as an aluminum swing door, sliding patio door, or casement window) in `/admin/products/[id]/setup`, the uploaded 3D model contains constituent hardware parts: door handles, locking latches, flush pulls, or rollers.

Under previous workflows:
1. All hardware meshes uploaded with a product were treated as static, immutable geometry. A door handle could not be swapped for an alternative handle (e.g. replacing a basic lever with an electronic digital lock or round privacy knob) without completely re-exporting and re-authoring a whole new 3D model.
2. Even if a part was marked as removable via `isRemovable`, the system could only toggle visibility on or off. It provided no mechanism to swap the part with a modular accessory from the catalog or reposition it to accommodate architectural handings (such as flipping a door handle from right-hand opening to left-hand opening, or adjusting a lock from bottom sill height to mid-height).

`IMP-MS75` transforms the administrative Part Inspector (`PartInspectorDrawer.tsx`) and auto-detection engine (`autoDetection.ts`) into a smart hardware slot configuration system:
- **Designate Parts as Swappable Accessory Slots:** Administrators can inspect any uploaded 3D sub-mesh (e.g. `door_handle_exterior`) and toggle *"Swappable with Accessories"*. This flags the part as a dynamic anchor slot that can receive compatible accessories created under `IMP-MS74`.
- **Target Category & Allowed Accessories Binding:** Administrators designate the compatible accessory category (e.g. `Handle`, `Lock`, `Roller`, `Hinge`) and choose whether the slot accepts all active accessories in that category or a restricted set of approved accessory items.
- **Strict Positional Placement Rules (Left/Right & Bottom/Up):**
  - **Horizontal Placement (Left vs Right):** Configures lateral handings. The mathematical invariant dictates that shifting between Left and Right stays on the exact same X-axis coordinate relative to the panel boundary (e.g. `x = -width/2 + offset` on the left stile versus `x = +width/2 - offset` on the right stile), maintaining the anchor plane without shifting Z depth or Y elevation.
  - **Vertical Placement (Bottom vs Up):** Configures elevation handings. Shifting between Bottom and Up stays on the exact same Y-axis vertical alignment line (e.g. `y = -height/2 + offset` near the bottom rail versus `y = +height * ratio` at mid-height or upper rail), maintaining horizontal and depth stability.
- **Automated Filename Auto-Detection (`autoDetection.ts`):** Uploading files or scene nodes containing keywords such as `handle`, `doorknob`, `lever`, `pull`, `lock`, `latch`, `deadbolt`, `smartlock`, `hinge`, or `roller` automatically flags them as swappable accessory slots, sets their target category, and applies canonical positional presets.
- **Interactive Test-Drive Validation Sandbox (`ValidationWorkspaceSection.tsx`):** In Step 6 (and Step 4's interactive canvas), the admin can test-drive swapping accessories from a live dropdown and toggle Left/Right and Bottom/Up positions in real time (< 16ms), ensuring perfect spatial alignment and zero clipping prior to catalog publication.

## 3. Non-Negotiable Invariants

1. **Strict Lateral X-Axis Invariant (Left vs Right):** When a component is positioned on the Left or Right, its spatial translation must strictly move along the lateral boundary of the host fixture or panel sash. It must preserve its reference anchor plane on the X axis without causing unwanted Y-axis elevation drift or Z-axis depth displacement.
2. **Strict Vertical Y-Axis Invariant (Bottom vs Up):** When a component is positioned at the Bottom or Up, its spatial translation must strictly move along the vertical alignment line on the Y axis. It must preserve its horizontal X-axis placement and Z-axis depth without distortion.
3. **Hardware Category Compatibility:** An accessory slot mapped to category `'handle'` must only accept accessories registered with `accessory_category = 'handle'`. Cross-category binding (e.g. mounting a bottom roller into a door handle slot) is strictly prohibited.
4. **Non-Destructive Default Fallback:** If no accessory is selected by a customer, the host fixture's original uploaded sub-mesh remains active and rendered at its default baseline position.
5. **Zero Em-Dashes:** All drawer headers, tooltips, position labels, and code comments must strictly avoid em-dashes per `BAN-PUNCT-01`. Use hyphens, colons, or parentheses.
6. **Strict Type Safety:** Zero usage of `any` across TypeScript interfaces, component props, and position rule schemas per `BAN-TYPE-05`.
7. **Design Token Parity:** All UI additions to `PartInspectorDrawer.tsx` and `ValidationWorkspaceSection.tsx` must reuse established Tailwind CSS tokens (`rounded-[8px]`, `rounded-[10px]`, `border-[#c3c3c3]`, `bg-[#0f1422]`, `text-[#07b6d3]`) per `BAN-UI-09`.

## 4. Technical Design & User Experience Architecture

### 4.1 Positional Placement Rule Schema

Define the positional placement rule structure for swappable components:

```typescript
export type HorizontalPosition = 'left' | 'right';
export type VerticalPosition = 'bottom' | 'up';

export interface AccessoryPositionOptions {
  allowHorizontalToggle: boolean;
  defaultHorizontal: HorizontalPosition;
  horizontalOffsetMm: number; // Lateral offset from edge
  
  allowVerticalToggle: boolean;
  defaultVertical: VerticalPosition;
  verticalOffsetMm: number; // Offset from bottom or top rail
}

export interface AccessorySlotConfig {
  isAccessorySlot: boolean;
  accessoryCategory: 'handle' | 'lock' | 'hinge' | 'roller' | 'other' | null;
  allowedAccessoryIds: string[] | null; // null indicates all accessories in category are permitted
  positionOptions: AccessoryPositionOptions;
}
```

### 4.3 Automated Filename Auto-Detection (`autoDetection.ts`)

In `src/lib/admin/products/autoDetection.ts`, extend the detection heuristic:

```typescript
export function autoDetectAccessorySlot(filename: string): Partial<PartInspectorConfig> | null {
  const lower = filename.toLowerCase();

  // Handles & Knobs
  if (/handle|doorknob|knob|lever|pull_bar|pullhandle/.test(lower)) {
    return {
      isAccessorySlot: true,
      accessoryCategory: 'handle',
      presentationCategory: 'Hardware',
      dimensionBinding: 'FIXED',
      positionOptions: {
        allowHorizontalToggle: true,
        defaultHorizontal: 'right',
        horizontalOffsetMm: 45,
        allowVerticalToggle: false,
        defaultVertical: 'up',
        verticalOffsetMm: 1000,
      },
    };
  }

  // Locks, Latches, Smart Locks
  if (/lock|latch|deadbolt|smartlock|electric_lock/.test(lower)) {
    return {
      isAccessorySlot: true,
      accessoryCategory: 'lock',
      presentationCategory: 'Hardware',
      dimensionBinding: 'FIXED',
      positionOptions: {
        allowHorizontalToggle: true,
        defaultHorizontal: 'right',
        horizontalOffsetMm: 35,
        allowVerticalToggle: true,
        defaultVertical: 'up',
        verticalOffsetMm: 1000,
      },
    };
  }

  // Rollers & Guides
  if (/roller|wheel|guide_wheel|track_roller/.test(lower)) {
    return {
      isAccessorySlot: true,
      accessoryCategory: 'roller',
      presentationCategory: 'Hardware',
      dimensionBinding: 'FIXED',
      positionOptions: {
        allowHorizontalToggle: false,
        defaultHorizontal: 'left',
        horizontalOffsetMm: 0,
        allowVerticalToggle: false,
        defaultVertical: 'bottom',
        verticalOffsetMm: 15,
      },
    };
  }

  return null;
}
```

## 5. Database Schema & Data Models

### 5.1 Supabase PostgreSQL Migration (`020_product_components_accessory_slots.sql`)

```sql
-- Migration: 020_product_components_accessory_slots.sql
-- Description: Adds accessory slot flags, target categories, and position options to public.product_components

ALTER TABLE public.product_components
ADD COLUMN IF NOT EXISTS is_accessory_slot BOOLEAN NOT NULL DEFAULT false,
ADD COLUMN IF NOT EXISTS accessory_category VARCHAR(50) NULL,
ADD COLUMN IF NOT EXISTS allowed_accessory_ids UUID[] NULL,
ADD COLUMN IF NOT EXISTS position_options JSONB NOT NULL DEFAULT '{
  "allowHorizontalToggle": true,
  "defaultHorizontal": "right",
  "horizontalOffsetMm": 45,
  "allowVerticalToggle": false,
  "defaultVertical": "up",
  "verticalOffsetMm": 1000
}'::jsonb;

-- Validate accessory category constraint
ALTER TABLE public.product_components
DROP CONSTRAINT IF EXISTS check_component_accessory_category;

ALTER TABLE public.product_components
ADD CONSTRAINT check_component_accessory_category
CHECK (
  (is_accessory_slot = false AND accessory_category IS NULL) OR
  (is_accessory_slot = true AND accessory_category IN ('handle', 'lock', 'hinge', 'roller', 'other'))
);

-- Index for querying products with swappable hardware slots
CREATE INDEX IF NOT EXISTS idx_product_components_accessory_slots
ON public.product_components (product_id, is_accessory_slot)
WHERE is_accessory_slot = true;
```
