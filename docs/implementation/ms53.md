## 1. Outcome and Scope

Detect the actual reference sheet automatically when the photo provides sufficient evidence. Customers should normally review an existing outline rather than map four corners. Selecting the wrong rectangular object must not silently establish metric calibration. Mapping remains available when detection fails, is ambiguous, or needs correction.

This begins a corrective sequence: MS53 reference detection, [MS54](ms54.md) projective measurement, [MS55](ms55.md) plane validity and recovery, [MS56](ms56.md) model and quotation synchronization, and [MS57](ms57.md) release validation. Existing MS45-MS52 files remain preserved. This sequence replaces their conflicting assumptions about automatic paper-size identification, global pixel scale, and guaranteed accuracy when implemented together. Detection alone does not enable the corrected accuracy claim.

## 3. Non-Negotiable Invariants

1. Automatically locating paper is separate from knowing its physical dimensions and verifying its placement plane.
2. An arbitrary projected quadrilateral cannot uniquely identify Short, A4, or Long paper from its image aspect alone. Request the actual standard before metric measurement. A suggested format remains unconfirmed.
3. Preserve exact dimensions: Short 215.9 x 279.4 mm, A4 210 x 297 mm, Long 215.9 x 330.2 mm. Do not confuse Philippine 13-inch Long with 14-inch Legal.
4. Never interpret a detector score as a probability of physical measurement accuracy. Never hardcode 0.95 confidence for manually pinned corners.
5. Use installed OpenCV and NumPy. No new detector weights, training service, dependency, or continuous camera tracking is required by this plan.

## 4. Detection and Selection Contract

### 4.1 Candidate Pipeline

1. Decode and normalize orientation once. Preserve the transforms between original, analysis, and workspace images as specified by MS54.
2. Retain multiple illumination paths, including local contrast and edges. Absolute brightness and whiteness are supporting signals only, because sample 1 places the sheet in shadow.
3. Generate convex four-corner proposals at bounded analysis resolutions; refine shortlisted boundaries against higher-resolution image evidence. Do not aggressively close separate objects into one contour.
4. Validate four distinct vertices, cyclic order, nonzero area, edge support, supported image region, and boundary stability across processing paths. Reject cropped or insufficiently observed boundaries for automatic acceptance.
5. Score evidence such as continuous boundary support, interior consistency, local boundary contrast, and stability. Image-space right angles and apparent paper ratios must not be hard gates under perspective.
6. Deduplicate by polygon overlap and corner proximity normalized by image size. Centroid distance alone must not merge nested panel outlines or different nearby objects.
7. Return ranked, bounded candidates and reason codes. Require both a validated best-candidate threshold and separation from the next distinct candidate. Tune thresholds on MS57 development fixtures, then freeze them before holdout testing.
8. If evidence remains weak or conflicting, return an abstention. Do not lower thresholds simply to force a sheet result in every photograph.

### 4.2 Proposed Result Fields

Extend the existing response additively and validate it with Pydantic and explicit TypeScript types. Proposed fields are planning contracts, not existing API guarantees.

| Field | Meaning |
|---|---|
| `detection_outcome` | `candidate_found`, `ambiguous`, or `not_found` |
| `candidates` | Bounded list with candidate ID, four cyclic corners, score components, and rejection reasons |
| `selected_candidate_id` | Accepted automatic selection or null |
| `reference_source` | `auto_detected`, `candidate_selected`, or `manual_corners` |
| `paper_standard` / `paper_standard_confirmed` | Actual declared standard and whether the user supplied or confirmed it |
| `coordinate_space` / image dimensions | Explicit source coordinate frame for every returned point |

Keep `POST /analyze-image` as the existing endpoint. Missing or invalid new fields must not be promoted into successful metric calibration by a legacy default.

### 4.3 Customer Flow

| Situation | Customer interaction | Result |
|---|---|---|
| One sufficiently supported candidate | Show its outline automatically; confirm actual paper format and same-plane placement | No four-corner mapping required |
| Multiple plausible candidates | Let customer select an existing outline or choose manual correction | Candidate selection precedes geometry calculation |
| Wrong candidate | Existing reject/change action, then another candidate or manual pins | Rejected candidate cannot remain the metric source |
| No reliable boundary | Offer existing four-corner editor, retake guidance, manual tape dimensions, or approximate preview | No false automatic success |
| Customer changes paper format | Recompute MS54 transform and invalidate previous dimension acceptance | Never retain measurements from the old size |

Use existing dialogs, focus behavior, pointer controls, mobile magnifier, and shared design tokens. A review confirmation is not manual corner mapping. Keep approximate preview available with its source visibly labeled.

## 5. Step-by-Step Implementation Plan

1. Capture current detector outputs on the supplied samples without treating them as correct labels; annotate actual visible sheet boundaries for evaluation.
2. Separate localization from format selection in `paper_calibration.py`, API response types, and `imageApi.ts`.
3. Implement deterministic evidence scoring, deduplication, candidate separation, and explicit abstention.
4. Connect explicit automatic mode through `ProductAwareUploadPage.tsx` and `DirectVisualizationPage.tsx` without replacing existing upload validation.
5. Reuse confirmation and pinning dialogs for candidate review and fallback; hand the selected corners to MS54 and placement evidence to MS55.
6. Register QAD-TC68 and reconcile upstream requirement wording during implementation only.

## 6. Verification and Acceptance Criteria

| Test ID | Scenario | Expected outcome | Severity |
|---|---|---|---|
| QAD-TC68.1 | Shadowed paper beside bright window | Correct outline or explicit abstention; frame never becomes accepted paper | P0 |
| QAD-TC68.2 | White sheet beside panel and doorway | Correct sheet selected automatically on eligible fixture | P0 |
| QAD-TC68.3 | Several similar rectangular objects | Ambiguity returned unless evidence separates the actual sheet | P0 |
| QAD-TC68.4 | Strongly foreshortened sheet | No rejection solely for non-right image angles or apparent aspect | P0 |
| QAD-TC68.5 | Unknown format, including rotated sheet | User declaration required; image aspect cannot silently choose metric size | P0 |
| QAD-TC68.6 | User rejects outline or edits corners | Source updates and old transform is invalidated | P0 |
| QAD-TC68.7 | Blank wall or rectangle without paper | No unsupported calibrated status | P0 |

Planned coverage extends `fastapi-service/tests/test_paper_calibration.py`, `tests/unit/calibrationIntake.test.ts`, and `tests/unit/paperConfirmationGateway.test.ts`. Use MS57 for quantitative release gates and commands. No tests or application changes are part of this document-only delivery.

## 7. Risks and Mitigations

Plain paper may be visually indistinguishable from another rectangle in difficult lighting. Candidate review and abstention are required recovery paths. A successful outline still needs MS54 geometry and MS55 placement eligibility before it may drive model dimensions.
