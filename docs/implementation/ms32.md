## 1. Executive Summary & Problem Context

In architectural glass and aluminum fabrication, small and medium enterprise (SME) owners require continuous visibility into sales pipelines, inquiry volume, pricing trends, and product demand to make data-driven operational decisions.

### 1.1 The Reported Defect & Architectural Root Cause

Under the current implementation in `src/features/admin/settings/SettingsContent.tsx`:

1. **Placeholder Export Handlers:** The `DataManagementCard` component renders three actionable items:
   - "Booking Records" with an "Export CSV" button.
   - "Product Records" with an "Export CSV" button.
   - "System Backup" with a "Download Backup" button.
   Each button handler (`handleExportBookings`, `handleExportProducts`, `handleExportBackup`) simply dispatches an ephemeral client-side toast (e.g., `onToast("Booking CSV export coming soon.", "success")`). No network requests are initiated, no route handlers exist, and no data is extracted.
2. **Hardcoded Backup Audit State:** The backup section displays static text `const lastBackupDate = "Sep 12, 2026 · 10:30 AM"`. The database table `public.system_preferences` contains no column to track real backup operations, leaving the administrator without knowledge of when a true backup was last executed.
3. **Missing Business Intelligence for the Owner:** Fabricator owners and managers currently have no mechanism to evaluate business telemetry (such as conversion rates from Pending to Done, gross quotation pipeline valuation in PHP, customer messaging platform preferences between Facebook Messenger and Viber, or high-demand architectural profiles).
4. **Standard CSV Readability Deficit:** Naive database CSV dumps emit raw unformatted columns that lack business context, currency formatting, or summary aggregations. The business owner must manually calculate totals, filter out foreign keys, and reconstruct pipeline stages.

### 1.2 Required System Behavior

To fulfill the requirements of `IMP-MS32`, the Data Management subsystem must deliver a cohesive business intelligence and data preservation suite:

1. **GlassFit-Connected CSV Architecture:**
   - **Executive Metadata Header:** Every generated CSV file contains a GlassFit branded header block with system metadata, generation timestamp in Philippine Standard Time (PST), requesting operator identity, and report classification.
   - **Executive KPI Snapshot Block:** Prior to the raw transaction table, the CSV embeds an executive summary block displaying high-level business indicators (Total Consultations, Triage Conversion Rate, Gross Pipeline Value in PHP, Average Quotation Size, and Channel Distribution).
   - **RFC 4180 and UTF-8 BOM Standard:** Files are formatted with RFC 4180 quote escaping, formula injection protection, and prepended UTF-8 Byte Order Mark (`\uFEFF`) to guarantee flawless opening in Microsoft Excel and Google Sheets without character corruption.
2. **On-Screen Native Business Analytics Modal with Visual Charts:**
   - Because raw CSV files cannot display dynamic graphics upon download, GlassFit bridges the gap with an interactive, on-screen **Business Intelligence Modal** (`BusinessIntelligenceModal.tsx`).
   - Accessible directly from `DataManagementCard`, the modal renders high-level KPI cards and native visual charts built strictly with pure SVG and Tailwind CSS 4 tokens (zero external chart library dependencies, adhering to `BAN-UI-09`):
     - **Status Pipeline Donut Chart:** Visual breakdown of bookings across Pending (`#07b6d3`), Ongoing (`#f59e0b`), and Done (`#10b981`).
     - **Consultation Volume and Valuation Trend Chart:** SVG polyline and gradient area chart showing inquiry flow over weeks/months.
     - **Customer Messaging Channel Share:** Horizontal segmented progress bar contrasting Facebook Messenger versus Viber inquiries.
     - **Product Catalog Distribution:** Breakdown of active versus draft products and category popularity.
3. **Comprehensive System Backup Engine:**
   - Creates a complete, deterministic, portable JSON snapshot of the enterprise tenant data: `system_preferences`, `products`, `product_templates`, `product_parameters`, `product_components`, `structural_rules`, `raw_materials`, `booking_requests`, `signed_booking_links`, `quotation_estimates`, and `quotation_items`.
   - Compiles a Cloudflare R2 binary storage manifest of all uploaded `.glb` models and quotation PDF keys.
   - Strictly redacts sensitive credentials, passwords, and API tokens (per `BAN-AUTH-04`).
   - Generates an SHA-256 cryptographic checksum for data integrity verification.
   - Automatically records `last_backup_at` and `last_backup_by` in `public.system_preferences` and reactively refreshes the UI date readout.
4. **Role-Based Security Gates:**
   - Booking and product exports require active `manage_settings` or `manage_bookings` permissions (accessible to Owner and Manager).
   - System Backup download is restricted exclusively to the `Owner` role (returning 403 Forbidden for Staff or unauthorized accounts).

### 1.3 Scope Boundaries & Non-Goals

- **Non-Goal (Automated Periodic Cron Backups):** `IMP-MS32` implements immediate on-demand manual system backup generation triggered by the Owner; automated cloud cron backups remain part of Supabase infrastructure management.
- **Non-Goal (External Charting Libraries):** No third-party charting libraries (such as Chart.js, Recharts, or D3) will be introduced. All visual charts are implemented via native pure SVG and Tailwind CSS 4 components, maintaining repository dependency integrity per `BAN-UI-09`.
- **Non-Goal (Binary Cloudflare R2 Tarball):** The system backup outputs a structured JSON snapshot containing relational records and an R2 asset manifest, rather than streaming gigabytes of binary mesh files directly through Next.js serverless lambdas.

### 3.3 Atomic Stored Procedure: `public.record_system_backup`

To guarantee that the audit timestamp updates synchronously with backup payload compilation, define a Security Definer function:

```sql
-- 2. Stored function to atomically record system backup execution
CREATE OR REPLACE FUNCTION public.record_system_backup(
    p_admin_id UUID
)
RETURNS TIMESTAMPTZ
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, pg_temp
AS $$
DECLARE
    v_updated_at TIMESTAMPTZ;
    v_is_owner BOOLEAN;
BEGIN
    -- Verify that the caller is an active Owner administrator
    SELECT EXISTS (
        SELECT 1 FROM public.profiles p
        JOIN public.admin_roles r ON r.role_id = p.admin_role_id
        WHERE p.profile_id = p_admin_id
          AND p.account_type = 'Admin'
          AND p.status = 'Active'
          AND r.role_name = 'Owner'
    ) INTO v_is_owner;

    IF NOT v_is_owner THEN
        RAISE EXCEPTION 'Unauthorized: Only an active Owner administrator may record system backups'
            USING ERRCODE = '42501';
    END IF;

    -- Update the singleton system preferences record
    UPDATE public.system_preferences
    SET last_backup_at = now(),
        last_backup_by = p_admin_id,
        updated_at = now()
    WHERE singleton_key = 'GLOBAL_PREFERENCES'
    RETURNING last_backup_at INTO v_updated_at;

    RETURN v_updated_at;
END;
$$;
```

### 3.4 Aggregated Business Analytics Function: `public.get_admin_business_analytics`

To eliminate client-side over-fetching and power on-screen visual charts with minimal latency, provide an atomic PostgreSQL aggregation function:

```sql
-- 3. Stored function for high-performance business analytics aggregation
CREATE OR REPLACE FUNCTION public.get_admin_business_analytics(
    p_start_date TIMESTAMPTZ DEFAULT NULL,
    p_end_date TIMESTAMPTZ DEFAULT NULL
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, pg_temp
AS $$
DECLARE
    v_result JSONB;
    v_start TIMESTAMPTZ := COALESCE(p_start_date, '1970-01-01 00:00:00+00'::timestamptz);
    v_end TIMESTAMPTZ := COALESCE(p_end_date, now());
BEGIN
    -- Verify caller is an authenticated administrator
    IF NOT (public.is_admin() OR public.has_admin_permission('manage_settings')) THEN
        RAISE EXCEPTION 'Unauthorized: Administrative access required for analytics'
            USING ERRCODE = '42501';
    END IF;

    SELECT jsonb_build_object(
        'overview', (
            SELECT jsonb_build_object(
                'total_bookings', count(*),
                'pending_count', count(*) FILTER (WHERE br.status = 'Pending'),
                'ongoing_count', count(*) FILTER (WHERE br.status = 'Ongoing'),
                'done_count', count(*) FILTER (WHERE br.status = 'Done'),
                'total_estimated_value', COALESCE(sum(qe.total_estimated_amount), 0),
                'total_negotiated_value', COALESCE(sum(COALESCE(qe.negotiated_amount, qe.total_estimated_amount)), 0),
                'avg_quotation_value', COALESCE(round(avg(COALESCE(qe.negotiated_amount, qe.total_estimated_amount)), 2), 0)
            )
            FROM public.booking_requests br
            LEFT JOIN public.signed_booking_links sbl ON sbl.link_id = br.link_id
            LEFT JOIN public.quotation_estimates qe ON qe.quotation_id = sbl.quotation_id
            WHERE br.created_at >= v_start AND br.created_at <= v_end
        ),
        'platforms', (
            SELECT jsonb_build_object(
                'messenger_count', count(*) FILTER (WHERE br.selected_platform = 'Messenger'),
                'viber_count', count(*) FILTER (WHERE br.selected_platform = 'Viber'),
                'other_count', count(*) FILTER (WHERE br.selected_platform NOT IN ('Messenger', 'Viber') OR br.selected_platform IS NULL)
            )
            FROM public.booking_requests br
            WHERE br.created_at >= v_start AND br.created_at <= v_end
        ),
        'catalog', (
            SELECT jsonb_build_object(
                'total_products', count(*),
                'active_products', count(*) FILTER (WHERE p.status = 'Active'),
                'draft_products', count(*) FILTER (WHERE p.status != 'Active'),
                'avg_base_price', COALESCE(round(avg(p.base_price), 2), 0)
            )
            FROM public.products p
        ),
        'product_distribution', (
            SELECT COALESCE(jsonb_agg(sub), '[]'::jsonb)
            FROM (
                SELECT p.product_type AS type_name, count(*) AS count
                FROM public.products p
                GROUP BY p.product_type
                ORDER BY count DESC
            ) sub
        ),
        'monthly_trends', (
            SELECT COALESCE(jsonb_agg(trend_row), '[]'::jsonb)
            FROM (
                SELECT
                    to_char(date_trunc('month', br.created_at), 'YYYY-MM') AS month_label,
                    count(*) AS count,
                    COALESCE(sum(COALESCE(qe.negotiated_amount, qe.total_estimated_amount)), 0) AS total_value
                FROM public.booking_requests br
                LEFT JOIN public.signed_booking_links sbl ON sbl.link_id = br.link_id
                LEFT JOIN public.quotation_estimates qe ON qe.quotation_id = sbl.quotation_id
                WHERE br.created_at >= (now() - interval '6 months')
                GROUP BY date_trunc('month', br.created_at)
                ORDER BY date_trunc('month', br.created_at) ASC
            ) trend_row
        )
    ) INTO v_result;

    RETURN v_result;
END;
$$;
```

## 4. GlassFit-Connected CSV Design Specification

### 4.1 Design Philosophy: Connecting CSV to GlassFit

Standard CSV files exported from raw SQL tables present several challenges:
- Column names are raw snake_case database identifiers without plain English meanings.
- No executive context explains when the file was created, who authorized it, or what business filters were applied.
- Opening a raw CSV in Microsoft Excel on Windows machines frequently corrupts Philippine Peso symbols (`₱`) or truncates leading phone digits due to lack of UTF-8 Byte Order Marks.
- Spreadsheets treat text starting with `=`, `+`, `-`, or `@` as formulas, posing a security vulnerability (CSV injection).

A "GlassFit-Connected CSV" overcomes these shortcomings through four design conventions:
1. **GlassFit Branded Executive Banner:** Styled comment block (`#`) identifying the enterprise system, document purpose, generation timestamp (PST), requesting operator name, and role.
2. **Executive KPI Summary Block:** High-level metrics placed at the very top of the CSV file, allowing the owner to instantly read overall sales performance, conversion rates, and channel ratios without writing formulas.
3. **Structured Relational Transactions Table:** Standardized RFC 4180 columns with clean English labels, localized Philippine currency formatting (PHP), and human-readable consultation statuses.
4. **Excel Compatibility & UTF-8 BOM:** Prepending the byte sequence `0xEF, 0xBB, 0xBF` (`\uFEFF`) guarantees that Excel displays UTF-8 characters cleanly and accurately.

### 4.4 RFC 4180 Escaping & Formula Injection Sanitization

All CSV fields must be formatted using a deterministic helper module `src/lib/export/csvFormatter.ts`:
1. **Field Escaping:** If a value contains a comma (`,`), double quote (`"`), newline (`\n`), or carriage return (`\r`), it must be enclosed in double quotes. Existing double quotes must be doubled (`""`).
2. **Formula Injection Sanitization:** Any text value starting with `=`, `+`, `-`, `@`, `\t`, or `\r` must be prefixed with a single quote (`'`) to disable automated formula execution in spreadsheet engines.
3. **Null Handling:** Null or undefined values format as empty strings `""` rather than emitting `"null"` or `"undefined"`.

### 5.3 Native Visual Chart Specifications

#### A. Status Distribution Donut Chart (`StatusDonutChart.tsx`)
- Computes circumference using standard SVG circle trigonometry: `C = 2 * pi * r`.
- Renders segmented arcs via `strokeDasharray` and `strokeDashoffset`.

## 6. System Backup Engine & Tenant Snapshot Protocol

### 6.1 Comprehensive Tenant Backup Scope

When the Owner triggers "Download Backup", the backend compiles a structured, portable JSON snapshot encompassing all relational state:

| Snapshot Partition | Included Database Tables & Entities | Description |
|---|---|---|
| `preferences` | `public.system_preferences` | Business name, contact email, operating hours, and schedule ranges |
| `catalog` | `public.products`, `public.product_templates`, `public.product_parameters` | Complete architectural product definitions and dimensional limits |
| `components` | `public.product_components`, `public.raw_materials` | 3D component bindings, dimension drivers, span ratios, and raw material pricing rates |
| `rules` | `public.structural_rules` | Dynamic engineering guardrails, panel mutation rules, and waiver conditions |
| `consultations` | `public.booking_requests`, `public.signed_booking_links` | Customer consultation requests, triage statuses, and signed booking references |
| `quotations` | `public.quotation_estimates`, `public.quotation_items` | Frozen quotation calculations, bill of materials snapshots, and negotiated prices |
| `identity_audit`| `public.profiles` (admin/customer metadata), `public.admin_email_change_events` | User accounts, roles, and administrative audit trails (strictly excluding password hashes) |
| `asset_manifest`| Compiled manifest of Cloudflare R2 object keys | Array of `.glb` model URLs, room photo keys, and quotation PDF paths |

### 6.2 Security, Credential Redaction & Role Protection

1. **Owner-Only Authorization:**
   - System backup contains company-confidential commercial and customer transaction data.
   - The route handler `/api/admin/export/backup` and the database procedure `record_system_backup` strictly verify that the authenticated user holds the `Owner` administrative role.
   - Unauthorized requests immediately receive `403 Forbidden`.
2. **Credential Redaction (BAN-AUTH-04):**
   - The backup compiler explicitly omits database passwords, Supabase service role keys, session cookies, auth tokens, and encrypted credentials.
3. **Cryptographic Checksum:**
   - The backend computes an SHA-256 hash over the serialized JSON table payload and attaches it to the backup envelope header:
     ```json
     {
       "glassfit_backup_version": "1.0.0",
       "generated_at": "2026-09-30T06:30:00.000Z",
       "authorizing_owner_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
       "checksum_sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
       "record_counts": {
         "products": 14,
         "raw_materials": 24,
         "product_components": 68,
         "booking_requests": 142,
         "quotation_estimates": 142
       },
       "data": { ... }
     }
     ```

### 6.3 Live Audit Tracking & UI Date Synchronization

Upon successful backup payload generation:
1. The route handler calls `public.record_system_backup(user.id)`.
2. PostgreSQL writes the current timestamp into `system_preferences.last_backup_at` and records `last_backup_by`.
3. The UI state updates the displayed date in `DataManagementCard` from `system_preferences.last_backup_at`, formatted via `new Intl.DateTimeFormat` (e.g., `Sep 30, 2026 · 2:30 PM`), replacing the obsolete hardcoded placeholder.
