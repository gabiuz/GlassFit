## 1. Outcome and Scope

When clients configure architectural doors or windows in the GlassFit visualization workspace (`ProductModelWorkspace.tsx`), hardware customization is often a decisive factor in their purchase decision. For example, a homeowner ordering an exterior glass swing door may want to compare a classic lever handle against a keyless smart electronic lock, or swap a standard door pull for a round privacy knob. Furthermore, the physical opening direction (Left-Hand vs Right-Hand swing) determines whether the handle must be positioned on the left stile or the right stile.

Previously, the client workspace lacked any mechanism to customize sub-component hardware:
1. Architectural fixtures loaded a single static GLB mesh where handles and locks were permanently fixed. Customers could not preview alternative hardware styles or finishes on the 3D canvas.
2. Handing adjustments were impossible. If a door was exported with a right-mounted handle, clients could not switch the handle to the left side to match their room layout.
3. In quotation handoffs and consultation PDFs, hardware was bundled as an opaque part of base pricing. Fabricators had no record of client hardware choices, leading to miscommunication during site oculars and material procurement.

`IMP-MS76` completes the hardware accessories architecture by connecting the customer 3D workspace, the parametric assembly engine, the quotation pricing engine, and the consultation PDF:
- **Customer Workspace Hardware & Accessories Dock:** When a customer selects a product containing swappable accessory slots (authored under `IMP-MS75`), a dedicated "Hardware & Accessories" dock appears in the workspace parameter sidebar. Customers can browse compatible accessories (e.g. Lever Handle, Round Doorknob, Smart Digital Lock) with instant visual cards, price deltas, and hardware finish swatches (Matte Black, Brushed Chrome, Satin Brass, Stainless Steel).
- **Interactive Handing Controls (Left/Right & Bottom/Up):**
  - **Left vs Right Positional Toggle:** If the slot supports horizontal selection, clients can click `[ Left Side ]` or `[ Right Side ]`. Following the strict spatial rule, the accessory translates laterally along the X axis (`x = -panelWidth/2 + marginX` vs `x = +panelWidth/2 - marginX`), remaining completely stable on the Y and Z axes.
  - **Bottom vs Up Positional Toggle:** If the slot supports vertical selection, clients can click `[ Bottom ]` or `[ Up / Mid ]`. Following the strict spatial rule, the accessory translates vertically along the Y axis (`y = -panelHeight/2 + marginY` vs `y = +panelHeight * ratio`), remaining completely stable on the X and Z axes.
- **Three.js Runtime Mesh Replacement (`parametricProductBuilder.ts`):** Dynamically unmounts the host fixture's default sub-mesh and mounts the selected accessory's 3D `.glb` model with sub-pixel surface alignment, pivot auto-centering, and PBR finish shaders in under 16ms.
- **Real-Time BOM Recalculation (`pricingEngine.ts`):** Calculates hardware cost deltas in under 50ms. Swapping an accessory replaces the baseline hardware allowance with the selected accessory's unit price, scrap allowance, and contractor margin.
- **Transparent Itemization in Quotation Modal & PDF:**
  - `MeasurementConfirmationModal.tsx` renders an itemized line item showing the chosen accessory, finish, and position (e.g. `"Hardware: Keyless Smart Digital Lock (Right Side, Mid-Height, Matte Black) - ₱4,500.00"`).
  - `quotationPdfGenerator.ts` includes the exact hardware item, finish, and handing in the PDF fixture specifications, giving Philippine fabricators complete clarity for door stile preparation and hardware ordering.

## 3. Non-Negotiable Invariants

1. **Sub-50ms Workspace Recalculation:** Swapping an accessory or toggling position between Left and Right must complete calculation and update the quotation total in under 50 milliseconds.
2. **60 FPS Canvas Reactivity:** Three.js mesh replacement and matrix transformation must execute in under 16 milliseconds without WebGL context loss, memory leaks, or camera disorientation.
3. **Strict Lateral X-Axis Invariant (Left vs Right):** Toggling Left or Right must strictly translate the accessory along the lateral X axis relative to the door sash boundary. Y-axis elevation and Z-axis depth must not drift.
4. **Strict Vertical Y-Axis Invariant (Bottom vs Up):** Toggling Bottom or Up must strictly translate the accessory along the vertical Y axis. Lateral X-axis placement and Z-axis depth must not drift.
5. **Single Authoritative Final Price:** The quotation modal and consultation PDF must incorporate all accessory price deltas into a single, binding grand total per `BRD-M5`.
6. **Zero Em-Dashes:** All UI text, tooltips, PDF callouts, and code comments must strictly avoid em-dashes per `BAN-PUNCT-01`. Use hyphens, colons, or parentheses.
7. **Strict Type Safety:** Zero usage of `any` across TypeScript interfaces, calculation hooks, and PDF formatters per `BAN-TYPE-05`.
8. **Design Token Parity:** All UI additions to `ProductModelWorkspace.tsx` and `MeasurementConfirmationModal.tsx` must reuse established Tailwind CSS tokens from `src/app/globals.css` per `BAN-UI-09`.

### 4.2 Three.js Assembly & Positional Matrix Engine (`parametricProductBuilder.ts`)

In `src/lib/visualization/parametricProductBuilder.ts`, update the component building pipeline to support swappable accessories:

```typescript
export function mountAccessoryMesh(
  parentGroup: THREE.Group,
  accessoryModel: THREE.Object3D,
  hostBounds: { widthM: number; heightM: number; depthM: number },
  positionOptions: AccessoryPositionOptions,
  horizontal: 'left' | 'right',
  vertical: 'bottom' | 'up',
  finishKey: string,
): THREE.Object3D {
  const clone = accessoryModel.clone(true);

  // Apply PBR finish material (Matte Black, Brushed Chrome, Satin Brass, etc.)
  const hardwareMaterial = createMaterialPalette(finishKey).hardware;
  clone.traverse((child) => {
    if (child instanceof THREE.Mesh) {
      child.material = hardwareMaterial;
      child.castShadow = true;
      child.receiveShadow = true;
    }
  });

  // Calculate strict X-axis coordinate for Left vs Right
  const lateralMarginM = (positionOptions.horizontalOffsetMm || 45) / 1000;
  const targetXM = horizontal === 'left'
    ? -hostBounds.widthM / 2 + lateralMarginM
    : hostBounds.widthM / 2 - lateralMarginM;

  // Calculate strict Y-axis coordinate for Bottom vs Up
  const verticalMarginM = (positionOptions.verticalOffsetMm || 1000) / 1000;
  const targetYM = vertical === 'bottom'
    ? -hostBounds.heightM / 2 + verticalMarginM
    : hostBounds.heightM * 0.05; // Standard mid-height elevation

  // Maintain Z depth flush to the front surface of the door stile
  const targetZM = hostBounds.depthM / 2 + 0.002;

  // Apply translation matrix
  clone.position.set(targetXM, targetYM, targetZM);

  // If positioned on the left side, mirror orientation if required by handle geometry
  if (horizontal === 'left' && positionOptions.defaultHorizontal === 'right') {
    clone.rotation.y = Math.PI;
  }

  parentGroup.add(clone);
  return clone;
}
```

### 4.3 Real-Time Pricing Engine Recalculation (`pricingEngine.ts`)

In `src/lib/pricing/pricingEngine.ts`, update the BOM calculation to incorporate accessory deltas:

```typescript
export interface AccessoryBOMAdjustment {
  slotComponentId: string;
  defaultComponentCost: number;
  selectedAccessoryPrice: number;
  finishRateDelta: number;
}

export function applyAccessoryBOMAdjustments(
  baseHardwareCost: number,
  adjustments: AccessoryBOMAdjustment[],
  scrapAllowance: number = 0.10,
  contractorMargin: number = 0.25,
): { netHardwareCost: number; priceDelta: number } {
  let netCost = baseHardwareCost;

  for (const adj of adjustments) {
    // Deduct default hardware allowance
    netCost -= adj.defaultComponentCost;
    // Add chosen accessory base price and finish delta
    const accessoryTotal = adj.selectedAccessoryPrice + adj.finishRateDelta;
    netCost += accessoryTotal * (1 + scrapAllowance);
  }

  const finalHardwarePrice = netCost * (1 + contractorMargin);
  return {
    netHardwareCost: netCost,
    priceDelta: finalHardwarePrice - (baseHardwareCost * (1 + contractorMargin)),
  };
}
```
