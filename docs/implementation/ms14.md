## 1. Decision Summary

IMP-MS14 is an implementation-ready increment for the existing browser-generated quotation HTML. It provides:

1. A responsive A4-like screen preview with usable viewport gutters.
2. A print stylesheet for user-initiated printing or Save as PDF through the operating system print dialog.
3. The repository's existing GlassFit logo without redrawing or inventing a replacement brandmark.
4. Single-fixture and multi-fixture snapshot rendering.
5. Preservation of the current itemized BOM and consolidated multi-fixture calculations.
6. Customer-facing pricing hierarchy and fabricator-facing ocular inspection fields.
7. Safe interpolation of customer, product, and image data into generated HTML.
8. Deterministic automated checks plus manual print verification.

### 1.1 Upstream PDF Boundary

`PRD-F11` requires server-side PDF rendering, Cloudflare R2 persistence, and storage of `quotation_estimates.pdf_r2_object_key`. The current repository has no approved production PDF renderer dependency or platform adapter capable of completing that pipeline.

IMP-MS14 therefore provides **partial PRD-F11 fulfillment only**. It improves the quotation preview and allows the user to choose Print or Save as PDF from the native print dialog. It does not:

- Generate a PDF byte stream in application code.
- Select the user's print destination.
- Guarantee that the user saves rather than prints or cancels.
- Upload a PDF artifact to R2.
- Update `quotation_estimates.pdf_r2_object_key`.
- Close `QAD-TC11` as fully verified.

Full completion of `PRD-F11` and `QAD-TC11` requires a separately approved server PDF rendering architecture. This boundary is not a waiver or redefinition of those upstream requirements.

### 1.2 User-Facing Action Names

The Step 1 actions shall be:

- **Preview quotation**: Opens the formatted screen preview.
- **Print / Save as PDF**: Opens the same preview and then requests the native print dialog after printable assets are ready.

The implementation shall not label the second action "Save to Device" because the browser cannot guarantee a saved file.

## 2. Problem Statement

The current `generateQuotationPdfHtml()` output has four confirmed deficiencies:

1. Screen presentation has no paper boundary or viewport gutter because print-only page margins do not affect normal screen rendering.
2. `snapshotImageUrl` is accepted and passed by `BookingFlow.tsx` but not rendered.
3. The preview omits the repository's established GlassFit logo.
4. `handleSavePdf()` downloads HTML while the UI presents the result as a PDF.

The redesign must correct these problems without regressing:

- Single-fixture itemized BOM calculations.
- Multi-fixture per-item breakdowns and consolidated totals.
- Structural waiver rendering.
- Sill-specific details.
- Existing booking message formatting exports.
- Existing quotation document package metadata exports.

## 5. Domain Contract

### 5.1 Metadata Interface

Extend the existing interface in `quotationPdfGenerator.ts` to the following contract:

```typescript
export interface QuotationPdfMetadata {
  quotationNumber: string;
  referenceCode?: string | null;
  shareableUrl?: string | null;
  customerName: string;
  customerPhone?: string | null;
  customerEmail?: string | null;
  siteLocation?: string | null;
  createdAtFormatted: string;
  quotationValidityText?: string | null;
  projectName: string;
  snapshotImageUrl?: string | null;
  brandLogoUrl: string;
  hasSill: boolean;
  structuralWaiver: boolean;
  bomResult: CalculatedBOMResult;
  items?: ItemizedProductQuotation[];
  consolidatedSummary?: ConsolidatedQuotationSummary;
}
```

Rules:

1. `projectName` and `brandLogoUrl` are required. The generator shall not invent product names or deployment origins.
2. `siteLocation`, contact fields, reference code, and shareable URL render only when present. Missing values display `Not provided` only where a visible field is necessary.
3. `quotationValidityText` is optional and shall not be derived from signed-link expiration. The template shall not append a hardcoded 7-day or 14-day period.
4. `referenceCode` and `shareableUrl` render only after a real signed reference exists. Draft placeholders such as `CF-2026-001` shall not be presented as persisted identifiers.
5. The template shall use `bomResult.glazingAreaSqm` and existing cost fields. It shall not recompute waste factors from width and height.
6. For multiple fixtures, `items` is the authoritative per-fixture source and `consolidatedSummary` is the authoritative aggregate source.

### 5.2 BookingFlow Metadata Source Map

| PDF field | Source |
|---|---|
| `quotationNumber` | Use `quotationNumber` only when `activeLinkId` is present; otherwise pass `DRAFT` |
| `referenceCode` | Use `referenceCode` only when `activeLinkId` is present; otherwise `null` |
| `shareableUrl` | Use `shareableUrl` only when `activeLinkId` is present; otherwise `null` |
| `customerName` | Authenticated profile state |
| `customerPhone` | Authenticated profile state |
| `customerEmail` | Authenticated profile state |
| `siteLocation` | Actual captured project/site value; otherwise `null` |
| `projectName` | `productNameSummary` |
| `snapshotImageUrl` | `finalSnapshotDataUrl` for the committed composite |
| `brandLogoUrl` | `new URL("/Logo.svg", window.location.origin).href` |
| `hasSill` | Single fixture value; for multiple fixtures render per-item values rather than a misleading aggregate label |
| `structuralWaiver` | Existing supplied flag; multi-fixture banner derives from `items.some(...)` |
| `items` | `quotationItems` |
| `consolidatedSummary` | Existing aggregated result |

Preview and print handlers shall call one shared `buildQuotationPdfMetadata()` helper so the two actions cannot drift.

## 6. Safe HTML and Asset Handling

### 6.1 Mandatory Escaping

Add and use a deterministic `escapeHtml(value: string): string` helper for all text inserted into HTML, including:

- Customer name, phone, email, and location.
- Quotation and reference identifiers.
- Product, variant, finish, glass, and specification labels.
- Project name and link text.
- Every string from `items`.

The helper must escape `&`, `<`, `>`, `"`, and `'`. Numeric values shall be formatted before interpolation. No user or product string may be inserted as raw HTML.

### 6.2 Image Source Policy

Add `sanitizeImageSource(value: string | null | undefined, allowedOrigins: readonly string[]): string | null` with this allowlist:

- `data:image/png;base64,...`
- `data:image/jpeg;base64,...`
- `data:image/webp;base64,...`
- `https:` URLs whose origin appears in `allowedOrigins`
- Same-origin `http:` URLs during local development only when that exact origin appears in `allowedOrigins`

`BookingFlow` shall pass `window.location.origin` and the configured `NEXT_PUBLIC_R2_PUBLIC_URL` origin when available. Reject `javascript:`, `data:text/html`, SVG data URLs, unlisted remote origins, protocol-relative URLs, and malformed URLs. An invalid source renders the fallback artwork.

The repository asset `/Logo.svg` is the only approved GlassFit logo for this milestone. Do not redraw it in `pdfAssets.ts`. `pdfAssets.ts` may contain a neutral snapshot fallback SVG and print-safe UI icons that make no brand claim.

### 6.3 Window Isolation

The click handler must retain the new window reference long enough to write the document. Immediately after obtaining that reference, set `printWindow.opener = null` before writing generated content. Generated content shall not read from or mutate the opener. If the browser blocks the popup, return a typed failure result and show an accessible message in the booking page.

## 7. Document Information Architecture

### 7.1 Shared Header

Render:

1. The official logo image using `brandLogoUrl`.
2. `PRELIMINARY CONSULTATION ESTIMATE`.
3. Quotation number.
4. Creation date.
5. Reference code and shareable URL only when a real signed reference exists.
6. Neutral partner wording: `Consultation Partner: R.R.D. Aluminum & Glass Works`.

Do not display PUP accreditation, a partner verification checkmark, a physical address, or a licensing claim unless those exact elements receive separate written approval.

### 7.2 Customer and Site Summary

Render customer identity, available contact fields, project name, and actual site location. Never substitute `Metro Manila, Philippines` for an unknown site.

### 7.3 Snapshot Rules

For a single fixture:

- Render `snapshotImageUrl` with `object-fit: contain`.
- Use a neutral label such as `Client-space visualization preview`.
- Display dimensions, finish, and glass from `bomResult`.

For multiple fixtures:

- Render the committed composite `snapshotImageUrl` as the project overview when available.
- Render each `item.imageUrl` in its fixture card when it passes image sanitization.
- A missing item image does not suppress that fixture's technical and BOM data.
- Do not label any image `verified`.

Fallback copy:

> Visualization preview not available. Product specifications and preliminary dimensions remain subject to on-site verification.

### 7.4 Executive Pricing Summary

Render the project name and estimated total prominently. For multiple fixtures, use `consolidatedSummary.finalGrandTotal`. For one fixture, use `bomResult.finalQuotation`.

Use the label `Preliminary estimated total`. Do not state that delivery or every accessory is included unless represented in the supplied BOM.

### 7.5 Single-Fixture BOM

Render the existing four groups without changing their arithmetic:

1. Aluminum framing.
2. Glass infill.
3. Hardware and consumables.
4. Fabrication and installation labor.

Hardware plus consumables must include both `hardwareSubtotal` and `consumablesSubtotal`. Glazing quantity must use `glazingAreaSqm` rather than multiplying aperture area by a second waste factor.

### 7.6 Multi-Fixture BOM

Preserve the current per-fixture breakdown. Every fixture card must include:

- Product name and quantity.
- Width, height, panel count, finish, glass, and sill state.
- Its own four BOM groups from `item.bomResult`.
- Unit price and fixture subtotal.
- Structural waiver label when `item.structuralWaiver` is true.

After all fixture cards, render consolidated direct materials, labor, margin, and grand total from `consolidatedSummary`.

The implementation must not show the first fixture's BOM as if it represented the whole multi-fixture project.

### 7.7 Structural Waiver

For one fixture, render the waiver only when `structuralWaiver` is true. For multiple fixtures, render a project-level alert when any item has a waiver and identify each affected fixture in its card.

The waiver copy must match the approved project wording in `docs/milestone.md`. It shall not claim engineering certification or transfer legal liability beyond that approved text.

### 7.8 Ocular Inspection Section

Render an unsigned, printable checklist:

- Aperture dimensions physically measured.
- Opening checked for square, plumb, and level.
- Perimeter substrate inspected.
- Access and work area reviewed.
- Final specifications reviewed with customer.

Render customer and estimator signature lines with printed name and date fields. Do not include a pre-checked payment or contract status.

### 7.9 Consumer Notice

Use the following approved baseline copy:

> This is a preliminary computer-generated estimate based on customer-provided inputs and current configured material rates. It is not a final binding contract. Dimensions, site conditions, access requirements, structural conditions, accessories, and final pricing must be verified during the on-site consultation before material cutting or fabrication.

The implementation may add a short RA 7394 traceability label but shall not characterize the wording as a legally mandated form.

## 8. Screen and Print Layout Contract

### 8.1 Screen CSS

The paper container shall be responsive:

```css
body {
  margin: 0;
  padding: 24px 16px 48px;
  background: #f1f5f9;
}

.document-sheet {
  box-sizing: border-box;
  width: min(210mm, 100%);
  margin: 0 auto;
  padding: clamp(24px, 5vw, 20mm);
  background: #ffffff;
  border-radius: 8px;
  box-shadow: 0 10px 30px rgba(15, 20, 34, 0.12);
}
```

The toolbar shall wrap on narrow screens. Snapshot captions and summary cards shall collapse to one column below `640px`. All table cells and metadata values shall use `overflow-wrap: anywhere`. Fixed pixel widths that exceed their container are prohibited. The preview must not cause horizontal page scrolling at viewport widths of `320px`, `375px`, `768px`, or `1440px`.

### 8.2 Print CSS

```css
@page {
  size: A4 portrait;
  margin: 15mm;
}

@media print {
  body {
    padding: 0;
    background: transparent;
    print-color-adjust: exact;
    -webkit-print-color-adjust: exact;
  }

  .no-print {
    display: none !important;
  }

  .document-sheet {
    width: 100%;
    margin: 0;
    padding: 0;
    border-radius: 0;
    box-shadow: none;
  }

  tr,
  .summary-card,
  .signature-block,
  .ocular-card {
    break-inside: avoid;
    page-break-inside: avoid;
  }

  thead {
    display: table-header-group;
  }
}
```

Do not apply `break-inside: avoid` to an entire multi-fixture BOM table or to the entire document. Rows and compact cards may avoid breaks; long collections must be allowed to paginate.

### 8.3 Preview Toolbar

The screen-only toolbar shall contain:

- Preview title and quotation number.
- `Print / Save as PDF` button.
- `Close preview` button.

Zoom controls are not part of this milestone. Browser zoom remains available. Buttons require visible focus styles and accessible text labels. Avoid emoji-only controls because print and platform fonts vary.

## 9. Print Window Lifecycle

Create one shared helper with a typed result:

```typescript
export type OpenQuotationPreviewResult =
  | { ok: true }
  | { ok: false; reason: "POPUP_BLOCKED" | "DOCUMENT_WRITE_FAILED" };

export interface QuotationPreviewDocumentPort {
  open(): void;
  write(...content: string[]): void;
  close(): void;
  readonly fonts?: { readonly ready: PromiseLike<unknown> };
  readonly images: HTMLCollectionOf<HTMLImageElement>;
}

export interface QuotationPreviewWindowPort {
  opener: unknown;
  readonly document: QuotationPreviewDocumentPort;
  print(): void;
}

export type OpenPreviewWindow = () => QuotationPreviewWindowPort | null;

export function openQuotationPreview(
  html: string,
  options: { autoPrint: boolean },
  openWindow?: OpenPreviewWindow,
): OpenQuotationPreviewResult;
```

Behavior:

1. Open the preview synchronously from the click handler.
2. If `window.open()` returns `null`, return `POPUP_BLOCKED` and show a visible message in `BookingFlow`.
3. Write and close the document inside a `try` block.
4. When `autoPrint` is false, do not invoke `window.print()`.
5. When `autoPrint` is true, wait for `document.fonts.ready` when supported and for every image to settle through `decode()`, `load`, or `error` before calling `window.print()`.
6. Include a bounded fallback timeout of 5 seconds so a failed image cannot block printing indefinitely.
7. Do not use an arbitrary 300 ms delay as the primary readiness condition.
8. Keep the preview open after the print dialog closes so the user can retry.

Production uses a default opener that delegates to `window.open("", "_blank")`. Unit tests inject a typed opener and a minimal window double, allowing popup failure and print readiness behavior to be tested with `node:test` without adding a DOM test dependency.

The UI shall explain that the user must choose **Save as PDF** in the native print dialog when a file is desired.
