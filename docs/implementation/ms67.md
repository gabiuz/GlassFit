## 1. Outcome and Scope

In Philippine glass and aluminum fabrication, architectural openings such as sliding and casement windows are routinely enhanced with modular additions:
1. **Insect Screens (Wire Mesh / Fiberglass Screen):** Essential for pest exclusion and ventilation in tropical climates, typically framed with lightweight extruded aluminum profiles matching or complementing the window frame finish.
2. **Security Grills (Protective Decorative Grilles):** Solid or tubular aluminum/steel bars arranged in repeating patterns (colonial grids, vertical bars, or modular diamond lattices) to deter intrusions while allowing airflow.

These additions are not part of the base window fixture itself. Instead, they represent optional, modular attachments that:
- Possess their own independent raw materials, dimensional scaling drivers, fabrication labor rates, and pricing structures.
- Must not be sold as standalone items to customers browsing the public catalog (a customer cannot buy a floating window screen without a window opening).
- Must be configured once by administrators as reusable add-on catalog templates, which host products (such as a Series 798 2-Panel Sliding Window) can inherit based on fabricator capabilities.

`IMP-MS67` delivers the relational database schema, administrative catalog authoring workflows, and host product inheritance bindings necessary to manage screens and grills:
- **Add-on Catalog Entity Model:** Extends `public.products` with an `is_addon` boolean flag and an `addon_type` classifier (`'screen'` or `'grill'`).
- **Strict Public Catalog Isolation:** Ensures public customer catalog queries (`getActiveProducts()`, `/product`, and `/product-details/[id]`) strictly exclude add-on products (`WHERE is_addon = false`), preventing add-on items from cluttering public catalog listings.
- **Admin Catalog Management Interface (`/admin/products`):** Introduces a dedicated "Add-on Accessories" view and filtering chips in the administrative product management portal, enabling admins to create, edit, deactivate, and price screen and grill templates.
- **Product Setup Wizard Inheritance Step (`ProductSetupWizard.tsx`):** Adds an "Add-on Attachments" configuration panel in Step 5 (Parameters and Rules) or Step 3 of the administrative setup wizard. When configuring a host window or door, administrators can selectively enable Screen inheritance, Grill inheritance, both, or neither, and bind them to the appropriate active add-on catalog template.
- **Relational Junction Persistence:** Establishes `public.product_compatible_addons` to persist the many-to-many relationship between host products and their compatible add-on attachments with referential integrity and Row-Level Security.

Parametric 3D procedural generation for screens and grills is specified in `IMP-MS68`. Customer workspace selection, mutual-exclusion toggling, dynamic quotation calculation, and consultation PDF handoffs are specified in `IMP-MS69`.

## 3. Non-Negotiable Invariants

1. **Strict Public Catalog Exclusion:** Add-on products (`is_addon = true`) must NEVER appear in public-facing customer catalog endpoints, product listing pages (`/product`), search queries, or direct public product detail routes (`/product-details/[id]`). Add-ons exist strictly as attachments inherited by host products.
2. **Mutual Exclusion Rule Compatibility:** When an administrator enables both Screen and Grill attachments for a host product, the system must record both as permitted candidates. However, the schema and configuration contracts must explicitly codify that a customer can only select at most one active add-on at a time during visualization and quotation.
3. **Cardinality Constraint per Type:** A host product can link at most one active Screen add-on and at most one active Grill add-on (`UNIQUE(parent_product_id, addon_type)`). Multiple screens or multiple grills cannot be bound to the same parent product.
4. **Referential Integrity on Deletion:** Deleting a host product cascades to its compatible add-on junction rows (`ON DELETE CASCADE`). Deleting an add-on product that is currently bound to active host products is strictly blocked (`ON DELETE RESTRICT`) to prevent orphaned inheritance chains.
5. **Tenant Isolation and RLS Policies:** All reads from `public.product_compatible_addons` follow public read permissions for active host products. All insert, update, and delete mutations require authenticated administrator privileges (`public.has_admin_permission('manage_products') or public.is_admin()`) per `BAN-RLS-07`.
6. **Zero Em-Dashes:** In strict compliance with `BAN-PUNCT-01`, all user interface labels, helper notes, documentation, and code comments must use hyphens, colons, or parentheses. Never use em-dashes.
7. **Strict Type Safety:** Zero usage of `any` across TypeScript interfaces, database DTOs, and mutation schemas per `BAN-TYPE-05`.
8. **Consistent UI Design Tokens:** All administrative controls (checkboxes, toggle switches, select inputs, and cards) must reuse established Tailwind CSS tokens from `src/app/globals.css` (`rounded-[10px]`, `border-[#c3c3c3]`, `focus:border-[#07b6d3]`) per `BAN-UI-09`.

## 4. Technical Design & Data Architecture

### 4.1 Relational Schema Migration: `016_product_addon_catalog_and_inheritance.sql`

Create migration file `supabase/migrations/016_product_addon_catalog_and_inheritance.sql`:

```sql
-- Migration: 016_product_addon_catalog_and_inheritance.sql
-- Function: Support modular add-on products (screens and grills) and host product inheritance bindings
-- Upstream Traceability: ERD-E3 (products), PRD-F1, PRD-F14, SDD-C1, SDD-C9

-- 1. Extend public.products with add-on classification columns
alter table public.products
  add column if not exists is_addon boolean not null default false,
  add column if not exists addon_type varchar(20);

-- Add check constraint for addon_type
alter table public.products
  drop constraint if exists products_addon_type_check;

alter table public.products
  add constraint products_addon_type_check
  check (
    (is_addon = false and addon_type is null) or
    (is_addon = true and addon_type in ('screen', 'grill'))
  );

-- Indexes for catalog query performance
create index if not exists idx_products_is_addon on public.products(is_addon);
create index if not exists idx_products_addon_type on public.products(addon_type) where is_addon = true;

-- 2. Create junction table public.product_compatible_addons
create table if not exists public.product_compatible_addons (
  id uuid primary key default gen_random_uuid(),
  parent_product_id uuid not null references public.products(product_id) on delete cascade,
  addon_product_id uuid not null references public.products(product_id) on delete restrict,
  addon_type varchar(20) not null check (addon_type in ('screen', 'grill')),
  is_default_enabled boolean not null default false,
  display_order integer not null default 0,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  constraint uq_parent_addon_type unique (parent_product_id, addon_type),
  constraint uq_parent_addon_product unique (parent_product_id, addon_product_id)
);

-- Indexes for fast lookup
create index if not exists idx_pca_parent_product on public.product_compatible_addons(parent_product_id);
create index if not exists idx_pca_addon_product on public.product_compatible_addons(addon_product_id);

-- 3. Row-Level Security (RLS) Policies
alter table public.product_compatible_addons enable row level security;

-- Public read for active products
drop policy if exists pca_public_read on public.product_compatible_addons;
create policy pca_public_read
  on public.product_compatible_addons for select
  using (
    exists (
      select 1 from public.products p
      where p.product_id = product_compatible_addons.parent_product_id
        and (p.status = 'Active' or public.is_admin())
    )
  );

-- Admin mutation policies
drop policy if exists pca_admin_insert on public.product_compatible_addons;
create policy pca_admin_insert
  on public.product_compatible_addons for insert to authenticated
  with check (public.has_admin_permission('manage_products') or public.is_admin());

drop policy if exists pca_admin_update on public.product_compatible_addons;
create policy pca_admin_update
  on public.product_compatible_addons for update to authenticated
  using (public.has_admin_permission('manage_products') or public.is_admin())
  with check (public.has_admin_permission('manage_products') or public.is_admin());

drop policy if exists pca_admin_delete on public.product_compatible_addons;
create policy pca_admin_delete
  on public.product_compatible_addons for delete to authenticated
  using (public.has_admin_permission('manage_products') or public.is_admin());
```

### 4.3 Server Actions & Persistence Services (`src/lib/admin/products/addonMutations.ts`)

Create `src/lib/admin/products/addonMutations.ts`:
1. `getAvailableAddonProducts(addonType?: AddonType)`: Fetches active add-on products (`WHERE is_addon = true AND status = 'Active'`) for populating setup wizard select inputs.
2. `getCompatibleAddonsForProduct(parentProductId: string)`: Fetches all configured add-on bindings for a host product.
3. `saveProductAddonInheritance(parentProductId: string, config: HostProductAddonConfig)`: Atomically updates `product_compatible_addons` for the specified host product. Removes disabled add-on types and inserts or updates enabled add-on bindings.

```typescript
import { createSupabaseServerClient } from "@/lib/supabase/server";
import type { CompatibleAddonBinding, HostProductAddonConfig } from "./types";

export async function saveProductAddonInheritance(
  parentProductId: string,
  config: HostProductAddonConfig
): Promise<void> {
  const supabase = await createSupabaseServerClient();

  // 1. Fetch existing bindings
  const { data: existing, error: fetchErr } = await supabase
    .from("product_compatible_addons")
    .select("id, addon_type")
    .eq("parent_product_id", parentProductId);

  if (fetchErr) throw new Error(`Failed to load existing add-ons: ${fetchErr.message}`);

  const existingTypes = new Set((existing || []).map((row) => row.addon_type));

  // 2. Handle Screen binding
  if (config.hasScreen && config.screenAddonProductId) {
    await supabase.from("product_compatible_addons").upsert(
      {
        parent_product_id: parentProductId,
        addon_product_id: config.screenAddonProductId,
        addon_type: "screen",
        is_default_enabled: false,
        display_order: 1,
      },
      { onConflict: "parent_product_id,addon_type" }
    );
  } else if (existingTypes.has("screen")) {
    await supabase
      .from("product_compatible_addons")
      .delete()
      .eq("parent_product_id", parentProductId)
      .eq("addon_type", "screen");
  }

  // 3. Handle Grill binding
  if (config.hasGrill && config.grillAddonProductId) {
    await supabase.from("product_compatible_addons").upsert(
      {
        parent_product_id: parentProductId,
        addon_product_id: config.grillAddonProductId,
        addon_type: "grill",
        is_default_enabled: false,
        display_order: 2,
      },
      { onConflict: "parent_product_id,addon_type" }
    );
  } else if (existingTypes.has("grill")) {
    await supabase
      .from("product_compatible_addons")
      .delete()
      .eq("parent_product_id", parentProductId)
      .eq("addon_type", "grill");
  }
}
```
