## 1. Outcome and Scope

In the current GlassFit administrative setup (Step 6 of `/admin/products/[id]/setup`, implemented in `src/features/admin/products/setup/ValidationWorkspaceSection.tsx`), administrators test draft products inside an interactive test-drive sandbox before activating them to the public catalog. Currently, the sandbox provides dimensional testing sliders (width from 600mm to 3600mm, height from 600mm to 2400mm) and a feature toggle for bottom sill removal (`has_sill`).

However, the Step 6 simulator evaluates calculations strictly against the single static material linked to each component in Step 4. When administrators configure multi-material candidate options per part (introduced in `IMP-MS64`), they have no mechanism in the preview sandbox to:
1. **Test Alternative Part Materials:** Switch individual framing extrusions, glass infill panels, or hardware components between their permitted materials to verify visual and structural compatibility.
2. **Verify Real-Time Pricing Responses:** Observe how selecting alternative materials (such as shifting from Analok to Powder Coated White aluminum, or from 6mm Clear Float to 6mm Tinted Bronze or Safety Tempered glass) shifts linear extrusion rates, area glass costs, waste allowances, fabrication labor floors, and gross margin totals.
3. **Inspect 3D Physical Material Representation:** Verify that Three.js PBR shader attributes (roughness, metalness, transmission, tint opacity, and surface colors) reflect the physical appearance of each candidate material on the assembled 3D product model.
4. **Pre-Activation Safety Verification:** Ensure that all component parts possess valid, non-zero material mappings and that all candidate permutations produce viable, non-negative quotation calculations before activating the product.

`IMP-MS65` implements this interactive pre-activation material simulation capability:
- **Interactive Part Material Switcher:** Adds an ergonomic material selector panel alongside the parameter sliders in Step 6, presenting the candidate materials configured in Step 4 for each component.
- **Dynamic Three.js PBR Shading:** Seamlessly updates Three.js mesh materials in real time (using `src/lib/visualization/materialClassifier.ts`) as the admin toggles candidate materials, without reloading 3D geometry or re-fetching GLB assets.
- **Instant Parametric BOM Recalculation:** Re-runs `calculateParametricBOM` client-side in under 50ms whenever any material selection changes, updating the live BOM breakdown card and total price.
- **Pre-Activation Readiness Gate:** Enforces comprehensive validation checks verifying that all parts have active material bindings with complete pricing data before allowing the administrator to publish the product.

Customer-facing visualization and quotation selection is specified in `IMP-MS66`.

## 3. Non-Negotiable Invariants

1. **Sub-50ms Calculation Latency:** Toggling any component's material in Step 6 must recalculate the complete Bill-of-Materials (including scrap allowances, labor floor, and margin) and update the DOM in less than 50 milliseconds.
2. **Zero Geometry Reload on Material Swap:** Switching a component's material must only update Three.js material shader properties (color, metalness, roughness, transmission, opacity). It must never re-fetch GLB files, re-parse mesh geometry, or reset camera orbit position.
3. **Strict Candidate Restriction:** The Step 6 sandbox must only allow selecting materials that were explicitly checked in Step 4 (`product_component_materials`). Arbitrary unassigned materials from the catalog cannot be selected.
4. **Isolated Sandbox State:** Material overrides selected in Step 6 are strictly transient for sandbox simulation and pricing testing. Toggling materials in Step 6 must never overwrite the saved default material (`is_default = true`) established in Step 4.
5. **Exact Mathematical Parity:** The pricing calculation in Step 6 must execute the exact same deterministic function (`calculateParametricBOM` from `src/lib/pricing/pricingEngine.ts`) used across customer quotations, guaranteeing zero divergence between admin preview and customer pricing.
6. **Pre-Activation Completeness Requirement:** An administrator cannot activate a product if any component part has zero assigned materials, zero base quantity, or zero unit rate.
7. **Design Token Consistency:** All UI controls in Step 6 must reuse established Tailwind CSS tokens from `src/app/globals.css` and existing GlassFit component styling (`rounded-[12px]`, `border-[#07b6d3]`, slate backgrounds) per `BAN-UI-09`.
8. **No Em-Dashes:** In compliance with `BAN-PUNCT-01`, all user-facing copy, badges, tooltips, and code comments must use hyphens, colons, or parentheses.

## 4. Technical Design & Algorithmic Specification

### 4.1 Sandbox Material State Management

In `ValidationWorkspaceSection.tsx`, introduce a localized state mapping each component key to its active preview material ID:

```typescript
// ComponentKey -> RawMaterialId
const [materialOverrides, setMaterialOverrides] = useState<Record<string, string>>({});
```

#### Initialization Protocol
When `fetchDraftStructuralDefinition(productId)` completes:
1. Inspect each component in `definition.components`.
2. Find the default material (`comp.allowedMaterials.find(m => m.isDefault)` or `comp.rawMaterialId`).
3. Initialize `materialOverrides[comp.componentKey] = defaultMaterialId`.
4. If a component has no assigned materials, initialize to empty string `""`.

### 4.2 Dynamic Three.js Material Shading Integration

Extend `src/lib/visualization/materialClassifier.ts` to export a PBR property resolver:

```typescript
export interface PBRMaterialAttributes {
  color: THREE.Color;
  metalness: number;
  roughness: number;
  transmission?: number;
  opacity?: number;
  transparent?: boolean;
  ior?: number;
}

export function resolvePBRProperties(rawMaterial: RawMaterial | null): PBRMaterialAttributes {
  if (!rawMaterial) {
    return {
      color: new THREE.Color(0x888888),
      metalness: 0.1,
      roughness: 0.5,
    };
  }

  if (rawMaterial.category === "Aluminum") {
    switch (rawMaterial.finish_type?.toLowerCase()) {
      case "analok":
        return {
          color: new THREE.Color(0x221d1a), // Deep dark bronze / warm black
          metalness: 0.65,
          roughness: 0.35,
        };
      case "powdercoatedwhite":
      case "powder coated white":
      case "white":
        return {
          color: new THREE.Color(0xf5f6f8), // Clean architectural white
          metalness: 0.05,
          roughness: 0.45,
        };
      case "anodized":
      case "mill":
      default:
        return {
          color: new THREE.Color(0xd4d8dc), // Natural silver aluminum
          metalness: 0.85,
          roughness: 0.25,
        };
    }
  }

  if (rawMaterial.category === "Glass") {
    switch (rawMaterial.finish_type?.toLowerCase()) {
      case "bronze":
      case "tinted bronze":
        return {
          color: new THREE.Color(0x4a3b2c),
          metalness: 0.0,
          roughness: 0.05,
          transmission: 0.75,
          opacity: 0.65,
          transparent: true,
          ior: 1.52,
        };
      case "clear":
      default:
        return {
          color: new THREE.Color(0xe6f4f8),
          metalness: 0.0,
          roughness: 0.02,
          transmission: 0.92,
          opacity: 0.25,
          transparent: true,
          ior: 1.52,
        };
    }
  }

  return {
    color: new THREE.Color(0x333333),
    metalness: 0.2,
    roughness: 0.6,
  };
}
```

In `ParametricModelView`, traverse the active 3D group and update mesh materials in place:
1. Locate child meshes matching `child.userData.componentKey`.
2. Resolve the active `RawMaterial` using `materialOverrides[compKey]`.
3. Apply `resolvePBRProperties(rawMaterial)` to `child.material` without instantiating new geometries.

### 4.3 Parametric BOM Recalculation Flow

Whenever `materialOverrides`, `parameters`, or `hasSill` changes:
1. Construct `ComponentPricingInput[]`:
   - For each component in `definition.components`:
     - Look up active material ID: `selectedMatId = materialOverrides[comp.componentKey]`.
     - Find matching `RawMaterial` from `rawMaterials` catalog list.
     - Build `ComponentPricingInput` with `rawMaterial: selectedMaterial`.
2. Invoke `calculateParametricBOM(componentPricingInputs, { widthMm, heightMm, hasSill })`.
3. Synchronize `calculatedBOMResult` state to update the BOM breakdown table and quotation total.

## 5. UI & Interaction Specification (Admin Step 6)

### 5.1 Test-Drive Simulator Layout

In `ValidationWorkspaceSection.tsx`, organize the right-hand inspection drawer into two tabs:
1. **Dimensions & Features Tab:**
   - Width slider: 600mm to 3600mm (10mm step)
   - Height slider: 600mm to 2400mm (10mm step)
   - Bottom sill toggle: `[x] Include Bottom Sill`
2. **Part Materials Sandbox Tab:**
   - Header: "Simulate Material Configurations"
   - Sub-header: "Test how different candidate materials impact product aesthetics and live pricing before activation."
   - Reset button: "Reset to Defaults" (restores all components to their Step 4 default materials).

### 5.2 Part Material Selector Component

Under the **Part Materials Sandbox Tab**, group components by `presentationCategory` ("Framing Members", "Glazing Infill", "Hardware & Consumables"):

For each component part:
1. **Part Identity:** Displays component name, component key (mono font), and base quantity.
2. **Material Option Selector:**
   - **Case A: Component has multiple allowed materials:**
     - Render a segmented pill selector or compact dropdown listing all allowed materials.
     - Each option displays: Material description, finish pill (e.g., "Analok", "White"), and unit price.
     - Price delta badge: Indicates price difference relative to default (e.g., `+$15.00/m` or `Base`).
     - Active selection highlighted with GlassFit cyan border (`border-[#07b6d3] bg-[#07b6d3]/10 text-[#07b6d3]`).
   - **Case B: Component has exactly one material configured:**
     - Displays material name and finish with a subtle lock icon: `[ 6mm Float Clear ] (Single material configured)`.
   - **Case C: Component has zero materials configured:**
     - Displays an amber alert badge: `[ ! Unassigned ] (Free component - zero cost)`.

### 5.3 Live BOM Breakdown & Pricing Sandbox Output

Display the itemized calculation card updating instantaneously:
- **Linear Extrusion Framing:** Itemized length (m), effective rate (PHP/m), waste factor (12.0%), and subtotal.
- **Glazing Infill:** Glass surface area (sqm), unit rate (PHP/sqm), waste factor (10.0%), and subtotal.
- **Hardware & Accessories:** Itemized counts and piece rates.
- **Consumables & Weatherseals:** Sealant tubes and gasket lengths.
- **Direct Workshop Labor:** Computed via `max(PHP 750.00, 0.25 * Materials Subtotal)`.
- **Contractor Gross Margin:** 25.0% markup.
- **Final Estimated Quotation:** Bold total in Philippine Pesos (e.g., `PHP 14,850.00`).
- **Material Price Sensitivity Delta:** Displays relative change compared to the all-default baseline (e.g., `+PHP 1,240.00 (+9.1%) vs Default Configuration`).

### 5.4 Pre-Activation Readiness Verification

Above the "Activate Product" button, render a pre-flight validation summary:
- **Green Checkmark (Ready):** "All N components have valid materials and positive unit rates. Pricing formula verified across test envelope."
- **Red Alert (Blocked):** "Activation Blocked: 1 component has zero materials assigned. Return to Step 4 to complete material mapping."

## 7. Implementation Sequence

1. **Extend Material Classifier with PBR Property Resolver:**
   - In `src/lib/visualization/materialClassifier.ts`, implement `resolvePBRProperties(rawMaterial)` for aluminum finishes and glass types.
2. **Update 3D Parametric Viewport in Step 6:**
   - In `ValidationWorkspaceSection.tsx`, update `ParametricModelView` to accept `materialOverrides` and dynamically mutate mesh PBR properties.
3. **Build Part Materials Sandbox Component:**
   - Create `src/features/admin/products/setup/PartMaterialsSandbox.tsx` (or embed in `ValidationWorkspaceSection.tsx`).
   - Render component list grouped by category with material option selectors and price delta callouts.
4. **Wire Dynamic BOM Recalculation:**
   - In `ValidationWorkspaceSection.tsx`, re-run `calculateParametricBOM` whenever `materialOverrides` updates.
   - Display live price sensitivity delta compared to default configuration.
5. **Implement Pre-Activation Readiness Verification:**
   - Add validation logic checking for unassigned materials or zero pricing before enabling product activation.
6. **Automated Testing & Static Verification:**
   - Create unit tests in `tests/unit/adminMaterialSandbox.test.ts` verifying BOM calculation responses to material overrides.
   - Run static checks: `npx tsc --noEmit`, `npm run lint`, `npm run build`.
