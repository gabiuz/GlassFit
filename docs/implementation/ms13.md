## 1. Problem Context & Motivation

In the GlassFit capstone thesis (*Copy of GlassFit Chapter 1-3.md*), the **Signed Consultation Reference Link** is a core functional deliverable bridging customer-side visualization and business-side consultation:

> **Signed Consultation Reference Link (Definition of Terms, line 401):**
> *"Refers to a secure system-generated link that provides access to a saved consultation reference. In GlassFit, this link may include the visualization snapshot, selected product configuration, and estimated quotation, and is used to help customers and business staff review the same consultation details."*

Under **Use Case Report 3: Generate Quotation Estimate and Consultation Request (UC3, lines 720 to 737)**, the system is specified to execute the following natural flow:
1. The Customer finishes reviewing the visualization preview and requests an estimated quotation.
2. The System computes and displays the estimated quotation summary.
3. The System prompts the Customer to create an account or log in before saving the consultation reference.
4. The System generates a signed consultation reference link and stores the visualization snapshot, selected product configuration, and quotation estimate.
5. The System prepares Messenger or Viber handoff links containing the signed consultation reference.
6. The Customer sends the consultation request through the selected external communication platform or copies the link manually.
7. Both the customer and business staff access the public reference page (`/q/[code]`) to review the identical consultation details.

### The Four Deficiencies in the Current Implementation

While UI wireframes and visual components for `/send-booking` and `/q/[code]` exist in the repository (`src/features/booking/` and `src/app/q/[code]/page.tsx`), the end-to-end link workflow is broken due to four critical architectural gaps:

#### 1. Localhost vs Production Domain Deadlock (The `glassfit.ph` Issue)
In `src/lib/booking/bookingActions.ts` (lines 178 to 180) and `src/features/booking/components/BookingFlow.tsx` (line 41 and line 328), the system hardcodes the production domain:
```typescript
const baseUrl = process.env.NEXT_PUBLIC_SITE_URL || "https://glassfit.ph";
const signedUrl = `${baseUrl}/q/${tokenHash}`;
const displayLink = `glassfit.ph/q/${referenceCode.toLowerCase()}`;
```
During current local development on `http://localhost:3000`:
- `process.env.NEXT_PUBLIC_SITE_URL` is undefined, defaulting to `https://glassfit.ph`.
- The production domain `glassfit.ph` is not yet registered or deployed.
- The UI presents `glassfit.ph/q/cf-2026-457` without a clickable protocol scheme (`http://` or `https://`).
- When the user copies the link or clicks Messenger/Viber sharing, the recipient or tester attempts to open `glassfit.ph`, resulting in a browser DNS failure (`ERR_NAME_NOT_RESOLVED`).
- Testers on `localhost:3000` have no working mechanism to open or verify the consultation reference page directly from the booking flow.

#### 2. Silent Authentication Catch Block & Phantom Reference Codes
In `src/features/booking/components/BookingFlow.tsx` (lines 323 to 330), when `generateSignedBookingLink()` throws an error (such as an unauthenticated session or database connection timeout), the UI silently suppresses the error and synthesizes an ephemeral mock code:
```typescript
} catch (err: unknown) {
  console.error("Failed to generate signed reference link:", err);
  const fallbackRef = `CF-2026-${Math.floor(100 + Math.random() * 900)}`;
  setReferenceCode(fallbackRef);
  setGeneratedLink(`glassfit.ph/q/${fallbackRef.toLowerCase()}`);
  setIsLinkGenerated(true);
}
```
This synthesized code (`CF-2026-XXX`) is never persisted to PostgreSQL. When a user pastes this link into the browser (`/q/cf-2026-xxx`), `getPublicBookingReference()` queries Supabase for `Q-2026-XXX`, finds no matching record, and triggers a 404 `notFound()`. This violates UC3 Step 5, which mandates that the customer must be prompted to authenticate before saving a consultation reference.

#### 3. Missing Visualization Snapshot in Cloud Storage & Public Presentation
According to the thesis definition, the reference link must display the **visualization snapshot** showing the customized product installed in the customer's space. However:
- `generateSignedBookingLink` in `src/lib/booking/bookingActions.ts` (lines 77 to 86) creates a dummy R2 key string (`snapshots/${profileId}/${Date.now()}_consultation.webp`) without actually uploading the customer's `finalSnapshotDataUrl` buffer to Cloudflare R2 or persistent storage.
- `getPublicBookingReference()` hardcodes `snapshotImageUrl: null` (line 398).
- `src/app/q/[code]/page.tsx` omits the visualization image entirely from its layout, displaying only a blank two-column text box for "Consultation Notes" instead of the room visual preview.

#### 4. Absent Expiration and Revocation Lifecycle Enforcement
The `public.signed_booking_links` table enforces status constraints (`Active`, `Expired`, `Revoked`, `Used`) and an `expires_at` timestamp. However, `getPublicBookingReference()` and `/q/[code]/page.tsx` never check whether `new Date() > new Date(linkRecord.expires_at)` or whether `status !== 'Active'`. Expired or revoked links are presented without distinction, failing UC3 Exceptions ("Signed consultation reference link expires or becomes invalid").

## 4. Core Architectural Techniques & Mechanics

### Technique 1: Dynamic Environment-Aware Base URL Resolution

#### The Problem
Hardcoded domain strings (`https://glassfit.ph`) break during local development, preview deployments, and staging environments. Conversely, relative paths (`/q/CF-2026-001`) fail when copied to clipboard or shared via Messenger or Viber because external recipients need a fully qualified URL including protocol and host.

#### The Solution: Multi-Tiered Origin Resolution
Create `src/lib/booking/urlResolver.ts` providing deterministic URL resolution across both client and server contexts:

1. **Client-Side Context (`typeof window !== "undefined"`):**
   Use `window.location.origin` directly. On local development, this evaluates to `http://localhost:3000`. In production, it evaluates to `https://glassfit.ph`.

2. **Server-Side Context (Server Actions / Route Handlers):**
   - Check environment variable `process.env.NEXT_PUBLIC_SITE_URL` or `process.env.NEXT_PUBLIC_APP_URL`.
   - If not explicitly set, inspect Next.js request headers via `headers()`:
     - Protocol: `headers.get("x-forwarded-proto") || (process.env.NODE_ENV === "production" ? "https" : "http")`
     - Host: `headers.get("x-forwarded-host") || headers.get("host") || "localhost:3000"`
     - Constructed Base URL: `${protocol}://${host}`

3. **URL Output Pair Contract:**
   The generator produces two distinct representations:
   - `shareableUrl`: Fully qualified playable URL with protocol scheme (e.g., `http://localhost:3000/q/CF-2026-0457` in local development, or `https://glassfit.ph/q/CF-2026-0457` in production). This value is copied to clipboard, sent in chat messages, and opened via buttons.
   - `displayBadge`: Clean, cosmetic label for UI cards (e.g., `localhost:3000/q/cf-2026-0457` in local development, or `glassfit.ph/q/cf-2026-0457` in production).

```typescript
export interface ResolvedBookingUrls {
  shareableUrl: string;
  displayBadge: string;
  tokenUrl: string;
}

export function buildBookingUrls(
  referenceCode: string,
  tokenHash: string,
  baseUrl: string
): ResolvedBookingUrls {
  const cleanBase = baseUrl.replace(/\/+$/, "");
  const hostOnly = cleanBase.replace(/^https?:\/\//, "");
  const cleanRef = referenceCode.toLowerCase();

  return {
    shareableUrl: `${cleanBase}/q/${referenceCode}`,
    displayBadge: `${hostOnly}/q/${cleanRef}`,
    tokenUrl: `${cleanBase}/q/${tokenHash}`,
  };
}
```

### Technique 2: Snapshot Persistence & Hybrid Asset Delivery

#### The Problem
The consultation reference link must allow both the client and fabricator to see the rendered visualization preview. Currently, `finalSnapshotDataUrl` (a `data:image/webp;base64,...` string) is available in the client visualization session but is dropped during booking link creation.

#### The Solution: Server-Side Ingestion and R2 Storage
Create `src/lib/booking/snapshotStorage.ts` to persist visualization snapshot images:

1. **Base64 to Buffer Conversion:**
   Extract MIME type and binary image buffer from data URL:
   ```typescript
   const matches = dataUrl.match(/^data:([A-Za-z-+\/]+);base64,(.+)$/);
   const contentType = matches ? matches[1] : "image/webp";
   const buffer = Buffer.from(matches ? matches[2] : dataUrl, "base64");
   ```

2. **Cloudflare R2 Bucket Upload:**
   If Cloudflare R2 environment variables (`R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`) are configured:
   - Use the AWS S3 SDK `PutObjectCommand` to upload to bucket key: `snapshots/${profileId}/${snapshotId}.webp`.
   - Set `ContentType: contentType` and `CacheControl: "public, max-age=31536000, immutable"`.
   - Store object key `snapshots/${profileId}/${snapshotId}.webp` in `public.visualization_snapshots.final_image_r2_key`.

3. **Development Local Fallback:**
   If R2 credentials are not configured on the local development workstation:
   - Persist the base64 data URL directly or save to a local public temp folder (`public/snapshots/`).
   - Allow local developers to inspect snapshots without requiring live Cloudflare API credentials.

4. **Public URL Resolution:**
   In `getPublicBookingReference()`, resolve the public snapshot URL:
   - If `final_image_r2_key` is already a full URL or base64 data URL, return it directly.
   - Otherwise, resolve through `getR2AssetUrl(final_image_r2_key)`.

### Technique 3: Dual-Key Lookup Engine & Database Consistency

#### Lookup Mechanics
The public consultation reference route `/q/[code]` must resolve two query formats seamlessly:
1. **Cryptographic Token Hash (SHA-256):** 64-character hexadecimal string (`^[0-9a-fA-F]{64}$`). Used when clicking high-security direct links (`/q/a1b2c3d4...`).
2. **Human-Readable Reference Code:** Standardized format `CF-YYYY-NNNN` (e.g., `CF-2026-457` or lowercase `cf-2026-457`). Mapped to database quotation number `Q-YYYY-NNNN`.

```typescript
export async function getPublicBookingReference(
  codeOrHash: string
): Promise<PublicQuotationSummary | null> {
  const serviceClient = createSupabaseServiceClient();
  const trimmed = codeOrHash.trim();
  const isHash = /^[0-9a-fA-F]{64}$/.test(trimmed);

  let query = serviceClient
    .from("signed_booking_links")
    .select(`
      link_id,
      token_hash,
      status,
      expires_at,
      created_at,
      profiles (
        full_name,
        email,
        contact_number
      ),
      visualization_snapshots (
        snapshot_id,
        final_image_r2_key
      ),
      quotation_estimates!inner (
        quotation_id,
        quotation_number,
        total_estimated_amount,
        created_at,
        quotation_items (
          item_name,
          quantity,
          unit,
          unit_price,
          estimated_subtotal,
          pricing_details
        )
      )
    `);

  if (isHash) {
    query = query.eq("token_hash", trimmed);
  } else {
    const cleanCode = trimmed.toUpperCase();
    const formattedQuoteNo = cleanCode.startsWith("CF-")
      ? cleanCode.replace("CF-", "Q-")
      : cleanCode.startsWith("Q-")
      ? cleanCode
      : `Q-${cleanCode}`;

    query = query.eq("quotation_estimates.quotation_number", formattedQuoteNo);
  }

  const { data: linkRecord, error } = await query.maybeSingle();
  if (error || !linkRecord) {
    return null;
  }
  // ... transform to PublicQuotationSummary
}
```

#### Trigger Consistency Enforcement
The database contains trigger `validate_booking_link_consistency()` on `public.signed_booking_links`:
- `profile_id` on `signed_booking_links` must equal `profile_id` on `quotation_estimates`.
- `snapshot_id` on `signed_booking_links` must equal `snapshot_id` on `quotation_estimates`.
- `generateSignedBookingLink()` must insert records in strict atomic dependency order:
  1. `visualization_snapshots` (returns `snapshot_id`)
  2. `quotation_estimates` (using `snapshot_id`, returns `quotation_id`)
  3. `quotation_items` (using `quotation_id`)
  4. `signed_booking_links` (using `profile_id`, `quotation_id`, `snapshot_id`)

### Technique 5: Strict Authentication & Session Guard for Reference Creation

#### The Problem
Unauthenticated users currently fall into the catch block that invents dummy reference codes (`CF-2026-XXX`), leading to 404 dead-ends.

#### The Solution: Authentication Enforcement Flow
1. **Pre-flight Session Verification:**
   Before invoking `generateSignedBookingLink()`, `BookingFlow.tsx` verifies that `supabase.auth.getUser()` returns an active user.
2. **Inline Login / Registration Dialog:**
   If unauthenticated, the UI displays a clean dialog:
   *"Account Required: Please log in or create an account to generate a permanent consultation reference link. This ensures your project snapshot and quotation are securely saved."*
   The dialog includes quick buttons to `/login?redirect=/send-booking` or `/register?redirect=/send-booking`.
3. **Preserving Visualization Session Across Auth:**
   The visualization session is stored in localStorage/sessionStorage (`useVisualizationSession`), so navigating to login and returning to `/send-booking` preserves the snapshot and product configuration seamlessly without data loss.

## 5. End-to-End Data Flow & Security Protocol

The following ordered sequence specifies the complete consultation reference lifecycle:

1. **Configuration & Snapshot Generation:**
   The customer configures dimensions, finishes, and panel setups in `ProductModelWorkspace.tsx`. Clicking "Save & Book Consultation" generates a WebP snapshot data URL via offscreen canvas compositing and navigates to `/send-booking`.

2. **Authentication Verification:**
   In `BookingFlow.tsx`, the client checks for an authenticated Supabase user. If unauthenticated, the authentication modal is presented.

3. **Server Action Invocation:**
   The authenticated client calls `generateSignedBookingLink(input)` via Next.js Server Action with product parameters and `finalSnapshotDataUrl`.

4. **Snapshot Upload to Storage:**
   The server extracts the binary image buffer from `finalSnapshotDataUrl` and uploads it to Cloudflare R2 bucket (`snapshots/{profileId}/{snapshotId}.webp`).

5. **Atomic Database Insertion:**
   Using `createSupabaseServiceClient()` to ensure transaction integrity:
   - Insert `public.visualization_snapshots` (generates `snapshot_id`).
   - Insert `public.quotation_estimates` (generates `quotation_id`, reference `Q-YYYY-NNNN`).
   - Insert `public.quotation_items` (records itemized 4-group lines).
   - Generate SHA-256 token hash: `crypto.createHash("sha256").update(crypto.randomBytes(32)).digest("hex")`.
   - Calculate expiration timestamp: `now + 7 days`.
   - Insert `public.signed_booking_links` with `status = 'Active'`.

6. **Environment-Aware URL Assembly:**
   The server resolves the current site base URL via `resolveSiteBaseUrl()` and returns `shareableUrl`, `displayBadge`, `referenceCode`, and `tokenHash`.

7. **User Interface Presentation (Step 2):**
   The customer views the generated reference link card:
   - Displays clean badge (e.g., `localhost:3000/q/cf-2026-0457` in development).
   - "Copy Link" button writes full `shareableUrl` (`http://localhost:3000/q/CF-2026-0457`) to clipboard.
   - "Test / Open in New Tab" button opens the public page in a new browser tab.

8. **Messaging Handoff (Step 3 & 4):**
   The customer selects Messenger or Viber. The system logs the intent in `public.booking_requests` with `status = 'Pending'` and launches the external platform with the pre-filled message.

9. **Public Reference Page Resolution (`/q/[code]`):**
   An external recipient (fabricator estimator or customer) opens the link:
   - Server Component calls `getPublicBookingReference(codeOrHash)`.
   - Resolves either 64-char SHA-256 token hash or `CF-...` / `Q-...` code.
   - Checks expiration date against current server time.
   - Fetches snapshot public URL from R2.
   - Renders the complete consultation page, including snapshot, design specs, itemized BOM, and waiver status.

export async function getServerBaseUrl(): Promise<string> {
  const envUrl = process.env.NEXT_PUBLIC_SITE_URL || process.env.NEXT_PUBLIC_APP_URL;
  if (envUrl && envUrl.trim() !== "") {
    return envUrl.replace(/\/+$/, "");
  }

  try {
    const headerList = await headers();
    const host = headerList.get("x-forwarded-host") || headerList.get("host");
    const proto = headerList.get("x-forwarded-proto") || (process.env.NODE_ENV === "production" ? "https" : "http");

    if (host) {
      return `${proto}://${host}`;
    }
  } catch {
    // Fallback when headers() is called outside request context
  }

  return process.env.NODE_ENV === "production" ? "https://glassfit.ph" : "http://localhost:3000";
}

export function getClientBaseUrl(): string {
  if (typeof window !== "undefined" && window.location.origin) {
    return window.location.origin;
  }
  const envUrl = process.env.NEXT_PUBLIC_SITE_URL || process.env.NEXT_PUBLIC_APP_URL;
  if (envUrl && envUrl.trim() !== "") {
    return envUrl.replace(/\/+$/, "");
  }
  return process.env.NODE_ENV === "production" ? "https://glassfit.ph" : "http://localhost:3000";
}

import { S3Client, PutObjectCommand } from "@aws-sdk/client-s3";

const R2_ACCOUNT_ID = process.env.R2_ACCOUNT_ID;
const R2_ACCESS_KEY_ID = process.env.R2_ACCESS_KEY_ID;
const R2_SECRET_ACCESS_KEY = process.env.R2_SECRET_ACCESS_KEY;
const R2_BUCKET_NAME = process.env.R2_BUCKET_NAME || "glassfit-assets";

export async function uploadSnapshotImage(
  dataUrl: string,
  profileId: string,
  snapshotId: string
): Promise<string> {
  const objectKey = `snapshots/${profileId}/${snapshotId}.webp`;

  // Verify R2 credentials availability
  if (!R2_ACCOUNT_ID || !R2_ACCESS_KEY_ID || !R2_SECRET_ACCESS_KEY) {
    console.warn("R2 credentials not set; storing data URL or local placeholder for snapshot.");
    return objectKey;
  }

  try {
    const s3Client = new S3Client({
      region: "auto",
      endpoint: `https://${R2_ACCOUNT_ID}.r2.cloudflarestorage.com`,
      credentials: {
        accessKeyId: R2_ACCESS_KEY_ID,
        secretAccessKey: R2_SECRET_ACCESS_KEY,
      },
      forcePathStyle: true,
    });

    const base64Data = dataUrl.replace(/^data:image\/\w+;base64,/, "");
    const buffer = Buffer.from(base64Data, "base64");

    await s3Client.send(
      new PutObjectCommand({
        Bucket: R2_BUCKET_NAME,
        Key: objectKey,
        Body: buffer,
        ContentType: "image/webp",
        CacheControl: "public, max-age=31536000, immutable",
      })
    );

    return objectKey;
  } catch (err) {
    console.error("Failed to upload snapshot to R2:", err);
    return objectKey;
  }
}
