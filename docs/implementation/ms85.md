## 1. Required Outcome

1. **Elimination of Repetitive Identical Raw Material Rows:** In client quotation views (`/quotation`), public consultation references (`/q/[code]`), and fabricator PDF documents, the Itemized Cost Breakdown table must never display repetitive, identical raw material rows with bare uninformative descriptions (e.g. five separate lines of `1-3/4" x 3" Aluminum Tube`). Raw materials belonging to the same material code and finish within a group must be consolidated into a single aggregated line item displaying the total linear meters (or total pieces / square meters), unit rate, and combined subtotal. Alternatively, when component-level itemization is requested, each row must explicitly include the parent component's structural role and label (such as `Top Frame Rail: 1-3/4" x 3" Aluminum Tube`) rather than raw material codes in isolation.
2. **Strict Isolation of Linear Extrusion Lengths from Discrete Multipliers:** For all 1D continuous perimeter framing extrusions (head rails, bottom frame rails, left jambs, right jambs), the computed linear quantity must strictly equal the continuous aperture span ($W$ or $H$, adjusted by span ratio) multiplied solely by the true physical extrusion count of that specific part in the unit (normally 1 for a single head rail or jamb). Secondary parameters such as add-on `hatchCount` (e.g. 4 operator hatches), `panelCount`, `bayCount`, or discrete blade counts must never leak into or multiply continuous perimeter frame members. A 45 in by 47 in ($1.14\text{m} \times 1.20\text{m}$) aperture must calculate approximately $1.14\text{m}$ for top rail, $1.14\text{m}$ for bottom rail, $1.20\text{m}$ for left jamb, $1.20\text{m}$ for right jamb, and $1.20\text{m}$ for a center mullion, yielding approximately $5.88\text{m}$ total framing rather than the inflated $23.52\text{m}$ ($4\times$) overcharge.
3. **Fixture-Appropriate Profile Suggestion and Pricing Accuracy:** The system must enforce profile taxonomy matching across product categories. Lightweight fixtures such as residential jalousie windows or sliding windows must not default to heavy commercial storefront extrusions (`1-3/4" x 3"` or `1-3/4" x 4"` Aluminum Tube at ₱300.00 to ₱400.00/m). Automatic material suggestions and setup wizards must present fixture-appropriate profile series: standard jalousie framing sections (₱85.00 to ₱110.00/m), Series 798 residential window framing (₱70.00 to ₱125.00/m), Series 38 casement profiles (₱95.00 to ₱130.00/m), and modular tubing (₱120.00 to ₱150.00/m). Heavy structural tubes are reserved for commercial transoms, storefront framing, and curtainwalls.
4. **Transparent Disambiguation of Removable Sills vs Bottom Rails:** When an optional sill is toggled off (`includeSill = false`), the quotation breakdown and consultation page must clearly distinguish between the omitted projecting sill profile (`JW_Window_Sill`, deducted from price) and the remaining structural bottom frame rail (`JW_Frame_Bottom`, retained as part of the four-sided perimeter box). An explicit line-item notice or deduction entry must confirm that the sill deduction was applied, preventing customer confusion.
5. **Universal Cross-Product Scope:** All corrective pricing and BOM logic must apply universally across all product families in the GlassFit catalog: Series 798 sliding windows and patio doors, Series 38 casement and awning windows, swing doors, jalousie windows, commercial transoms, modular display cabinets, and add-on attachments (insect screens and security grilles).
6. **Implementation Authorization:** The owner requested implementation on November 2, 2026. Runtime changes are limited to the in-scope contracts below. No database mutation or production deployment is required.

## 2. Verified Starting Point and Root-Cause Diagnosis

Investigation of the calculation path across `pricingEngine.ts`, `quotationDocument.ts`, `ProductModelWorkspace.tsx`, and `StructuralComponentsSection.tsx` demonstrates the exact architectural breakdowns that caused the reported issue:

```
Customer Input: 45in x 47in Jalousie Window, Screen Add-on with 4 Operator Access Hatches, Sill: OFF
               │
               ▼
[Geometry Resolution]
Width = 45 in = 1.143 m, Height = 47 in = 1.194 m
Calculated Multiplier Bug: baseQuantity = 4 (or hatchCount = 4 applied to all framing parts)
               │
               ▼
[pricingEngine.ts Calculation Loop]
Top Frame (Width):     1.14 m x 4 = 4.56 m @ ₱300.00 = ₱1,368.00  (Overcharged 4x)
Left Jamb (Height):    1.20 m x 4 = 4.80 m @ ₱300.00 = ₱1,440.00  (Overcharged 4x)
Right Jamb (Height):   1.20 m x 4 = 4.80 m @ ₱300.00 = ₱1,440.00  (Overcharged 4x)
Center Mullion (H):    1.20 m x 4 = 4.80 m @ ₱300.00 = ₱1,440.00  (Overcharged 4x)
Bottom Frame (Width):  1.14 m x 4 = 4.56 m @ ₱300.00 = ₱1,368.00  (Overcharged 4x)
               │
               ▼
[quotationDocument.ts Line Item Labeling]
Every item sets description = mat.description ("1-3/4\" x 3\" Aluminum Tube")
Zero consolidation: generates 5 identical rows for ₱7,056.00 framing total instead of ~₱1,764.00!
```

### 2.1 Detailed Root-Cause Breakdown

| Failure Symptom | Code Location | Root Cause and Mathematical Distortion Mechanism |
|---|---|---|
| Repetitive Identical Line Items | `pricingEngine.ts` line 264; `quotationDocument.ts` lines 194-211 | **Unconsolidated Raw Material Emission with Blind Description Overwrite:** In `pricingEngine.ts`, the code evaluates `itemDesc = (isFixedComponent && comp.componentName) ? comp.componentName : (mat ? mat.description : comp.componentName)`. Because framing components are bound to a catalog raw material, every individual framing part (Top Rail, Bottom Rail, Left Jamb, Right Jamb, Center Mullion) has its component name discarded and replaced by `mat.description` (`1-3/4" x 3" Aluminum Tube`). In `quotationDocument.ts`, `groupsFromBom` maps each item directly to the snapshot array without consolidating identical raw materials. The resulting breakdown renders 5 identical rows with the exact same title. |
| 4x Length Quadrupling (4.56m and 4.80m) | `pricingEngine.ts` lines 205-214; `PartInspectorDrawer.tsx` line 1284 | **Extrusion Formula Multiplier Leak:** In `pricingEngine.ts`, 1D cuts evaluate `computedQty = widthM * comp.spanRatio * comp.baseQuantity` and `computedQty = heightM * comp.spanRatio * comp.baseQuantity`. When an administrator sets up a jalousie fixture with 4 operator hatches or 4 blades per operator, or bulk-edits parts in the Part Inspector Drawer, `baseQuantity` is bulk-updated to `4` on all components. Because framing extrusions do not validate their physical piece count, a single top rail of length $1.14\text{m}$ is multiplied by 4, producing $4.56\text{m}$. Similarly, $1.20\text{m}$ jambs become $4.80\text{m}$. The entire framing total reaches $23.52\text{m}$ ($4\times$ actual physical length). |
| Heavy Structural Profile Misallocation | `autoDetection.ts` lines 820-835; `csvMaterialParser.ts` | **Absence of Profile Suitability Tiering:** The catalog raw materials list seeds `1-3/4" x 3" Aluminum Tube` at ₱300.00/m as a generic aluminum framing profile. When `suggestCandidateMaterials()` runs in Step 3 of the Admin Product Wizard, it matches the generic category "Aluminum" and automatically selects the first active framing profile in the catalog. For lightweight jalousie windows, this assigns heavy commercial structural tube at ₱300.00/m instead of standard residential jalousie frame profiles (₱85.00 to ₱110.00/m), tripling baseline material rates. |
| Sill Omission Confusion | `autoDetection.ts` lines 347-357; `pricingEngine.ts` lines 145-156 | **Dual-Component Bottom Framing without Semantic Labeling:** The 3D jalousie asset contains both `JW_Frame_Bottom` (`OUTER_SILL_RAIL`, the permanent structural bottom box rail) and `JW_Window_Sill` (`REMOVABLE_SILL`, the optional projecting drip sill). Toggling **Include Window Sill** off correctly excluded `JW_Window_Sill`. However, `JW_Frame_Bottom` remained active as a necessary structural rail. Because both parts were named `1-3/4" x 3" Aluminum Tube` with length $4.56\text{m}$, the customer observed an active 4.56m tube at the bottom and concluded the sill toggle failed to work. |
| Non-Attributed Line Items | `src/app/q/[code]/page.tsx` lines 414-432; `quotationPdfGenerator.ts` | **Customer View Table Schema Limitations:** The public consultation table renders only `Item Group`, `Quantity`, `Unit Price`, and `Subtotal`. It provides no column or subtitle for component attribution (e.g. which parts of the window use this material). When raw materials are un-consolidated, the table becomes confusing and appears broken. |

## 3. Technical Contract and Architectural Design

To resolve these defects permanently across all product categories, the system requires four coordinated technical contracts:

### 3.1 Universal Raw Material Consolidation Contract

Raw material line items generated during parametric BOM calculation must be consolidated by `material_code` and `finish_type` within each quotation group before presentation to the user, with component trace tags preserved for transparency.

```typescript
export interface ConsolidatedBOMItemDetail {
  materialCode: string;
  description: string;
  category: "Framing" | "Glazing" | "Hardware" | "Consumable";
  finishType: string;
  totalQuantity: number;
  unit: "m" | "sqm" | "pc" | "lot" | "set";
  unitPrice: number;
  wasteFactor: number;
  subtotal: number;
  contributingComponents: Array<{
    componentKey: string;
    componentName: string;
    pieceCount: number;
    unitCutLength?: number;
    subtotalQuantity: number;
  }>;
}

export function consolidateBOMItems(
  items: BOMItemDetail[],
  category: "Framing" | "Glazing" | "Hardware" | "Consumable"
): ConsolidatedBOMItemDetail[] {
  const grouped = new Map<string, ConsolidatedBOMItemDetail>();

  for (const item of items) {
    const key = `${item.code}|${item.unit_price}|${item.unit}`;
    const existing = grouped.get(key);

    if (existing) {
      existing.totalQuantity = round4(existing.totalQuantity + item.quantity);
      existing.subtotal = round2(existing.subtotal + item.subtotal);
      if (item.componentTrace) {
        existing.contributingComponents.push(item.componentTrace);
      }
    } else {
      grouped.set(key, {
        materialCode: item.code,
        description: item.description,
        category,
        finishType: item.finish_type || "Standard",
        totalQuantity: round4(item.quantity),
        unit: item.unit as "m" | "sqm" | "pc" | "lot" | "set",
        unitPrice: item.unit_price,
        wasteFactor: item.waste_factor,
        subtotal: item.subtotal,
        contributingComponents: item.componentTrace ? [item.componentTrace] : [],
      });
    }
  }

  return Array.from(grouped.values());
}
```

1. **Quotation Document Snapshot Schema Update:** In `src/lib/pricing/quotationDocument.ts`, update `groupsFromBom` to invoke `consolidateBOMItems`.
2. **Component Trace Subtitle:** When rendering line items in `/quotation`, `/q/[code]`, and consultation PDFs:
   - If a consolidated item combines multiple components, display:  
     **Item Group:** `1-3/4" x 3" Aluminum Tube`  
     **Contributing Parts:** `Top Frame (1.14m), Bottom Frame (1.14m), Left Jamb (1.20m), Right Jamb (1.20m), Center Mullion (1.20m)`  
     **Quantity:** `5.88 m` | **Unit Price:** `₱300.00` | **Subtotal:** `₱1,764.00`
   - This eliminates repetitive rows while providing full fabrication transparency.

### 3.2 Extrusion Linear Length Guardrails & Perimeter Multiplier Isolation Contract

To prevent piece counts, panel counts, bay counts, or hatch counts from multiplying linear cut lengths:

```typescript
export function computeExtrusionLinearMeters(params: {
  dimensionBinding: "WIDTH" | "HEIGHT" | "PERIMETER";
  apertureWidthM: number;
  apertureHeightM: number;
  spanRatio: number;
  baseQuantity: number;
  bayRole?: DynamicBayRole | null;
  effectiveBayCount?: number;
  effectiveMullionCount?: number;
}): { linearMeters: number; pieceCount: number } {
  const span = typeof params.spanRatio === "number" && params.spanRatio > 0 ? params.spanRatio : 1.0;
  const role = params.bayRole;

  // 1. Continuous Perimeter Rails (Head, Bottom Rail, Outer Jambs)
  // Continuous perimeter rails ALWAYS span the aperture once per physical profile in the assembly.
  const isContinuousHead = role === "OUTER_HEAD";
  const isContinuousSillRail = role === "OUTER_SILL" || role === "REMOVABLE_SILL";
  const isContinuousJamb = role === "OUTER_JAMB_LEFT" || role === "OUTER_JAMB_RIGHT";

  if (isContinuousHead || isContinuousSillRail) {
    // Physical head/sill rail count is strictly 1 per frame boundary (or 2 for dual-track bypass)
    const physicalRailCount = Math.max(1, Math.min(2, params.baseQuantity || 1));
    return {
      linearMeters: round4(params.apertureWidthM * span * physicalRailCount),
      pieceCount: physicalRailCount,
    };
  }

  if (isContinuousJamb) {
    // Left or right jamb is 1 vertical extrusion per side
    const physicalJambCount = Math.max(1, Math.min(2, params.baseQuantity || 1));
    return {
      linearMeters: round4(params.apertureHeightM * span * physicalJambCount),
      pieceCount: physicalJambCount,
    };
  }

  // 2. Intermediate Mullions (scales with effective mullion count in multi-bay units)
  if (role === "BAY_DIVIDER") {
    const mullionCount = params.effectiveMullionCount ?? 0;
    return {
      linearMeters: round4(params.apertureHeightM * span * mullionCount),
      pieceCount: mullionCount,
    };
  }

  // 3. Sash Rails and Stiles (sliding or casement panels)
  if (params.dimensionBinding === "WIDTH") {
    const count = Math.max(1, params.baseQuantity || 1);
    return {
      linearMeters: round4(params.apertureWidthM * span * count),
      pieceCount: count,
    };
  }

  if (params.dimensionBinding === "HEIGHT") {
    const count = Math.max(1, params.baseQuantity || 1);
    return {
      linearMeters: round4(params.apertureHeightM * span * count),
      pieceCount: count,
    };
  }

  // 4. Perimeter Subframes (2W + 2H)
  const count = Math.max(1, params.baseQuantity || 1);
  return {
    linearMeters: round4(2 * (params.apertureWidthM + params.apertureHeightM) * span * count),
    pieceCount: count,
  };
}
```

1. **`hatchCount` Isolation:** In `pricingEngine.ts`, `hatchCount` is an add-on hardware parameter governing the number of access doors in an insect screen. It must NEVER participate in the host window's framing calculation. `hatchMultiplier` is restricted strictly to components belonging to the screen add-on with `dimensionBinding === "FIXED"`.
2. **Admin Setup Wizard Guardrail:** In `PartInspectorDrawer.tsx`, when editing a part with `bayRole === "OUTER_HEAD"`, `OUTER_SILL`, `OUTER_JAMB_LEFT`, or `OUTER_JAMB_RIGHT`, the `Base Quantity` input is constrained between 1 and 2, with an informative helper text: "Continuous perimeter extrusions are restricted to 1 piece (or 2 for dual-track rails) to prevent aperture overbilling."

### 3.4 Removable Sill and Bottom Rail Disambiguation Contract

To eliminate confusion between the structural bottom frame rail and the optional projecting sill:

1. **Clear Semantic Labeling:**
   - In `autoDetection.ts`, classify bottom horizontal framing into two distinct roles:
     - `OUTER_SILL`: Structural Bottom Frame Rail (permanent 4-sided enclosure, non-removable). Component Label: `Bottom Frame Rail`.
     - `REMOVABLE_SILL`: Projecting Exterior Sill / Threshold Flashing (optional, client-removable via `includeSill`). Component Label: `Projecting Exterior Sill`.
2. **Explicit Sill Omission Audit Entry:**
   - When `includeSill === false`:
     - Exclude the `REMOVABLE_SILL` component from the BOM calculations.
     - Retain `OUTER_SILL` (`Bottom Frame Rail`) so the window remains structurally boxed.
     - In the customer quotation summary card and consultation reference, display:  
       `✓ Bottom Sill Profile: Omitted for flush-floor threshold (Net Deduction Applied)`
     - In the itemized breakdown, do NOT leave the remaining bottom frame rail ambiguously labeled as generic "Sill". Label it explicitly as `Bottom Frame Rail`.
