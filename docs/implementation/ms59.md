## 1. Outcome and Scope

Accurate real-world opening measurement depends directly on the pixel-level localization accuracy of the paper fiducial corners. Because a standard sheet of paper measures approximately 216 mm by 279 mm (Short) or 210 mm by 297 mm (A4), while architectural openings span 1200 mm to 3000 mm, planar homography projects paper coordinates across the wall with an extrapolation factor of 5x to 12x. Under oblique camera angles (such as 25 to 45 degree yaw), a localization error of merely 2.5 pixels on a paper corner can project into a 25 mm to 55 mm measurement error on the window aperture.

Standard polygon approximation algorithms (`cv2.approxPolyDP`) frequently misplace corner vertices by several pixels due to edge rounding, corner dog-ears, thumb occlusions, or shadow gradients. Furthermore, during manual refinement with the 2.5x circular loupe, human touch precision on mobile displays is typically limited to 3 to 6 display pixels.

This milestone resolves corner localization error through a dual-stage precision architecture:
1. **CV Backend Edge Line Intersection:** Replaces vertex-only corner estimation with robust 4-edge line fitting (M-estimator / RANSAC) along each contour boundary, computing corners as the exact mathematical intersections of adjacent straight edges.
2. **Frontend Magnetic Loupe Snapping:** Equips the interactive 2.5x loupe with client-side local gradient snapping. When a user drags a corner pin within 8 to 12 pixels of a dominant edge or corner gradient, the crosshair magnetically snaps to the optimal sub-pixel boundary with visual lock feedback.

This milestone ensures that whether corners are mapped automatically via click (MS58) or adjusted manually, their pixel coordinates achieve sub-pixel mathematical precision prior to metric planar projection (MS60).

## 3. Non-Negotiable Invariants

1. **Physical Straightness Guarantee:** Paper edges are physically straight. The four corners of the fiducial quadrilateral must be derived from the intersection of four straight edge lines, eliminating corner rounding artifacts.
2. **Convexity and Aspect Guardrails:** The refined quadrilateral must remain strictly convex. Internal angles must fall within the admissible perspective range ($[45^\circ, 135^\circ]$).
3. **Sub-Pixel Numeric Precision:** Corner coordinates must be stored as IEEE 754 double-precision floating-point values in the canonical workspace coordinate frame, never rounded to whole integer pixels before homography computation.
4. **User Override Primacy:** Magnetic snapping assistance must never lock the user into an unwanted position. Dragging beyond the 12px snap radius immediately releases the pin to follow the pointer freely.
5. **Zero External Libraries:** Line fitting and edge gradient analysis must use existing OpenCV and NumPy routines in Python, and HTML5 Canvas 2D ImageData in TypeScript. No external ML models or dependencies are permitted.

## 4. Technical Design and Algorithmic Specification

### 4.1 Backend: Robust Line Fitting and Intersection Corner Derivation

In `fastapi-service/paper_calibration.py`, replace simple contour vertex extraction with edge line intersection:

```text
Algorithm: Sub-Pixel Edge Line Intersection
Input: source_gray (np.ndarray), initial_quad (4 ordered points)

1. Segment Contour into 4 Discrete Edge Point Sets:
   For each edge i from 0 to 3:
     Point A = initial_quad[i], Point B = initial_quad[(i + 1) % 4]
     Sample N points along segment AB (excluding outer 10% near corners to avoid fold/shadow distortion).
     Along normal vectors at each sample point, extract local gradient peaks using Sobel filters.
     Collect valid edge point coordinates E_i = {(x_k, y_k)}.

2. Robust Line Fitting per Edge:
   For each point set E_i:
     Fit line equation using cv2.fitLine(E_i, distType=cv2.DIST_HUBER, param=0, reps=0.01, aeps=0.01)
     Obtain unit direction vector (vx, vy) and collinear point (x0, y0).
     Convert to canonical line equation: A_i * x + B_i * y + C_i = 0, where A_i^2 + B_i^2 = 1.

3. Mathematical Line Intersections:
   For each adjacent pair of lines (L_i, L_j) where j = (i + 1) % 4:
     Determinant D = A_i * B_j - A_j * B_i
     If abs(D) < 1e-5: Lines are nearly parallel (degenerate perspective); reject candidate.
     Intersection X = (B_i * C_j - B_j * C_i) / D
     Intersection Y = (A_j * C_i - A_i * C_j) / D
     Refined Corner P_j = (X, Y)

4. Validation and Quality Checks:
   Verify refined corners form a convex quadrilateral (cv2.isContourConvex).
   Verify distance between refined corners and initial vertices <= MAX_REFINEMENT_DRIFT (12px).
   Return refined corners in deterministic order [top_left, top_right, bottom_right, bottom_left].
```

### 4.2 Frontend: Client-Side Magnetic Edge Snapping in the 2.5x Loupe

In `src/features/visualization/components/FiducialPaperPickerModal.tsx` and `PaperDetectionConfirmationModal.tsx`:

```typescript
interface EdgeSnapResult {
  snapped: boolean;
  snappedPoint: { x: number; y: number };
  gradientStrength: number;
  edgeAngleRad: number;
}

/**
 * Evaluates local image gradient within snapRadius of the current drag position.
 * Uses an offscreen 24x24 canvas extraction around the point.
 */
function computeMagneticSnap(
  currentPos: { x: number; y: number },
  imageData: ImageData,
  snapRadius: number = 10
): EdgeSnapResult;
```

Execution Details:
1. When the user touches or drags a pin, extract a 24x24 pixel patch of `ImageData` from the workspace image canvas around `currentPos`.
2. Compute horizontal and vertical Sobel convolution kernels on the luminance channel.
3. Identify candidate edge pixels where gradient magnitude $M = \sqrt{G_x^2 + G_y^2}$ exceeds dynamic threshold $\tau = 1.5 \times \mu_M$.
4. If a strong edge cluster is within `snapRadius` (default 10px), snap the pin crosshair to the sub-pixel peak along the gradient normal.
5. Provide visual feedback:
   - When snapped, the loupe crosshair changes from standard sky blue to glowing emerald (`#10b981`).
   - A subtle haptic vibration (`navigator.vibrate(10)`) triggers on supported mobile devices.

### 4.3 Visual Collinearity and Edge Straightness Indicators

The confirmation modal renders:
1. **Straightness Guide Lines:** Fine dashed reference lines projected along each edge of the quadrilateral, extending 20px beyond the corners.
2. **Edge Alignment Metric Badge:** Shows an "Edge Fit Quality" percentage in the corner of the loupe:
   - Fit $\ge 90\%$: Green badge ("Sharp Edge Alignment")
   - Fit $70\% - 89\%$: Yellow badge ("Moderate Edge Contrast")
   - Fit $< 70\%$: Muted badge ("Manual Alignment Recommended")

## 7. Risks and Mitigations

- **Risk: Wall texture (such as brick lines or tile grout) creates competing edge gradients near the paper boundary.**  
  *Mitigation:* The edge extraction samples gradients strictly in the direction of the quadrilateral edge normal, and filters out lines whose orientation deviates by more than 15 degrees from the initial contour segment.
- **Risk: High computational cost of real-time Sobel filtering during loupe drag.**  
  *Mitigation:* Processing is strictly confined to a tiny 24x24 pixel sub-patch extracted from the offscreen canvas, requiring fewer than 1,200 arithmetic operations per pointer event.
