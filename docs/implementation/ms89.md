## 1. Problem and Intended Outcome

First-time customers should understand the next useful action on the visualization page without learning the entire editor. Their first success is seeing their chosen product positioned convincingly in their own photo. Completing a tour is not the success criterion.

The user's proposed entry-path branches are appropriate: photo-first users need Add Product, product-first users already have a selection, and paper-reference users need paper calibration guidance. Following the user's UI direction (November 16, 2026), first-time guidance uses a focused **step-by-step popup tour with a darkened backdrop** (`bg-black/60` style) during paper calibration review (after uploading in Paper Reference mode) and workspace placement, paired with explicit **Skip** (dismiss current tour) and **Don't show again** (persistent opt-out for returning users) actions. No extra pre-upload popup tour is added before photo selection.

This is a refinement of the existing Operate surface. Reuse the repository's layouts, tokens, modal surfaces (`rounded-[20px]`), photo examples, and mobile sheet/editor patterns. No new third-party tour library is proposed.

## 3. Recommended Journey by Entry Path

The entry path determines the starting state. Current photo, reference, product, and placement state determine the next action after that. Use one shared guide rather than eight independently maintained tours.

| Entry | Photo mode | Product capability | Recommended sequence |
|---|---|---|---|
| Photo first | Automatic | Fit supported | Upload and analyze, Add Product, Fit opening, review preview |
| Photo first | Automatic | Free placement | Upload and analyze, Add Product, move and resize, review preview |
| Photo first | Paper reference | Fit supported | Prepare paper, upload and analyze, review reference, Add Product, Fit opening, review preview |
| Photo first | Paper reference | Free placement | Prepare paper, upload and analyze, review reference, Add Product, move and resize, review preview |
| Product first | Automatic | Fit supported | Upload and analyze, Fit selected product, review preview |
| Product first | Automatic | Free placement | Upload and analyze, move and resize selected product, review preview |
| Product first | Paper reference | Fit supported | Prepare paper, upload and analyze, review reference, Fit selected product, review preview |
| Product first | Paper reference | Free placement | Prepare paper, upload and analyze, review reference, move and resize selected product, review preview |

For paper paths, choosing Continue Approximate Preview replaces successful reference confirmation as the intake exit. It does not mark the paper verified or silently convert the session to automatic mode. For nonplanar products, paper review alone cannot establish all physical dimensions or depth.

### 3.1 Before upload

Keep Automatic Detection as the current default alongside the existing `CalibrationModeSelector`, `UploadImage`, and `GuideLine` components on both entry pages. Briefly explain Automatic Detection's approximate-preview meaning in `CalibrationModeSelector`. Do not add a pre-upload popup tour, intercept the native file chooser, or make opening the upload control count as a completed upload. Switching between Automatic and Paper Reference continues to update `GuideLine` as implemented today.

### 3.2 After upload (Intake & Paper Review Tour)

Preserve existing validation, loading, cancellation, retry, and success behavior for this milestone. Pause any active tour popup whenever upload/analysis loading or an error modal is visible; workspace tour steps start only after the accepted photo is ready and intake dialogs are closed.

In paper mode, `PaperDetectionConfirmationModal` remains the verification surface, enhanced for first-time users with a **step-by-step Paper Calibration Review popup tour** (darkened backdrop emphasis, with **Skip** and **Don't show again**):

1. Select Paper Format (`Short`, `A4`, or `Long`).
2. Check 4-Corner Boundaries (including tap-to-snap and manual 4-corner pinning).
3. Select Sheet Orientation (Portrait or Landscape).
4. Confirm Wall Plane (same-plane verification).
5. Apply or Preview (`Confirm & Enter Workspace` or `Continue Approximate Preview` if the photo lacks a valid flat reference).

Every confirmation gate remains intact. Do not repeat physical setup after the reference is confirmed, and retain recovery through tap-to-snap, corner adjustment, another photo, or approximate preview. A failure must explain how to proceed without pretending reference calibration succeeded.

### 3.3 First workspace action

On desktop, present the active workspace step inside a **popup tour card over a darkened backdrop** (`bg-black/60 backdrop-blur-xs`) to emphasize the next required action, with a primary action button, a **Skip** button (dismisses current run), and a **Don't show again** control (persists opt-out for returning users). When the user triggers an action that opens another modal (such as `AddProductModal` or `PerspectivePlanePicker`), pause/hide the tour popup cleanly while that modal owns the screen, and show the next step only after the action completes successfully. Suggested copy:

| State | Guidance | Primary action |
|---|---|---|
| No product or placed objects | Choose a product to see it in your space. | Add Product |
| Fit-capable product ready | Fit this product to the opening in your photo. | Fit opening, invoking the existing Fit action |
| Free-placement product ready | Drag the product into position. Use a corner handle to resize it. | Next (advances to the final tour step; dismisses backdrop so the user can drag/resize freely) |
| Preview ready (final tour step) | Your preview is ready to adjust. You can refine finishes or compare it with your original photo. | Got it (marks tour completed) alongside Continue to Comparison when the existing workflow permits |

The empty state should emphasize Add Product and avoid presenting Change Product and destructive actions as equally useful choices. In a selected-product state, emphasize Fit or canvas placement. Preserve existing advanced controls and keep configuration accordions collapsed unless the user opens them or follows a relevant optional hint.

The guide must not auto-open Fit, force a modification, or require customization. A user may choose free placement for a fit-capable product through a secondary Place manually action in the popup. This selects the movement/resize guidance without changing existing geometry; it must not invoke the destructive-to-fit Free Place action automatically. An already satisfactory initial placement can advance with Next without an artificial drag gesture.

Successful Confirm Fit enters a post-fit tour step with Next and the existing Edit Corners action where eligible. It does not itself mark onboarding complete. Clicking Got it on the final tour step accepts/completes the tour and records guide completion. Continuing to comparison before completing the tour remains permitted; pause the guide for preparation and suspend the run only after navigation succeeds, without inventing a tour completion event.

### 3.4 After placement

End the core guide after the customer accepts the first preview. Offer a short optional facing check after Fit: choose Front (Exterior) or Back (Interior) in Placement if the visible side is wrong. Retain the default when it is already correct.

Expose optional Finishes, Add another product, Save Snapshot, and Continue to Comparison through existing controls. Do not require a tour of lighting, shadows, occlusion, layers, add-ons, accessories, rotation, or every material setting.

State clearly that visual fit is not measurement confirmation. Continue to Comparison must retain its existing snapshot and measurement checks. Guide completion never authorizes quotation dimensions.

## 4. Guidance State and Lifecycle Contract

Implement a pure next-action resolver over existing domain facts, with a small separate presentation state for the guide. Suggested task states are paper preparation, reference review, add product, fit opening, free placement, preview ready, paused, and dismissed. Exact names are an implementation choice.

Before a photo is accepted, paper preparation is driven directly by the selected upload mode and remains available independently of the optional workspace guide. Once intake has produced a photo session, use this workspace resolution priority:

1. Respect dismissed or completed guidance unless the user requests help.
2. Wait for session hydration and a valid image. Do not flash a new-user guide during restoration. The photo-first page may supply its accepted local image before a shared asset session exists.
3. Pause for upload/analysis, product loading, an error, or an active modal. The modal owns its own instructions.
4. Resolve pending paper review only for a paper-mode intake; reference recovery remains available independently of guide visibility.
5. If no active product and no placed products exist, recommend Add Product. If only placed products exist, offer selection or continuation without incorrectly claiming the canvas is empty.
6. For a ready active product, inspect its current placement and actual Fit capability. Existing fitted/restored work must not be reset to satisfy a guide step.
7. Resolve preview readiness from a successful placement action plus user review. Rendering a model at its default center is not evidence the user positioned it intentionally.

| Event | Expected behavior |
|---|---|
| Open Add Product, then cancel | Remain at product selection; do not advance. |
| Select product, build fails | Pause with existing recovery. Do not highlight Fit for an unusable model. |
| Product build succeeds | Resolve Fit or free placement for that product instance. |
| Open Fit, then cancel | Stay at placement; retain previous geometry. |
| Confirm Fit | Advance only after the current product/image fit is committed successfully. |
| Fit or move without valid metric calibration | Allow visual preview; preserve approximate measurement provenance. |
| Switch active existing product | Use its current placement state, with no upload or paper replay. |
| Add or duplicate a product | Preserve photo/reference and earlier placements. Offer contextual placement help only if guidance is active or requested; respect dismissal. |
| Remove last product | Restore the useful Add Product empty state; do not restart a dismissed tour. |
| Replace image or begin a fresh session | Clear image-dependent progress; retain the user's learned/dismissed preference. Follow existing configuration reset behavior. |
| Return from comparison or refresh | Resume only with a valid restored session; otherwise follow the existing upload redirect. Never promise restoration the app does not provide. |
| Skip guide | Hide teaching cues immediately; do not skip paper validation, product guards, measurement confirmation, or other domain checks. |
| Restart guide | Start at the next useful step in the current workspace without altering the photo, products, dimensions, or reference. |

### 4.1 Shared Fit Capability and Bounded Correction

Introduce one pure Fit-capability helper, proposed at `src/lib/visualization/workspaceCapabilities.ts`, consumed by the desktop toolbar, mobile toolbar, Fit/Edit Corners action guards, and onboarding resolver. Resolve capability only after the product definition is ready. Its policy is:

| Product definition | New Fit / Edit Corners eligibility |
|---|---|
| Explicit canonical `Cabinet` | False, even if the product name includes door, a component key includes door, or a component is named window-sill. Guide free placement. |
| Any other supported or legacy type | Preserve the existing eligibility result exactly: current window/sill and door/name/component predicates. This milestone does not broaden or narrow other categories. |
| Definition still loading or unavailable | Do not recommend or invoke Fit; show the existing loading/error recovery state. |

Partitions, enclosures, railings, and Other are not categorically excluded. Characterize their current predicates with fixtures, including door-named components, and retain those results. A wider category-policy change is outside MS89.

The explicit Cabinet override belongs in the shared Fit-capability helper. Do not alter the existing `isDoorProduct` or `isWindowProduct` consumers for fallback width/height, `computeEstimatedDimensions`, sill options, or picker labeling as a side effect. Characterization tests must establish that a product with unchanged configuration retains the same dimensions and estimation outputs. Any independently identified sizing defect must be documented separately.

Previously fitted cabinet configurations remain renderable and retain stored corners, dimensions, facing, and calibration evidence on restoration. Hide or disable new Fit/Edit Corners operations consistently on desktop and mobile and guard their handlers. The customer can retain the restored pose or deliberately choose the existing Free Place action. Do not clear old geometry merely because capability is now false, and do not require refitting to continue to comparison. Keep a short explanation available: "This cabinet uses free placement. Your existing placement is kept."

Audit representative product definitions during implementation, but the expected policy above is settled. If live catalog access is unavailable, use repository-owned fixtures and leave live-asset browser acceptance explicitly pending. The capability correction is part of MS89 implementation, not a code change required during this planning pass.

### 4.2 Preferences and Completion

Use a versioned browser-local preference with three outcomes: `unseen`, `completed`, and `dont_show_again` (plus a per-session/per-run `skipped` presentation state). Automatic popup tours are eligible only while `unseen` and not `skipped` in the current run.

- **Skip:** Dismisses the active popup tour for the current run/session without setting a permanent opt-out, so a first-time user who simply needed to glance at the workspace can still resume via Help or on a fresh start if they haven't completed it.
- **Don't show again:** Records `dont_show_again` in browser-local preference storage for experienced or returning users, suppressing automatic paper-calibration and workspace tour popups on later photos/products.
- **Next / Got it:** `Next` advances intermediate tour steps, and `Got it` on the final tour step marks the guide `completed`, closing the darkened backdrop and suppressing automatic replay on later photos/products.

A skipped, completed, or `dont_show_again` preference never hides essential paper-mode validation controls, reference recovery, the empty-state `Add Product` cue, or the manual `Help` / `Restart guide` button.

Help/Restart guide enables one manual guide run from the next useful current task without clearing the persistent preference or resetting domain state. Closing that run restores the previous automatic-display preference; completing it may record `completed`. Selecting Continue to Comparison pauses guidance during preparation and measurement confirmation. If preparation fails, remain paused while error recovery owns attention, then resume the previous task. If confirmation or navigation is cancelled/fails, resume the previous task once that interaction closes, unless the user skipped or opted out. Persist per-run comparison suspension only when navigation to comparison succeeds; this neither fabricates successful completion nor opts the user out permanently. Returning from comparison keeps that run suspended until Help is requested.

Preference storage contains no photos, customer details, geometry, or measurement evidence. Invalid stored shapes must be ignored safely. Unavailable local storage falls back to the shared in-memory preference for the current app lifetime. No cross-device or durable preference guarantee is made when storage is denied. Do not introduce independent learned-topic flags in this milestone.

### 4.3 Route Handoff, Instance Identity, and Storage

Own guide state in a shared feature provider mounted inside the existing `VisualizationSessionProvider` in `src/components/shared/LayoutWrapper.tsx`, above the route pages. Keep the pure reducer/resolver and presentation components under `src/features/visualization/`. Do not depend on state owned only by `DirectVisualizationPage` or `ProductModelWorkspace`, because those components can unmount during navigation.

| Identity / storage | Contract |
|---|---|
| Image identity | `spaceImageSession.sessionId` is the accepted image identity before and after product selection. Do not use the temporary image URL as identity. |
| Guide generation | Increment or replace a guide generation on explicit image/session reset, even if an old image ID is reused. Old action acknowledgements must no longer match. |
| Asset session | `setPreparedSpaceImage` calls `createPreparedSpaceImageState`, which creates a new `assetSessionId`. This is an asset/cache boundary, not a new photo or a reason to restart guidance. |
| Product instance | Allocate a stable guide instance ID for each newly selected, added, changed, or duplicated product instance. A no-op change to the same product preserves identity. Product ID or layer number alone cannot distinguish duplicates. |
| Overlay aliases | Maintain explicit mappings between the guide instance ID and current active/placed overlay IDs. `activeOverlayId` can start as `active-${productId}` and `createPlacedOverlay` generates a fresh UUID; neither is a stable lifetime guide identity. |
| Runtime persistence | Shared provider memory is authoritative for route transitions. Store a versioned, small sessionStorage guide record separately from the existing visualization record for refresh recovery. Persist image/generation, run status, active instance and aliases, and accepted progress only. |
| Restoration | Restore guide progress only after the existing visualization session is hydrated and valid and image/instance associations match. If matching cannot be established, derive the next useful state from existing domain facts without treating it as new-user evidence or replaying completed steps. |

The first-product handoff must reserve the guide instance and publish guide progress to the shared provider before calling `setPreparedSpaceImage` and navigating. The destination adopts that same instance for the matching product and image; successful model readiness advances from Add Product to the appropriate placement step. This handoff does not repeat paper review or reinitialize the guide when `assetSessionId` changes.

When an active product is captured as a placed/comparison overlay, explicitly associate the newly generated overlay ID with its guide instance before switching the active target. Capturing the same instance again preserves its guide identity. Duplicating it creates a different guide identity even when configuration and product ID are identical. Editing an existing overlay resolves its mapped instance; replacing a product retires the replaced instance and creates a new one. Do not rewrite renderer/cache overlay IDs merely to support onboarding.

Async guide acknowledgements must match image ID, guide generation, guide instance ID, and current action attempt before advancing. This supplements existing domain cancellation/identity checks and never replaces them. Removal/reset invalidates the relevant pending acknowledgements and mappings.

If sessionStorage is unavailable, shared memory must still preserve progress across client-side route transitions. After a full reload, rely on whatever valid domain session can actually be restored and persistent skip/completion preferences if available. A direct-page reload before product selection may lose its locally held photo; the guide must not imply the photo survived or construct a workspace from guide storage. Old/invalid guide records are discarded, not used as domain evidence.

## 5. Desktop, Mobile, and Accessibility

Use existing components, tokens, spacing conventions, focus styles, and compact editor behavior. No new tour library is needed.

On desktop, render the step-by-step tour as a centered popup card over a darkened backdrop (`bg-black/60 backdrop-blur-xs`, matching existing modals such as `ImageSuccessModal`), with `Next` / `Got it`, `Skip`, and `Don't show again` controls. On mobile phones (`shouldLockMobileEditor` and small viewports), adapt the same darkened backdrop into a **compact bottom-sheet / anchored mobile card** (following `MobileBottomSheet` conventions with safe-area padding, `max-h-[45dvh]` or compact scrolling, and `min-h-11` touch targets) rather than a tall centered desktop popup, so it remains thumb-reachable in portrait and landscape without clipping or obstructing the fullscreen editor chrome once dismissed.

Resolve distinct mobile and desktop targets and wait until targets are mounted and visible. A missing target should fall back to readable popup/sheet instructions, not an empty spotlight or a retry loop.

For optional Placement help on mobile, lead to Controls before Placement. For continuation, explain that Done returns to the page where Continue to Comparison is available. Changing orientation must not restart the guide or leave guidance attached to a hidden desktop control.

Keep Skip, Don't show again, and Help/Restart guide reachable with keyboard and touch. Preserve dialog focus ownership, `Escape` dismissal parity where safe, and focus restoration after closing dialogs. Do not rely on hover, color, animation, or spatial pointing alone to explain an action. Announce important step changes concisely and respect reduced motion. Test that the guided placement task remains achievable with the repository's accessible controls; document any existing manipulation accessibility gap rather than claiming the guide resolves it.

## 8. Settled Decisions and Readiness Boundary

1. Use a **step-by-step popup tour with a darkened backdrop** (`bg-black/60 backdrop-blur-xs`) for first-time guidance during post-upload Paper Calibration Review (`PaperDetectionConfirmationModal`) and Desktop Workspace placement (`ProductModelWorkspace`), while keeping the pre-upload page (`CalibrationModeSelector`, `UploadImage`, `GuideLine`) free of an extra popup tour.
2. Automatically show relevant tour popups for first-time (`unseen`) users, with `Next` / `Got it` step progression, **Skip** (dismiss current run), and **Don't show again** (persistent opt-out for experienced users), plus manual `Help` / `Restart guide`.
3. End the core tour after the placement step (`Next` -> `Got it`). Keep facing, finishes, and comparison guidance short and optional.
4. Retain the current analysis-success dialog (`ImageSuccessModal`) for the first milestone. Consider consolidating it only if usability observation shows it adds friction.
5. Apply the bounded Cabinet Fit correction in Section 4.1 through one shared capability helper. Preserve non-cabinet eligibility, unrelated sizing behavior, and previously fitted cabinet data.

## 9. Supporting UX Rationale

Contextual help places instructions near the task that needs them and avoids asking users to memorize an editor tour. See [Nielsen Norman Group: Onboarding Tutorials vs. Contextual Help](https://www.nngroup.com/articles/onboarding-tutorials/). Progressive disclosure supports prioritizing primary tasks while keeping secondary controls available. See [Nielsen Norman Group: Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/).
