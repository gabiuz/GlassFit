## 1. Authorized Requirement

In the GlassFit photo-based visualization workspace (`/visualize/[productId]/workspace`), the "Fit" feature (also referred to as "Fit to Opening" or perspective plane fit) allows users to drag four corner handles over a room opening in their uploaded photo. When the user confirms the fit, the 3D product model is warped into the defined quadrilateral using perspective transformation (`perspectiveFitCorners`).

### 1.1 Current Behavior (Defect)

Upon confirming a perspective fit, the `onConfirm` callback in [`ProductModelWorkspace.tsx`](file:///Users/gab/Developer/glassfit/src/features/visualization/components/ProductModelWorkspace.tsx#L3789-L3808) computes heuristic yaw and pitch values derived from the geometric asymmetry of the user-drawn quadrilateral:

```typescript
const deltaH = (leftH - rightH) / maxH;
const deltaW = (bottomW - topW) / maxW;

const initialYaw = Math.round(clampNumber(deltaH * 35, -25, 25));
const initialPitch = Math.round(clampNumber(deltaW * 25, -20, 20));

setPerspectiveCorners(corners);
setYaw(initialYaw);
setPitch(initialPitch);
```

This means:
1. If the left edge of the quadrilateral is longer than the right edge, the model receives a positive yaw offset (and vice versa).
2. If the bottom edge is wider than the top edge, the model receives a positive pitch offset (and vice versa).
3. Even small geometric inconsistencies in the user's corner placement (a few pixels of asymmetry) result in non-zero yaw and pitch values (commonly 2 to 8 degrees).
4. The approved `PRD-F6` behavior defines perspective-fit confirmation as a neutral orientation reset. The perspective warp maps the rendered overlay to the selected quadrilateral; it does not determine the yaw or pitch state.

### 1.2 Required Behavior

When the user confirms a perspective fit placement, both yaw and pitch must be set to 0 degrees. The CSS perspective warp continues to map the rendered overlay to the selected quadrilateral. The orientation reset is an explicit product behavior and must not be inferred from the quadrilateral geometry.

Specifically:
1. After confirming "Fit to Opening," yaw must be 0 degrees and pitch must be 0 degrees.
2. The yaw and pitch sliders and stepper controls must display 0 deg.
3. The Three.js 3D model renderer must receive yaw=0 and pitch=0 on the render following fit confirmation.
4. Users retain full control to manually adjust yaw and pitch after placement via sliders, steppers, or any future controls.

No database migration, backend CV microservice change, pricing engine modification, or new external dependency is authorized. This document is an implementation specification; no application code is to be executed or committed during planning.

## 2. Verified Current State

### 2.1 Perspective Fit Confirmation Handler

In [`ProductModelWorkspace.tsx`](file:///Users/gab/Developer/glassfit/src/features/visualization/components/ProductModelWorkspace.tsx#L3789-L3808), the `PerspectivePlanePicker` `onConfirm` callback:

1. Lines 3789-3798: Computes `deltaH` and `deltaW` from the pixel-space edge lengths of the four user-placed corners (`p0`, `p1`, `p2`, `p3`).
2. Line 3800: Derives `initialYaw` by scaling `deltaH` by a factor of 35 and clamping to [-25, 25] degrees.
3. Line 3801: Derives `initialPitch` by scaling `deltaW` by a factor of 25 and clamping to [-20, 20] degrees.
4. Lines 3803-3805: Sets `perspectiveCorners`, `yaw`, and `pitch` state.
5. Lines 3806-3808: Resets `rotateAngle` to 0, bumps `modelRevision`, and closes the perspective picker.

### 2.2 State Initialization and Reset

1. Line 245: `const [yaw, setYaw] = useState(initialConfiguration?.yaw ?? 0);` (initial default is 0).
2. Line 246: `const [pitch, setPitch] = useState(initialConfiguration?.pitch ?? 0);` (initial default is 0).
3. Lines 1162-1163: `resetProductPlacement()` already resets both to 0.
4. Lines 1202-1203: `applyProductConfiguration()` restores saved yaw and pitch from configuration snapshots.

### 2.3 Configuration Snapshot Persistence

The `currentConfiguration` memo captures `yaw` and `pitch` in the `ProductConfigurationSnapshot` object. When a perspective fit is confirmed with heuristic yaw/pitch, those non-zero values propagate into saved snapshots, quotation payloads, and session storage. By resetting to 0 at fit time, saved configurations will correctly reflect the neutral orientation.

## 3. Scope

### 3.1 In Scope

1. Removal of the heuristic yaw/pitch computation in the `PerspectivePlanePicker` `onConfirm` callback.
2. Replacing `setYaw(initialYaw)` and `setPitch(initialPitch)` with `setYaw(0)` and `setPitch(0)`.
3. Removing the now-unused `deltaH`, `deltaW`, `initialYaw`, and `initialPitch` local variables.
4. Removing the now-unused edge-length computations (`leftH`, `rightH`, `topW`, `bottomW`, `maxH`, `maxW`) that solely served the heuristic.
5. Verifying that existing tests, lint, typecheck, and build pass without errors.

### 3.2 Out of Scope

1. Perspective Plane Picker Modifications:
   - No changes to [`PerspectivePlanePicker.tsx`](file:///Users/gab/Developer/glassfit/src/features/visualization/components/PerspectivePlanePicker.tsx). The corner selection UI, drag interaction, and `onConfirm` contract remain unchanged.
2. Three.js Model Rendering Pipeline:
   - No changes to `src/lib/visualization/modelRenderer.ts` or Three.js Euler angle conversion. The renderer already accepts yaw=0 and pitch=0 as valid inputs.
3. CSS Perspective Transformation:
   - The `matrix3d` CSS warp computed from `perspectiveFitCorners` is unaffected. It operates independently of 3D model yaw/pitch.
4. Database Schema or Migration Changes:
   - The `product_configurations` table already supports numeric yaw and pitch. No DDL or migration is needed.
5. Slider or Stepper Control Modifications:
   - No orientation control behavior or styling changes are in scope. After IMP-MS39 is implemented, its steppers, like the existing sliders, display 0 deg after fit and remain available for post-fit adjustment.
6. Computer Vision Microservice:
   - No modifications to FastAPI endpoints, YOLOv8 segmentation, or image analysis.
7. Pricing or BOM Logic:
   - Yaw and pitch do not affect window framing dimensions, glass cutlists, or BOM pricing.

## 4. Functional Contract

### 4.1 Perspective Fit Orientation Contract

| Condition | Expected Yaw | Expected Pitch |
|---|---|---|
| User confirms perspective fit with a symmetric quadrilateral | 0 deg | 0 deg |
| User confirms perspective fit with an asymmetric quadrilateral (left edge longer) | 0 deg | 0 deg |
| User confirms perspective fit with an asymmetric quadrilateral (bottom edge wider) | 0 deg | 0 deg |
| User confirms perspective fit with extreme trapezoidal distortion | 0 deg | 0 deg |
| User manually adjusts yaw/pitch after fit via slider or stepper | Reflects user adjustment | Reflects user adjustment |
| User resets product placement after fit | 0 deg | 0 deg |

### 4.2 State Synchronization

After confirming a perspective fit, the following must all reflect 0 degrees:
1. React state: `yaw === 0` and `pitch === 0`.
2. Range slider thumb position: centered at the 0 mark.
3. Degree numerical readout: displays `0 deg`.
4. Stepper buttons: both `-` and `+` enabled (neither boundary reached at 0).
5. Three.js renderer: receives `yaw=0` and `pitch=0` in the next render cycle.
6. Configuration snapshot: `currentConfiguration.yaw === 0` and `currentConfiguration.pitch === 0`.

## 8. Definition of Done

IMP-MS40 is considered complete only when all of the following criteria are satisfied:

1. The heuristic yaw/pitch computation (edge-length ratio scaling) has been fully removed from the `PerspectivePlanePicker` `onConfirm` callback.
2. Both `setYaw(0)` and `setPitch(0)` are called upon confirming a perspective fit placement.
3. All removed variables (`deltaH`, `deltaW`, `initialYaw`, `initialPitch`, and the edge-length intermediaries) are no longer present in the fit-confirmation callback.
4. No unused imports remain after cleanup.
5. The perspective fit visual alignment (via `perspectiveFitCorners` and CSS `matrix3d`) is unaffected.
6. Dimension estimation (if applicable via `pxCorners`) continues to function correctly.
7. Manual verification confirms yaw=0 and pitch=0 after symmetric and asymmetric fit placements.
8. Full repository verification commands (`npm run lint`, `npx tsc --noEmit`, `npm run build`, `npm run test`) execute with zero errors.
9. Focused automated regression coverage for QAD-TC55 proves that confirmation resets both angles and later manual adjustments still update them.
