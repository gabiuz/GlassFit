## 1. Problem Context & Motivation

YOLOv8s-seg detects foreground objects from the COCO-80 class set (`RELEVANT_COCO_LABELS` in `fastapi-service/segmentation.py`), producing per-object binary masks that the frontend composites as occlusion layers. This enables realistic "behind-the-sofa" or "behind-the-chair" product placement.

However, **protruding architectural elements (wall columns, piers, partitions, soffits, and beams) are not COCO classes**. These are foreground structures that "hang" or protrude in front of the wall surface where the product is placed. For example, in a room with two window openings separated by a center wall column, the user places the glass product on the back wall behind each window opening. The center column sits physically in front of the product and should occlude it. Without a mask for this column, the product overlay renders on top of the column, breaking visual realism.

**Critical distinction:** The target is not the entire wall surface. The back wall (where the product sits) must remain unmasked so the product remains visible. Only protruding foreground architectural elements that hang in front of the product placement area require occlusion masking.

SegFormer (ADE20K) already detects wall regions (`ADE20K_WALL = 0` in `fastapi-service/scene_detection.py`), but its output is a whole-wall semantic mask covering both the back wall and any protruding columns indiscriminately. It cannot distinguish between the product placement surface (back wall) and foreground architectural protrusions (columns, piers). This makes the SegFormer wall mask unsuitable for selective occlusion.

**Approach selected:** Interactive manual brush-painting mask tool on the frontend. The user paints only the specific protruding elements (columns, piers, partitions, beams) that should appear in front of the product overlay, leaving the back wall surface unpainted. This approach:
- Gives the user precise control over which foreground elements occlude the product.
- Naturally excludes the back wall surface (the user simply does not paint it).
- Works for any protrusion shape (columns, soffits, ceiling beams, L-shaped partitions).
- Requires no new ML model or training data.
- Reuses the existing occlusion compositing pipeline (`drawMaskedBackgroundLayer` with `destination-in` composite operation).
- Ships as a progressive enhancement alongside the existing auto-detected object occlusion.

## 4. Technical Specification

### 4.1 Type Additions

**File:** `src/lib/visualization/types.ts`

Add `manualOcclusionMaskDataUrl` to `ProductConfigurationSnapshot`:

```typescript
export type ProductConfigurationSnapshot = {
  // ... existing fields ...
  activeOcclusionIds?: string[];
  manualOcclusionMaskDataUrl?: string | null;
  ambientLight?: boolean;
  // ... remaining fields ...
};
```

The field stores a base64 PNG data URL (white-on-transparent mask, identical format to YOLO object masks). This ensures round-trip persistence through the existing configuration snapshot and restore flow.

### 4.2 ManualMaskPainter Component

**File:** `src/features/visualization/components/ManualMaskPainter.tsx` (NEW)

**Props interface:**

```typescript
interface ManualMaskPainterProps {
  backgroundImageUrl: string;
  canvasWidth: number;
  canvasHeight: number;
  initialMaskDataUrl?: string | null;
  onSave: (maskDataUrl: string) => void;
  onCancel: () => void;
}
```

**Component capabilities:**

| Feature | Implementation Detail |
|---|---|
| Instruction text | A guidance banner displayed at the top of the painter: "Paint over protruding elements (columns, piers, beams) that should appear in front of the product. Do not paint the back wall where the product is placed." |
| Brush tool | User paints white strokes on a transparent canvas layer. Brush radius adjustable via slider (10px to 80px). |
| Eraser tool | Toggles canvas `globalCompositeOperation` to `destination-out` to remove painted areas. |
| Undo stack | Stores canvas `ImageData` snapshots (up to 20 entries). Supports Ctrl+Z keyboard shortcut and undo button. |
| Clear all | Resets the overlay canvas to fully transparent. |
| Done action | Converts the colored preview overlay to a white-on-transparent mask (matching YOLO mask format), exports as PNG data URL via `canvas.toDataURL("image/png")`, and calls `onSave(dataUrl)`. |
| Cancel action | Discards all painting changes and calls `onCancel()`. |
| Visual feedback | Semi-transparent cyan overlay (approximately 40% opacity) so the user can see painted regions against the background image. |
| Cursor indicator | Custom circular cursor matching the current brush radius, rendered via CSS or a secondary canvas layer. |

**Rendering structure:**
1. A fixed/absolute-positioned modal overlay covering the workspace canvas area.
2. Background layer: the room photograph rendered at workspace dimensions for spatial reference.
3. Painting layer: a transparent `<canvas>` element at the same dimensions, receiving pointer events.
4. Toolbar: positioned at the top or bottom of the modal with brush/eraser toggle, size slider, undo button, clear button, done button, and cancel button.

**Mask export conversion:**
When the user clicks "Done," the painted canvas (which shows cyan strokes for visibility) is converted to the white-on-transparent format required by `drawMaskedBackgroundLayer`:
1. Create a temporary canvas at the same dimensions.
2. Iterate pixel data: any pixel with non-zero alpha in the painted canvas becomes `rgba(255, 255, 255, 255)` in the export canvas; all other pixels remain `rgba(0, 0, 0, 0)`.
3. Export via `canvas.toDataURL("image/png")`.

## 5. Compositing Pipeline (Unchanged)

The existing compositing pipeline in `captureWorkspaceSnapshot` processes layers in this order:

| Layer Order | Source | Compositing Strategy |
|---|---|---|
| 1 | Background room photograph | `drawObjectContainImage` onto output canvas |
| 2 | Placed product overlay layers | `drawImage` per placed overlay |
| 3 | Active product overlay (current) | `drawSnapshotOverlay` with rotation, flip, and filter |
| 4 | Auto-detected YOLO occlusion masks | `drawMaskedBackgroundLayer` per active object (iterates `activeOcclusionObjects`) |
| 5 | **Manual brush-painted occlusion mask (NEW)** | `drawMaskedBackgroundLayer` with `manualMaskDataUrl` |

Layers 4 and 5 both use the same `drawMaskedBackgroundLayer` function, which:
1. Draws the background image onto a temporary canvas.
2. Applies `globalCompositeOperation = "destination-in"` with the mask image.
3. Draws the resulting masked region onto the output canvas.

This means the manual mask seamlessly integrates without any changes to the compositing engine.

## 7. Definition of Done (Exit Criteria)

1. `ManualMaskPainter.tsx` renders as a modal overlay with brush, eraser, undo, clear, done, and cancel functionality.
2. Painted mask produces a white-on-transparent PNG data URL compatible with `drawMaskedBackgroundLayer`.
3. Live DOM rendering shows the manual mask as an occlusion layer using CSS `mask-image` (identical to auto-detected object masks).
4. "Apply Changes" snapshot export includes the manual mask in the composited output.
5. "Edit" restores the previously painted manual mask for further editing.
6. Auto-detected YOLO object occlusion continues to function independently alongside the manual mask.
7. `npm run lint` passes with zero new errors.
8. `npx tsc --noEmit` passes with zero new type errors.
9. `npm run build` succeeds.

## 8. Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| User paints the entire back wall instead of only protruding elements, hiding the product | Medium | High | Instruction banner in the painter clearly states to paint only protruding columns, piers, and beams. Eraser tool and undo stack allow easy correction. Cyan preview overlay makes painted area visually obvious. |
| Large mask data URLs increasing memory pressure on mobile devices | Medium | Medium | Limit canvas resolution to workspace dimensions (typically 1024px to 1600px). Compress with `canvas.toDataURL("image/png")` which uses lossless compression on sparse binary masks. |
| Brush painting feels imprecise on mobile touch screens | Medium | Low | Provide adjustable brush size (10px to 80px). Zoom-pinch on the workspace canvas provides finer control. Eraser tool corrects overpainting. |
| Manual mask misalignment after workspace resize | Low | Medium | Mask canvas dimensions are tied to workspace dimensions. If the workspace image changes, the manual mask is invalidated (reset to null with user notification). |
| Base64 data URL exceeds browser storage limits for configuration snapshots | Low | Low | Binary masks with large transparent regions compress well in PNG format. A 1600x1200 sparse mask typically produces a 5KB to 50KB data URL. |
