## 1. Outcome and Scope

Prove that accepted measurements improve real model width and height, rather than only passing formulas derived from the current scalar implementation. Evaluate automatic detection separately from measurement accuracy, and report abstentions so the system cannot appear accurate simply by refusing every image.

This acceptance protocol now has executable benchmark tooling. No measured physical benchmark results, automatic detection success rate, physical accuracy, or release pass is claimed. Automated verification is recorded separately below.

## 2. Baseline and Evidence Collection

Before implementing MS53-MS56, record current detector choice, corners, chosen format, scalar output, opening fit, predicted dimensions, and quotation dimensions on the same evaluation inputs. Record application revision and dirty working-tree state because existing MS45-MS52 implementation changes are present locally.

| Evidence | Required record |
|---|---|
| Supplied samples 1-3 | Original filenames, dimensions, orientation, checksum, visible paper annotations, and expected recovery behavior |
| Physical reference | Confirmed paper standard, measured sheet dimensions if nonstandard or trimmed, and flatness/placement declaration |
| Target opening | Defined installation perimeter and tape-measured width/height; top/bottom and left/right when shape differs |
| Capture context | Same plane or known mismatch, approximate angle category, paper visibility, lighting, device and lens mode if available |
| Geometry annotations | Independent paper and opening corner labels with localization uncertainty |
| Evaluation result | Automatic versus corrected corners, accepted/rejected status and reasons, per-axis errors, sensitivity, latency, and measurement revision |

The supplied photographs lack physical ground truth. Use them immediately for detection and workflow regression, but mark metric accuracy unavailable until actual dimensions are measured. Do not use nominal door sizes, perceived body height, tiles, furniture, or a predicted model size as ground truth.

Store room photos as private test resources under existing repository/data handling practices. Do not publish sample 3 or any supplied room image in `public/` or commit private photos simply to make CI convenient. Automated public fixtures can use synthetic scenes or permitted anonymized captures; private fixture absence must be reported as skipped, not passed.

## 3. Dataset and Test Matrix

Collect at least 60 distinct photos from at least 10 measured openings and at least 3 camera devices. Include Short, A4, and Long references, portrait/landscape placement, frontal and oblique views, shadow, bright backlight, white-on-white boundaries, distracting rectangles, partial boundaries, and small or far-away paper.

Include at least 15 unsafe/no-reference images spanning handheld paper, adjacent-wall paper, absent paper, and invalid geometry. Keep at least 5 cases per principal release stratum: frontal eligible, oblique eligible, low-contrast eligible, and unsafe/no-reference. These are proposed minimums for a capstone acceptance benchmark, not proof of population-wide accuracy.

Split development and held-out data by physical opening/capture session, not random near-duplicate photos. Reserve at least 20 held-out images. Freeze detector thresholds, geometry thresholds, and supported capture envelope before evaluating the holdout set. Report counts where strata overlap.

| Test layer | Purpose | Required cases |
|---|---|---|
| Synthetic projective geometry | Isolate mathematical correctness | Known metric plane, rotations, large perspective, distant target, anisotropic resize, crop, and inverse round trip |
| Invalid input | Establish safe rejection | Duplicate/crossed/collinear corners, nonfinite matrix, wrong units, horizon crossing, malformed API response |
| Detection fixtures | Isolate sheet selection | Correct sheet amid distractors; ambiguous/no-paper abstentions; shadow and low contrast |
| Physical photo benchmark | Measure practical axis errors | Tape ground truth with automatic corners, then separately with independently corrected corners |
| Plane and workflow integration | Enforce safe recovery | Handheld declaration, uncertain placement, different-wall second product, tape fallback |
| Scene and quotation parity | Detect downstream drift | Fit, zoom, refresh, recalibrate, add/change product, save quotation, inspect snapshot and PDF |

## 4. Metrics and Proposed Release Gates

For each accepted metric result and each axis, calculate `absolute_error_mm = abs(predicted_mm - tape_mm)` and `relative_error_percent = 100 * absolute_error_mm / tape_mm`. Width and height must pass independently. Report signed bias, median, 95th percentile, maximum error, and the number of accepted and rejected cases for every stratum.

| Gate | Proposed pass criterion |
|---|---|
| Automatic sheet acceptance precision | At least 95% of automatically selected accepted outlines correspond to the annotated sheet; publish numerator and denominator |
| Automatic localization coverage | At least 80% of eligible held-out photos have the correct sheet automatically selected without corner editing; report separately for each lighting/angle stratum |
| Metric coverage | At least 70% of eligible held-out captures reach an accepted planar estimate after format/placement review and opening fit, without manual paper corners; unsafe captures excluded only by predefined labels |
| Per-result physical accuracy | Every accepted held-out planar estimate is within 5% on width and within 5% on height; reject or narrow the supported envelope if this fails |
| Typical physical accuracy | Median relative error at most 2% per axis among accepted held-out planar estimates; this is a benchmark target, not an advertised guarantee |
| Unsafe placement | Zero metric promotions after declared mismatch or unknown placement, including manually mapped handheld paper |
| Negative image safety | Zero automatically trusted metric results from annotated no-paper inputs |
| Numeric geometry | Synthetic noise-free tests meet MS54 relative tolerance of 0.000001 |
| Model/quotation parity | Values match the accepted measurement within documented boundary rounding, with no stale revision |

Coverage and accuracy must pass together. Report automatic, candidate-selected, and manually corrected reference results separately. Compare automatic versus annotated corners to distinguish localization failure from plane/geometry/model failure. A 5% capstone photo-estimate target is not a fabrication tolerance; do not reuse older "millimeter-accurate" or "quote-ready" claims without separate supporting evidence.

Record detection-only p50/p95 latency separately from total CV inference on a documented CPU and input resolution. Establish a measured latency budget before release; do not inherit the unverified sub-45ms requirement from older milestones. Keep input resolution and bounded candidate count explicit for reproducibility.

## 5. Step-by-Step Verification Plan

1. Build the private or permitted benchmark manifest and collect tape dimensions using a consistent installation perimeter.
2. Capture current behavior as a baseline. Annotate actual sheet corners independently of algorithm predictions.
3. Implement and test MS53 detection, MS54 geometry, MS55 eligibility, and MS56 propagation in that dependency order. MS55 state modeling can proceed alongside geometry, but trusted measurements require both.
4. Freeze thresholds on development data and evaluate the held-out set once per release candidate. Any tuning requires a fresh declared evaluation cycle.
5. Run browser checks on mobile and desktop for all three user samples, using permitted local fixtures. Include display zoom and image letterboxing checks.
6. Record the acceptance matrix, failures, abstentions, supported capture limits, and environment. No claim is complete until its evidence exists.
7. Reconcile `docs/index.md`, `docs/milestone.md`, upstream PRD/SDD/DSD/ERD wording as needed, and `docs/qad-glassfit.md` during implementation. Keep tooling completion separate from physical release acceptance.

## 7. Risks and Rollout

Ship detection, geometry, eligibility, and downstream propagation as a coherent calibrated-measurement change. If release gates fail, retain clearly approximate preview and manual tape entry while fixing the failed stage. Do not restore the global scalar as a trusted accuracy fallback. Preserve legacy quotation readability and existing customer configuration throughout rollback.
