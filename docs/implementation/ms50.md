## 1. Outcome and Scope

The ultimate purpose of fiducial paper calibration is to ensure that parametric 3D models placed into client room photos represent true real-world dimensions (within 2% to 5% accuracy) rather than rough visual ballpark estimates.

In prior implementations, several mathematical gaps degraded dimensional accuracy:

1. **Heuristic Height Blending:** In `src/lib/visualization/scaleEstimation.ts`, `computeEstimatedDimensions()` blended estimated scale with conservative default height assumptions (120cm for windows, 210cm for doors) capped at an arbitrary 0.85 weighting factor. Even when a physical calibration marker was present, the model height was pulled toward template averages, skewing tall or short custom fixtures.
2. **Arbitrary Initial Starting Dimensions:** When adding new products into the room or switching between models, initial dimensions defaulted to static values (such as 210cm width x 150cm height) rather than calculating the physical footprint from opening pixel spans and calibrated metric scale.
3. **Quotation Audit Disconnect:** Fabricators reviewing quotation summaries lacked clear verification of whether dimensions were derived from calibrated physical markers or uncalibrated ballpark estimates.

`IMP-MS50` resolves these discrepancies by mathematically grounding 3D model dimensions, perspective fits, and quotation line items directly in the verified coplanar scale factor:

- **Direct Coplanar Scale Application:** Modifies `computeEstimatedDimensions()` in `src/lib/visualization/scaleEstimation.ts` to assign 100% weight to `best_scale_cm_per_px` when calibrated paper scale is active (`method.startsWith("paper_fiducial")`). Heuristic height blending and depth correction distortions are completely bypassed.
- **Scale-Aware Initial Sizing:** Enhances `getScaleAwareInitialDimensions()` to compute starting width and height for added products using the active calibrated scale factor, ensuring new fixtures placed in the scene match true spatial dimensions immediately.
- **Perspective Quad Fit Synchronization:** When the user fits a 4-point perspective quadrilateral around an opening, the pixel bounds convert directly into physical centimeters, dynamically updating the Three.js parametric mesh, frame extrusions, and glass infill.
- **Quotation Audit Trust Badges:** In `MeasurementConfirmationModal.tsx`, presents calibrated dimensions with an emerald "Calibrated Visual Estimate (±2-5% Precision)" badge and persists `pricing_details.dimension_source = "calibrated_visual"` to Supabase quotation items.

### 1.1 Non-Negotiable Invariants

1. **Bypass Heuristic Blending on Calibrated Sessions:** The system must never blend template default heights (e.g. 120cm or 210cm) when a verified paper fiducial scale is active. Calibrated scale must receive 100% mathematical weight.
2. **User Tape-Measure Authority:** While calibrated visual estimates provide quote-ready accuracy (±2% to 5%), customers always retain the authority to override dimensions with manual tape measurements in `MeasurementConfirmationModal.tsx`.
3. **Architectural Safety Clamping:** All calculated dimensions are clamped within realistic physical fenestration limits: width within [30cm, 600cm] and height within [30cm, 400cm].
4. **Style Consistency:** All measurement badges, choice cards, and dimension inputs must strictly conform to existing design tokens in `src/app/globals.css` and established component conventions (`BAN-UI-09`).
5. **No Em-Dashes:** All documentation, code comments, and copy must use hyphens, colons, or parentheses (`BAN-PUNCT-01`).
6. **No Box Diagrams in Code Blocks:** All UI tables, dimension formulas, and state flows must use standard Markdown tables and ordered prose (`BAN-DIAG-03`).

## 3. Grounded Dimension Formulation & Scaling Math

### 3.1 Direct Coplanar Dimension Derivation

Given:
- Opening pixel width: $W_{\text{px}}$ (derived from overlay bounds or perspective quadrilateral)
- Opening pixel height: $H_{\text{px}}$
- Verified coplanar scale factor: $S = \text{scale\_cm\_per\_px}$ (in centimeters per pixel)

When `isPaperCalibrated` is true:

$$W_{\text{cm}} = \text{round}(W_{\text{px}} \cdot S)$$
$$H_{\text{cm}} = \text{round}(H_{\text{px}} \cdot S)$$

$$W_{\text{grounded}} = \max(30, \min(600, W_{\text{cm}}))$$
$$H_{\text{grounded}} = \max(30, \min(400, H_{\text{cm}}))$$

Zero depth corrections or template height ratios are applied. Because the fiducial paper lies on the exact same wall surface plane as the opening, the scale factor is planar and mathematically exact across that entire wall.

### 3.2 Enhanced `computeEstimatedDimensions()` Implementation

In `src/lib/visualization/scaleEstimation.ts`:

```typescript
export function computeEstimatedDimensions(
  quadWidthPx: number,
  quadHeightPx: number,
  scaleSignal: ScaleEstimationSignal | null | undefined,
  isDoor: boolean,
  templateDefaultHeightCm: number | null | undefined,
  depthAtQuadCenter: number | null | undefined,
): DimensionEstimate {
  // Check if high-precision paper calibration is active
  const isPaperCalibrated =
    Boolean(scaleSignal?.method?.startsWith("paper_fiducial")) &&
    (scaleSignal?.best_scale_cm_per_px ?? 0) > 0 &&
    (scaleSignal?.confidence ?? 0) >= 0.65;

  if (isPaperCalibrated) {
    const scale = scaleSignal!.best_scale_cm_per_px!;
    // Ground directly on coplanar scale: zero depth correction or default height blending!
    const exactWidthCm = Math.round(quadWidthPx * scale);
    const exactHeightCm = Math.round(quadHeightPx * scale);

    return {
      widthCm: Math.max(30, Math.min(600, exactWidthCm)),
      heightCm: Math.max(30, Math.min(400, exactHeightCm)),
      confidence: scaleSignal!.confidence,
      method: scaleSignal!.method,
    };
  }

  // Fall back to existing IMP-MS10 heuristic blending...
  // ...
}
```

### 3.3 Enhanced `getScaleAwareInitialDimensions()`

```typescript
export function getScaleAwareInitialDimensions(
  scaleSignal: ScaleEstimationSignal | null | undefined,
  defaultWidthCm: number,
  defaultHeightCm: number,
  defaultOverlayWidthPx: number,
  defaultOverlayHeightPx: number,
  canvasWidthPx: number,
  canvasHeightPx: number,
  photoWidthPx?: number,
  photoHeightPx?: number,
): { widthCm: number; heightCm: number } {
  const isPaperCalibrated =
    Boolean(scaleSignal?.method?.startsWith("paper_fiducial")) &&
    (scaleSignal?.best_scale_cm_per_px ?? 0) > 0;

  if (isPaperCalibrated) {
    const scale = scaleSignal!.best_scale_cm_per_px!;
    // Proportional starting size grounded to physical scale
    const targetPxWidth = defaultOverlayWidthPx || Math.round(canvasWidthPx * 0.35);
    const targetPxHeight = defaultOverlayHeightPx || Math.round(canvasHeightPx * 0.35);

    const calculatedWidthCm = Math.round(targetPxWidth * scale);
    const calculatedHeightCm = Math.round(targetPxHeight * scale);

    return {
      widthCm: Math.max(30, Math.min(600, calculatedWidthCm)),
      heightCm: Math.max(30, Math.min(400, calculatedHeightCm)),
    };
  }

  // Fall back to template defaults...
  return { widthCm: defaultWidthCm, heightCm: defaultHeightCm };
}
```

## 4. Multi-Product Workspace Integration & Perspective Fit

### 4.1 Inheritance by Added Products

When a user adds a second product into a room (e.g. adding a sliding window next to an existing sliding door):

1. `transitionSessionState()` stages the new product definition.
2. The active room `spaceImageSession.scaleEstimation` is passed to `getScaleAwareInitialDimensions()`.
3. The newly added product initializes its width and height using the verified physical scale.
4. The product overlay is drawn at the correct physical scale relative to the room background, avoiding oversized or undersized 3D meshes.

### 4.2 Perspective Quadrilateral Fit Grounding

In `ProductModelWorkspace.tsx`, when the user confirms a 4-point perspective quad around an opening:

```typescript
if (perspectiveCorners) {
  const photoCorners = denormalizeCorners(
    perspectiveCorners,
    photoWidthPx || canvasDisplaySize.width,
    photoHeightPx || canvasDisplaySize.height,
  );
  const { widthRatio, heightRatio } = estimateDimensionsFromCorners(photoCorners);

  if (heightRatio > 0 && widthRatio > 0) {
    const estimate = computeEstimatedDimensions(
      widthRatio,
      heightRatio,
      activeScaleSignal || spaceImageSession?.scaleEstimation,
      isDoorProduct,
      null,
      null,
    );
    setWidthCm(String(estimate.widthCm));
    setHeightCm(String(estimate.heightCm));
    setOverlaySize(
      getOverlaySizeFromDimensions(String(estimate.widthCm), String(estimate.heightCm)),
    );
  }
}
```

### 5.2 Quotation Item Persistence

When the customer confirms measurements, quotation items are generated with explicit source attribution:

```typescript
const quotationItemPayload = {
  // ...
  pricing_details: {
    // ...
    dimension_source: isCalibrated ? "calibrated_visual" : "manual_tape",

```

This persistent metadata informs fabricator estimators that dimensions were physically referenced against a known standard, suppressing ocular measurement overhead and reducing on-site scrappage (`BRD-M5`, `BRD-M6`).

## 9. Risks and Mitigations

| Risk | Severity | Mitigation |
|---|---|---|
| Extreme perspective skew causes opening pixels to appear smaller than physical | Medium | Planar homography matrix rectifies projective distortion on the wall plane; dimension estimates use quadrilateral edge geometric means. |
| User inputs opening quad covering entire photo | Low | Architectural safety clamping limits maximum dimensions to 600cm width and 400cm height, preventing overflow. |
| Fabricator requires 100% mm-accurate shop drawing measurements | Low | Fabricator consultation PDF and measurement modal clearly disclose visual estimate tolerance (±2% to 5%), providing clear disclaimers while reducing initial quotation overhead. |
